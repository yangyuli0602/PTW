# V1.2.115：费用生成结果补「AI 待办契约」字段；规程拆进总则与费用分册

日期：2026-11-12　背景：外部 AI 测试反馈「读到了 warnings，但没执行 AI 分析」

## 诊断（先纠正方向）

不是「提示藏起来」：warnings 里本来就写着清单路径、结果文件名、「重新生成即生效」。
真正的问题有三条：

1. **没有机器可核对的待办**：`exp` 顶层只有 `ok/warnings/main/checks/ai/next`，
   任务藏在 `main.tasks`，且全部 `blocking=false`，`ok=true` 被当成「完成」；
2. **输出位置与货币资金不一致**：`cash` 顶层有 `tasks/blockingTasks/docHint/version`，`exp` 没有；
3. **文档缺入口**：`00_总则` 阶段5 的结清表只列货币资金 4 个 id；费用模块提示里
   指向的 `FOR_AI.md` 早已移入 `_历史/`、不在包内。

## 1. 费用生成结果补契约字段（只新增，不改计算）

`ptw.py cmd_exp` 返回新增：

| 字段 | 含义 |
|---|---|
| `tasks[]` / `blockingTasks[]` | 与 cash 同位置、同语义（费用全为 false，缺 AI 也能出稿） |
| `aiTasks[]` | 结构化待办：`id / title / target / readPath / savePath / expectCount / doneCount / status / afterDone` |
| `deliverableReady` | `blockingTasks` 空且 `aiTasks` 全部 `done` 才为 true |
| `docHint` | 该读哪一节：`文档/10_费用.md · AI 三件事`（未结清时）、`文档/00_总则.md · 阶段5` |
| `version` | 本次版本号 |

`aiTasks[].status` 四态：`pending`（结果文件不存在）/ `partial`（条数不足）/
`done`（够数）/ `unknown`（无法判定）。`main` 里也放一份，老调用方只看 main 也读得到。

任务卡本身补两个字段（`tasks.py add_task(readPath, expectCount)`）：
外部 AI 不用从 title 里正则抠条数，也不用拼清单路径。

实测：清掉三份 `*_result.json` 后 `deliverableReady=false`、三项 `pending`（3 / 17 / 13）；
写回结果文件再生成，`aiTasks` 清空、`deliverableReady=true`。

## 2. 规程拆进现有文档，不再单独建 FOR_AI.md

包内已有 `SKILL.md`（入口）+ `00_总则.md`（状态机）+ `10_费用.md`（分册），
再加一个根目录文件只会多一个入口。改法：

- `文档/00_总则.md · 阶段5`：结清表补 `exp-oar-bucket` / `exp-table2-concl` / `exp-oar-reason` 三行；
  新增一段「别只看 warnings」，说明 `aiTasks` 四态与 `deliverableReady` 的含义；
- `文档/10_费用.md · §12`：任务卡表后补「闭环五步」——生成 → 读 `aiTasks` → 写 `savePath` →
  同样参数再生成 → 验收（`aiTasks` 空、`tasks` 空、`deliverableReady=true`、无 `【待AI撰写`）；
- `SKILL.md` 三步的第 3 步：跑完先看 `aiTasks`，`deliverableReady=false` 不算完成；
- 费用模块提示里那句「发布包根目录的 FOR_AI.md 是总规程」改为指向 `文档/00_总则.md` 与 `文档/10_费用.md`。

## 3. 包内 SKILL.md 的版本号不再写死

`applies_to` 改占位符 `__VERSION__`，`build_pkg.py` 打包时替换成实际版本
（历史上出现过包是 1.2.111、文档写 1.2.105）。

## 没做的（按"不打乱现有结构"原则）

- 不改 `blocking` 默认值、不加 `--require-ai` 强制门禁：现有手工流程照旧；
- 不改 `expense.py` 的三条 AI 通道与结果侧合并逻辑；
- 不改货币资金的输出结构。
