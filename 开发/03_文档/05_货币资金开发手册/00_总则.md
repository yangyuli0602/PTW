> **这份手册是开发规格，不是给项目组的执行说明。**
> 对象：改货币资金生成逻辑的开发者与 AI。
> 与 `03_文档/_参考_货币资金口径.md` 的关系：那份是业务口径简介（对外/给项目组看），
> 本手册是逐表实现规格。**两者冲突时以本手册为准**，修完代码回头把结论回写那份。

## 2. 生成顺序（必须按此序，不可调换）

```text
① C.00 BKD   ──┬─→ ② C.00 Lead        （取 BKD 折算人民币列做 SUMIF）
               ├─→ ③ C.01b 特殊账户   （筛 BKD 其他货币资金非零行）
               ├─→ ④ C.02a 外币测算   （按 BKD 币种列 SUMIF 原币/本币）
               └─→ ⑤ C.03 Cutoff      （用 BKD 账户清单 + Lead 的 TE 定阈值）
```

理由（顺序不是排版偏好，是数据依赖）：

| 表 | 依赖谁 | 依赖什么 | 违反后果 |
|---|---|---|---|
| ② Lead | ① BKD | 科目分组金额、数据区行范围 | SUMIF 区域写错→金额打空，且 `ok` 仍返回 True |
| ③ C.01b | ① BKD | 其他货币资金明细行、账号、币种 | 账户清单与 BKD 不一致，合计对不上 |
| ④ C.02a | ① BKD | 币种列 F、原币 G、人民币 J | 差异列变成"原币×汇率−别的数" |
| ⑤ C.03 | ① BKD + ② Lead | 测试范围内的银行账户、截止期间、TE 阈值 | 阈值取空 → 全量收付被视为样本；无流水 → 样本区空 |

**① BKD 行数定稿后，后面四张表的引用区间一次性算好并落地**，不允许边插行边算区间
（`SUMIF` 区域、C.02a 的 `$F$10:$F$201` 这类区间一旦滞后就是静默错位）。

## 3. 位置一律不写死

本手册为便于核对，给出了模板实测坐标。**这些坐标是「定位结果的校验值」，不是「写入依据」。**

- 代码里必须按**表头文字 / 标签文字**定位行与列，找到后与本手册的参考坐标比对；
- 比对不上 → 报错并说明"找过哪里、按什么条件找的"，**不许跟着新位置继续跑**（模板版本差异是常态，
  坐标漂移往往意味着结构变了，硬跟着写会把数灌进说明区）；
- 多候选（同一标签出现两次，如 Lead 的科目名在表 1、表 2 各出现一次）→ 按"第几次出现"消歧，
  并把消歧依据打进日志。

模板版本差异有前科：C.01b 与 C.00b 在两版模板里位置互换过；同一张表的数据区预置行数
（BKD 6 行、C.01b 3 行、C.02a 4 行、C.03 各 5 行）也可能被客户改过。**行数一律现数，不按记忆。**

## 4. 共性取数口径

### 4.1 科目匹配

只抓三个一级科目：`库存现金` / `银行存款` / `其他货币资金`。

- 优先用余额表的 `acct_l1` 精确匹配；
- `acct_l1` 为空时兜底 `trim(acct_code)`、`trim(acct_name)` 精确匹配；
- **禁止 `LIKE '1002%'`**：会把二级明细重复抓一遍，并把名称含"银行"的无关科目带进来。

序时账判断货币资金科目用「任一命中」：科目全等 + 名称含关键字 + 编码前 4 位。
（曾用全等，`acct_l1` 全空时一条都判不进，样本区全空。）

### 4.2 多币别长表（最容易出 D 类）

余额表是「综合本位币行 + 各外币原币行」的长表。实测数据：
15 家主体、189 个账户，每个账户**恰好一行** `综合本位币`，另有 0~n 行外币原币行。

规则：

- **本币金额只取 `综合本位币` 行**（`end_debit − end_credit`）；
- **原币金额取该账户外币行**（`end_bal_fx` 或 `end_debit_fx − end_credit_fx`），币种取该行的 `currency`；
- 两者不可同时全取（本币会重复加总），也不可只取外币行（人民币账户会漏）；
- 库存现金通常无账号，会按币种拆成多行，属正常形态，不是重复。

实测校验（2026-11-05 数据包）：综合本位币 189 行合计 = 1,657,987,393.47，
BKD 192 行（库存现金按币种拆 4 行）合计同值 —— 拆行不产生重复。

### 4.3 金额字段

- 金额一律**元**，两位小数。
- 余额表 `end_bal` 在实测数据包里**整列为空**，必须用 `end_debit − end_credit`，不要依赖 `end_bal`。
- 借贷方向：资产类正常为正，出现负数不要擅自取绝对值，保留并在 Notes 说明。

### 4.4 主体

- 主体名一律用 `company_name`，为空退 `book_name`，再退 `(未标注主体)`。
- 集团多主体**不做过滤**（取数不带主体条件），单主体出报告要人工确认范围——
  这是已知边界，不是 bug。底稿里必须能看出每行属于哪个主体，否则删错一行就是事故。

### 4.5 哪张表用 H（本币）、哪张用 J（折算人民币）

两列相等的前提是折算率 = 1。外币主体填了真实折算率后，两列必然分离，用错就是假差异。

| 表 | 用哪列 | 理由 |
|---|---|---|
| C.00 Lead | **J**（折算人民币） | 要与 FS 披露闭合，口径必须统一到"人民币" |
| C.01b 特殊账户 | **J** | 与 Lead 其他货币资金行闭合 |
| C.02a 外币测算 | **H**（期末账面本币） | 本表就是验证折算，拿折算后的数去验证折算等于自证 |
| C.03 Cutoff | 流水原币 | 配对按同一币种比，不跨币种折算；无流水时无样本 |

一句话：**做汇总的用 J，验证折算的用 H。**

## 5. 插列 / 插行的硬规矩

货币资金 BKD 需要新增两列（折算率、折算人民币），这是本模块唯一需要改结构的地方。

| 规矩 | 原因 |
|---|---|
| **先解合并，再插列** | 插列只搬格子，不搬合并区；先插后解会把模板内容连同样式清成 Normal（V1.2.35 真实翻车） |
| **折算两列紧接本币列之后** | 即插在 H（本币）之后，原有 I~L 整体右移；**不许插在原币 G 与本币 H 之间**（把一对金额列劈开），也不许放到 Notes 之后（读不到） |
| 样式逐属性复制 | `nc._style = c._style` 会因 StyleArray 索引错位串样式，必须逐个 copy font/fill/border/alignment/number_format |
| 插列后同步列宽、数据验证、条件格式 | 三者都不随插列自动右移 |
| 插行用"保留版面"的方式 | 直接 `insert_rows` 不搬合并区，说明输入框会被压进数据区 |
| 行内公式统一重写 | 插行后公式不跟随，且引用要带 `$` 防拉丢 |

## 6. 公式与缓存值

**红线：程序写的公式必须同时写缓存值。** 只写公式的后果实测过——
本轮底稿 192 行金额、合计、勾稽在 `data_only` 读取下**全部为空**，任何下游校验（含人工核数）
拿不到数，只能靠人打开 Excel 重算，三方核对直接做不了。

- 公式照写（复核人要看得见算法），缓存值同步落盘；
- 缓存值必须等于该公式在 Excel 里的计算结果，不能"先写个数占位"。

## 7. 标黄与留空

- 需要人工补的位置标黄 `FFFF00`，**不填 0**、不填占位符；
- 折算率列默认 `1` 并标黄（平台没有汇率源，汇率由项目组填）；
- 未取得资料（对账单、资产证明书）留空标黄；
- 模板自带的其他客户示例数**必须清零**（这是硬伤：同页出现两套数）。

## 8. 校验不变量（每次生成后自动跑）

```text
Σ BKD 本币（H 列）        == Lead 期末账面数合计（F41）
Σ BKD 折算人民币（J 列）  == Lead 期末账面数合计（F41）        ← Lead 实际取 J 列
Lead 未审 H41             == 账面 F41 + 账表调整 G41
Lead 审定 J41             == 未审 H41 + 调整 I41
Lead Diff H45/J45/K45     == 0（A3 行填写后）
C.01b 合计 H              == BKD 其他货币资金合计（差异需解释）
C.02a 末行勾稽 G          == 0
C.03 P 列（M+I）          == 0（仅有流水样本时）
C.03 截止期间              == 以 Lead 的资产负债表日为基准前后各 N 天
```

任一不成立 → 输出「科目 / 预期 / 实际 / 可能原因」，**不许用 `+1` 或 `ROUND` 调平**。

## 9. 共用基础信息（全底稿一份，V1.2.37 起）

客户名称 / 资产负债表日 / 会计准则 / 记账本位币 / TE / SAD 不再由各模块各传各的，
统一存在 `<数据目录>/project_info.json`，由 `baseinfo.py` 读写。

| 参数 | 落点（按标签定位，非固定格） | 缺失后果 |
|---|---|---|
| 客户名称 | Lead 标签「客户名称」右侧 | 表 1 的账套名称列（`=C2`）全空，整张表没有主体 |
| 资产负债表日 | 标签「资产负债表日」右侧 | 表头单位空、C.03 截止期间无从确定 |
| TE / SAD | 标签「可容忍误差」「名义金额」右侧 | 认定阈值 D14:D18 全 0，C.03 阈值取空 |
| 会计准则 / 本位币 | 标签「适用会计准则」「记账本位币」右侧 | 封面空，`F34` 显示「货币/单位: 」 |

**两条硬规矩：**

1. **先写 C4/C5，再 `read_te_sad()`**。反了 TE 永远走兜底，整份底稿的判断阈值全错还不报错。
2. **空着比编一个值好**。没填就留空 —— 空着时 `read_te_sad` 会出 `TE_NOT_READ` 告警，看得见；
   写个假值进去，告警没了，人还以为项目组填过。

调用方式：

- 界面：底稿生成页「基础信息」卡片 → 保存为全底稿共用（`/api/build/baseinfo/save`）
- 命令行：`ptw.py cash --date … --customer … --te … --standard … --currency …`
- 代码：`baseinfo.merged(data_dir, **本次覆盖值)` → `baseinfo.fill_lead_header(wb, info)`

## 10. 数值分类（本模块逐格适用）

| 类 | 本模块典型场景 | 处理 |
|---|---|---|
| A | TB 综合本位币金额、外币原币金额、账户行 | 照取，留来源指向（表名+字段） |
| B | 上年 BKD 回捞的账号/银行、模板遗留汇率 | 保留原值 + 标注 + 进待确认清单 |
| C | 该有账号却定位不到、该有币种却空 | 视为 bug，必须修 |
| D | 本币 vs 折算人民币混用、期间口径错位、引用指向标题行 | 最高优先级，先解释再出数 |
