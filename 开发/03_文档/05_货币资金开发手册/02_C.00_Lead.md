# 02 · C.00 Lead（货币资金引导表）

> 上数方式：**公式**（SUMIF 取 BKD，其余全部链接）
> 生成顺序：**第 2 张**，依赖第 1 张 BKD 定稿
> 模板 sheet：`C.00 Lead`

## 1. 角色

Lead 是科目级汇总：把 BKD 的账户明细压成三行科目（库存现金 / 银行存款 / 其他货币资金），
做出「账面 → 未审 → 审定」的调整链，并通过 A3 / Diff 行与 TB、审定表完成三项勾稽。

它同时是**下游的唯一出口**：表2 与检查表取 `J41`（审定合计）、C.03 取 `D14/D15`（认定阈值）定测试阈值、
BKD 勾稽回指 `F41`。**Lead 的合计行一旦错位，三张表同时错。**

## 2. 表结构（模板 V7 实测，作定位校验）

### 2.1 封面区（第 2~7 行，标签在 B 列、值写 C 列）

| 标签格 | 标签文字 | 值格 | 内容 |
|---|---|---|---|
| `B2` | 客户名称 | `C2` | 客户全称（**必填**） |
| `B3` | 资产负债表日 | `C3` | 日期（**必填**，`yyyy-mm-dd`） |
| `B4` | 可容忍误差(TE) | `C4` | 金额（**必填**） |
| `B5` | 名义金额(SAD) | `C5` | 金额 |
| `B6` | 适用会计准则 | `C6` | 如「中国企业会计准则」 |
| `B7` | 记账本位币 | `C7` | 如「人民币」 |

> 注意 `D2:P7` 是合并区（右侧的 Canvas PSP 说明文字），**不能往上写**。C 列是唯一落点。

### 2.2 认定与阈值区（第 12~22 行）

| 格 | 内容 |
|---|---|
| `B13`~`E13` | 表头：认定 / CRA / 各项认定1 / 所有相关认定2 |
| `B14:B18` | 五项认定：完整性(C)、存在性(E)、计价(V)、权利和义务(R&O)、列报和披露(P&D) |
| `C14:C18` | CRA 等级，数据验证列表 `Minimal,Low,Moderate,High,N/A`，**默认必须填 `Minimal`** |
| `D14:D18` | `=IF(C14="Minimal",$C$4*100%,IF(C14="Low",…))` 按 CRA 折算 TE 的百分比 |
| `E14` | `=MIN($D$14:$D$18)` —— **Lead 的测试阈值**，被 `C30` 引用 |

> **坑：C14:C18 空着会让 `E14=0`、`D14=0`，连带 `C.03` 的阈值取到 0 或取空。**
> 默认必须写 `Minimal`，不是留空等人工填。

### 2.3 表 1（第 33~45 行）

| 行 | 内容 |
|---|---|
| 33 | `B33` = `表1`，`F33` = `\|------- TB -------\|`，`K33` = `\|------- PY -------\|` |
| 34 | `F34` = `="货币/单位: "&C7`（合并 `F34:K34`） |
| 35 | `F35` = `=C3`（本期列头，合并 `F35:J35`）；`K35` = `=DATE(YEAR($C$3)-1,12,31)`（上期列头，合并 `K35:M35`） |
| **36** | **表头行**（`B36:N36`） |
| 37~39 | 三个科目行（库存现金 / 银行存款 / 其他货币资金） |
| 41 | `E41` = `合计`，`F41:N41` 各列 `=SUM(x37:x39)` |
| 42 | `F42:K42` = `Rx` |
| 44 | `G44` = `A3`（审计确认数，值写 `H44` / `J44` / `K44`） |
| 45 | `G45` = `Diff`，`H45` = `=H41-H44`，`J45` = `=J41-J44`，`K45` = `=K41-K44` |

表头（第 36 行）：

| 列 | 表头 | 本表写法 |
|---|---|---|
| B | 账套名称/账套编码 | `=C2`（**客户名一空，整列全空**） |
| C | 总账科目编码 | `1001` / `1002` / `1012` |
| D | 科目名称 | `库存现金` / `银行存款` / `其他货币资金` |
| E | 索引号 | `C.00 BKD/` |
| F | 期末账面数 | `=SUMIF('C.00 BKD'!$C$10:$C$201,"库存现金",'C.00 BKD'!$J$10:$J$201)` |
| G | 账表调整数 | 人工/来自调整表，默认 0 |
| H | 期末未审数 | `=F+G` |
| I | 审计调整数 | `=SUMIFS(调整表金额, 调整表科目, 本行科目)` |
| J | 期末审定数 | `=H+I` |
| K | 上期末审定数 | 上年 Lead 回捞或人工 |
| L | 变动金额 | `=J-K` |
| M | 变动% | `=IF(K<>0,L/K,1)` |
| N | Notes | `[A]` 等标记 |

`O37`（判断列，表头无字）：`=IF(AND(ABS(L37)>=$C$30,ABS(M37)>=$C$31),"是","否")`
—— `$C$30`=`=E14`（阈值金额），`$C$31`=0.1（波动幅度 10%）。

### 2.4 波动说明（第 47~50 行）

`B47` = `波动说明`，`B48` = `[A]`（`B48:F50` 为输入区，合并 `B48:F50`）。
用于写本期余额与波动预期。

### 2.5 调整汇总表（第 52~57 行）

`B52` = 标题，`B53` = `调整类型`，数据验证在 `B54:B57`（`管理层账表调整(CLA), 已更正审计调整(AA/RA/OA), 未更正审计调整(SAD)`）。
不适用时模板允许删除，**但不要删表头行**（I 列的 SUMIFS 依赖该表结构）。

### 2.6 表 2 For Disclosure（第 59~71 行）

| 行 | 内容 |
|---|---|
| 59~61 | 标题 + 表头（`C61`=`=J36`，`D61`=`=K36`） |
| 62~65 | 库存现金 / 银行存款 / 其他货币资金 / 存放财务公司款项 |
| 62~64 | `C` 列 `=J37/J38/J39`，`D` 列 `=K37/K38/K39` |
| 66 | 合计 `=C62+C63+C64+C65`；勾稽 `E66`=`=C66-J41`、`F66`=`=D66-K41` |
| 67 | `C67:D67` = `Rx` |
| 68 | 其中：存放在境外的款项总额 = `SUMPRODUCT` 按币种筛 BKD 外币行 |
| 70~71 | 所有权或使用权受到限制的资产 / 货币资金 |

`C71`（受限货币资金）= **关联 BKD 的受限金额列合计格**（实测引用 `'C.00 BKD'!O203`）。

> 这个引用是**动态算出来的**：受限列按表头文字定位、合计行按数据末行定位，`O203` 只是本次 192 行的落点。
> 校验时验的是"这一格是不是 BKD 受限列的 SUM 格"，**不是验具体坐标**。
> （早期版本曾怀疑这里是硬编码，核对代码后确认不是。）

## 3. 科目行怎么定位

**不固定行号，按科目名现场找：**

- 在 `B:D` 列扫 `库存现金` / `银行存款` / `其他货币资金`；
- 表 1 取**第 1 次**出现（第 37~39 行）；
- 表 2 取**第 2 次**出现（第 62~64 行）；
- 找不到 → 报错并说明扫了哪些列、找了什么文字，**不许退回到默认行号硬写**。

「合计」有时写在 E 列、B/D 为空，扫行时要扫到 E 列（实测 `E41`、`E66`）。

## 4. 每个数怎么来

| 数 | 来源 | 口径 |
|---|---|---|
| 期末账面数 F37:F39 | `SUMIF(BKD 科目列, 本行科目, BKD **J** 列)` | **走折算人民币 J，不走本币 H** |
| 账表调整 G37:G39 | 调整表 / 人工 | 默认 0，不填 0 也不留空 |
| 未审 H | `F + G` | 模板公式，保留 |
| 审计调整 I | `SUMIFS(调整表)` | 无调整时为 0 |
| 审定 J | `H + I` | 模板公式，保留 |
| 上期末审定 K | 上年 Lead / 人工回捞 | 拿不到时留空并标黄，**不许填 0 当成"上期为 0"** |
| 变动 L | `J − K` | K 空 → L 应为空，不是"全部本期新增" |
| 变动% M | `=IF(K<>0,L/K,1)` | **模板给的是 1（=100%）**，K 空/0 时应改为空或标黄，见"已知坑" |

## 5. A3 与 Diff（勾稽核心）

- `H44`、`J44`、`K44` = 审计确认数（账面 / 审定 / 上期），**默认链接合计行**；
- `H45`、`J45`、`K45` = 三项 Diff，**必须全部为 0**；
- 不为 0 → 输出「科目 / 预期 / 实际 / 可能原因」四列，不许留个红色数字了事。

实测本版 `H44/J44/K44` 三个值全空 → `Diff = 合计 − 空 = 合计`（等于把全部余额报成差异）。
这是必须修的一项。

## 6. 校验

```text
C2 / C3 / C4 / C6 / C7 均非空
C14:C18 均非空（默认 Minimal），E14 > 0
F41 == BKD J 列合计 == BKD H 列合计（无外币时两者相等）
H41 == F41 + G41
J41 == H41 + I41
H45 == J45 == K45 == 0        （A3 填写后）
E66 == 0 且 F66 == 0          （表 2 勾稽）
F41 的 SUMIF 区域末行 == BKD 实际数据末行
C71 引用的是 BKD 受限列的 SUM 格（按定位函数产出，非固定坐标）
```

## 7. 已知坑

1. **客户名没写进 C2** → `B37='=C2'` 全空、`F34` 显示「货币/单位: 」、`K35` 上期列头算成 1900-12-31。
   一个空格带出一串错。
2. **`M` 列 `IF(K<>0,L/K,1)`**：K 为空或 0 时返回 **1**，页面上显示「变动 100%」，
   与"上期无数据"混淆。应改为 `IF(N(K)=0,"",L/K)` 并对空值标黄。
3. **表 1 / 表 2 同名科目**：必须靠"第几次出现"消歧，只按文字匹配会写到第一处。
4. **TB 勾稽行可能由两项相加**（如 `T13 + T17`）：删项会静默改变结果，改前先确认构成。
5. **`C30`=`=E14` 是波动阈值金额**，`C31`=0.1 是幅度百分比。`C31` 若被覆盖成 0，
   `O37` 判断会恒为「是」。
6. **科目行定位失败会退回写死的 37/38/39、62/63/64、68、35**（`LEAD_FALLBACK`），
   同时留 `LEAD_ROWS_DEFAULT` 告警。**这个兜底不是免死金牌**：如果客户模板不是 V7 结构，
   兜底会把数字写进错误的行，所以看到这条告警必须人工核一遍。

## 9. 关键信息 / CRA / 调整汇总表（2026-11-06 新增）

### 9.1 两张配置表写进工作簿

生成时在**最前面**插两张表：

| 表名 | 作用 | 范围 |
|---|---|---|
| `关键信息` | 客户名称 / 资产负债表日 / 会计准则 / 记账本位币 / TE / SAD | **全底稿共用一份** |
| `CRA_<科目>` | 五档 CRA 等级占 TE 的百分比 + 五项认定的等级 | **本类底稿专用**（货币资金一张、费用一张） |

为什么要进工作簿：底稿一旦离开项目组，没人说得清它用的是哪套 TE、哪套 CRA。
写进表里，底稿自带出处；改百分比也只改这一处。

> `关键信息` 表只是**留档 + 导出源**。改它不会回写 PTW——要改请到平台「基础信息」改，
> 再重新生成。这一句也写在表里第 11 行，避免有人改错地方。

### 9.2 CRA 阈值公式改为查表

模板原公式（写死百分比）：

```text
=IF(C14="Minimal",$C$4*100%,IF(C14="Low",$C$4*75%,IF(C14="Moderate",$C$4*50%,
  IF(C14="High",$C$4*25%,IF(C14="N/A","-","")))))
```

现在：

```text
=IF($C14="","",IF($C14="N/A","-",
  IFERROR(VLOOKUP($C14,'CRA_货币资金'!$A$4:$B$8,2,FALSE)*$C$4,"")))
```

- 百分比只存在 `CRA_<科目>` 表 A4:B8，改表即生效，不用再逐格改五个嵌套 IF；
- 乘的 TE 单元格**按「可容忍误差」标签现找**，不写死 `$C$4`（换版模板 TE 行一挪就会乘错格子）；
- `C` 列为空 → `D` 返回空，与模板原行为一致，**不替项目组编风险等级**；
- 每类底稿查各自的表（`CRA_货币资金` / 将来的 `CRA_费用`），互不覆盖。

### 9.3 调整汇总表（五列）

模板原来只有 B 列一个「调整类型」表头，金额无处可填，表1 的 I 列只能手工抄。现在：

| 列 | 内容 |
|---|---|
| B | 调整类型（保留模板数据验证：CLA / AA·RA·OA / SAD） |
| C | 主体 |
| D | 调整说明 |
| E | **科目名称**（表1 的行靠它匹配） |
| F | 调整金额 |

表1 的 `I` 列（审计调整数）改为：

```text
=SUMIFS($F$54:$F$57,$E$54:$E$57,$D37)
```

**条件只用科目名称**，不带调整类型：调整类型是给人判断的标签，决定这笔钱落哪一行的是科目；
把类型也塞进条件，同一科目分两条写就会少算。

### 9.4 校验补充

```text
Lead D14:D18 公式引用的表名 == 实际存在的 CRA_<科目> 表
CRA 表 A4:B8 覆盖 Minimal/Low/Moderate/High（N/A 为「-」）
C 列为空时 D 列必须为空（不许出现默认阈值）
表1 I 列 == SUMIFS(调整金额, 科目名称, 本行科目)
调整汇总表表头五列齐全，且 E 列（科目名称）与表1 D 列用词一致
```

### 9.5 上年 Lead 作为一张表（2026-11-06）

平台「上年度 Lead」上传入口（与「上年底稿 BKD」并列）。上传后：

| 动作 | 说明 |
|---|---|
| 嵌入 `上年 C.00 Lead` | 只搬两块：表1「科目名称 / 期末审定数」、表2「报表科目 / 期末审定数」，纯数值无公式 |
| 表1 `K` 列 | `=SUMIF('上年 C.00 Lead'!$B$4:$B$n,$D37,'上年 C.00 Lead'!$C$4:$C$n)` —— **按科目名**，不按行号 |
| 表2 `D` 列 | 同上，按「报表科目」名链接 |
| 上年有、本年没有的科目 | **自动插行**（定期存款、存放财务公司款项…），插在最后一个科目行之后 |

插行后必须补三处，否则表会坏（都已实现）：

1. `_lead_insert_subjects` 先拆掉下方所有合并区，插完按 +n 重挂——openpyxl 的
   `insert_rows` 只搬格子不搬合并区，不处理会把「波动说明」和表2 压掉；
2. 表1 合计行公式整行重写（模板的 `SUM(F37:F39)` 覆盖不到新行）；
3. `_fix_lead_after_insert` 重写表2 合计（原 `=C62+C63+C64+C65` 会指到表头，算出 `#VALUE!`）
   与 Diff 行（原 `=H41-H44` 指向错位后的合计与 A3）。

> 踩过的坑：新行映射写成 `last + i`，正确的是 `last + 1 + i`（新行插在 last **之后**），
> 差一行会让「其他货币资金」整行被覆盖成「定期存款」，而金额看着仍然有数。

上传入口的字段：前端 `prior_lead_fid`；命令行 `--prior-lead <path>`。

### 9.6 合计行与表2 合计：列按表头定位、空值不造假数（2026-11-06）

插行后模板公式的引用不会跟着挪，三处必须重写（`_rewrite_lead_total` / `_rewrite_lead_disclosure`）：

| 位置 | 模板原样 | 重写为 |
|---|---|---|
| 表1 合计 F~变动金额 | `=SUM(F37:F39)` | `=SUM(F37:F<最后一个科目行>)` |
| 表1 变动% | `=IF(K41<>0,L41/K41,1)` | 列按表头「变动%」定位；**上期为 0 时留空**，不再回落成 1（100%） |
| 表1 是否重大波动 | `=IF(AND(ABS(L41)>=…,ABS(M41)>=…),"是","否")` | 前面加 `IF(OR(L="",M=""),"")` —— 变动% 为空时 `ABS("")` 是 `#VALUE!` |
| 表2 合计 C/D | `=C62+C63+C64+C65` | `=SUM(C<首行>:C<合计行-1>)`，覆盖到「存放财务公司款项」 |
| 表2 Check E/F | `=C66-J41` | `=C<合计>-J<表1合计>`、`=D<合计>-K<表1合计>` |

**列号一律按表头文字定位**（`_lead_cols`：期末账面数 / 账表调整数 / 期末未审数 / 审计调整数 /
期末审定数 / 上期末审定数 / 变动金额 / 变动%）；「是否」列模板没有表头，按「公式里同时有 是 和 否」
认（`_lead_flag_col`）。

> **踩过的坑（本次线上报错）**：合计行重写时把列号写死成 12/13，于是
> `L43 = IF(K43<>0, L43/K43, 1)`——自己引用自己。Excel 一打开就弹「循环引用」，
> 整张表算不出数。列号写死一个格子，代价是整份底稿不可用。

> **第二个坑**：插进来的上年科目只复制了样式、没带公式，`变动金额/变动%` 整行空白，
> 变动分析直接断。现在 `1.5) 科目行公式补全` 会对**每一行**补
> `H=F+G`、`J=H+I`、`L=J-K`、`M=L/K`、`O=是否`。

> **第三个坑**：表2 的 `=C62+C63+C64+C65` 是写死的四行，而 V7 模板表2 实际有
> 「存放财务公司款项」那一行，位置在合计行上方——写死后合计少算它。

### 9.7 插行后条件格式与数据验证必须一起平移（2026-11-06）

openpyxl 的 `insert_rows` **只搬单元格**：值、样式、合并区之外，**条件格式（sqref）和数据验证
（dataValidation.sqref）一格都不动**。所以插完行必须调 `_shift_marks_after_insert(ws, anchor, n)`。

不平移的后果，全是"看得见、但不报错"：

| 区域 | 不平移时 | 平以后 |
|---|---|---|
| `O37:O39` / `P37:P39` / `F37:F39` / `B37:D39` / `K37:K39` | 新增的「定期存款」「存放财务公司款项」两行没有空白高亮，合计行反倒有 | `37:41`，合计行高亮移到 `O43` / `P43` |
| `C68:D68`（表2 境外款项） | 高亮停在表2 的科目行上 | `C70:D70` |
| `C71:D71`（受限货币资金） | 同上 | `C73:D73` |
| `B48:B49`（波动说明输入框） | 高亮比输入框高一行 | `B50:B51` |
| 数据验证 `P37:P39 P41`（是否重大波动） | 下拉少两行，且最后一个下拉落在科目行 | `P37:P41 P43` |
| 数据验证 `B54:B57`（调整类型） | **表头也有下拉、最后两行没有**，选的时候才发现 | `B56:B59` |

规则很简单：**整段在插入点之下就 +n；末行正好等于插入点（被撑开的那块）就只把末行 +n**。

> 这一条同样适用于 BKD 之外的任何插行场景（费用、长期资产）。判断标准只有一句：
> **凡是"区域"（conditional_formatting / dataValidation / merged_cells / print_area），插行后都要检查。**

### 9.5.1 上年 BKD 与上年 Lead 的选表方式完全一致（2026-11-06）

上传上年底稿后，第 2 步会出现**两组外观、写法、交互完全相同**的控件：

```
上年 BKD 明细工作表  [ C.00 BKD（推荐） ▾ ]   该表表头所在行 [ 9 ]
账号列 E 账号1   金额列 H 本币   状态 已识别为 BKD 明细

上年 Lead 工作表     [ C.00 Lead（推荐） ▾ ]   该表表头所在行 [ 13 ]
科目行 5 行   读到审定数 5 格   状态 已识别为 Lead
```

- 两组下拉都列出**全部工作表**，推荐的标「（推荐）」、识别不出的标「（未识别）」；
- 两组都允许改表头行；改完立刻按新行重新判断，状态行跟着变；
- 传参同构：`prior_spec = {sheet, header_row, lead:{sheet, header_row}}`，
  顶层两个键仍是 BKD 的（向后兼容老调用），`lead` 是新增的；
- **指定了就必须用指定的**：`_parse_prior_lead_bytes(data, spec)` 收到 sheet 就只读那张，
  读不到直接返回错误（含具体行号或可用表名），**不再回退到自动择优**——否则用户改了
  却没用上，比不给选更糟。

选错的后果与提示：

| 情况 | 表现 |
|---|---|
| 下拉里选了没有 Lead 表头的表 | 面板立刻黄条提示；生成时结果页红字「上年 Lead 未使用…」 |
| 表头行填错 | 生成时红字给出「工作表 X 第 N 行找不到…」 |
| 不选（默认推荐） | 与旧行为一致：按"读到审定数最多"自动挑 |

`_prior_plan` 为此多返回 `leadHeaderRow / leadRows / leadAmountCells / leadUsable`
与 `leadRecommended` 五个字段，供前端标推荐项与状态行。

### 9.5.2 上年 Lead 整表复制 + 动态范围识别（2026-11-06）

**做法变了**：以前只把「科目名 + 期末审定数」拼成两列放进新表；现在把上年 Lead
**整张表**复制进本年工作簿（表名 `上年 C.00 Lead`），封面、认定区、波动说明、表1、
调整汇总表、表2 全部原样保留，**所有公式换成计算后的数值**。

#### 复制的范围

| 复制项 | 说明 |
|---|---|
| 单元格值 | 取 `data_only=True` 的缓存值；公式没有缓存值时留空，**绝不把上年公式搬进来** |
| 字体 / 填充 / 边框 / 对齐 / 数字格式 | 逐属性复制（不能照搬 `_style` 索引，跨簿会串样式） |
| 合并区 | 单元格级复制后重新 merge（openpyxl 的 insert/复制都不搬合并区） |
| 列宽 / 行高 | **按 min..max 区间展开**（源文件是 `C~J` 共用一个宽度、`T` 一直到 16384）；只按字典键复制会只生效第一列，其余列退回默认宽，数字挤成 `####` |
| 条件格式 / 数据验证 | 逐条重建（dxf 是工作簿级的，直接搬对象不会进本簿样式表） |
| 冻结、网格线、缩放、页面设置、默认行高列宽 | 一并照抄 |

#### 范围怎么定（全部现算，不写死行列）

```text
表1 表头行  = 第一行同时含「科目名称」与「上期末审定数」，且不含「报表科目」
表1 各列    = 按表头文字映射（期末账面数/账表调整数/期末未审数/审计调整数/
              期末审定数/上期末审定数/变动金额/变动%/Notes）；
              「期末审定数」必须排除含「上期」的表头，否则会认到「上期末审定数」列
表1 数据区  = 表头行+1 起，遇到科目列含「合计」即止，该行就是合计行；
              连续两行科目列为空也视为结束（防止一路吃到表2）
表2 表头行  = 第一行同时含「报表科目」与「上期末审定数」
表2 数据区  = 同上规则，科目列换成「报表科目」
```

真实样本（`BKD脱敏.xlsx`，表名就叫 `Sheet1`）跑出来的索引：表1 表头 37、数据 38–45、
合计 47；表2 表头 86、数据 87–95、合计 96——和模板的 36/37–39/41 完全不同，
靠写死行号必然错位。

#### 由此带来的两个行为变化

1. **表1 与表2 会同步补行**：上年有、本年模板没有的科目（定期存款（流动/非流动）、
   大额存单（流动/非流动）、受限资金）在表1、表2 都插入，插在各自合计行之前；
   插完重新定位并平移条件格式/数据验证（`_shift_marks_after_insert`）。
2. **上年数用 SUMIF 按科目名取**，指向复制表的动态区间：
   `K37 = SUMIF('上年 C.00 Lead'!$D$38:$D$45, $D37, '上年 C.00 Lead'!$J$38:$J$45)`
   （取上年「期末审定数」＝本年的上期末）；表2 同理指向 `$B$87:$B$95 / $C$87:$C$95`。

> 选表也不再按表名过滤：真实文件常常就叫 `Sheet1`。现在扫描全部工作表，
> 谁读到的审定数条数多就用谁，表名带 `lead` 的只加一点点权重。
