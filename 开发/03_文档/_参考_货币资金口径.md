## 2. 取数口径（金额对不对全靠这）

只抓**一级科目** = 库存现金 / 银行存款 / 其他货币资金 的行：

- 用 `acct_l1` 精确匹配；`acct_l1` 为空时兜底 `trim(acct_code)` / `trim(acct_name)` 精确匹配
- **不用 `LIKE '1002%'`** —— 会把二级明细重复抓一遍、把名称含「银行」的无关科目带进来
- 多币别余额表的「综合本位币」汇总行与各外币行**不能同时全取**（本币会重复加总）

**综合本位币怎么处理，由清洗配方决定（平台取数层只做防御）**：

| 清洗里配的动作 | 底稿结果 | 适用 |
|---|---|---|
| `drop_base_cur` 删除综合本位币行 | 用分币别明细上数，**有原币与折算列** | 客户导了两种视图（默认推荐） |
| `keep_base_cur` 只保留综合本位币行 | 按汇总层上数，**没有原币明细列** | 客户只导了汇总视图 / 项目组决定按汇总层出稿 |

- 两个都不能不配：并存时平台取数会排除汇总行；若整表只有汇总层，会取不到账户并明确提示去配这两个动作之一。
- 取数报错会**分因**说清（一级科目未派生 / 全为综合本位币层 / 全是核算维度=合计的汇总行 / 确实没有货币资金科目），不再统一说"请确认一级科目"。
- 序时账判断货币资金科目用「任一命中」：全等 + 名称含关键字 + 编码取前 4 位
  （曾用全等，`acct_l1` 全空时一条都判不进，样本区全空）

## 3. C.00 BKD

**写入**：主体、科目（银行存款 / 其他货币资金）、银行、币种、原币金额、本币金额（人民币列）、
是否函证、Notes、受限资金（人工列）。

- **0 余额、本年销户账户必须保留**（完整性证据），销户信息写 Notes。
- 上年有、本年无的账户也要进表（金额 0 + Notes 说明），否则证明不了「销户都包含了」。
- 上年同账户的账号 / 银行用「科目 + 银行」回捞；取不到留空，**不生成新编号**。
- 账号单元格设 `@` 文本格式（防前导零丢失）；金额 `#,##0.00`；日期 `yyyy-mm-dd`。
- 合计 = `SUM(本币列 dataStart:dataEnd)`，必须等于 Lead 期末账面数合计。
- 银行存款的「是否函证」恒为「是」，不标黄；其他货币资金才需要判断。

**外币折算**：BKD 右侧两列「折算率」（人工，默认 1）/「折算人民币」（公式 = 本币 × 率）。
折算列接在模板已用列最右，**绝不插进模板中间**。合计、勾稽、Lead 的 SUMIF 全部走折算人民币。
外币主体拿本币去勾稽必现假差异——这是口径不同，不是错。

## 4. C.00 Lead

科目行（库存现金 / 银行存款 / 其他货币资金 / 定期存款 / 大额存单 / 受限资金）由模板固定语义，
**不固定行号**——用 `locate_lead_rows()` 按科目名现场找（表 1 取第 1 次出现、表 2 取第 2 次）。

- `期末账面数 = SUMIFS(BKD 本币, BKD 科目, 本行科目)`
- `审计调整 = SUMIFS(调整表金额, 调整表科目, 本行科目)`
- `未审 = 账面 + 账表调整`；`审定 = 未审 + 调整`；`变动 = 审定 − 上期`；`变动% = 变动 / 上期`
- TB 勾稽行链接 console TB 的对应格，**可能由两项相加**（如 `T13 + T17`），删项会静默改变结果
- **封面必须写**：C2 客户名称、C3 资产负债表日、C6 适用会计准则、C7 记账本位币
  （参数已传但没写进文件时，表头显示「货币/单位: 」、日期空白）
- **A3 行**：审计确认数，默认链接合计；**Diff 行必须为 0**，不为 0 输出「科目 / 预期 / 实际 / 可能原因」

行号定位的坑（都是**静默错位**，`ok` 仍返回 True）：

- 「合计」有时写在 E 列、B/D 是空的 → 扫行时要扫到 E 列
- 境外资金找「存放在境外」、日期行找 F 列 `=C3`
- 定不到就退回默认行号并告警，`main.leadRows` 会报写到哪几行

## 5. 派生表

| 表 | 规则 |
|---|---|
| C.01b | 取 BKD 中「其他货币资金且非零」的平台账户；对账单未取得 → 留空标黄；差异列用 `IF(I="","",I-G)`（直接 `=I-G` 会在 I 空时算出「差异 = −账面」） |
| C.00b | 先判模板是「明细式」还是「结论式」。结论式：现金 = Lead(银行存款 + 其他货币资金)；现金等价物按判断填 N/A 或明细；H44/H45 勾稽 |
| C.02 | **先判断有无调节项**。无 → 结论 + 表 1.2/1.3 填 N/A；有 → 按账户填表 1.1 并双向核对（企收银未收 / 银收企未收）。**没有客户对账单时，自动下「无调节项」属禁止动作** |
| C.02a | 按币种 `SUMIF` 原币与本币；差异 = 原币 × 汇率 − 本币；末行勾稽 BKD 合计 = 0。**F 列用「期末账面金额（本币）」**，不是折算人民币。汇率取人行当日中间价，并把该日公告页截图自动嵌到 Notes 下方（见 `08_货币资金_C02a.md`） |
| C.01 Confirmations | 函证清单默认**不自动生成**（要收件人、地址、函证方式），工具留骨架 |

**按表号解析、不按序号**：C.01b 与 C.00b 在两版模板里位置互换过。表号取「第一个空白/中文前的字符段」
精确比对，否则 `C.02` 会把 `C.02a` 一起吃掉。模板没有该表就跳过并记理由，**绝不新建 sheet**。

## 7. C.03 Cutoff 截止性测试

**表 1.1**：B7 = 测试阈值（覆盖原公式）、B8 = 资产负债表日、B11:F13 = 说明文字（自动生成，末尾留人工补理由）。
**表 1.2**：期末前数据区第 20–24 行、期末后第 29–33 行（各预置 5 行，超出自动插行并复制样式/行高/条件格式/数据验证）。

**列位**：B 样本号 / C 公司 / D 付款银行 / E 付款账号 / F 付款日期 / G 凭证号 / H 币种 /
I 付款金额(负) / J 收款银行 / K 收款账号 / L 收款日期 / M 收款金额(正) / N 是否跨期 / O 备注 / P `=M+I`

**数据来源：银行流水，不是序时账。**

序时账只有科目、凭证号、金额，看不到收付款双方与到账时间；靠「同凭证号一借一贷」或
「跨日金额相等」凑配对，凑出来的是推测——内部调拨、同一账户的两笔不同业务都可能被凑成一对。
截止性测试要证的是「钱什么时候真正进出银行」，只有对账单口径的流水能证。

**当前状态（2026-11-06）**：平台尚未接入流水数据源，本期 C.03 只写参数
（`B7` 阈值、`B8` 资产负债表日）与 `B11` 说明，**样本区留空**，且不写「未识别到转账」——
那会被当成"已经测过、确实没有"。这是有意的空，接入流水后按下面口径补：

1. 账户范围同 BKD（主体 + 账号 + 币种），按截止期间切片
2. 按「主体 + 金额 + 日期」找同一笔资金的两条流水（一出、一进，账号不同）
3. 归表按**付款方日期** ≤ 截止日 → 期末前，> 截止日 → 期末后
4. 配不上的单边流水进「单边清单」留档，不许悄悄丢

## 8. 校验不变量

```text
Σ BKD 本币            == Lead 期末账面数合计
Σ BKD 受限列          == Lead 受限资金调整行
Lead 未审             == Lead 账面 + 账表调整
Lead 审定             == Lead 未审 + 调整
Lead TB Diff          == 0（账面 / 审定 / 上期三项）
C.01b 合计            == BKD 其他货币资金 − 已单独列示的受限/保证金（差异需解释）
C.00b 现金总额        == Lead(银行存款 + 其他货币资金)   仅结论式模板
C.02 调节后差异       == 0
C.02a 勾稽            == 0
C.03 P 列（M+I）      == 0        （仅在接入流水、有样本时适用）
```

## 10. 已知边界

- **集团多主体不做过滤**：取数不带主体条件，多公司账套会全部塞进一张底稿。
  单主体出报告要手删其它主体，删错一行就是事故——**出报告前必须人工确认主体范围**。
- 受限资金识别、受限重分类、C.01b 范围、C.00b 结论、C.02 调节项结论 = **C 级（只准备不落笔）**。
- 不做 `+1` / `ROUND` 调平；差额必须解释，未取得资料留空标黄 `FFFF00`，不填 0。
- 折算率列（BKD I 列）是人工判断列，默认 1，按主体填资产负债表日汇率；
  但 **C.02a 的汇率不用人填**：V1.2.92 起按资产负债表日现查人行公告页取中间价，
  并自动截图嵌入（找不到公告页/无浏览器/该日无公告时才留任务卡，见 `08_货币资金_C02a.md`）。
