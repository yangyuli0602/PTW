# V1.2.110：折算汇率改为 XLOOKUP 客户「公司mapping」的两列汇率

日期：2026-11-12　对象：瑞云 RAYCLOUD 1-9 月

## 需求

客户「公司mapping」表按公司给了两列汇率（余额汇率 / 损益汇率），不同科目用不同汇率；
BKD 的折算汇率、两个样本池的折算率都不要再写死 6.8454，改成 XLOOKUP 那张表。

## 做法

1. **整表搬进底稿**：生成时把 PBC「公司mapping」原封不动复制成新 sheet `公司mapping`
   （编号/简称/全称/2026账簿名称/2025账簿名称 + 客户自己的汇率列），
   放在 `口径Mapping` 后面。按表头文字找列，客户加列不用改代码。
2. **BKD 折算汇率列**：`=IFERROR(XLOOKUP($B30,'公司mapping'!$C$2:$C$23,'公司mapping'!$G$2:$G$23),1)`
   - 取哪一列由科目判定：`rate_kind_of()`，含 存款/借款/应收/应付/预付/预收/货币资金 等 → 余额汇率，其余 → 损益汇率；
   - 费用表实际全部走「损益汇率」。
3. **两个样本池的折算率列**：`=本币/原币 × IFERROR(XLOOKUP(主体,...,损益汇率),1)`，
   与 BKD 同源，池子 1.1 总体继续等于 BKD 合计。
4. **Python 侧同源**：汇率列是公式，openpyxl 读不到值，`aud_amount()` / OAR 汇总按同一份
   mapping（`rate_of()`）再取一次；生成时把 sheet 上实际生效的汇率同步进内存。
5. **没填汇率的兜底**：客户表缺这两列时，生成时补两列并预填（外币主体 6.8454、人民币 1）；
   某主体汇率为空/为 0 时列进 `rateMissing` 上报，不静默按 1 算。

## 验证（瑞云 1-9 月）

| 项 | 结果 |
|---|---|
| 客户表两列汇率 | 香港/新加坡 余额 6.7351、损益 6.8454；人民币主体 1 |
| BKD 汇率列 | XLOOKUP 公式，取值 6.8454（损益列） |
| 池子折算率 | 同一条 XLOOKUP，新加坡行 6.8454 |
| 审定（VC/VD） | 42,792,685.73 / 32,506,012.64（与改前一致） |
| 池子合计 = BKD 审定 | 75,298,698.37 |
| TOD 1.1 check | 0 / 0 / 0 |
| Excel 全量重算错误值 | 234（模板基线） |
| rateMissing | 空 |

## 注意

- 上期列是**上期人民币**，本版不做折算（用户 2026-11-12 明确）。
- 平台读的是**导入时的副本**（`_files.path`），把还原目录里的新版文件覆盖上去不会自动生效，
  需要在平台重新导入该文件。

## 修正（V1.2.111）：不再单独建「公司mapping」页，汇率并进「口径Mapping」公司段

单独一张 sheet 是多余的一层：口径Mapping 本身就按主体列了「主体全称 / 简称 / 备注」，
汇率本来就该落在这一段，而不是另开一页。

- 「口径Mapping」公司段由三列扩到五列：`H 主体全称 / I 简称 / J 备注 / K 余额汇率（本币-人民币） / L 损益汇率（本币-人民币）`，
  两列汇率取自客户 PBC 的「公司mapping.xlsx」，生成时就带上，来源仍写 `PBC 公司mapping`。
- BKD 折算汇率列、两个样本池（TOD / cut off）的折算率列，XLOOKUP 全部指向
  `口径Mapping!$H$6:$H$23` → 余额列（K）或损益列（L），按科目判定走哪列。
- `find_company_map_ref()` 改为在「口径Mapping」里按表头文字找公司段（含「主体全称」且含「汇率」的那一行），
  数据区取连续有主体名的行，不写死行号。
- 客户表缺汇率时，按外币主体 6.8454 / 人民币主体 1 补齐并在备注里写明，缺的列进 `rateMissing` 上报。
