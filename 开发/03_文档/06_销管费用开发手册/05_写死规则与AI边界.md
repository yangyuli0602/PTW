# 05 · 写死 vs 灵活 vs AI 分工（模板 → 最终版的全量盘点）

> 回答三个问题：哪些是写死的（还能再分「写死列」「写死单元格」）？哪些是运行时现场定位的？
> 哪些环节必须把 PTW 自带提示词交给 AI？
> 依据：`expense.py` / `expense_cutoff.py` / `expense_tod.py` / `expense_oar.py` / `oar_map.py` 现状 + 基准底稿实测。

## 0. 一句话结论

**结构写死、内容灵活、判断分层**：
- **写死**的是模板给的结构（列语义、固定行、固定格）与业务口径词表；
- **灵活**的是行数（明细/口径段/样本）、页底位置、合计行、sheet 名；
- **AI 只在两个地方出手**：口径该归哪类、变动原因是什么。抽样、属性测试、异常解释都不归 AI，也不归工具，归人。

## 3. 灵活区域（运行时现场定位 / 动态生成）

| 区域 | 怎么定 |
|---|---|
| BKD 表头行与关键列 | 正则扫前 60 行 × 前 30 列，命中 ≥3 个字段才算表头；`book / name / amount / prior` 缺一不可（`_locate`） |
| BKD 明细起止 | 表头行 +1 ~ 合计行 −1；**合计行按 D 列出现「合计」定位**，不按固定行 |
| BKD 页底 / 蓝带 | 认「B~H 列 ≥5 格深蓝」的横带，不扫装饰列（S 列整列深蓝） |
| BKD 表1 口径行数 | = 实际口径数，按 \|金额\| 降序；随后 `合计 / A3 / check` 三行 |
| BKD 表2 段数 | = 达阈值口径数 + 未超范围的说明行；段落数随数据变 |
| BKD 表3 分录行数 | = 实际调整分录数（模板预留 20 行，不够再插） |
| TOD 表1 明细 | 容量 14 行，超出**整行插入**并逐格复制样式 |
| TOD 负值明细 | 容量 3 行，超出插入 |
| 01.4 表3 | 容量 5 + 5，超出在日后标题前整行插入 |
| 样本池行数 | = 序时账全量（本期 + 日后 30 天），基准 10,709 行 |
| sheet 名 | 写死中文名（`VC.00 销售费用BKD`、`样本池-TOD`…），改了要同步常量与所有跨表公式 |

> 一句话：**行可以长，列不能动**。行数一律动态；列位置只认「表头文字 + 从金额列起算的固定偏移」。

## 4. 写死的判定规则（业务口径，藏在代码里的"经验"）

| # | 规则 | 写死的程度 |
|---|---|---|
| 1 | 结转损益 = 凭证含 4103/4104 **或** 摘要 ∈ {结转本期损益, 结转损益, 期间损益结转} | 完全写死（不用裸「结转」，避免误删真实费用） |
| 2 | 科目性质顺序：股权激励 → 折旧摊销 → 薪酬 → 租赁 | 顺序写死，反了会归错 |
| 3 | 折旧摊销按资产类型拆四类（使用权 / 无形资产 / 长期待摊 / 固定资产） | 关键词写死 |
| 4 | 预提冲销 = 同主体 + 同科目码 + 同\|金额\| 一正一负，下限 100 元，只在未排除行间配 | 写死 |
| 5 | 负值必须最后判（性质都归完才进负值桶） | 顺序写死 |
| 6 | P 列 X-ref：无形资产 → 长期待摊 → 使用权资产 → 固定资产 → 应付职工薪酬，日期跟资产负债表日 | 六组关键词写死 |
| 7 | T 列口径三组词（薪酬 / 折旧摊销 / 广告费）+ 未命中且 ≥100 万时用科目名单列，其余「其他」 | 写死；换客户容易失准 |
| 8 | 阈值：C22 = TE×50%、C23 = 10%、SAD 缺省 = TE×10%、关键项/截止性门槛同为 TE×50% | 写死（系数） |
| 9 | 抽样ID `TOD-%04d`，覆盖剔除项之外全部本期样本，按台账序不按金额 | 写死 |
| 10 | NB 编号判据用 OR（金额或比率任一超），明细行 Q 列用 AND | 写死（两种口径并存，故意的） |
| 11 | 表2 叙述模板句的档位：0.95 / 0.85 / 0.60 / 0.40 / 0.45 / 0.20，金额一律千元 | 写死 |
| 12 | 一次性事项词表（上市、IPO、股权激励、股份支付、减值、重组、清算…） | 写死 |

**这些是最该被配置化、但目前写死的部分。** 换客户出问题，八成落在这 12 条里的第 3、6、7、11、12 条。

## 5. AI 参与点（必须用 PTW 自带提示词）

### 5.0 上年口径怎么来的（V1.2.87 两级读取）

```
① 上年底稿的「口径Mapping」页   —— 上年已定论，主体是公司全称、值是静态文本（最干净）
② 上年 BKD 的「OAR 口径」列      —— 键是账簿名（要 book_map 折）、值可能是公式（无缓存就空）
③ 两级都没有 → 规则建议（黄底）+ 进待办清单，等 AI 判
```

- 识别靠表头内容：同时有「科目名称」「OAR 口径」，且**没有**「账套/账簿」→ mapping 页；
  有「账套/账簿」→ BKD 页。说明行（一句话图例）里也含这些词，所以必须**整格等于**表头词才算表头。
- 两层的来源统一写**「上年底稿」**；同名科目跨主体沿用的线索放备注列，不占来源列。
- 上年 mapping 里来源为「规则推导-待AI复核」的行**跳过**：那是去年的猜测，沿用它等于把猜测传下去。
- 值与该客户 `oar_map_ai.json` 里已确认的一致时，来源仍写「由AI判断」并带出依据与置信度 ——
  值没变，可信度信息不该因为"上年 mapping 里也有这行"就丢。

### 5.1 唯一"必须 AI 判断"的环节：OAR 口径归类

```
ptw.py oarmap-draft --out pending.json          → 导出「本年新增-待判断」清单
AI 读 03_文档/AI提示词_口径判断.md 逐条判定       → {"items":[{company,name,bucket,reason}]}
ptw.py oarmap-fill --file ai_result.json        → 落 data/bkd_work/oar_map_ai.json（跨年沿用）
```

- 提示词是**判定行为本体**，不许压缩、不许摘要；要改就改源头 md
- 结果写回 → BKD 的 T 列（双层 XLOOKUP：主体\|科目 → 科目名兜底）
- 硬约束：**同类必须归并**（差旅费_* / 办公费_* / 运输费_* 全进「其他」），否则 5 个口径会变成 35 个

### 5.2 第二个 AI 环节：OAR 变动原因结论（V1.2.83 重做）

```
ptw.py exp … --ai-out ai_pending.json     → 导出 oarReason.items（每个口径 + 序时账证据）
AI 按 instruction 写 80~140 字            → {"oarReason":{"items":[{label,bucket,text}]}}
ptw.py ai-fill --file ai_result.json --xlsx 底稿.xlsx
```

- **证据按口径的 `subjects` 合并取**（`_cand_evidence`）：证据字典的键是**科目名**，
  拿口径名去查永远查不到 —— V1.2.82 及以前导出的 `groups` 一直是空数组，所以 AI 只能写空话
- 每项给到 12 组：对手方 / 业务性质 / 单笔摘要 / 金额 / 占本口径比重，AI 才写得具体
- 回填只替换公式**最后那段字符串**，金额与比例仍走 `TEXT()` 公式；未写的段落保留占位符
  `【待AI撰写：变动原因需结合业务判断】` 并**标黄**
- 结论落 `<data>/bkd_work/oar_concl.json`，重新生成自动带上（与表2 的 `table2_concl.json` 同机制）
- 上期数从「上期BKD」页按**账套名称 + 科目编码**取实体值：BKD 的上期列是 SUMIFS 公式，
  openpyxl 读回字符串，会让「有没有上期」永远判成没有，句子就写「上期无数据」而表上有数

### 5.4 三张任务卡：让"另一台电脑的 AI"也知道该干什么（V1.2.87）

参照货币资金 C.02a「汇率公告截图」那套（`derived._fx_shot_task`）：**任务卡自包含**——
读哪个文件、写哪个文件、什么格式、允许什么值、怎么自检、写完怎么生效，全部写死；
AI 没有任何项目上下文，照着卡也能做完。

生成时（`expense._export_ai_tasks`）自动写三份清单 + 登记 `tasks[]`（`blocking=false`）：

| 任务 id | 清单（`<data>/bkd_work/ai_tasks/`） | AI 写到这里 | 结清判据 |
|---|---|---|---|
| `exp-oar-bucket` | `oar_bucket_pending.json` | `oar_map_ai_result.json` | 口径不再是「规则推导」黄底 |
| `exp-table2-concl` | `table2_pending.json` | `table2_concl_result.json` | 表2 段换成 AI 文字；格批注消失 |
| `exp-oar-reason` | `oar_reason_pending.json` | `oar_concl_result.json` | OAR 分析段换成 AI 文字 |

- **结果侧文件是旁路**：`load_ai_map_all` / `load_table2_concl` / `load_conclusions` 会把它合并进来
  （侧文件优先），所以 AI 只要把 JSON 放到那个路径、**重新生成一次**即可，不用跑任何命令、不改正本。
- 已经有 AI 文字的口径不再进清单 → 任务做完一件少一条，`tasks[]` 为空即全部结清。
- 底稿里也留同一张卡：表2 分析段与 OAR 分析段的**格批注**（打开就看到），
  口径Mapping 黄底行的备注列指向清单路径。
- 三条任务都不阻断出稿：缺 AI 时数字全对、文字退化成规则描述，只是要人补。

### 5.5 落在别的模块的提示词

- `03_清洗达标提示词.md`：导入清洗阶段判「清洗是否到位」，**不属本模块**，但它的输出决定进 `journal` 的数据质量。

## 6. AI 缺席会怎样（实测）

拿海柔数据跑过一次，`data/bkd_out/OAR_evidence_费用.json` 里 8 个科目**全部**是「未匹配-待判断」（销售 3.4679 亿、管理 0.9579 亿都在这一格），prior 全 0、groups 全空。

后果是连锁的：

```
口径没建 → T 列全「未匹配」
        → 表1 只有一个口径行（销售额=全部），NB 只有 1 条
        → 表2 只能写「金额巨大但业务类别需人工归类」
        → OAR 页 10 个口径退化成 2 个，变动分析写不出
```

**这不是代码 bug，是提示词环节没跑。** 判断标准：`oar_map_ai.json` 是否存在、`未匹配-待判断` 的金额占比是否接近 100%。
