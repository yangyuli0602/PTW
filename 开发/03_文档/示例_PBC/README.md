# 示例 PBC · 随客户给的那一半

> **这是样例，不是平台内容。** 它只演示「项目级目录该长什么样」，不含任何客户数据。
> 实际使用时复制到平台包**外面**，改名 `<客户简称>_PBC/`，与本平台包并列存放。
> 平台包是**通用**的（代码 + 模板 + 通用规则）；换客户只换这一层。

## 目录结构

```text
<客户>_PBC/
  数据/
    ledger.duckdb            ← 清洗后的库（连同 .wal 一起给）
    上传原件/                 ← TB、JE 的原始导出（只读留档）
  项目/
    清洗映射规则.md           ← 客户差异（表头写法、映射、清洗步骤、口径选择）
    上年底稿.xlsx             ← 上年 BKD + Lead（同一份可兼 prior 与 prior-lead）
    基线.xlsx                 ← 人工核过的标准答案（没有就不做逐格比对）
    输入清单.md               ← 这份基线怎么跑出来的：数据、参数、补过什么、关键数
    指纹.json                 ← 输入指纹（input_fingerprint.py 生成）
  交付/                       ← 本次产出的底稿、JSON、截图、说明
```

## 四条规矩

1. **一客户一目录**。不同客户的清洗规则、上年底稿、基线绝不混放——混了就是「一包发多家」串数据的根源。
2. **上年底稿与本期数据必须同口径**：同一集团、同一账簿范围、同一币别处理方式。
3. **基线只增不改**。换了期或换了模板，先人工核过新产物，再加一份新基线；不要为了比对通过去改基线里的数。
4. **指纹先核再跑**。指纹对不上，说明拿错了数据或期间，停下来问，不要「差不多就行」。

## 怎么生成指纹

```bat
程序\runtime\python\python.exe 程序\tools\input_fingerprint.py --data-dir "<数据目录>" ^
    --prior "项目\上年底稿.xlsx" --out "项目\指纹.json"
```

生成后**人工核一遍关键数**（行数、货币资金行数、本币合计、期间），确认无误再当验收基线用。

## 指纹里各项什么意思

| 字段 | 含义 | 变了说明什么 |
|---|---|---|
| `db.sha256` | 库文件指纹 | 库被重导或改过 |
| `db.tb_rows` / `db.journal_rows` | 行数 | 数据范围变了，或清洗删/加行 |
| `cash.rows` / `cash.local_sum` | 货币资金行数与本币合计 | 清洗口径或数据变了（**这是最关键的两个数**） |
| `cash.period` | 期间范围 | 期数不对 |
| `cash.companies` | 主体数 | 账簿范围变了 |
| `prior.sha256` / `prior.rows` | 上年底稿指纹与行数 | 上年底稿换了版本 |
| `tool.version` | 生成指纹时的平台版本 | 版本不一致时指纹不可直接比 |

## 交付时要给回什么

把 `交付/` 里这四样一起给项目组：底稿 xlsx、生成时的 JSON、汇率公告截图（若自动截）、一份说明（输入 / 补过什么 / 哪些格还空 / 谁签字）。有基线的附 `wp_diff` 报告。
