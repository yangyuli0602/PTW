## 4. 三条口径（不许改）

**① 本期账面数 = 借方 −（贷方 − 结转损益贷方）**

月末「结转本期损益」把科目冲平，不剔除算出来全是 0；但**禁止按关键字整行剔除**——
「结转----确认上市费用」是真实借方费用，按关键词删会少一半金额。
`_xfers` 用「凭证内含 4103/4104 科目」或摘要精确匹配「结转本期损益 / 结转损益 / 期间损益结转」判定。

**② OAR 口径**：薪酬 / 折旧摊销 / 广告费 / 单列大额 / 其他。
单列门槛 = 该科目**合计** ≥ 100 万（约 2×TE）——**按合计判，不按单行**
（中介费 1,304 万拆到 8 个账簿每行 160 万，逐行判会全落「其他」）。

**③ 变动**：`变动额 = 本期审定 − 上期审定`；`变动率 = 变动额 ÷ |上期审定|`（上期为 0 留空，不写 100%）。

## 5. 口径 Mapping（换客户的关键）

`口径Mapping` 一个 sheet 两段：

| A~F | H~J |
|---|---|
| 主体 \| 科目名称 \| OAR 口径 \| 匹配键 \| 来源 \| 备注 | 公司全称 \| 简称 \| 备注 |

来源四档优先级：**AI/人工确认 > 上年底稿 > 上年按规则推导 > 本年新增-待判断**（黄底）。

BKD 的 T 列是双层 XLOOKUP：先按 `主体全称|科目` 精确，查不到再按科目名兜底。

**AI 判断通道**（关键词表只能覆盖八成，换客户命名就变）：

```bash
ptw.py oarmap-draft --out pending.json    # 导出待判断清单
# AI 按 03_文档/AI提示词_口径判断.md 判定，产出 {"items":[{company,name,bucket,reason}]}
ptw.py oarmap-fill --file ai_result.json  # 回填，落 <data>/bkd_work/oar_map_ai.json，跨年沿用
```

**最要紧的一条规则：同类必须归并**。差旅费_*、办公费_*、运输费_* 一律进「其他」，
不许把明细科目名当口径（否则 5 个口径会变成 35 个，OAR 从「挑重点」退化成「全量罗列」）。

**坑**：上年底稿存的是**账簿名**（`RAYWING PTE.LTF.美金`），本年 B 列是**公司全称**
（`RAYWING PTE.LTD.`）。建 mapping 前必须用账簿对照折一次，否则本年全落「待判断」。

## 6. 进一步调查列（Q / R）

```
Q = IF(OR(N="",O=""), IF(ABS(E)>=$C$22,"是（本期达阈值）","否"),
       IF(AND(ABS(N)>=$C$22, ABS(O)>=$C$23),"是","否"))
```

- `C22` = 波动幅度 = TE × 50%，`C23` = 波动率 10%
- **TE 必须写进 Lead C4/C5**，否则 `C22 = 0`，`ABS(N) >= 0` 恒真，整张表全标「是」，等于没判
- 上期缺失时 `N/O` 是空字符串，直接 `ABS("")` 报 `#VALUE!` → 必须先判空
- 明细行用 **AND**（金额和比率都超才标）；表 1 的口径汇总用 **OR**（任一超就值得看）

认定等级 `C8:C11` → `E8 = MIN()` → `C22 = TE×50%`。**四个格空着 C22 就是 0**，
所以界面可配（Minimal / Low / Moderate / High），默认全 Minimal。

## 7. 上期三段式

- K 上期未审 = 上年底稿的上期审定数（静态回捞）
- L 上期调整 = 调整表「上期调整数」列 SUMIFS
- M 上期审定 = `K + L`

匹配顺序：`(规范化账簿名, 科目名称)` → 退 `("", 科目名称)`。
都不中则 K 留空 + 进待确认清单，理由必须区分「未提供上年费用底稿」和「该科目在上年费用底稿里没匹配到」。

## 8. 调整汇总表（表 3，BKD 下方）

```
B 调整类型 | C 简称 | D 调整说明 | E 科目名称 | F 本期调整数 | G 上期调整数 | H FOR BKD
```

- `I`（本期审计调整）= `SUMIFS($F…, $C…, $A行, $H…, $D行)`
- `L`（上期调整）= `IF(K行="","",SUMIFS($G…, $C…, $A行, $H…, $D行))`
- **FOR BKD 必须与 BKD 的「科目名称」逐字一致**，否则 SUMIFS 取不到
- 数据区只画左右外框 + 末行底线，**内部不画网格**（先 `border=Border()` 归零再设，否则模板残留横线清不掉）
- 表格占的行数超出页面底边时，**在底边那行整行插入**让蓝带下移，不能硬画

## 9. 表 1 / 表 2（BKD 下方的波动说明区）

**表 1 按 OAR 口径汇总**

- 标题红字在框外；表头 6 列（OAR 口径 / 本期审定数 / 上期审定数 / 变动金额 / 变动率 / 是否需调查）
- 数据行**只有左右外框、内部完全无横线**；合计行**不加上下边框**
- 金额都是 `SUMIF($T$…, $B行, $J$…)`，上期用 `IF(COUNT(K)=0,"",SUMIF)` 留空，不显示 0
- NB 编号写在框外 H 列（**不能写进 B 列**，B 是 SUMIF 的条件）
- 末尾两行：`A3` = **主表 A3**（不是本表合计）、`check` = 本表合计 − 本表 A3；**本期、上期各一个 check**

**表 2 变动分析**

- 每段一句，前缀 `NB1：`；段间有横线、左右竖线贯通（内外框都要有）
- 金额一律**千元**（`TEXT(D/1000,"#,##0")&" 千元"`）
- 业务描述从序时账摘要提炼（`group_account` → `_narrate`），写不出就如实说「需人工归类」，不编
- 描述拼进公式时，双引号换 `'`、花括号换全角，否则公式报废

## 10. 截止性测试（01.4）

**样本池-cut off**：销售 + 管理费用的**借方**序时账，15 列（主体/科目/日期/凭证/摘要/币种/原币/折算率/折合人民币/是否排除/说明）。

> **V1.2.82：贷方行根本不进池子**。费用科目的贷方几乎全是月末结转（借本年利润 / 贷费用），
> 借贷两侧一起收，整列加总必然抵成 0 —— 瑞云 1-9 月实测借方 38,362,151.70 = 贷方 38,362,151.70，
> 池子合计 0.00，样本按金额排序、按阈值挑关键项全建在这个 0 上。改后池子 10,709 → 6,714 行，
> 合计从 −0.00 变成 **70,311,758.90**，与 BKD「本期账面数」一分不差。
> 负数借方（红字冲销）仍是借方行，照旧保留，负值分析 743 行不受影响。

排除顺序**不能乱**：

```
结转损益 → 科目性质（工资薪酬 / 四类折旧摊销）→ 预提冲销 → 负值 → 否
```

- **负值必须最后**。一上来判负值，一笔「折旧 −5 万」会被负值吃掉，a 段折旧桶就少一块。
- **预提冲销**：同主体 + 同科目代码 + 同金额一正一负（只在剩余行里配）。
  「预提费用（含预提和冲销）」净额必然为 0 —— 这是对的，加批注写清「预提 X / 冲销 −X」。
- 剔除标签的颗粒度＝TOD 1.2 剔除项，两边**同一套取值**（`ALL_KINDS`）。
- **V1.2.82 起工资薪酬听 OAR 口径**：OAR 口径属人工成本 → 进这个桶；OAR 明确给了别的口径，
  关键词也不许把它判成薪酬（「劳务费」「董事津贴」这类名字最容易误伤）。查不到口径才退回关键词。

**01.4 表 3**：测试期 = 资产负债表日 ±30 天（B10 填 30），门槛取 `C22`（TE×50%）。
按付款日期归本期/日后两段；金额按**绝对值**判（大额冲减正是要看的）。

**01.4 表 2** 抽样策略自动成文，数字取**实际写进表 3 的条数**：

> 经分析，剔除薪酬、折旧等已在其他底稿测试的费用明细后……在资产负债表日前识别到 **N** 个测试样本，
> 在资产负债表日后识别到 **M** 个测试样本。

## 11. TOD（01.2 年审 + 01.2 预审+剩余期间 + 样本池-TOD）

模板里本来就两版 TOD 底稿，**两份一起生成**（项目组用哪份自己删）：
`VC&VD.01.2 TOD 年审`（全年一张）与 `VC&VD.01.2 TOD 预审+剩余期间`（金额拆预审段/剩余段）。
两份看的是**同一个样本池**，所以口径永远一致。

样本池-TOD = 截止性池**多 3 列**（是否关键项 / 抽样ID / TOD 说明），分类直接复用「是否排除」列。

**池子只收本期及期后**：账套常带上一年 12 月的计提+结转，结转那一半被判成「结转损益」剔掉、
计提那一半留下来，TOD 总体就会比 BKD 合计多一块（瑞云这笔 80,378.56）。生成时先按
「期间起月 1 日」把期初之前的行掐掉，`beforePeriod` 报掐了几条。

**抽样ID 覆盖「剔除项之外的全部本期样本」**，不是只给关键项编号：关键项只是其中达阈值的一小部分，
代表性样本要从同一批编号里挑。编号按台账顺序（日期→主体→科目→凭证）`TOD-0001` 起连续，
池子从上往下读编号连续，表1 里写 `TOD-1477` 就能回池子找到第 1477 个样本。
日后凭证属截止性测试范围，不编号。

**1.1 总体**（年审页）：`F12/F13 = 'VC.00'!J205 / 'VD.00'!J150`；合计 `F15 = F12+F13`。
**1.1 总体**（预审页）：按 `归属 + 日期` 从池子切两段。V1.2.82 起池子只含借方，
结转凭证进不来，「结转损益」桶恒为 0，公式里仍保留 `N,"<>结转损益"` 作兜底
（少数账套把结转挂在借方）。
合计 `H15` 应等于年审页 `F15`，否则先查池子里有没有年度外的日期。

**1.2 剔除**（一一对应模板行，V1.2.113 起 9 项）：

| 行 | 剔除项 | 行 | 剔除项 |
|---|---|---|---|
| 19 | 固定资产折旧费 | 24 | 租赁费 |
| 20 | 使用权资产折旧费 | 25 | 预提费用（含预提和冲销） |
| 21 | 无形资产摊销费 | 26 | **股权激励（股份支付）** |
| 22 | 长期待摊费用摊销费 | 27 | 其他剔除 |
| 23 | 工资薪酬 | 28 | 负值 |

预审页每桶拆 `G 预审 / H 剩余`，`I = G+H` 用模板原式。

> **第 26 行「股权激励（股份支付）」是生成时插进去的**，模板本身没有这一行：
> `_ensure_equity_row` 插行后其下所有行号 +1，模板的跨行公式由 `_shift_formula_rows` 重写
> （只改本表引用，跨表引用和字符串不动），新行公式由 `_clone_row_formulas` 补齐。
> 改行位时三处必须同步：`EXCL_ROWS` 常量、`R_*`/`P_*` 行号常量、`_fix_excl_total` 的 SUM 范围——
> 少一处就是「分类有、表上没有」的静默漏数。
>
> **股权激励为什么不并进工资薪酬**：并进去以后它被排除出池子却无处核对，池子与 BKD 的勾稽会断。
> 单列之后，**工资桶的 check 必须把股权激励那段摘出去**，否则 check 差整整一个股权激励的金额
> （瑞云这一期是 3,855,078.54）。

**摘要兜底（V1.2.112）**：科目名认不出性质时看摘要，只认明确词——

- 摘要含「长期待摊」「装修费摊销」→ `长期待摊费用摊销费`
- 摘要含「股份支付」「股权激励」「限制性股票」「员工持股」→ `股权激励（股份支付）`

**不许用「摊销」两个字单独兜底**：服务费摊销、软件摊销会成片误伤。

> 纯靠摘要判定的剔除项（例如长期待摊费用摊销，科目名叫「装修费」、只有摘要写着长期待摊），
> **check 列不核对**，F 列写明「按摘要判定，无科目维度可比」。
> 按科目名 SUMIFS 会得到 0，硬核只会报一个假差异。

**上年 TOD 的剔除表怎么用**：它是**按桶列金额**的，不带科目和摘要，所以**核对而不是照抄**——

- 上年某桶有金额、本年该桶为 0 → 十有八九是本年分类漏了，回样本池按科目名/摘要找；
- 上年有、本年确实没有 → 在 1.2 该行 F 列 X-ref 侧写一句「本年无此类业务」；
- **绝不把上年金额搬过来**，两年业务不一样。

**生成后必核三件事**：

1. **1.1 总体 = BKD 合计**：年审页 1.1 的「与 BKD 合计核对」必须为 0；
   分段页 1.1 合计与年审页 1.1 相等（两页都从样本池 SUMIFS，口径必须同源）。
2. **总体 − 1.2 各桶 = 剩余总体**：差额不为 0 时先查「是否排除」列有没有空值、
   有没有新分类没进 SUMIFS 的 SUM 范围。
3. **关键项按折合人民币判**：阈值比较用池子「折合人民币」（原币 × 折算率），
   不是原币、也不是账簿本位币——外币主体按本位币判会整片判不出关键项。
   关键项编号 `KEY-001…`，代表性样本 `TOD-0001…`，**两套前缀不混用**、各自连续。

> **V1.2.80 起租赁费不再默认排除**（短期/低价值租赁直接进费用、没有使用权资产底稿可承接）。
> 模板 D24 那一行保留行位但金额恒为 0、F 列写「—」，否则会出现"口径说不含、数字里还剔着"。
> **check 列按池子里的科目名称精确 SUMIFS**，不再用 `*关键词*`；
> 预提费用/负值/其他剔除不是科目维度，仍写「-」并在批注说明不可比的原因。
>
> **V1.2.82：工资薪酬的 check 改为对 BKD 的「OAR 口径」列取数**，不再逐个科目名匹配：
>
> ```excel
> =$I23-(SUMIFS(VC!G30:G204, VC!T30:T204, "薪酬")
>       +SUMIFS(VD!G30:G149, VD!T30:T149, "薪酬")
>       +SUMIFS(VC!G30:G204, VC!T30:T204, "股权激励") + …)
> ```
>
> 口径名清单取自池子里工资桶实际命中的口径（瑞云：薪酬 3,225 行 + 股权激励 10 行），
> 所以两侧是**同一批科目**。口径列（T）与明细末行都按表头文字/合计行现场定位，不写死列位。
> **V1.2.113 起股权激励已从工资桶摘出、在 1.2 第 26 行单列**，所以这条 check 的 SUMIFS
> 要显式排除口径名含「股权激励/股份支付」的部分，否则 check 恒差一个股权激励的金额。

- **所有 SUMIFS 必须带日期上界** `<= DATE(年,月,日)`：池子是全量的（含日后 30 天凭证），
  不加会把次年 1 月大额凭证算进剔除项，`G31` 对不上 `F15` **而且不报错**。
- **一笔只进一个桶**：负数按性质先归桶，剩下没性质的才进「负值」。
- **表 2 分析全部负值**，不是只算「负值」桶：
  `全负 = SUMIFS(M,M,"<0") − SUMIFS(M,N,"结转损益",M,"<0")`；`D83 = 全负 − D82`；核对行 = `D84 − 全负 = 0`。
  预审页 `D112` 原式是 `=D111-I27`（跟「负值」桶比），同样改成跟全负比 —— 负值桶只装没性质的负数，
  工资/折旧那些负数在 a 段各桶，两者天然不等。
- **预审/剩余怎么切**：`pre_end` 月月末为界，`--pre-end 6` → 预审 1-6、剩余 7-9；
  不给就取资产负债表日所在月（剩余段为空，右半列是 0，这是事实不是漏填）。
  表1 装预审段关键项、表1.2 装剩余段，两表合起来正好是年审页表1 的全部；
  分配策略（模板 D48 输入框）自动成文，数字取两段实际条数。

**预审段样本从上一期 TOD 表1 原样复制**（V1.2.80）：不再只写一句「见上期页」。
底稿是按本期这一页看和归档的，跳页引用会让样本、抽样ID、对方单位在本页消失。
现在逐行搬 C~S 列（值 + 格式），超容量按需插行，搬完按新行号重写 `O = J − N`。
定位靠「C 列写着抽样ID 的那一行」，不写死行号（两版模板表头分别在 55 / 59 行）。

**关键项 2 段的两个人工判断项**（`性质特殊[款项性质]`、`[其他项目组认为存在风险的样本]`）
E/F/G/H 默认填 **0**，不引上期、不黄底 —— 这是审计师的判断，工具不替人决定。

**TOD 页整页从模板复制**：`openpyxl` 跨工作簿不能 `copy_worksheet`，必须逐格复制
**字体/填充/边框/对齐/数字格式的「值」**。

> 绝不能 `nc._style = copy(c._style)` —— 那是样式**索引**，跨工作簿后指向目标文件的另一套样式表，
> 结果是字体变、加粗丢、medium 变 thin、底纹全没，**而且不报错**。

规则：只插行、只填值，格式一律沿用模板。数字格式只在模板是 `General` 时才补。
插行后行内公式（表1 的 `O = J − N`、表2 的 `D112`）不会自动跟，按新行号统一重写。

**客户特有的东西不进这份文档。** 本节写的是「什么业务该排除」的判据，任何客户都适用；
某家客户的具体科目名、金额、藏在哪个奇怪科目里，写进
`04_归档/01_PTW项目级配置文件/<期间+客户>PTW配置文件/` 下的客户档案
（如 `瑞云_费用TOD排除口径_20261112.md`）。
混在一起的后果很实在：下期换客户，判据里全是上一家的科目名，人会照着硬套。


## 12. 平台命令

```bash
# 费用底稿（含 OAR / 口径Mapping / 样本池 / 01.4 / TOD / 调整表）
ptw.py exp --from 1 --to 9 --date 2026-09-30 --customer "客户全称" \
           --te 550000 --sad 55000 \
           --standard "中国企业会计准则" --currency "人民币" \
           --assurance "Minimal,Low,Minimal,Minimal" \
           --pre-end 6 \
           --prior "上年度费用底稿.xlsx"     # 上一期 TOD 页就在这一份里，不用另传

# 只重算 OAR 文字
ptw.py oar-fill --file 费用BKD_最新.xlsx --conclusions ai.json

# AI 通道（平台本身没有模型，命令只负责摊平和回填）
ptw.py exp … --ai-out ai_pending.json          # 导出：OAR 待匹配科目 + 表2 待分析口径
#   把 ai_pending.json 交给平台 AI，按 items[] 填 bucket/reason/confidence 与 table2.items[].text
ptw.py ai-fill --file ai_result.json [--xlsx 底稿.xlsx]
```

**三条 AI 通道的口径**（V1.2.80 起，OAR 分析 V1.2.83 起，任务卡 V1.2.87 起）：

- **OAR 口径**（V1.2.87 两级读取）：先读**上年底稿自己的「口径Mapping」页**
  （上年已定论、主体已是公司全称、值是静态文本），读不到再落到**上年 BKD 的「OAR 口径」列**
  （键是账簿名、值可能是公式，文件没被 Excel 保存过就是空）。两层的「来源」都写**「上年底稿」**；
  「同名科目跨主体沿用」这条线索挪到备注列，不占来源列。
  上年 mapping 里自己还标着「规则推导-待AI复核」的行**跳过不读**——那是去年的猜测，不是依据。
- **来源列只有三个值**：`由AI判断` / `上年底稿` / `规则推导-待AI复核`。
  第三种是黄底 + 进待办清单；`口径` 的 C 列**永不留空**（留空会让 XLOOKUP 取空、OAR 的 SUMIF 静默漏金额）。
- **BKD 表2**：超波动范围的口径由 AI 写结论，文字更贴审计判断（驱动因素／是否一次性／是否追加程序），
  **金额与比例仍是公式**，AI 不重复数字。
- **OAR 页「二、变动分析」**（V1.2.83）：与表2 同一套做法，每项带该口径下的序时账证据
  （对手方／业务性质／金额／占本口径比重，最多 12 组）；AI 只换公式**最后那段文字**，金额与比例仍走公式。
  工具自带的 `_narrate` 只在 AI 没写时兜底，写不出就标黄留占位，不编业务原因。

**任务卡（V1.2.87，照货币资金「汇率截图」那套）**

平台不调模型、也不联网，三件事天生要外部 AI 做。生成时自动写三份清单到固定路径，
并在生成结果的 `tasks[]` 里登记（`blocking=false`，缺 AI 也能出稿）：

| 任务 id | 清单 | AI 把结果写到 |
|---|---|---|
| `exp-oar-bucket` | `bkd_work/ai_tasks/oar_bucket_pending.json` | `bkd_work/oar_map_ai_result.json` |
| `exp-table2-concl` | `bkd_work/ai_tasks/table2_pending.json` | `bkd_work/table2_concl_result.json` |
| `exp-oar-reason` | `bkd_work/ai_tasks/oar_reason_pending.json` | `bkd_work/oar_concl_result.json` |

**闭环就五步，照这个顺序做**（不用跑 `--ai-out`，清单在生成时已自动落盘）：

1. `ptw.py exp …` 生成一次；
2. 读结果的 **`main.aiTasks[]`**（不是只扫 warnings）：每条有 `readPath`（清单）、`savePath`（结果文件）、
   `expectCount`（应有条数）、`status`；
3. 逐条：读 `readPath` 的 `items[]` → 按里面的 `instruction` 判断 → 按 `outputFormat` 写 `savePath`；
4. **用同样的参数再生成一次**（结果侧文件在生成时自动合并，不重跑等于没做）；
5. 验收：`aiTasks` 为空（或全 `done`）、`tasks` 为空、`deliverableReady=true`，
   且底稿里不再有 `【待AI撰写` 标记。

`aiTasks[].status`：`pending` 没写 / `partial` 条数不够 / `done` 够数 / `unknown` 无法判定。
`deliverableReady=false` 时不要交付，也不要把它当成"已分析"。

结果侧文件是**旁路**：不用跑任何命令、不改正本，重新生成一次就自动合并进去
（`load_conclusions` / `load_table2_concl` / `load_ai_map_all` 都会带上它）。
已经有 AI 文字的口径不再进清单，所以任务做完一件事就少一条，`tasks[]` 为空即全部结清。
底稿里也留了同一张卡：表2 段落与 OAR 分析段的**格批注**写了「读哪个文件、写哪个文件、
什么格式、怎么自检、写完怎么生效」；口径Mapping 的黄底行在备注列指向清单。

接口：
`POST /api/build/wp/run {"subject":"exp","period_from":"1","period_to":"9","balance_date":"…","customer":"…","te":550000,"sad":55000,"standard":"…","currency":"…","assurance":[...],"prior_fid":"…"}`
`POST /api/build/exp/prior {"fid":"…"}` → 校验上年底稿能认出多少键
`GET /api/build/exp/plan` 预览

## 13. 坑（都是踩过的）

| 现象 | 原因 |
|---|---|
| 整表「进一步调查」全「是」 | TE 没写进 Lead C4 → C22=0 |
| 分析段乱码「金额 销售费用_宣传推广费 元」 | `TEXT()` 套在 D 列（科目名称）上，改列引用 |
| `ABS("")` → `#VALUE!` | 上期数为空，先判空再算 |
| OAR 从 10 个口径变 35 个 | 口径词典按别家命名写死，换客户后科目名被直接当口径 |
| NB 编号全空 | 判阈值读了公式列（openpyxl 拿到字符串），应读静态值列 |
| OAR 句子里写「上期无数据」，可表上 E/F/G 三列都有数 | 上期列是 SUMIFS 公式，openpyxl 读回字符串 → `hasPrior` 恒假。改从「上期BKD」页按**账套名称 + 科目编码**取实体值；句子结构同时改成 `IF($E="",…)` 自适应，不再用生成时的值定死 |
| OAR 分析只列到「本期以人力成本为主」这种模板句 | 导给 AI 的证据按**口径名**去查（`gp[c.name]`），而证据的键是**科目名**，永远查不到 → 一直是空数组。改按 candidates 的 `subjects` 合并取证据 |
| 表 2 只出 4 段 | 模板残留 `[A][B]` 合并区冲突，`merge_cells` 抛异常，整段静默中断 |
| 表 1 右侧叉出一根线 | 模板零散横线没清，写表前要把 B~I 整段 `border` 归零 |
| 底部蓝带横穿表格 | 算「内容末行」只认有值，而空表区无值 → 改成「有值 **或** 有边框」 |
| 列宽设了又变回去 | 插列时的搬移被后续列宽设置覆盖 → 末尾再钉一次 |
| 表头上方灰底带断成两截、日期左右各一块孤立灰斑 | `insert_cols` 只搬已有格子，**新两列是"裸格"**（无字体/无底纹/无合并）。要把表头行及以上的新列按右侧邻列逐格复制样式，且必须在合并 K:M 之前做（合并后就是 MergedCell，设不进去） |
| 上年日期那格白底、和左边本期日期不对称 | 重建表头时复制了字体/边框/对齐，**漏了 fill** |

## 14. 边界（没做的，别去找）

- 只做销售费用 + 管理费用；其他期间费用科目不做。
- 集团多主体不做过滤（同货币资金）。
- 凭证影像 OCR、银行流水匹配：不在本模块。
- 结论类（OAR 变动原因、受限资金判定、调整项结论）= **AI 起草 + 人确认**，工具只出证据与占位。
- 禁止 `+1` / `ROUND` 调平；差额必须解释，未取得资料留空标黄 `FFFF00`，不填 0。
