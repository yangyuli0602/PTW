## 板块机制（接手第一件要懂的事）

每个板块是 `程序\modules\<key>\` 一个目录：

```
modules/bkd/
├── manifest.json   声明：key / label / order / type / entry / static / children / icon
├── routes.py       可选。暴露 GET_ROUTES / POST_ROUTES，路径**自带 /api 前缀**，框架不改写
├── core.py         板块自己的业务逻辑
└── web/            可选。manifest 里 static:"web" 后，/bkd/** 就指向这里
```

`type` 两种：

- **`native`** — 复用主页面框架。需要在 `程序\web\assets\app.js` 的 `VIEWS` 里登记渲染函数（如 `import: renderImport`）。
- **`embed`** — 独立 HTML 页，iframe 嵌入，自带 css/js，互不干扰。**加这类板块连 JS 都不用写**。BKD 就是这种。

**新增一个板块的最短路径**：建目录 → 写 `manifest.json` → 有后端就加 `routes.py` → 重启服务。`server.py` 和 `app.js` 都不用动。

`GET /api/modules` 返回装配结果（含每个板块的 label/children/order），前端据此渲染导航；`server.py` 的 `VERSION` 是版本号唯一来源，页面从该接口读取。

## 数据检查（v2.1.0 起）

`core/recon.py` 是唯一入口，`run()` 依次跑 4 组，每组独立 try，一组失败不拖垮其他组：

| 组 | 函数 | 落表 |
|---|---|---|
| 一 余额表自平衡（按公司：本期/累计借贷差、余额勾稽） | `_check_tb_self` | `_recon_tb_self` |
| 二 序时账自平衡（总额 / 月 / 唯一凭证号） | `_check_jr_self` | `_recon_jr_total` `_recon_jr_month` `_recon_jr_voucher` |
| 三 两表 公司+一级科目 | `_pair_check(key_kind="l1")` | `_recon_pair_l1` |
| 四 两表 公司+科目全称 | `_pair_check(key_kind="full")` | `_recon_pair_full` |

- 每组 `parts[]` 里带 `columns` / `headers`（中文表头）/ `rows` / `table` / `view_cols`（前端显示哪几列）。导出 Excel 直接读 `_recon_*` 表，不重算。
- 主体口径沿用 `entity_expr()`：company_name → book_name → (未标注主体)。
- 期间过滤**只作用于第三、四组**；一、二组是自平衡，永远全量。
- 新增标准字段：`journal.voucher_key`、`journal.acct_full`、`tb.acct_full`。`_init()` 里已有 `ALTER TABLE ADD COLUMN IF NOT EXISTS` 循环，老库自动补列。
- 凭证键优先级：映射了 `voucher_key` → 用它；否则现场 `concat_ws('-', 主体, 期间, vno)` 并给 warning。
