# V1.2.67 · 导入与清洗模块交互改造（8 项）

**来源**：用户逐条提出 8 个交互问题（导入入口分散、表类型要手选、原始表不能多删、达标卡收起失效、
必备字段不显眼、辅助核算缺开户行、辅助核算1 含义不明、导出数据包不全）。

## 改动文件

| 文件 | 改了什么 |
|---|---|
| `程序/web/assets/app.js` | 导入页三块同排 + 拖拽；自动识别回填；原始表多选删除；达标卡折叠持久化；映射页必备字段分块；辅助核算提示 |
| `程序/web/assets/style.css` | `.imp3` 三列布局、`.drop-sq` 紧凑拖拽区、`.map-sec.req` 必备块、`.picked` 选中行 |
| `程序/core/fields.py` | 新增 `bank_name`（银行开户行名）字段与角色；`detect_target()` 自动识别；账簿名称/一级科目改为必备 |
| `程序/core/db.py` | CANON 加 `bank_name` 列；`drop_sheets()` 批量删；数据包加 `sheets.json` / `books.json` 并在导入时回放 |
| `程序/modules/ingest/routes.py` | `/api/drop` 支持 `sids` 批量；新增 `/api/detect` |

## 逐项：问题 → 做法

1. **三个入口散成三张竖排卡片** → 改成同一行三块（`导入原始数据` / `导入数据包` / `账簿对照表`），
   每块各有一条虚线拖拽区，拖到哪块就按哪个用途处理（zip 只接数据包，xlsx/csv 只接对照表）。
2. **表类型靠人一个个选** → `fields.detect_target()` 按**表头优先、文件名兜底**打分：表头出现「凭证」
   直接判序时账；期初/期末余额、本期发生额判科目余额表；交易日期/对方账号判流水；原值/累计折旧判台账
   （名字带期初归 `fa_beg`）。分差不够或特征太弱就**返回空**，不硬猜。前端在分组卡上填好下拉框、
   标绿「自动识别：XX」并写明依据，人只需复核；手动改过之后不再被覆盖。
3. **原始表不能多删** → 加勾选列 + 全选/取消全选 + 「删除选中(n)」，后端 `/api/drop` 收 `sids`
   一次事务删完（`drop_sheets`），删到一半失败不会留半拉子。
4. **达标卡收起后切模块又展开** → 收起状态原来只记在 DOM 上，重绘即丢。改存 `localStorage`
   （`ptw.cleanGuide.closed`），切走再回来仍是收起。
5. **必备字段混在长列表里看不见** → 映射页拆成「必备字段」「其他字段」两块，必备块红底、标
   `已映射 x/y，还差 n 个`，未映射的行整行标浅红。同时把**账簿名称、一级科目**补进必备集
   （它们在 BKD/检查里都是硬依赖）。
6. **辅助核算1 含义不明** → 字段下方直接标「银行账户唯一标识（货币资金按它分户）」，辅助核算块尾
   补一段说明：填「开户行&账号」最稳，只填账户名会把同名账户并成一行。
7. **辅助核算缺开户行** → 新增语义列 `bank_name`（银行开户行名），排在 `bank_account` 上方。
   角色关键词也从 `bank_account` 里把「开户行/银行」拆出来（以前开户行被当账号抽数字，抽不出还把真账号挤掉）。
   合并时按 `_aux` 角色自动落到 `tb.bank_name` / `journal.bank_name`，老库由 `_init()` 的 ALTER 自动补列。
8. **数据包只装洗好的表** → 导出改为 `kanzhang/v2`：除 `journal/tb` 的 parquet 外，加
   `sheets.json`（每张原始表的清洗动作 + 字段映射 + 目标表 + 表头行）、`books.json`（账簿 → 公司/简称对照表）、
   `rules.json`（方案库）。导入时按「文件名 + 工作表名」把映射/清洗动作回挂到本地同名表，
   对照表整表还原。返回里带 `config: {books, sheetConfigs}` 报还原了多少。

## 验证

- 接口：`/api/detect` 六组样例全对（余额表/序时账/流水/台账/台账期初/无线索→空）；
  `/api/drop {sids:[2]} → deleted=2`；`/api/state` 里 TB 必备字段含账簿名称、一级科目，
  辅助核算顺序为「辅助核算1/2/3 → 银行开户行名 → 银行账号」。
- 数据包：导出 zip 内含 `books.json / sheets.json / rules.json / *.parquet`，`manifest.format=kanzhang/v2`；
  清空对照表后重新导入，`config={books:2, sheetConfigs:1}`，账簿 2 条与 6 个清洗动作都回来了。
- 界面（Edge 实测截图）：三块同排、拖拽区正常；待导入两组自动识别为「科目余额表 / 序时账」并带依据；
  点「收起」→ 切到导入页再回清洗页仍为收起（localStorage=1）；映射页必备块显示 `已映射 0/14，还差 14 个`；
  辅助核算块「银行开户行名」在「银行账号」上方，辅助核算1 下方有唯一标识提示。
- 产品链路：用测试账套跑 `ptw.py cash` 正常出底稿（gaps=257，不变量全通过），新增列未影响 BKD 取数。

## 已知边界

- 自动识别只认「表头文字 + 文件名」，客户导出表头完全自定义（如 "Col1/Col2"）时会给「未识别」，
  仍要人工选——宁可让人选，也不塞一个错的。
- `bank_name` 是新列：老账套要在平台里重新合并一次才会有值；只导入不合并时该列是空的。
- 回归套件（`01_测试/自动回归`）在本版之前就已经是红的（脚本按 `tmp/` 相对路径写死了 sys.path，
  移到新目录后 import 失败），与本次改动无关；本次用接口 + 界面实测替代，未用它做发版判据。
