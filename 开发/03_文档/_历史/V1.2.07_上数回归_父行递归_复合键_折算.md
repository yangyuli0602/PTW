## 1. 生成一级科目：父行「纯汇总才删」，带残值的父行必须留

**问题**：原来判断父行该不该删，用的是「金额是否等于叶子之和」，还兼容了「等于所有后代之和」。
两种口径一起用，三层科目结构（父 → 子 → 孙）会出现两种错：

- 父行 560,406 已含孙辈，再加上孙辈金额去比，比例失真 → 真正的纯汇总父行被判成「有残值」而保留，明细重复累加
- 父行带着自己的钱（如 `560406_BM00003` 1,941.13 + 子行 134,505.32），按叶子之和比不相等 → 若只看「编码是别人的前缀」就整组删，1,941.13 直接消失

**现在**：Python 里自下而上递归算「这一行贡献给上级多少」：

```
叶子     贡献 = 自身金额
中间层   自身金额 ≈ 各子行贡献之和  → 纯汇总，删，贡献 = 自身金额
         不相等                    → 有残值，留，贡献 = 自身金额 + 子行贡献之和
```

子行编码比父行长，按编码长度倒序处理即可保证先算子后算父。判定结果作为 `_src_row` 白名单拼回 SQL，其余逻辑（同码去重、全称拼接）不变。

`clean.py` 的 `run()` 现在把 `p["_conn"] = conn` 传给 builder；少了连接直接返回 `noop` 并报「内部错误」，不再静默按旧规则删。

**验证**：`tmp/test_t01_t08.py` T10（带残值父行保留，合计 136,446.45 不变）、T10b（纯汇总父行仍删）均通过。

## 2. BKD 复合键补上「科目 + 币种」

**问题**：`bkd_key` 原来只有「主体 + 账号（或银行）」，同一个账号挂在两个一级科目下、或同账号两种币别时，上年数会串到另一行。

**现在**：`bkd_key(company, subject, acct_no, bank, currency)`，主体 + 一级科目 + 账号（或 银行 + 科目）+ 币种。
merge 的主索引与三处回退（仅账号 / 公司+银行 / 公司+科目）全部带上币种；「公司+科目」兜底仍只在**本行无账号无银行**时启用（库存现金专用），避免把新开账户配到去年注销的账户上。

## 3. 上年有、本年账面无的账户，照样进 BKD

**问题**：底稿的用途之一是「确保本期内新增、销户的账户均包含在表格中」。原来 merge 只按本年科目余额表出行，上年有、今年注销的账户直接消失，审计师要自己翻上年底稿补。

**现在**：这类账户以金额 0 进表，Notes 写「本期账面已无此账户（上年有余额，需确认是否已销户）」，并在 `stats.priorOnlyCount` 里计数，页面提示里能看到。

## 4. 银行存款「是否函证」直接写「是」

准则要求银行账户必须函证，没有判断空间。
`confirm` 列对**一级科目 = 银行存款**的行硬写「是」，不再标黄；其他货币资金（保证金户、第三方支付）仍需判断，继续留空标黄交人工/AI。

## 5. 外币主体折算：BKD 右侧新增「折算率」「折算人民币」两列

**背景**：主体本位币是港币/美元时，账套里的「本币」是外币，底稿报表口径是人民币，必须再折一次。
以前没有落点，只能人工在 Excel 里补，而且 Lead 的 SUMIF 取的是本币列，折完还要手改公式。

**做法**：

- BKD 数据区右侧（模板已用列之后，不插进模板中间，不动 P 列受限资金之类的位置）新增两列：

  | 列 | 内容 |
  |---|---|
  | 折算率 | 人工按主体填，默认 1（本位币即人民币） |
  | 折算人民币 | **公式** `=IF(本币="","",ROUND(本币*折算率,2))`，改折算率结果立刻跟着变 |

- 表头浅蓝底标记为平台新增列；新增账户原有的浅黄底照旧
- 合计行：折算人民币列同步 `=SUM(...)`；勾稽行改用折算合计与 `C.00 Lead` 比
  （有外币主体时本币合计 ≠ Lead 是正常的，仍拿本币去勾稽会产生假差异；勾稽格加批注说明口径）
- `C.00 Lead` 的 F 列（期末账面数）SUMIF 的求和列改为折算人民币列；「境外资金」同样按折算口径
- OAR 的 `bySubject` 也按折算人民币汇总，与 BKD 一致（全填 1 时数字完全不变）

**界面**：一键上数卡片下出现「折算率（按主体）」，列出全部主体，含外币账户的主体加粗并标 `⚠ 含外币`。
只给有外币账户的主体出输入框会漏——本位币是外币但币种标签仍写「人民币」的账套很常见，所以全部列出、默认 1。

**边界**：折算率是人工判断（期末汇率），平台不取汇率源；上期数（Lead K 列 / OAR 上期）仍按上年底稿原值，不重折。
