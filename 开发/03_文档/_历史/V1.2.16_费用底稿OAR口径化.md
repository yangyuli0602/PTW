> 数据：瑞云脱敏账套（`tmp/_demo`，序时账 55,996 行 / 余额表 6,798 行，期间 2026-01~09）
> 触发：用户提的 4 条 —— ①BKD 加 OAR 口径列 ②OAR 按口径分析且文字乱码、不要表格 ③「进一步调查」公式没下拉 ④VC/VD 分开、TE=55 万

## 1. 新增：BKD 最右侧「OAR 口径」列

两张 BKD 都在 Notes(Q) 右边加一列 R「OAR 口径」，每个明细行按业务性质归口：

| 口径 | 关键词 |
|---|---|
| 薪酬 | 薪酬/工资/奖金/提成/社会保险/公积金/福利/职工教育/工会/离职补偿/辞退/劳务/董事/监事/年金/补贴/津贴/社保 |
| 折旧摊销 | 折旧 / 摊销 |
| 广告费 | 广告 / 宣传 / 推广 / 展会 / 市场推广 / 市场费用 |
| **单列大额** | 归不进上面三类、且**该科目合计** ≥ 100 万（约 2×TE）→ 单独成一类，用去掉「销售费用_」前缀的科目名 |
| 其他 | 剩下的 |

两个实现要点：

- **按科目合计判断，不按单行**。同一科目会按账簿拆成多行（瑞云 8 个账簿），逐行判断会让「中介费 1,304 万」因为分摊到 8 个账簿各 160 万而全部落进「其他」——那正是要单列的东西。
- **只归类、不改金额**。一个科目只落一个口径，SUMIF 汇总后总额与 BKD 合计相等（实测 3,833.7 万 + 3,197.5 万 = 7,031.2 万）。

瑞云实测：销售费用 5 个口径（广告费 1,833 万 / 薪酬 1,471 万 / 其他 236 万 / 技术服务费 229 万 / 折旧摊销 65 万），管理费用 5 个（中介费 1,305 万 / 薪酬 1,217 万 / 股权激励 386 万 / 其他 232 万 / 折旧摊销 57 万）。

## 2. OAR 页重写

### 2.1 按口径，不按科目

旧版把 78 个科目逐行列出来，复核人看不出「薪酬一共多少」。新版：

```
一、销售费用 · 按 OAR 口径汇总     ← 5 行口径 + 合计
二、管理费用 · 按 OAR 口径汇总     ← 5 行口径 + 合计
三、变动分析                      ← 每个需调查的口径一段文字
四、说明
```

**VC / VD 分成两块**，各自汇总、各自判定（这是用户第 4 条要求）。合计与 BKD 直接对得上。

### 2.2 分析段改成叙述式

用户要求「不要用表格，变动金额、变动比例放在文字里」。现在一行一句话：

> 「广告费」本期审定数 18,328,933.79 元，占本类 47.8%；上期无数据，无法计算变动。本期金额已超波动幅度阈值 275,000.00 元。主要构成为「北京视锐达科技有限公司」10,907,536.78 元、「AIGC」4,127,032.89 元、「谷歌广告（上海）有限公司」514,402.98 元。【待AI撰写：请依据上方构成与序时账摘要补充原因。】

- 金额、占比、构成都是**公式引用**，BKD 一改文字跟着变；只有判断文字是静态的（且必须人/AI 写，不留工具编的）。
- 有上期时自动变成「较上期增加 X 元（Y%）」。

### 2.3 乱码根因：列引用错位

旧公式引用明细表的 **D 列**当金额，而 D 列是「科目名称」。`TEXT(D10,"#,##0.00")` 作用在文本上原样返回，于是句子变成：

> 「销售费用」上期无发生额，本期为新增，金额 **销售费用_宣传推广费** 元。

用户看到的就是这堆"乱码"。已改为：科目名引 `$C`、本期引 `$D`、变动引 `$F`、变动率引 `$G`、占比引 `$H`（按新版明细表列位）。

## 3. 「进一步调查基于波动幅度？」公式补全

模板只在预设的 3 行里写了公式（30-32），一插行就断——用户看到的就是「公式没拉下去」。实测 VC 表 176 个明细行里只有 4 行有公式。

已改成按行逐条写，且**修掉模板原公式的空值缺陷**：

```excel
=IF(OR(L30="",M30=""),
    IF(ABS(E30)>=$C$22,"是（本期达阈值）","否"),
    IF(AND(ABS(L30)>=$C$22,ABS(M30)>=$C$23),"是","否"))
```

原公式 `ABS(L30)>=$C$22` 在 L 是空字符串时直接算成 **#VALUE!**（没有上年数时 L/M 就是 `""`）。现在没有上期可比时退回「本期金额是否达到波动幅度」，并在单元格里写明依据。

实测：VC 是 20 / 否 156 / 错误 0；VD 是 13 / 否 108 / 错误 0。

## 4. TE = 55 万，阈值随之推导

旧版 TE/SAD **从来没写进 Lead**（C4/C5 是空的）→ `C22 = E8 = MIN(TE×各级占比) = 0` → O 列 `ABS(L)>=0` 恒真 → 全表都是"是"。

现在生成时写 Lead C4=TE、C5=SAD（默认 SAD=TE×10%），并据此算波动幅度：

| TE | SAD | 波动幅度 C22 = TE×50% | OAR 需调查起点 |
|---|---|---|---|
| 550,000 | 55,000 | **275,000** | 275,000 |

`C22` 的取值按模板同一套规则重算（第 8 行完整性 50/25/15/10%，其余三行 100/75/50/25%，取最小），不吃 openpyxl 读到的公式字符串。

顺带修了个静默问题：**VD 模板的认定风险等级 C8:C11 是空的**（VC 有 Minimal）→ 空 → D 列全空 → E8=0 → VD 整张表都是"是"。现在空就按 Minimal 起。

CLI：`ptw.py exp --te 550000 --sad 55000`；界面第 3 步加了「可容忍误差 TE」输入框。

## 6. 已知限制

1. **没有上年费用底稿时，变动金额与变动率算不出来**（K 列为空）。此时文字写「上期无数据，无法计算变动」，判定退回「本期金额是否达阈值」。用户这次给的数据包不含上年底稿，所以看到的都是这种。给 `--prior` 一份上年底稿就能出变动分析。
2. 口径关键词表在 `expense.OAR_BUCKET_RULES`，改规则要改代码（界面没有编辑器）。单列门槛 `OAR_BIG=100 万` 同理。
3. 回填（`oar-fill`）的结论 key 用「销售费用·广告费」这种带类别前缀的形式，也兼容只写「广告费」。
