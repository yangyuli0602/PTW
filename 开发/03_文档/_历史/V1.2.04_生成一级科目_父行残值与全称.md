## 2. 父行残值（3.1）

### 原来的判据

「同主体内存在更长编码以本编码为前缀」就删。对下面这三行：

| 科目编码 | 科目名称 | 本年累计借方 |
|---|---|---:|
| 560406 | 研发费用_测试费 | 136,446.45 |
| 560406_BM00003 | 研发费用_测试费_行政部 | 1,941.13 |
| 560406_BM00003_SP00002 | 研发费用_测试费_行政部_其他 | 134,505.32 |

`560406_BM00003` 有更长的子码，被整组删掉 → **1,941.13 凭空消失**，
TB 研发费用 150,037.77 vs 序时账 151,978.90，差正好 1,941.13。

### 新的判据

删父行之前先比金额：**只有当父行金额等于它下面子行的合计时，才认定它是纯汇总、可以删**。

难点在于"子行合计"有两种口径，客户的导法不一样：

| 口径 | 适用 | 560406 | 560406_BM00003 |
|---|---|---|---|
| 叶子后代之和 | 标准层级（父 = 子，子 = 孙） | 134,505.32 ≠ 136,446.45 | 134,505.32 ≠ 1,941.13 |
| 全部后代之和 | 跨级汇总（用友把孙辈也加进父行） | 136,446.45 = 136,446.45 ✓ | 134,505.32 ≠ 1,941.13 |

只取一种都会判错一边。所以**两种都算，任一吻合就判纯汇总**：

```
if |父行金额 − 叶子后代之和| ≤ tol  or  |父行金额 − 全部后代之和| ≤ tol:
    删（纯汇总）
else:
    保留（父行带着自己的金额）
```

结果：`560406` 两种口径都吻合 → 删；`560406_BM00003` 两种都不吻合 → 保留。
三行变成两行，合计仍是 136,446.45。

容差是新参数 `parent_tol`（默认 0.01 元），数据本身有尾差时可放宽。

## 3. 科目全称重复父名（3.2）

原来的拼接是「各级标准名用 `_` 连起来」。但客户的科目名称本身就是完整路径：

```
其他业务收入            (父)
其他业务收入_其他        (子)  ← 名称里已经带了父名
```

拼出来变成 `其他业务收入_其他业务收入_其他`，而序时账那边是 `其他业务收入_其他`，
第四组按科目全称核对就全是"仅余额表有"。

V1.2.02 加的"相邻重复段去重"只处理完全相同的段，处理不了这种"子名包含父名"。

修：拼全称前先看这一行的标准名**是不是已经含分节符**（`_` 或编码分隔符）——
含就说明它本身是完整路径，直接用，不再前置父名。

- `其他业务收入_其他` → 全称 `其他业务收入_其他` ✓
- `工商银行`（不含分隔符）→ 正常拼成 `银行存款_工商银行` ✓
- `1002_1002` 这种编码重复的 → 相邻重复段去重，得 `银行存款` ✓

## 4. 3.3 单体系币别视图（未动）

这条不在「生成一级科目」里，是核对口径的问题：

单体系源表只有「综合本位币」，序时账是「人民币」。核对时按币别分组，
TB 侧只有综合、序时账侧只有人民币，各缺一个组 → 成批"仅余额表有 / 仅序时账有"。

两条路，我倾向第 2 条：

1. 清洗侧加「复制为综合本位币视图」的动作 —— 但两个视图并存时金额会翻倍，需要额外的防重逻辑，
   而且这本来就是数据本身没有的东西，造出来容易误导。
2. **核对侧做视图归并**：某主体 TB 只有一种币别时，直接视同本位币组，不再要求另一个视图。

第 2 条改的是 `core/recon.py` 的币别分组，属于核心逻辑，影响面比清洗动作大。
按项目规矩（默认不动既有代码），这个改动需要你点头我再做。
