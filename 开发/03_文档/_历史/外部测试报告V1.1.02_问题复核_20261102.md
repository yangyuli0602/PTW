## 1. P0-1 期间过滤：`2026-01` 与数字期间 `1` 不兼容

### 是否仍然存在：**存在，且比报告描述的更严重（双向失效）**

### 代码定位（与报告一致）

| 位置 | 内容 |
|---|---|
| `core/recon.py:121-131` | `_period_key()`：数据侧，纯数字补零到 2 位（`'1'` → `'01'`），其余原样 |
| `core/recon.py:134-137` | `_pval()`：用户输入侧，**只对 1 位数字补零**，`'2026-01'` 原样返回 |
| `core/recon.py:140-159` | `_period_cond()`：拼 `period_key >= '2026-01'` |
| `web/assets/app.js:2165/2167` | 输入框 `placeholder="2026-01"` / `"2026-12"` —— 引导用户填错格式 |

### 实测证据（内存 DuckDB，当前代码原样调用）

```
数据期间='1'..'12'，输入 2026-01~2026-06   →  命中  0 / 12 行   ❌
数据期间='1'..'12'，输入 1~6               →  命中  6 / 12 行   OK
数据期间='2026-01'..'12'，输入 2026-01~06  →  命中  6 / 12 行   OK
数据期间='2026-01'..'12'，输入 1~6         →  命中  0 / 12 行   ❌
```

**报告只发现了第一种（数字期间 + `YYYY-MM` 输入）。反向同样失效**：数据是 `2026-01`、用户按"传 1~6 也行"的说明填 `1`/`6`，也一样过滤成 0 行。

`_pval` 实测输出：

```
_pval('1')       -> '01'
_pval('6')       -> '06'
_pval('2026-01') -> '2026-01'     ← 没有跟着数据格式走
_pval('10')      -> '10'
```

### 为什么会产生"几千条假差异"（链路还原）

1. 期间条件把序时账过滤成 **0 行**；
2. 余额表侧不受期间影响（`tb` 本身没有期间维度，这是对的）；
3. `_pair_check` 做 `FULL OUTER JOIN`，序时账侧全空 → 每一条都判成 **「仅余额表有」**；
4. 报告看到的 1,461 / 6,369 条"不符"就是这么来的。

**而且没有任何兜底**：代码里没有"过滤后序时账 0 行、余额表有数据 → 提示期间格式不匹配"的判断。`_pair_check` 的 `warnings` 只处理公司名缺失、原币列缺失几类情况。

另有一处会加重误导：`recon.py:544` 的 note 打成「按「一级科目」列归集（余额表 N 行 / 序时账 N 行）」，其中 `n_jr` 取的是 `recon.py:535` 的 `_n_rows(conn, "journal", "acct_l1")`（**全量，未按期间过滤**）。用户看到"序时账 129 万行"却全是"仅余额表有"，更想不通。

### 是否建议修改：**强烈建议立即改**

这是"静默输出错误结论"的一类缺陷，比崩溃更危险——用户不会怀疑工具，会去查账。

### 修改方案（三档，可叠加）

**A. 最小修复（推荐先做，约 20 行）**

`_pval` 改成"跟着数据格式走"。在 `_period_cond` 里先取一次数据样本：

```python
# 伪代码：先看数据长什么样
sample = conn.execute(
    'SELECT period FROM journal WHERE nullif(trim(period),"") IS NOT NULL LIMIT 50'
).fetchall()
is_numeric = all(re.fullmatch(r"\d+", str(r[0]).strip() or "") for r in sample)

def _pval(v):
    s = str(v or "").strip()
    if is_numeric:
        # 数据是 1..12：把 2026-06 截成 06
        m = re.fullmatch(r"(\d{4})-(\d{2})", s)
        if m:
            return m.group(2)
        return s.zfill(2) if s.isdigit() else s
    else:
        # 数据是 2026-01：把 1 补成 2026-01（年份从 vdate 或数据样本取）
        if s.isdigit():
            return "%s-%s" % (year, s.zfill(2))
        return s
```

注意 `_period_cond` 现在的签名是 `(frm, to, cols)`，拿不到连接，需要改成 `(conn, frm, to, cols)` 或多传一个 `period_format` 参数。

**B. 兜底自检（同样重要，5 行）**

在 `_pair_check` 里加一段，过滤后序时账行数为 0 而余额表有数据时，直接返回错误而不是输出明细：

```python

    n_hit = _scalar(conn, 'SELECT count(*) FROM "journal" WHERE 1=1 %s' % (" AND " + pcond), 0)
    if n_hit == 0:
        res["error"] = ("期间过滤后序时账 0 行。数据里的期间格式可能是「1」~「12」，"
                        "而你填的是「2026-01」；或反之。请把期间改成与数据相同的格式。")
        return res
```

**C. 从根上消除（推荐排进 V1.2）**

合并时统一把 `period` 写成 `YYYY-MM`。现在 `core/db.py:1073-1074` 只在**没映射 period 列**时才用 `vdate` 推 `YYYY-MM`；一旦映射了原始 `period`，就原样写入。建议改成：映射了 period 也做一次归一（能解析出年月就转 `YYYY-MM`，否则保留原值并给 warning）。

**D. UI 侧**

- 占位符不要硬写 `2026-01`，改成动态显示"检测到期间格式：1–12"或"2026-01"；
- 输入框旁加一行小字说明当前数据格式；
- 前端提交前做一次格式校验，明显不匹配时先提示。

### 附带要改的文档

`03_文档/AI作业指南_导入清洗检查.md:395` 写着「传 `"1"`~`"12"` 或 `"2026-01"` 都行，系统会归一化」——**这句是错的**，必须改。报告第 4 节的这条指正成立。

## 3. P1-1 第二组不受期间过滤

### 是否仍然存在：**存在，但这是有意设计**

### 代码定位

```python
# recon.py:781
def run(conn, period_from=None, period_to=None, tol=0.01, tb_base="ytd"):
    for fn in (_check_tb_self, _check_jr_self):
        checks.append(fn(conn, tol))          # ← 期间参数根本没传进去
    for kind in ("l1", "full"):
        checks.append(_pair_check(conn, tol, tb_base, period_from, period_to, kind))
```

`_period_cond` 全文件只用了一处：`recon.py:601`，在 `_pair_check` 内部。

### 实测证据

```
全量数据（1-6 月平衡 + 7-12 月单边）: bad = [('total',1,1), ('month',6,12), ('voucher',6,12)]  ok=False
只留 1-6 月                        : bad = [('total',0,1), ('month',0,6),  ('voucher',0,6)]   ok=True
```

与报告完全一致：7 月数据进来，第二组必然全线不平。

### 属于设计还是缺陷

**设计上是对的**：第一、二组是"自平衡校验"，校验的是"账本身是否借贷相等"，与期间无关。如果只核期间内，反而会放过期间外的错账。

**问题出在呈现**：结论页把"通过/失败"四组并列，用户看到第二组红着，第一反应是"数据有问题"，而不是"我期间填错了"或"我导多了期间"。报告里那句"用户看到的是第二组失败"说得很准。

### 是否建议修改：**建议改呈现，不改判定**

不建议给第二组加期间过滤（会破坏自平衡的意义）。建议：

1. **标题和 note 明示**：`2.1 总额平衡（全部期间，未按期间过滤）`；
2. **探测期间越界**：若 `max(journal.period) > 余额表最大期间`，在第二组卡片顶部挂一条橙色提示：
   「序时账含期间外数据（7–12 月共 N 行，借贷差 X），自平衡按设计看全量，因此出现不平。如需只看期间内，请先清洗掉期间外行。」
3. **可选**：再给一组"期间内"的附加结论（不改判定、只并列展示），让用户能对上号。实现上就是把 `period_from/to` 也传进 `_check_jr_self`，只在**展示层**多跑一次。
4. **结论汇总**里第二组状态不要简单标"有问题"，标成"有问题（含期间外数据 N 行）"。
