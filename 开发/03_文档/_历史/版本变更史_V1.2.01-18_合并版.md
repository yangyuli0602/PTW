## V1.2.01 · 底稿板块重构 + 第五组检查

- 底稿板块升级为 **「WP初稿生成」**，分子级：货币资金 / 销管费用。能力两层：工具做机械活（本年上数、千元口径），AI 做判断活（上年数、变动归因）。
- 新增 **银行存款 C.00 BKD 上数**：按「主体×银行×账号×币种」写明细，Lead 打 SUMIF；**按表头文字定位列**，不写死列字母；缺资料标黄 FFFF00 并进检查表「待确认清单」。
- 新增 **费用 VC/VD BKD**（`expense.py`）：借方 −（贷方 − 结转类贷方），不剔结转分录会把费用全冲成 0；B 列填映射后公司名，需先传「账簿↔公司」对照表；上期审定数无源整列标黄。
- 新增 **OAR 货币资金**（`oar.py`）：千元口径，三行 + CHECK 全公式；定期/大额存单拆分、受限资金留人工。
- 新增 **上年 WP 结构探测**：导出结构探测包 → AI 回 `{sheet, header_row}` → 平台按它解析。
- 数据检查新增 **第五组：货币资金辅助核算可用性**，成因五分档：`present` / `never_present`（原始表没这列，客户重新导出）/ `never_filled`（客户没填）/ `not_mapped`（字段映射页补 aux 即可，不用重导）/ `lost`（疑清洗误删，查剔除留痕）。只有 `lost` 是真被删了。

**已知限制**：性质/是否函证/受限资金只标黄不给值；销管费用 TOD 未做；G3/C.01b/C.00b/C.02 未做。

## V1.2.02 · 「生成一级科目」核算维度明细优先

- **问题**：老配方同码多行按「金额最大」只留 1 行，把维度明细删了——金额恰好对、行数错，检查全过但账户级明细已丢，函证/对账单/截止测试全做不了。
- 三个新参数（不传 = 行为与 01 一致）：`aux` 核算维度列（任一非空即明细行）、`detail_first` 有明细只留明细、`group_cols` 分组列（留空自动带币别列；多币种必须按币别分组）。
- 剔除留痕分三类：`非末级科目行` / `有明细的汇总行` / `无明细科目的同码重复行`。
- 任何一步把整表删成 0 行，说明会变成 ⚠ 提示（通常是先删了「所有账簿」层导致无值可填）。
- 科目全称去相邻重复段（`1002_1002` → `银行存款`）。
- **使用顺序**：文本归一 → 全局向下填充 → 按关键词删「所有账簿」层 → 生成一级科目（aux=核算维度名称，明细优先=开，分组列=主体+币别）。**「所有账簿」层必须删，但必须在填充之后删。**

## V1.2.03 · WP 上年数联调（修 4 个问题，其中 1 个硬 bug）

- **硬 bug**：上年回捞的性质/是否函证从没写进 Excel——判断列循环里只查了 `vals`，这两个字段从没进去过。**此前每次生成的 BKD 性质列都是空的**。已修。
- 库存现金无账号无银行，永远匹配不上上年：加「公司+科目」兜底索引，**只在本行既无账号也无银行名时启用**（否则新开账户会错配到去年注销的账户）。
- `/api/build/c00/run` 原来根本没接上年数据（`prior` 恒 None）：新增 `_load_prior`，c00/oar 接口接收 `prior_fid + prior_spec`。
- OAR 上期列原是写死标黄：改为按一级科目汇总上年审定数填 D 列，E/F 公式自动出数。

## V1.2.04 · 父行残值 + 全称重复

- **父行带自身残值被整组删（数据丢失）**：`560406_BM00003` 有更长子码就被删，1,941.13 凭空消失。改为**父行金额等于子行合计（叶子之和 或 全部后代之和，任一口径吻合）才判纯汇总删除**，否则保留。容差参数 `parent_tol` 默认 0.01 元。
- **全称重复父名**：子行名称本身含父名（`其他业务收入_其他`）时不再前置父名，全称直接用原名称；不含分隔符的才正常拼接。
- 单体系只有「综合本位币」视图导致核对缺组的问题 → 移交 V1.2.05 在核对侧解决。

## V1.2.05 · 币别视图归一（数据检查一/三/四组）

- **根因**：余额表按币别字符串分组、序时账一律归本位币组，两边归一规则不一致。币别写「人民币」的客户此前第三组必报假差异，**第一组则空转报「平衡」（数字栏空、结论写平衡，比报差异更严重）**。
- 新规则：按主体定形态——有汇总行走汇总行；无汇总行且只有一种币别时**整个主体视同本位币组**；无汇总行且多种币别时全部行进本位币组、各币别另开原币组。
- 外币组按「主体×币别」开（不再甲公司有美元给乙公司也开空美元组）；两边都给得出原币才开组，否则提示「外币组已跳过，共 N 行」。
- **行为变化**：单币种主体不再出现第二个币别组；第一组开始真的报不平（此前这类客户显示全部平衡是把没做的检查补上了）；勾稽差不再出现 `-0.0` / `1e-09`。
- 真实脱敏库（tb 456 行 / journal 100 万行）新旧五组逐行比对：改造前后的行内容**完全一致**——本版只影响报告 3.3 描述的那类数据。

## V1.2.06 · 按列值删行：中文列名 + 多条件「且」

- 判断列下拉改从标准字段定义取（序时账 31 列 / 余额表 38 列全中文），原来日期、金额根本选不到。
- 条件行可增删，多条之间 **「且」（AND）**；条件 5 种：等于 / 包含 / 不等于 / 为空 / 不为空。
- 修掉三个隐患：「包含」把 `%` `_` 当通配符（已转义按字面）；「不等于」漏空值（SQL 三值逻辑，已显式带上）；值没填就删（必须显式选「为空」，否则报 400）。
- 删除前先 **dry_run 试算**：弹窗列出行数、条件、将被删的样例，试算数与实际删除数保证相等；整表备份到 work 目录后直接生效不可撤销；删空整表会额外提示。

## V1.2.07 · 上数回归修复 + 外币主体折算

- **父行递归判定**：V1.2.04 的双口径在三层结构会两种错（纯汇总被判有残值而重复累加、带残值父行被删）。改为 Python 自下而上递归算「这一行贡献给上级多少」：自身 ≈ 子行之和 → 纯汇总删；不等 → 有残值留。
- **bkd_key 补复合键**：主体 + 一级科目 + 账号（或 银行+科目）+ **币种**。同账号挂两个科目或两种币别时上年数不再串行。
- **上年有、本年账面无的账户照样进 BKD**：金额 0 + Notes「需确认是否已销户」，`stats.priorOnlyCount` 计数——底稿要能证明销户账户都包含了。
- 银行存款「是否函证」硬写「是」不再标黄（准则要求，无判断空间）；其他货币资金仍留人工。
- **折算率按主体**（外币主体专项）：BKD 右侧新增「折算率」（人工，默认 1）/「折算人民币」（公式 `=ROUND(本币×率,2)`）两列，接在模板已用列最右，不插模板中间。合计、勾稽、Lead 的 SUMIF、OAR 汇总**全部走折算人民币**；折算率全填 1 时数字与旧版完全不变。外币主体拿本币勾稽必现假差异——那是口径不同不是错。折算率是期末汇率人工判断，平台不取汇率源。

## V1.2.09 · 判断留痕数据层（_judgments / _todos）

**是什么**：把「AI 判断并留痕」变成可校验的数据结构，并让底稿里上百个黄格子各自带着处置办法。
本版只落数据层，**底稿生成逻辑一行未改**，输出与 V1.2.08 逐格一致。

- 新增 `core/judge.py` + `_judgments` / `_todos` 两张表 + 七个接口
  （`plan` / `apply` / `save` / `review` / `list` / `todos` / `todos/sync`）。
- **主键是业务键哈希**，不是自增：`md5(scope|entity|subject|dim_type|dim_key|period|field)[:16]`。
  同一格重生成十次落在同一条上，写库天然 upsert。`dim_key` 走账号归一
  （`7559-3264-1710-201` 与纯数字视为同一账户），但**只对 `dim_type='acct'` 归一**——
  供应商名不能被「去前导零、去连字符」糟蹋。
- **六级取值链**：本期人工确认 → 往期继承 → 上年底稿回捞 → 平台规则 → AI 起草 → 空。
  两个顺序不可换：**规则在 AI 之前**（准则明确的事不该让 AI 再说一遍）；
  **AI 起草的值仍标黄**（写进格子是为让人看着改，不是让它变结论）。
- **黄格四分类**：A 能定 / B 缺料追客户 / C 待判 AI 起草 / D 配错标橙自己改。
  D 类最值钱——映射漏配被当成「缺资料」发给客户是纯内耗。
- 两条硬边界：`draft` 不算「已有结论」（否则 AI 一落草案就跳到 A 类，等于静默落笔）；
  AI 不能覆盖人工已确认的结论（`upsert` 直接拒绝）。
- `apply` 四条校验，不合格整条打回、不静默丢：jid 必须在本批 plan 内、取值必须在枚举内、
  依据 ≥8 字、置信度 <0.6 不写值。

## V1.2.10 · 导入清洗 bug 排查修复

**是什么**：对「数据导入清洗」做攻击性测试（专测正常路径走不到的边界），修 7 处，
其中 2 处会直接算错数。上数板块未改动。

### 会算错数的两处

1. **「删除小计行」把明细删光只留合计**。`run()` 里 filter 类动作的 `cond` 是**保留条件**，
   `_b_drop_subtotal` 返回的是「命中合计」的条件，少一个 `NOT`。默认预设不用这个动作，
   所以日常导入不踩；手动加了就一次性毁表。
2. **「本年累计借方发生额」被映射成本期发生额**。`cur_debit` 靠「发生额」、`ytd_debit` 靠「本年」
   对这个列名同分，按规则表顺序 cur 在前抢走 → 本年累计数变当期数，凡是用 ytd 的核对全错。
   修法：ytd 的「本年/累计」权重 2 → 3。

### 静默错值（不报错但结果错）

3. **期间列是日期时不归一**：`2026年10月` / `2026-10-31` / `2026/10/31` / `20261031` 原来原样返回，
   同一期间被当成两个。新增这些分支，并加两道闸——年份限 19xx/20xx/21xx（`1121.01.01`
   这类科目编码不会被当日期）、8 位数字要求月日合法（流水号 `10537050` 不会被当 1053 年 70 月）。
4. **文字里夹数字被当金额**：`合计123` → 123、`1A公司(100)` → 1100。现在只有
   「数字 + 千分位 + 货币符号 + 单位后缀」才允许宽松解析，其余返回 NULL。
   顺带支持了欧式千分位 `1.234,56`。
5. **表头重名仍可能撞车**：`金额 / 金额_2 / 金额` 会生成两个 `金额_2`，DuckDB 自动改名成
   `金额_2_1`，用户看到的列名与实际入库列名对不上。改为「逐列检查到名字唯一」。
6. **补前导零位数不稳定**：`_auto_len` 在长度并列时没有次序，同一份数据两次跑分别得到 4 和 10，
   取到 10 会把 `22` 补成 `0000000022`。改为并列取最短。

### 健壮性与口径一致

7. **非法正则中断整条流水线**（填 `[` / `(abc` / `*` → 后面的步骤全不执行）。
   现在构造阶段预校验，不合法则该步降级为 noop 并提示，后续步骤继续。
   另补四个空列表保护。
- **`drop_subtotal` 口径收严**：关键词必须出现在格子**开头或结尾**，不再子串匹配
  （否则会删掉「管理费用—其他合计性支出」这类真科目）。`audit.tb_subtotal` 同步同一口径，
  并改掉那条把用户引向误删的修复建议；`PROMPT` 也补了这句判定口径。

### 测试基础设施

- 9 个离线测试里 **6 个没有 `sys.exit`**，断言失败也返回 0 —— 此前显示的 PASS 只能说明脚本没崩。
  `regress.py` 加了输出兜底（含 `✗` / `有不符` / `失败 N 项` / `Traceback` 判 FAIL），
  无断言的 `test_c00` / `test_flow` 改为 **CHECK（人工核验）**，不再冒充通过。
- 新增 4 个攻击性测试（入口解析 / 清洗动作 / 表头映射 / 流水线）共 93 条断言，纳入离线组。

### 影响面

- 宏 `_num` / `_period_norm` 改动只影响此后执行。**之前合并过的数据要重新生成标准表**
  才会按新口径重算期间与金额。
- 真实数据验证：余额表 945 个金额单元格、序时账 187,897 个金额单元格、期间列 7 个值，
  新旧解析差异 **0**；全表 4,506 个取值里 418 处差异**全部是「旧值把摘要/公司名解析成数字、
  新值返回 NULL」**，无一例真实金额被改变。

## V1.2.11 · WP 初稿生成：交互重构为统一四步

**是什么**：把「WP 初稿生成」每个科目内部打散的 8 个卡片，收敛成固定的四步。
货币资金与销管费用共用同一套流程骨架，只是每步里的字段按科目不同。
**底稿生成逻辑零改动**，输出与 V1.2.10 逐格一致。

### 四步固定顺序

| 步 | 做什么 | 货币资金 | 销管费用 |
|---|---|---|---|
| 1 | 读取科目余额表（**只展示前 10 行**） | tb 的货币资金账户 | 序时账汇总的费用发生额 |
| 2 | 模板与资料 | 底稿模板 + 上年底稿（可选） | 底稿模板 + 账簿对照表 |
| 3 | 关键信息 | 资产负债表日、客户、折算率、截止测试 | 期间、资产负债表日、客户 |
| 4 | 一键生成 | BKD + Lead + Cutoff + 检查表 + OAR | VC/VD BKD + 检查表 |

### 改了什么

- 删掉两套并行的生成入口（旧的「步骤 1/2/3/4 + /api/generate」与「★一键上数」），
  只留第 4 步一个按钮。同一件事只有一个入口，是这次重构的核心。
- 新接口 `POST /api/build/wp/run`：按科目把产物一次算完。主底稿失败即整体失败；
  OAR 失败只记 warning，不让已经算好的 162 行 BKD 白跑。
- `_run_c00` 增加 `cutoff_fields` 参数：C.03 截止性测试并入一键生成，
  截止测试出错也只记 `cutoffError`，不阻断主底稿。
- 新接口 `GET /api/build/exp/tb`：费用取数预览（前 10 行 + 合计 + 已剔除结转损益）。
- 第 4 步加了**生成前置检查**：余额表有没有读到、模板在不在、上年传没传，
  三条一眼看清，按钮直接按条件禁用，不再点下去才报错。
- 结果区四个页签：BKD 前 10 行、待确认清单、Cutoff 结果、OAR 汇总，
  两个下载按钮并排（主底稿 / OAR）。

### 顺带修的两个真问题

1. **DuckDB 并发冲突**：`ThreadingHTTPServer` 每请求一线程，却共用一个 `Ledger.conn`。
   两个请求撞一起会抛 `connection is busy with another call`，表现是随机某个按钮报错。
   现在 `/api/` 全部走一把 `RLock` 串行（本地单用户，没有并发吞吐需求）。
2. **regress.py 会污染用户账套**：子进程没设 `KZ_DATA_DIR`，脚本回退到真实 `data/`，
   建了空库和 `server.lock`。现在统一指向 `tmp/_regdata`，并新增
   `scripts/guard_data.py`（snap/check 比对 data/ 的文件与表行数）盯住这件事。

## V1.2.12 · 面向 Agent 的执行层（CLI + 执行手册）

**是什么**：交付包的使用者不是人，是本地 Agent（Qoder 等）。它不能联网、不会点按钮、
但能执行命令。本版把「怎么跑」这件事从界面上挪到命令行和文档里。
**底稿生成逻辑零改动。**

### 新增 CLI `程序/ptw.py`

不起 HTTP 服务，直接调 core。一条命令一个任务，输出单行 JSON：

```bat
程序\runtime\python\python.exe 程序\ptw.py state
程序\runtime\python\python.exe 程序\ptw.py import "科目余额表.xlsx"
程序\runtime\python\python.exe 程序\ptw.py cash --date 2026-10-31 --prior 上年.xlsx
程序\runtime\python\python.exe 程序\ptw.py exp --from 1 --to 6
```

为什么需要：Agent 做「起服务 → 记端口 → 拼 JSON → 解析返回 → 下载文件」这一串，
每一步都可能失败，而且端口占用、单实例锁这类失败跟业务毫无关系。

**错误码**：失败时返回 `{"ok":false,"code":"TB_EMPTY","error":"...","next":"..."}`。
`code` 是稳定英文标识（TB_EMPTY / NO_CASH_ACCT / NO_EXP_DATA / TPL_MISSING /
FILE_NOT_FOUND / NO_SHEET_IMPORTED / BAD_RATE / UNKNOWN），Agent 按码分支而不是理解中文。

## V1.2.18 · 费用 OAR 分析段由工具直接成文

### 改了什么

分析段从「罗列公司名 + 金额 + 【待AI撰写】」改成**按业务性质写的描述**。

### 行为

- 性质 10 类（市场投放 / 股份支付 / 人力成本 / 中介与专业服务 / 折旧摊销 / 技术服务 /
  差旅交通 / 办公及租赁 / 业务招待 / 会议培训）。**顺序即优先级**：股份支付必须在
  人力成本前，否则「股权激励」被「员工」抢走，把股份支付写成工资。
- 占比分母用**本口径本期审定数**，不是证据之和（证据只取各科目金额最大的几组，
  用证据之和会把 30% 写成 80%）。
- 覆盖率 ≥ 85% 才说「全部为 X」，否则退「主要集中于 X」。
- 单家点名只点一家且不给金额（≥45% 才点）；一次性事项要占本口径 ≥ 20% 才提，
  并与性质去重。
- **写出来就不标黄**，写不出来（无证据）才留占位标黄；`pending` 同步只列没写出来的。
- 一次性词表去掉裸「调整」和「暂估」：前者会命中「调整投放」，后者是月度计提的入账标记，
  写进变动原因就是噪音。

### 边界

描述里的「六成左右」「明显收缩」是生成时快照，BKD 改数后金额/比例（公式）会变、
区间词不变，数据大改请重新生成。工具只写「是什么」，「为什么」仍是审计判断。

1. 差额必须解释，**禁止 ROUND/+1 调平**；未取得资料留空标黄 FFFF00，不填 0。
