> 版本：v3（2026-11-04），依据 `底稿/01_最终版底稿` 文件夹中的
> `C SWP 货币资金 20260930 瑞云.xlsx`、`G3 SWP 预付账款及待摊费用 20260930 瑞云.xlsx` 与
> `U_exp SWP VC&VD 20260930 瑞云.xlsx`（销管费用最终版，29 张表）的实际公式与结果整理。
> 用途：给“上数工具”的开发方（含 AI 开发代理）提供可直接落地为 ETL 的规则，并明确人机分工边界（第 10 章）。
> 文中数字均为 20260930 期的最终结果，可直接作为回归测试基准。

## 0. 总览与术语

底稿不是“手工填数字”，而是四层结构：

```
TB（科目余额表 / 序时账 / 明细账）
   └─ BKD（明细底稿：逐账户、逐科目、逐供应商）
        └─ Lead（科目层汇总 + 审计调整 + 与 TB 勾稽）
             └─ OAR / SRM（千元报表口径 + 变动分析）
   └─ TOD（细节测试：样本池 → 剔除 → 关键项 → 代表性样本 → 测试表）
```

上数工具的正确姿势：**只把最底层的数据（TB 明细、序时账、明细账）写进 BKD / 样本池，其余全部用公式向上汇总**。任何“把汇总数直接贴到 OAR”的做法都会在下一期失去可追溯性。

| 术语 | 含义 |
|---|---|
| BKD | 明细底稿（breakdown），账户/科目/供应商级最底层数据 |
| Lead | 引导表，科目层汇总 + 审计调整 + 与 TB 勾稽 |
| OAR | 千元报表口径的余额/发生额分析表 |
| SRM | 管理层波动分析（Management Representation 支撑表） |
| TOD | Test of Details，细节测试 |
| SL / GL | 明细账 / 总账 |
| RX | 已复核/已勾稽的标记 |
| TE / SAD | 可容忍误差 / 名义金额（SAD = TE × 10%） |

## 1. 通用原则（八条）

1. **单一数据源**：一个数字只允许一个“原始录入点”。C.00 BKD 的 I 列、VC/VD BKD 的 E 列、G3 BKD 的 O 列、样本池-TOD 的 K 列是原始录入点；Lead、OAR、派生表一律公式引用。
2. **公式优先，缓存值兜底**：写公式时同时写 `<v>` 缓存值；交付前用 Excel 只读重算一次，校验缓存与公式一致。
3. **口径表驱动**：公司编号、科目归集口径、费用类别全部来自映射表，不在公式里硬编码中文名称。
4. **完整性优先于整洁**：BKD 保留余额为 0、已销户的账户/供应商，否则无法证明“本期新增/销户均已包含”。
5. **差额必须解释，不许抹平**：Check 只暴露差异；差异要么有 X-ref 说明，要么标黄待补。**禁止用 +1、ROUND、手填数把差调成 0**（见 §4.3 反面案例）。
6. **未取得的数据留空并标黄（FFFF00）**，不填 0、不填“待定”。
7. **关键参数只引用不硬编码**：TE 从 `PMTE!$B$5` 读、汇率从汇率单元格读、阈值从 Lead 读。TE 本期已由 785,860.20 更正为 **779,338.37**，所有派生阈值随之变化。
8. **人工判断留痕**：凡属第 10 章 B/C 级的判断，必须在 Notes / X-ref / 黄标中留下“谁、依据什么、结论是什么”，工具不得静默替人下结论。

### 3.3 G3 明细账 BKD（新增）

**结构**：第 1 行为字段名，明细 **2–98 行（97 个供应商）**，100 行合计，101 行 Check。

| 列 | 字段 | 计算 / 来源 |
|---|---|---|
| A | 公司名称 | 原始录入（主体简称） |
| B | 供应商 | 原始录入 |
| C | 是否关联关系 | **人工判断**（是/否） |
| D | 披露分类 | 原始录入（预付产能/费用款/租赁款/软件使用费/待认证进项税/预付其他） |
| E | 核算内容（费用二级科目） | 原始录入 |
| F | 款项性质-EY | **人工归类**（IDC采购/材料款/其他） |
| G | 交易币种 | 原始录入 |
| H/I | 年初原币 / 年初本位币 | 上期结转 |
| J/K | 本年累计借方（原币/本位币） | 明细账取数 |
| L/M | 本年累计贷方（原币/本位币） | 明细账取数 |
| N/O | 期末余额（原币/本位币） | 明细账取数 |
| P | 审计调整 | **人工分录**；部分行 `=-O`（全额转出） |
| Q | 审定数 | `=O+P` |
| R–W | 账龄桶 0-90 / 91-180 / 181-360 / 361-720 / 721-1080 / 1080+ | 按“期末 − 业务发生日”分桶 |
| X | 账龄合计 | `=SUM(R:W)` |
| Y | Check | `=Q-X`；多数为 0，但被审计调整**全额转出**的行会保留原余额账龄（如 P=-O 时），非零属正常，需人工说明 |
| Z | 变动金额 | `=Q-I` |
| AA | 变动幅度 | `=IF(I<>0,Z/I,1)` |
| AB | 是否异常 | `=IF(AND(ABS(Z)>=Lead!$E$15,ABS(AA)>=10%),"Y","N")` |

```excel
I100 = SUM(I2:I98)   ' 3,196,534.00（年初审定数）
O100 = SUM(O2:O98)   ' 128,921,184.03（期末账面数）
Q100 = SUM(Q2:Q98)   ' 75,648,698.15（审定数）
```

**要点**：账龄桶是“到期分布”，不是简单的余额拆分；同一供应商可能跨桶。工具应按“单笔预付款的受益期终点”落桶，不能按供应商汇总后再分。

> `20250630G.01.01明细账BKD` 是上期快照，其第 80 行 Check 仍保留旧口径的硬编码（58,402,253.46），**不能作为本期勾稽依据**；本期只认 930 BKD 的合计与 G.00/G.01。

### 6.3 预提冲销配对算法

```text
for each row:
    if 已有性质标签: skip
    if |amount| < 0.005: skip

key = half(month) + "|" + code3 + "|" + abs(amount).toFixed(2)
      half = month <= 6 ? 1 : 2          // 两段各自配对

每个 key 内:
    pos = 正数降序；neg = 负数升序（绝对值降序）
    k = min(pos.length, neg.length)
    for i in 0..k-1: pos[i].label = neg[i].label = "预提冲销"
```

## 10. 自动化边界：AI 可全自动 / 需人工判断 / 禁止自动

### 10.1 分级定义

| 级别 | 含义 | 交付要求 |
|---|---|---|
| **A（AI 全自动）** | 输入确定、规则唯一、结果可机器校验 | 直接写入，附校验结果 |
| **B（AI 起草 + 人工确认）** | 规则可计算，但参数/口径需人定 | AI 生成建议值与理由，人工确认后才写入 |
| **C（必须人工判断/执行）** | 涉及职业判断、外部证据、管理层沟通 | AI 只能准备数据与留痕位置，不得代填结论 |
| **D（禁止自动化）** | 会破坏可审计性或误导使用者 | 工具不得执行 |

**速览**

- **可以完全交给 AI（A）**：映射解析、上期回捞、明细生成与去重、币种折算（汇率已定）、所有合计/结构比/变动率、Lead 汇总与 TB 勾稽、样本池过滤归一化、性质标签与预提冲销配对、账龄分桶、Check 与回归比对。
- **AI 出草稿、人工点头（B）**：期末余额取数口径、TE/SAD 取值、波动调查“是/否”、关键项阈值与样本量、C.02a 汇率与差异容忍、程序索引。
- **必须人工判断（C）**：账户性质与是否函证、受限资金识别与金额、受限重分类、C.01b 范围、C.00b 分类结论、C.02 调节项结论、审计调整分录、抽样执行与例外评价、G3 款项性质/关联方、所有叙述性结论。
- **禁止（D）**：用 +1/ROUND/手填调平 Check、自动填对账单、自动下“无调节项/无受限/无减值”结论、改动非目标 sheet。

### 10.3 人机交接点（工具必须产出）

1. **待确认清单**：新增账户、无上期账号/性质的账户、P 列为空但 J 列显示“保证金/受限”的账户。

### 10.4 一条实用原则

> **AI 负责“让数字对得上”，人工负责“让判断站得住”。**
> 凡是会写进审计结论、会影响他人判断的内容（分类、受限、调节、调整、抽样结论），工具只提供证据位置和计算结果，不替人落笔。

## 11. 实现建议

### 11.1 处理管线

```
① 主数据（公司/科目映射、TE、汇率）
② TB/明细账/序时账 → BKD 明细 / 样本池（原始字段）
③ 公式列（期间、币种、折算、口径、账龄）
④ 标签算法（性质 → 预提冲销 → 负值）
⑤ Lead 汇总 → OAR/派生表 → TOD 汇总
⑥ Check 计算 + 差异/黄标/待确认清单
⑦ 只读重算 → 回归比对 → 交付
```

### 11.2 写入方式

- **优先 OOXML 直接编辑**：通过 `xl/workbook.xml.rels` 按 sheet 名解析 part，修改 sharedStrings / styles / sheet XML 后重打包。
- 写公式同时写 `<v>` 缓存；新增公式后删除 `xl/calcChain.xml`，并在 `workbook.xml` 设 `fullCalcOnLoad="1"`。
- 不要用 Excel COM 打开再保存含外部链接的底稿（会重写 `[n]` 索引、重算依赖单元格）。
- 数字用 `String(+v)` 全精度写入。

### 11.3 验证协议

1. **逐部件 diff**：除目标 sheet 与 `styles.xml`/`sharedStrings.xml`/`calcChain` 外，其余文件逐字节一致。
2. **只读重算**：`ReadOnly=true` + `CalculateFullRebuild`，`SpecialCells(xlCellTypeFormulas, xlErrors)` 扫描应为 0。
3. **勾稽清单**：
   - `C.00 BKD!I139`、`SUM(P10:P135)=Lead!I44`
   - `C.00 Lead!H50/J50/K50`
   - `OAR 26930!C15/D15`
   - `C.01b!H34/L34`
   - `C.00b!H45`
   - `C.02!C36`
   - `C.02a!F16`
   - `TOD!I13`、`TOD!K27`、`TOD!H43`
   - `G.00 Lead!H57/J57/K57`、`G.01!I23`、`BKD!Y`
   - 费用 `OAR-管理!C15`、`OAR-销售!C15`
4. **数字回归**：与附录 C 比对，差异需列原因。

### 11.4 幂等

- 重跑前清空目标区域，保留格式模板行。
- 不依赖固定行号读取结果，用“标签定位 + 相对偏移”。
- 手工覆盖（调整、备注、结论）放在独立列/sheet，重跑不得清除。
