## 1. TE / SAD 从工作簿读，不再写死

**改前**：`build_workbook` 里 `amt_threshold=100000` 是硬编码，`_build_check_sheet` 也用它当「金额变动较大」的门槛。TE 一变，认定层阈值、截止性测试阈值、变动调查阈值集体失准，而且看不出来。

**改后**：新增 `core.read_te_sad(wb)`，按三级顺序取：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | `PMTE!B5` / `B6` | 项目主数据表，TE 的唯一权威来源 |
| 2 | `C.00 Lead!C4` / `C5` | 模板自带的阈值输入位（`D14` 等公式引用的就是 C4） |
| 3 | `TE_DEFAULT = 100000` | **同时报 `TE_NOT_READ` 警告**，不静默用错值 |

SAD 缺失时按 `TE × 10%` 推算并给出提示（与模板 `D8` 的口径一致）。

**为什么兜底值还是 100000**：这样「模板没填 TE」的项目，输出与改前完全一致——本版不改已有结果，只让填了 TE 的项目用真值。

**CLI**：`cash` 返回的 `main.teSource / te / sad` 直接可读；`teSource=default` 时 `warnings` 里带 `TE_NOT_READ`。

## 2. 受限资金：BKD 一列、Lead 一个落点

### 2.1 BKD 新增「受限资金」列

- 位置：模板已用列之后、折算列**之前**。顺序写死为「…模板列 | 受限资金 | 折算率 | 折算人民币」——先分配受限列、再调 `_locate_fx_cols`，否则折算列会先占住最右位，受限列反而挤到它右边，看着像折算的一部分。
- 样式：表头浅橙（`FDE9D9`，与系统写入的蓝底区分），带批注说明「一笔只写一次，Lead 会自动汇总，不要重复加」。
- **空值不标黄**：空 = 不受限。162 行里有 150 个正常账户，标黄等于把真正缺资料的格子淹掉。
- 合计行同步 `=SUM(...)`，供 Lead 引用。

### 2.2 两种 Lead 形态，按模板实际结构选

Skill §4.3 的口径是「Lead 用审计调整从其他货币资金重分类到受限资金」，但那要求表1 里有「受限资金」科目行。**V7 模板只有 37/38/39 三行，没有这一行**。

按 Skill §7「先识别模板形态，再决定写入内容」，`_fill_lead_restricted` 实现两条路径：

| 形态 | 判定 | 写入 |
|---|---|---|
| `reclass` | 表1 D 列有「受限资金 / 受限货币资金」科目行 | 该行 I 列（审计调整）= 受限合计；F 列填 0；调整汇总表记一笔重分类 |
| `disclosure` | 表1 无该行，但有「所有权或使用权受到限制的货币资金」披露行 | 披露行 C 列 = 受限合计（V7 走这条，落 71 行） |
| `none` | 两者都没有 | 不写，记 `restrictedNote` 说明原因 |

**两处不重复计数**的落地方式：BKD 每笔只记一次，Lead 只有一个单元格引用它（`='C.00 BKD'!M{合计行}`），不存在第二处加减。

### 2.3 不变量 `cash_restricted` 从 skip 变成真判

- 受限总额为 0 → pass（无需列示）
- 有受限且已落到 Lead（reclass/disclosure）→ pass，并报出落在哪一行
- 有受限但 Lead 无处可落（none）→ **fail**，报出 `restrictedNote`

### 2.4 人工入口

正常由人在 Excel 里填。为「AI 起草 + 人工确认」和自动化测试，另外给了参数入口：

```bat
ptw.py cash --date 2026-09-30 --restricted 755932641710201=500000
```

`/api/build/c00/run` 与 `/api/build/wp/run` 的 `restricted` 字段同义，支持 `{账号: 金额}` 或 `[{company, acctNo, amount}]`。

## 3. 派生表 `derived.py`：C.01b / C.00b / C.02 / C.02a

新增 `程序/modules/bkd/derived.py`，四张表各自独立 try——一张失败不影响另外三张。

**三条设计原则**（来自 Skill §4.5 与 §7）：

1. **按表号解析，不按序号**。`C.01b` 与 `C.00b` 在两个版本里位置互换过。表号用「取第一个空白/中文前的字符段」精确比较，避免 `C.02` 把 `C.02a` 一起吃掉。
2. **模板没有就跳过并记理由**，不新建 sheet（改结构属 D 级禁止）。
3. **只填账面能派生的**。对账单金额、现金等价物分类、调节项结论、汇率来源都是 C 级判断。

### C.01b 特殊账户程序

- 取 BKD 里「其他货币资金且非零」的账户，写入 B/C/D/E/F/G/H 列
- I 列（对账单/资产证明书金额）**留空标黄 + 进 gaps**，不填 0（填 0 会让「差异 = 账面」看起来像真差异）
- J 列公式从模板的 `=I-G` 改成 `=IF(I="","",I-G)`——原式在 I 空时会算出「差异 = −账面」
- L 列（本期末实际受限金额）直接取 BKD 受限列
- 超出模板预置行数时状态记 `partial` 并列出未写入的账户，不硬插行

### C.00b Other classification

- 表1 填受限货币资金明细（受限金额非零的账户），合计行 `SUM`
- 表1 的「现金 / 现金等价物」分类与表2 现金等价物明细**不填**，记在 `pending` 里交人工
- 受限列全空时状态 `skip`，理由写明「需先在 BKD 受限资金列填写」

### C.02 银行余额调节：只出清单，不落笔

「本期是否存在调节项」必须有客户的对账单/余额调节表才能判断。Skill 把「自动下无调节项结论」列为 D 级禁止——工具在这里落一个「无调节项」，等于凭空出具审计结论。

所以本表状态固定为 `manual`：只统计有多少个候选账户（期末余额非零的银行存款与其他货币资金）并列出来，**sheet 一个单元格都不写**（测试里专门断言了表1.1 的 B18 仍是模板原值 `C.01`）。

### C.02a 外币测算

- 按定位到的真实 BKD 列重写 C 列（原币）与 F 列（账面本位币）的 `SUMIF`，不沿用模板里写死的 `F:F` / `G:G`
- 币种别名归一：`人民币/RMB/CNY` → CNY，`美元/美金` → USD 等。不归一的话「本期有美元账户」会被判成「模板行没被使用」，美元汇率不标黄，静默算出一个差异为 0 的假象
- 人民币行汇率恒填 1（这不是判断）；外币汇率留空标黄并要求在 Notes 写明来源
- **只对 BKD 里真的出现过的币种要求汇率**：模板预置 USD/JPY 是给「可能有」的项目用的，本期没有美元账户却要求填美元汇率，会把格子白白标黄
- F 列用「期末账面金额（本币）」而不是「折算人民币」——C.02a 比的是本位币口径，折算人民币是报表口径（再乘主体折算率），混用会把币别差和折算差搅在一起

### 新不变量 `cash_derived`

有 `error` 判 fail；有 `partial` 时在 detail 里点名「哪几张没写全需人工补」。

## 5. 费用按段：**语义纠正**

计划里第 4 项写的是「费用按段汇率（预审段/年审段）」。落地时核对 Skill 后发现这条挂在 §5.3「样本池-TOD 构建」下：

> 汇率按期间段区分：预审段与年审段可能使用不同汇率（如 6.8836 / 6.8454）；在池中按「所属段」折算。

而费用 BKD 的「本期账面数」取的是序时账**本币**（`debit − (credit − 结转)`），全程不涉及原币，**没有汇率可折**。汇率折算发生在 TOD 池的「未审本币」列，属 V1.2.15。

所以本版按实际语义落地：新增 `read_expense_by_segment(conn, from, to, pre_end)`，把费用发生额按预审段/年审段拆开，结果进 `info.bySegment`（`preEnd / pre / final / total`），**不改 BKD 输出**。

```bat
ptw.py exp --from 1 --to 9 --pre-end 6
```

这一步是 TOD 的前置：§5.4 的预提冲销配对必须按段做（`half = 期间 ∈ pre ? 1 : 2`），跨段配对会把一段的净额挪到另一段。
