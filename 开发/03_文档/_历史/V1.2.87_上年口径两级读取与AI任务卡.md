## 一、上年 OAR 口径：两级读，来源压平

**原来的问题**：`read_prior` 只认「科目名称 + 账套/账簿」表头的页，而「口径Mapping」页没有
账套/账簿列 → 整页被跳过。最干净的一层（上年已定论、主体已是公司全称、值是静态文本、
带现成的「主体\|科目」匹配键）一直没用上，只能退到上年 BKD：键是账簿名（要 book_map 折算）、
值还可能是 XLOOKUP 公式（文件没被 Excel 保存过就读成空）。

**现在**：

```
① 上年「口径Mapping」页    → 主体是公司全称、口径是静态文本
② 上年 BKD 的「OAR 口径」列 → 键是账簿名、值可能为空（公式无缓存）
③ 两级都没有              → 规则建议（黄底）+ 进待办清单
```

- 页类型靠表头区分：有「科目名称」「OAR 口径」且**无**「账套/账簿」→ mapping 页；
  有「账套/账簿」→ BKD 页。**必须整格等于表头词**——说明行（一句话图例）里也含这些词，
  用包含匹配会把图例行当表头、整页 `continue`（实现时踩到了，已修）。
- 上年 mapping 里来源为「规则推导-待AI复核」的行**跳过**：那是去年的猜测，不是依据。
- 来源列从 5 个值压到 3 个：`由AI判断` / `上年底稿` / `规则推导-待AI复核`。
  同名科目跨主体沿用的线索改放备注列（「上年同名科目沿用（当时主体：X）」）。
- 值与该客户 `oar_map_ai.json` 已确认的一致时，来源仍写「由AI判断」并带出依据与置信度
  ——值没变，可信度信息不该因为"上年 mapping 里也有这行"就丢掉。

## 二、费用端三张任务卡

照货币资金 C.02a「汇率公告截图」的写法（`derived._fx_shot_task`）：任务卡自包含，
AI 换台电脑、没有项目上下文也能做完。

生成时自动落三份清单到 `<data>/bkd_work/ai_tasks/`，并登记 `tasks[]`（`blocking=false`）：

| 任务 id | 清单 | AI 写到这里 |
|---|---|---|
| `exp-oar-bucket` | `oar_bucket_pending.json` | `oar_map_ai_result.json` |
| `exp-table2-concl` | `table2_pending.json` | `table2_concl_result.json` |
| `exp-oar-reason` | `oar_reason_pending.json` | `oar_concl_result.json` |

**关键设计：结果侧文件是旁路。** `load_ai_map_all` / `load_table2_concl` / `load_conclusions`
都会合并 `*_result.json`（侧文件优先），所以 AI **只要把 JSON 放到那个路径、重新生成一次**，
不用跑任何命令、不改正本（正本里可能有上一年人工改过的段落）。
已经有 AI 文字的口径不再进清单 → 任务做完一件少一条，`tasks[]` 为空即全部结清。

底稿里也留同一张卡：表2 分析段、OAR 分析段的**格批注**（打开就看到）；
口径Mapping 黄底行的备注列指向清单路径。prompt 五段：读什么 / 写什么（含格式与允许取值）/
怎么写（判断要求）/ 写完自检四条 / 收尾（重新生成即生效），并注明"做不到就写 skipped，不要编"。

## 已知边界

- **平台仍然不调模型、不联网**：任务卡只是把"该做什么"写清楚，判断那一步必须由使用 PTW 的
  AI（或人）完成。没做也能出稿，只是文字是规则版、口径有黄底。
- 上年底稿若既没有「OAR 口径」列、也没有「口径Mapping」页，全部按科目名规则推，
  来源一律「规则推导-待AI复核」并进清单（`read_prior` 的 note 里会写明）。
- 结果侧文件是**覆盖式合并**（同键以侧文件为准），不支持"只改某几行不写其它"；
  若 AI 只写部分口径，其余仍是正本里的旧值——这是有意的：不会因为漏写把已定论的口径清掉。
- 本版未改数字口径；回归套件仍是红的（陈旧断言，与 V1.2.83/84 同一批），
  本版判定依据是 `verify_v1287.py` 13 项 + 逐格比对 + 任务卡闭环实测。
