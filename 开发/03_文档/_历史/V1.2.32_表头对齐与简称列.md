# V1.2.32 表头上方对齐 + 调整表简称列前移

> 承接 V1.2.31 插两列。用户指出两处：表头上方「像断开了一样」；调整表的简称列应在调整说明之前。

## 一、表头上方（TB / PY 段）

### 现象
插两列后，表头行（29）上方右半边是空的，TB / PY 两条标记与日期对不上，看着像表头被切下来。

### 原因
模板在 K 列（原上期审定）放了两个「PY 段」表头：

- `K26 = |------- PY -------|`（段标记）
- `K28 = =DATE(YEAR($E$28)-1,12,31)`（上年日期）

`insert_cols` 把它们整体推到 M 列。M 是新三列（上期未审 / 调整 / 审定）的最后一列，
于是标记只盖住一列、日期也挤在 M，K / L 上方一片空白。

而且 M28 当时落在模板的合并区（`L28:M28`「本期和上期发生额」）里，
是一个 `MergedCell`，**值根本读不出来** —— 事后扫 M 列找不到它。

### 修法
插列**之前**先从 K 列把这两格连样式一起抓下来，插完重建到 K 并横向合并 K:M：

```
K26:M26  |------- PY -------|
K28:M28  2025-12-31          ← 对齐方式跟 E28 的「2026-09-30」一样居中
```

现在 TB 段（E26，盖 E..J）、PY 段（K26，盖 K..M）左右对齐，两个日期各自居中。

## 二、调整表：简称挪到调整说明前面

```
旧：B 调整类型 | C 调整说明 | D 简称 | E 科目名称 | F 本期调整数 | G 上期调整数 | H FOR BKD
新：B 调整类型 | C 简称     | D 调整说明 | E 科目名称 | F 本期调整数 | G 上期调整数 | H FOR BKD
```

BKD 的两列 SUMIFS 条件列从 `$D$` 改成 `$C$`：

```
I 列 审计调整数 = SUMIFS($F…, $C…, $A30, $H…, $D30)
L 列 上期调整数 = IF(K30="","",SUMIFS($G…, $C…, $A30, $H…, $D30))
```

列宽也跟着换：C（简称）10、D（说明）26。

## 三、顺带修掉：VD 页 Notes 的 `[A][B]`

VC 页模板是 `Q30="[A]"`、`Q32="[B]"` 分开写，VD 页是**一格写 `"[A][B]"`**。
原来按 `in ("[A]","[B]")` 精确匹配，VD 那格没被清掉。改成按子串判断。

## 五、边界

- PY 段表头靠「含 PY 字样 / 含 DATE(YEAR( 公式」识别，换模板时若这两个表头换了写法会认不出
  （认不出就维持插列后的原位置，不会崩，只是不合并）。
- 调整表列序变了，项目组此前手工填过的表（按旧列序）在下次生成时会被当成新表重建网格，
  已填数据在旧列位上不会自动搬 —— 底稿是每次重新生成的，不涉及历史数据迁移。
