# V1.2.17 费用底稿：接上上年数（K 列回捞 + 变动分析）

> 上一版 V1.2.16 把 OAR 做成了「按口径 + 叙述式」，但**上期审定数 K 列没有任何数据源**，
> 所以「变动金额 / 变动率 / 按变动挑分析对象」这三件事一直没被真正跑通过。
> 本版把它接上，并把界面缺的上传入口补出来。

## 1. 上年数怎么进来的

```
上年度费用底稿（VC/VD 两张表，含「上期审定数」列）
  → POST /api/upload 拿 fid
  → POST /api/build/exp/prior 校验：能认出多少 (账簿, 科目) 键
  → 生成时带 prior_fid → parse_prior_expense → 回填 K 列
```

匹配顺序（`_fill_sheet`）：

1. `(规范化账簿名, 科目名称)` —— 精确匹配
2. `("", 科目名称)` —— 账簿名改了（「期初」→「期初数」）时的兜底

两条都不中，K 列留空并进待确认清单，理由分两种：
「未提供上年费用底稿」/「该科目在上年费用底稿里没匹配到」——
**这两种必须区分**，否则用户分不清是没传还是传了但没对上。

## 2. 变动分析的双条件

```
|变动金额| >= max(SAD, TE×50%)   且   |变动率| >= 10%
按 |Δ| 降序，取前 N 个写分析段
```

只看金额不看率，会出现「变动 0.3% 也要写一段分析」；只看率不看金额，
小科目的翻倍会挤掉大额变动。两个都要。

实测（瑞云 2026-01~09，TE 55 万）：

| 口径 | 本期 | 上期 | 变动 | 率 | 入选 |
|---|---|---|---|---|---|
| 销售·广告费 | 18,328,933.79 | 31,311,512.27 | -12,982,578.48 | -41.5% | ✅ |
| 销售·薪酬 | 14,706,993.23 | 14,932,700.56 | -225,707.33 | -1.5% | ❌ 率不够 |
| 管理·中介费 | 13,048,099.39 | 2,870,581.86 | +10,177,517.53 | +354.5% | ✅ |
| 管理·薪酬 | 12,173,976.42 | 13,744,470.26 | -1,570,493.84 | -11.4% | ✅ |
| 管理·股权激励 | 3,855,078.54 | 1,349,277.49 | +2,505,801.05 | +185.7% | ✅ |
| 管理·其他 | 2,324,095.19 | 2,275,746.33 | +48,348.86 | +2.1% | ❌ 金额/率都不够 |

销售合计 −13,324,021.14（−25.8%）、管理合计 +11,142,149.34（+53.5%）。

## 3. 修掉的两个真缺陷

### ① 一键生成接口没把 TE 传下去

`/api/build/exp/run` 传了 `te/sad`，但界面走的是 `/api/build/wp/run`（一键生成），
那条路径**没有传**。后果：Lead C4/C5 空 → C22（波动幅度）= 0 →
「进一步调查」的公式 `ABS(L)>=0` 恒真 → 176 行全部标「是」，等于没判。

上一版加了 TE 输入框，但点了不生效，正是这条断链。

### ② `_write_te` 抽成独立函数

TE 写入原来埋在 `build_expense_workbook` 的 25 行 try 块里，
测试没法复用同一段代码（只能各写一遍，各自漂移）。
现在 `EXP._write_te(wb, te, sad)` 返回 `(te, sad)`，主流程和测试跑同一段。

## 4. 界面上补的入口

第 2 步「模板与资料」新增子块 **上年度费用底稿**：

- 上传按钮 → `/api/upload` → `/api/build/exp/prior` → 显示「已载入 295 条」
- 载入失败时清空 `state.expPriorFid`，避免带着读不出来的文件去生成
- 生成成功时状态行区分三种情况：正常 /「上期审定数已回填」/「上期数未回填：<原因>」

原来的提示「**上期审定数（K 列）暂无数据源，一律留空标黄**」已删除——它现在是错的。

## 6. 验证

新增 `tmp/test_exp_prior.py`（25 项，已进 regress），不依赖数据库：

1. K 列写入上年审定数、L/M 是公式且引用 J/K
2. 双条件筛选：+3% 的不入选、金额太小的不入选、−50% 的入选
3. 分析段句子含「较上期增加/减少」+ 百分比，且不含科目名（旧 bug 回归）
4. 不给上年底稿：K 全空（不填 0）、每条都进待确认清单、M 列有判空保护
5. 部分匹配：缺的那条理由写「没匹配到」而非「未提供」
6. TE 写进 Lead C4/C5，OAR 记下 TE/阈值

回归：**17 通过 / 0 失败 / 1 人工核验 / 3 跳过**；`test_exp_layout` 50/50、`test_exp_prior` 25/25。

Excel 全量重算：VC 是 3 / 否 172 / `#VALUE!` 0；VD 是 3 / 否 117 / 0。

## 7. 还没做

- 上年数据是**模拟**的（`tmp/gen_prior_exp.py`：按科目名缩放 0.22~1.75，有增有减）。
  真实客户给的上年底稿结构可能更乱（自建表、科目合并、跨年改名），目前只认
  「账套名称 / 科目名称 / 上期审定数」三列能定位到的情况。
- 上年底稿只读 `上期审定数`，**审计调整后的审定数**若在上年表里另有分列，需要人工选定用哪列。
- 集团多主体：上年底稿按账簿匹配，账簿名与本年不一致时会退化到「只按科目名」，
  多主体同名科目会串（已知限制，未修）。
