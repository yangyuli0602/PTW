## 二、去重：先证明"是不是副本"，再决定删什么

**方法**：对每个序时账文件逐行生成规范化签名（按列标号拼接非空单元格值 → 53 位哈希），文件内去重后求两两交集。

**结果**：

| 比对 | 结果 |
|---|---|
| 上卷 ∩ 中卷 | 0 行 |
| 上卷 ∩ 下卷 | 0 行 |
| 中卷 ∩ 下卷 | 0 行 |
| 合并后唯一行 | 2,087,716 |

结论：三卷是同一套导出按每卷约 100 万行切分的**互补分卷**，不是副本；上卷末行与中卷首行属同一张凭证的不同分录，可直接拼接。

**文件内"疑似重复"行的处理**：上/中/下卷分别有 60,324 / 186,000 / 2,687 行与其它行签名相同（例如结转损益中同一科目、同一金额出现多行）。抽样核对后确认是**不同明细行**（导出字段不含分录行号或唯一 ID），因此**未做行级删除**，避免误删真实分录、破坏借贷平衡。若按行去重，这三卷会少计约 24.9 万行。

**剔除的文件及理由**：

- `凭证_7月.xlsx`：账簿、凭证号、摘要、科目、往来单位列全空，仅剩日期与金额，属导出不完整；且期间为 2026-07，不在本次 TB 的 2026.1–6 内。
- `凭证_2026-银行（货币资金JE）.xlsx`：按科目范围（1001/1002）属全量序时账的子集，纳入会重复计数。
- `货币资金TB-…20260714.xlsx`：全量 TB 的货币资金科目子集。

> 风险提示：上/中卷都恰好为 1,000,000 / 1,000,003 行，疑似触发导出工具的行数上限。若原导出被截断，合并总数会小于系统实际凭证行数——建议与总账"凭证行数"核对一次。

## 三、代号规则

| 代号 | 含义 | 数量 |
|---|---|---|
| A公司 ~ P公司 | 集团内主体，按账簿编号 1/2/4~16 顺延；分公司挂 A 后（A公司上海分公司…）；副账簿（H公司副账簿…） | 30 个代号 |
| 外部公司001 ~ 2123 | 摘要/文本中出现的第三方公司；同主体的大小写、全半角、括号写法共用一号 | 2,123 个代号 / 2,153 种写法 |
| 客商001 ~ 1993 | 往来单位字段的客商与个人；「客户/供应商/员工/银行/其他往来单位」等类别词不编号 | 1,993 个代号 / 2,009 种写法 |
| 账号001 ~ 190 | 银行账号与 IBAN；数字串本身作键，可逐位还原 | 190 个 |

编号原则：**只追加、不重排**。同一客户跨期间复用同一份映射，历史期间的"外部公司017"始终指向同一家。

映射条目合计 4,273 条（含账簿标签与同一主体的多种写法），另有 190 个账号代号。

## 四、技术方案

### 4.1 部件级改写，不重写工作簿

直接在 OOXML 包内操作：解包 → 改写 `xl/sharedStrings.xml`、`xl/worksheets/*.xml`、`xl/workbook.xml`、`docProps/*` → 原样打包。不经过表格库重写，因此字体、颜色、合并单元格、列宽、批注、富文本全部保留（源文件本身无公式与图片）。

### 4.2 大文件流式处理

单卷序时账的工作表 XML 达 780 MB、2,000 万单元格，超过单字符串上限。处理方式：按 `</row>`（工作表）/ `</si>`（共享字符串）边界分块流式改写，块内完成替换后落盘，内存不随行数增长。800 MB 部件单次读取即可完成，无需二次解包。

### 4.3 替换引擎

- 将全部词条按长度倒序合并为一个正则，一次扫描完成替换，保证"长名先吃掉"（如"某某科技股份有限公司上海分公司"先于"某某"命中）。
- 含 `&` 的名称额外登记 XML 转义写法（`&amp;`），否则在原始 XML 上匹配不到。
- 银行账号：纯数字账号只替换**完整数字串**（避免误伤票据号中恰好出现的 8 位日期串）；IBAN、带币种后缀的账号走整串替换。
- 账号只在 `<t>` 文本节点与 `t="str"` 缓存值中替换，金额 `<v>` 数值单元格不参与任何替换。

### 4.4 元数据清理

删除 `workbook.xml` 中的 `x15ac:absPath`（含个人目录路径），清空 `docProps/core.xml` 的 `dc:creator` / `cp:lastModifiedBy`。属删除型脱敏，不参与回退。

三项校验的定义：

1. **结构对比**：单元格数、公式数、合并数、sheet 名单、数值单元格个数与数值合计与源文件逐一比对。三卷序时账分别为 1,999 万 / 2,042 万 / 175 万单元格，数值合计未变。
2. **残留扫描**：4,273 个词条在全部 XML 部件中 0 命中；对输出文件全文检索客户字号，命中 0 次。
3. **往返校验（抽样）**：对每个文件的共享字符串抽样做"正向替换 → 反向还原"，与原文比对——

## 六、回退方法

映射 JSON 与《脱敏数据回退mapping表.xlsx》同源，二选一驱动回退：

```bash
# 环境：无独立 node，用桌面端 Electron 当 Node
Q="<Qoder CN 安装路径>/Qoder CN.exe"
S="<skills>/desens-xlsx/scripts/desens.cjs"
M="<skills>/desens-xlsx/mappings/<client>-final.json"

ELECTRON_RUN_AS_NODE=1 "$Q" "$(cygpath -w "$S")" restore "<脱敏件.xlsx>" \
  --map "$(cygpath -w "$M")" -o "<回退.xlsx>"
```

- 回退是文本级替换，不认单元格位置：按脱敏版重排、拆列、汇总后的新表同样能还原。
- 交回退件前建议对结构化字段（账簿、往来单位、账号列）做一次抽样比对吧。

## 七、已知限制（复核重点）

1. **人员姓名未处理**：制单、审核、过账、出纳四列，以及摘要中的入住人、收款人、联系人等自然人姓名仍是明文。往来单位字段中的个人已按 `客商NNN` 处理。
2. **银行名称保留**：机构名称属公开信息，仅账号代号化。
3. **品牌/公司简称未逐一代号化**：摘要中像"京东""Barron"这类非完整名称仍是明文（完整法定名称均已替换）。
4. **一个代号一个主体**：同一主体的多种写法共用一个代号，回退取最长全称；需要逐字还原只能给每种写法单独发号（会让同一主体出现多个代号）。
5. **对照表本身是未脱敏数据**：《脱敏数据回退mapping表.xlsx》含全部原始名称与账号，只能内部留存，不得随脱敏件外发。
6. **分卷限制**：Excel 单表上限 1,048,576 行，2,087,716 行序时账只能分三卷交付。

## 八、可供复核的检查点

- 打开三卷序时账，检索客户字号（如"XX"）、任一原始银行账号、任一往来单位原值，应均为 0 命中。
- 检查 `xl/workbook.xml` 不再含 `absPath`，`docProps/core.xml` 的作者为空。
- 抽查脱敏件某行：账簿、往来单位、摘要中的公司名、账号是否均为代号，借贷金额与原件一致。
- 用映射表把任一脱敏件回退，结构化字段应与原件一致（摘要中的简称会还原为全称）。
- 核对总行数：三卷合计 2,087,716 行，与原件扣除表头后的合计一致。

## 附：本次使用的一次性批量流程

1. `--discover-only` 扫描：抽取主体候选（中文后缀词 + 英文 Ltd/Inc/LLC/GmbH/PTE 等后缀）、往来单位列取值、账号（IBAN 与"账号"上下文中的数字串）。
2. 清洗候选：剥离"收/支付/付款/单号/日期"等前缀，剔除银行类、类别词、括号不闭合、单号混入的伪主体；同一主体的不同写法按规范化合并同号。
3. 追加映射（只追加、不重排），写入 `replacements` 与 `accounts.list`。
4. 逐文件流式替换 + 元数据清理 + 结构对比 + 残留扫描 + 往返抽样。
5. 导出 4 个 sheet 的回退对照表（使用说明 / 公司与标签 / 外部客商 / 银行账号）。
