## 三、做法

### 3.1 账表调整数 = 0

模板 F 列（账表调整数）是空的，而 G 列是 `=E+F`（本期未审数）。空着时 Excel 把 F 当 0，
算出结果没错，但审计看不到"到底调没调"。现在显式写 0，要不要调由项目组改。

### 3.2 进一步调查基于定性考虑 = 否

P 列全填「否」。定性调查是职业判断，工具不能替审计下"是"；
默认「否」+ 项目组按需改，比留空更明确（留空会被当成"忘了填"）。

### 3.3 For X-ref：别让审计以为薪酬漏测了

薪酬、折旧摊销这些费用**已经在应付职工薪酬 / 固定资产 / 无形资产底稿里测过**，
在费用 BKD 里只需要一个交叉索引。索引格式 = 底稿名 + 资产负债表日：

```
应付职工薪酬20260930
无形资产20260930
长期待摊费用20260930
固定资产20260930
使用权资产20260930
```

日期取 `balance_date` 去掉分隔符（`2026-09-30` → `20260930`），换年自动变。

映射按**科目名**判，顺序有讲究（先具体资产、后薪酬，否则「无形资产摊销」会被
「摊销」这个词带到固定资产上去）：

| 科目名关键词 | 索引 |
|---|---|
| 无形资产 / 软件服务费摊销 / 软件摊销 | 无形资产 |
| 长期待摊 / 待摊费用 | 长期待摊费用 |
| 使用权资产 | 使用权资产 |
| 累计折旧 / 折旧费 / 固定资产 | 固定资产 |
| 股权激励 / 股份支付 | 应付职工薪酬 |
| 薪酬 / 工资 / 奖金 / 提成 / 社保 / 公积金 / 福利 / 劳务 / 董事 / 补贴… | 应付职工薪酬 |

瑞云实测分布：

| 页 | 应付职工薪酬 | 无形资产 | 固定资产 | 使用权资产 |
|---|---|---|---|---|
| 销售费用 | 105 行 | 1 | — | 3 |
| 管理费用 | 36 行 | 2 | 2 | 1 |

### 3.4 NB 编号把表2 和明细串起来

表2 分析过哪些口径，明细里就要能看到对应标记，否则审计抽样时对不上。

- 表1 新增 **H 列「编号」**：分析过的口径依次 `NB1/NB2/NB3…`（红色加粗）
- 表2 每行右边同样标 `NB1…`
- 明细行 **Q 列（Notes）** 同步标同一个号（红色加粗）

判定与表1 的 G 列**同一口径**（OR：金额或比率任一超阈值），Python 侧先算一遍
（openpyxl 读不到公式结果），两边必须一致，所以测试里专门断言了
「NB 口径与是否需调查一致」。

瑞云实测：

| 口径 | 是否需调查 | 编号 |
|---|---|---|
| 广告费 | 是 | NB1 |
| 薪酬 | 否 | 无（正确：金额 −22.6 万、比率 −1.5% 都没超） |
| 其他 | 是 | NB2 |
| 技术服务费 | 是 | NB3 |
| 折旧摊销 | 是 | NB4 |

明细 Notes：销售费用 70 行、管理费用 39 行带 NB 标记。

**为什么编号放 H 列而不是 B 列**：B 列是 SUMIF 的条件（`$B213`），
写成「NB1 广告费」会让 SUMIF 匹配不到，整张表变 0。这个坑测试里也守了一道。

### 3.5 顺带修的顺序问题

`_write_te()` 原来在 OAR 块里，而 `_fill_sheet` 在它之前执行 ——
表2 的 NB 编号要用 `TE×50%` 判阈值，拿不到就只能全编号或全不编号。
本版把 `_write_te` 提到 `_fill_sheet` 之前。

## 五、已知边界

1. **索引名是按科目性质推的，不是真的去读那几本底稿**。`应付职工薪酬20260930` 意思是
   "这部分金额已在应付职工薪酬底稿覆盖"，前提是客户确实做了那本底稿；没做的话
   要人工把这一列清掉。
2. **科目名认不出就不给索引**（返回空），不硬套一个。所以「技术服务费」「代理机构服务费」
   这类 N 列是空的 —— 它们本来也没有对应的资产负债表科目底稿。
3. NB 编号只覆盖**表2 里"是"的口径**；「否」的口径没有编号，明细行 Notes 保持模板原值
   （部分行是 `[A]`/`[B]` 脚注）。
4. F 列填 0 会覆盖模板原有的空值；如果项目组习惯"空着表示不适用"，需要改回来。
