# PTW平台 V1.2.01 · 本次更新说明

> 日期：2026-11-03　上一版：V1.1.05（2026-11-02）
> 用途：给接手测试的 AI / 人快速知道「这一版多了什么、去哪里点、哪些还没做」。

## 一句话

底稿板块从「货币资金 BKD 生成器」升级成 **「WP 初稿生成」**（子级按科目分：货币资金 / 销管费用），
能力拆成两层：**工具做机械活**（本年上数、千元口径），**AI 做判断活**（上年数、变动归因）。
同时数据检查加了第五组，专门盯「货币资金有没有账户粒度」。

## 1. 底稿板块重构：三、底稿生成 → 三、WP初稿生成

- 导航下分两个子级：**货币资金**、**销管费用**（`manifest.json` 的 children + 前端 `?sub=` 路由）。
- 页面按能力分两区：
  - **工具能力**：本年 Lead + BKD、费用 BKD、OAR 骨架
  - **AI 能力**：上年 WP → 上年数、OAR 变动分析

## 2. 银行存款 C.00 BKD 上数（工具能力）

- 从 `tb` 取 1001/1002/1012，按「主体 × 银行 × 账号 × 币种」写明细，Lead 打 SUMIF。
- **按表头文字定位列/表头行/合计行**，不写死列字母：本地 V7 是 B~L，客户底稿 A~M+P 也能跑。
- 缺资料标黄 FFFF00 + 进「检查」表末「五、待确认清单」。
- 实测（脱敏 TB）：162 行，本币合计 1,422,875,661.78，与余额表逐科目一致；标黄 324 格。

## 3. 费用 VC/VD BKD 上数（工具能力，新增模块 `expense.py`）

- 序时账按「账簿 × 科目编码」汇总，**借方 −（贷方 − 结转类贷方）**。
  不剔除「结转本期损益」的话，月末结转会把每个费用科目冲平，全部算成 0。
- B 列填映射后公司名，原始账簿留在检查表「账套映射」；需先上传「账簿↔公司」对照表。
- 上期审定数无源 → 整列标黄；变动额/变动率随之留空，不会算成「本期全额都是变动」。
- 实测：VC 184 行 / VD 132 行，合计 212,548,269.46。

## 4. OAR 货币资金（工具能力 + AI 待接）

- 千元口径，自动填库存现金 / 银行存款 / 其他货币资金三行，合计与 CHECK 均为公式。
- 定期存款、大额存单的流动/非流动拆分、受限资金属人工判断 → 留空标黄并写原因。
- 实测：合计 1,422,875.66 千元 = Lead 合计，CHECK 可归零。

## 5. 上年 WP 结构探测（AI 能力的入口）

- 上传上年底稿 → 「导出结构探测包」：每个 sheet 的行列数、表头匹配分、前 12 行样张 → markdown。
- 复制给 AI，AI 回 `{sheet, header_row}`，平台按它解析（`/api/build/prior/apply`）。
- 规则文档：包根 `AI作业指南_WP初稿生成.md`。

## 6. 数据检查新增第五组：货币资金辅助核算可用性

前四组是「两边对不对」，第五组是「数据够不够用」：

| 检查 | 输出 |
|---|---|
| 科目余额表 | 账户行数 / 需要账户粒度的行（仅 1002+1012）/ 带辅助核算 / 名称可反解 / 能定位 / 无法定位 |
| 序时账 | 相关行数 / 带明细码 / 带辅助核算 / 摘要含银行名 |

**核心是成因判定**，靠 `raw_<sid>` 列名 → `_sheets.mapping` 的 aux 配置 → `tb` 实际值 → `_dropped_<sid>` 剔除数 四层对比：

| 判定 | 含义 | 动作 |
|---|---|---|
| `present` | 结果里有值 | 正常 |
| `never_present` | 原始表没这列 | 客户重新导出，不是清洗问题 |
| `never_filled` | 有列但全空 | 客户没填，不是清洗问题 |
| `not_mapped` | 原始有值、映射没配 | 字段映射页补 aux1/aux2，**不用重导** |
| `lost` | 映射配了、结果空 | 疑清洗误删，查剔除留痕 |

只有 `lost` 才是真的「被删了」。五种场景已用内存库逐一验证。

## 8. 已知限制（不是 bug）

| 项 | 说明 |
|---|---|
| 性质 / 是否函证 / 受限资金 | 职业判断，工具只标黄，不给默认值 |
| 上期数 | 需先跑「上年 WP」，否则 OAR 与费用变动列整列为空 |
| OAR 后五行 | 定期存款/大额存单/受限资金需人工拆分 |
| OAR 变动归因 | 分析口径已写入指南，代码尚未接 |
| 销管费用 TOD | 未做。TOD 逻辑在 `审计底稿上数逻辑说明` 第 6 章，需另配 `TOD SWP U_Exp` 工作簿 |
| G3 / C.01b / C.00b / C.02 | 未做（缺原件或属 C 级人工判断） |
| 包内不带数据 | `data/` 只有模板。测试需自行导入科目余额表与序时账 |

## 9. 怎么验证这一版

见 `V1.2_上数功能开发计划_20261103.md` 的 **§11 交给别人测试时的步骤**，含逐项核对清单。

最短路径：

1. 双击 `启动PTW平台.bat`
2. 「一、导入与清洗」导入 TB → 映射（**注意 `期末余额(借)` 是原币、`期末本位币(借)` 才是本币**）→ 合并
3. 「三、WP初稿生成 → 货币资金」→ 预览 → 生成 → 看 C.00 BKD 的标黄格与检查表
4. 「合并与检查 → 数据检查」→ 拉到第五组，看辅助核算诊断
5. 「费用底稿」→ 上传对照表 → 生成 → 看 VC/VD 的 E 列与 K 列标黄
