# V1.2.03 · WP 初稿生成：上年数联调（自己造数测出来的 4 个问题）

> 背景：手上没有上年 WP 的真实脱敏文件，用「模拟本年在审 + 上年已审」自造数据把这条链路跑了一遍。
> 结论：**4 个问题，其中 1 个是硬 bug（上年数据白回捞），已全部修掉。**

## 1. 怎么造的数据

`tmp/gen_mock_wp.py` 生成两个文件：

| 文件 | 内容 |
|---|---|
| `本年科目余额表_模拟.xlsx` | 3 主体 / 8 个账户（含美元户、其他货币资金、两家公司的库存现金），期末本币合计 **12,215,000** |
| `上年货币资金BKD_模拟.xlsx` | 8 个账户，期末本币合计 **11,438,000**，带性质与是否函证 |

两边刻意设计成：**6 个精确匹配 + 1 个按科目兜底匹配（库存现金）+ 1 个本年新增 + 1 个去年注销**。
这样每个分支都能被验证，不是"全都对得上"的理想数据。

## 2. 测出来的 4 个问题

### ① 上年回捞的性质 / 是否函证压根没写进 Excel（硬 bug）

匹配对了、`merge()` 里 `row["nature"]` 也有值，但导出的 BKD 里 I/J 两列全空 + 全标黄。

根因在 `_fill_bkd`：判断列的循环里先查 `vals`（待写单元格），而 `vals` 只有
公司/科目/银行/账号/币种/金额这些字段，**性质、是否函证从来没被放进去过**。
于是每一行都走"没值 → 标黄"分支：

```python
for fld, label, reason in (...):
    c = col.get(fld)
    if T(vals.get(c)):
        continue          # 永远不会命中：nature / confirm 没进过 vals
    vals[c] = None
    gap_cols.add(c)       # 所以每行都标黄
```

这个问题跟有没有上年数据无关 —— **之前每次生成的 BKD，性质列都是空的**，
只是当时没有上年文件，看起来像"没数据源"，所以一直没暴露。

修：循环里先取 `row.get(fld)`，有值就写。

### ② 库存现金永远匹配不上上年

现金没有账号、没有开户行，匹配索引只有「公司+账号」「仅账号」「公司+银行」三条，
三条都用不上 → 被判成"本年新增"，同时上年的现金进"上年有本年无"清单。
每家客户都会遇到，等于每次都多两条噪音。

修：加「公司 + 科目」兜底索引，**但只在本行既没账号也没银行名时才启用**。
不加这个限制的话，新开的银行账户会被错配到去年注销的账户上。

### ③ 生成接口根本没接上年数据

`/api/build/c00/run` 只收 `balance_date` / `customer`，`_run_c00(prior=None)` 恒为 None。
`merge()` 支持上年、`parse_prior_xlsx()` 能解析、前端也能上传并探测结构 ——
但**中间这根线没接**。表现是：页面上传了上年底稿，生成出来的 BKD 上年列照样空。

修：
- 新增 `_load_prior(fid, spec)`：按 AI 确认的 `{sheet, header_row}` 解析，没给就自动挑匹配分最高的表
- c00 / oar 两个接口接收 `prior_fid` + `prior_spec`
- `/api/prior/plan` 上传时顺手入库并返回 `fid`（前端不用再传一次文件）

### ④ OAR 的上期列是写死的标黄

`build_oar()` 里 D 列硬编码为空 + 标黄，注释写着"本次无上年 WP"。
所以变动额、变动率永远是空，>TE 的项目永远不会浮现，AI 的变动分析也就无从谈起。

修：加 `by_subject_prior` 参数，按一级科目汇总上年审定数填 D 列；没有上年才标黄。
E/F 两列本来就是 `=IF(OR(C="",D=""),"",C-D)`，D 一填上就自动出数。

## 3. 修完的结果

```
上年 WP 结构探测     → C.00 BKD 第 9 行（匹配分 20）
BKD                  → 8 行 / 金额 12,215,000 / 缺口只剩 2 格
匹配统计             → matched=7（精确 6 + 按科目 1）、本年新增 1、上年注销 1
性质 / 是否函证      → 7 户全部回捞，只剩"本年新增的乙公司现金"标黄
OAR                  → 本期 3 行 + 上期 3 行，合计 12,215 千元 = Lead，CHECK 归零
```

核对过导出文件：
- BKD 合计 `=SUM(H10:H17)`、勾稽 `=H19-'C.00 Lead'!F41`，范围随行数自适应
- Lead 三条 SUMIF 都指向 `$C$10:$C$17` / `$H$10:$H$17`
- 检查表「五、待确认清单」只有 2 处，原因写明"本年新增账户（上年无对应记录）"
- OAR：库存现金 15 − 8 = 7 千元、银行存款 11,700 − 10,980 = 720 千元

## 4. 还没做的

- **费用（VC/VD）没有上年回捞**。费用 BKD 的 K 列上期审定要按「账簿 × 科目」匹配上年，逻辑和货币资金不同，
  这次没动。
- **上年有本年无的账户**只在 `stats.missCount` 里有数，没有在检查表里列明细。审计上"上年有本年没有"
  通常意味着销户，需要拿到销户证明，值得单独列一张清单。
- **OAR 的变动分析**（|变动额| ≥ TE 的项目归因）仍停在提示词层面，没有自动跑。
