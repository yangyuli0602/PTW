# 网银流水 × BKD 银行账号 Mapping — 生成逻辑说明

> 这份文档用于交接：说明 `网银流水与BKD账号mapping_20261027.xlsx` 是怎么从 207 份流水文件和 BKD 底稿生成的。另一个 AI 读完应能理解数据口径、匹配规则、输出结构，并能按同样逻辑复现或修改。

---

## 1. 任务目标

把 `13、20260630网银流水` 文件夹里的每一份银行流水，对应到 BKD 底稿中的“银行存款”账号，形成逐文件/逐账号的 mapping 表，并标记：

- **底稿有流水无**：BKD 有账号，但文件夹里没有对应流水；
- **流水有底稿无**：流水里的账号在 BKD 中找不到；
- **无法识别 / 待确认**：文件里拿不到本方账号，或 PDF 无法解析。

本任务只做**账号层面**的 mapping，不做金额核对、不做截止测试、不判断流水期间是否完整覆盖某个会计期间。

---

## 2. 输入与输出

### 2.1 输入

| 输入 | 路径 | 说明 |
|---|---|---|
| BKD 底稿 | `input/货币资金BKD_20261027_140328.xlsx` | 使用工作表 `C.00 BKD` |
| 网银流水文件夹 | `PBC/海柔AI优化资料-C/13、20260630网银流水` | 207 份流水（不含 `.files` 辅助目录） |
| 已生成的 mapping 表 | 同流水文件夹 | `网银流水与BKD账号mapping_20261027.xlsx` |

BKD `C.00 BKD` 表结构：

- 第 9 行是表头；
- 数据从第 10 行开始；
- 列（1-based）：
  - B 列 = 公司名称
  - C 列 = 科目名称
  - D 列 = 银行/存款机构名称
  - E 列 = 账号1
  - F 列 = 币种
  - G 列 = 期末账面金额（原币）
  - H 列 = 期末账面金额（本币）

只取 **C 列 = "银行存款" 且 E 列账号非空** 的行，共 **159 个账号**。

### 2.2 输出

输出工作簿包含 6 个工作表：

1. `说明` — 统计和识别逻辑；
2. `文件映射` — 逐文件、逐账号的 mapping（多账户文件会拆成多行）；
3. `账号汇总` — 159 个 BKD 账号全覆盖，含流水文件数；
4. `底稿有流水无` — 75 个没有流水的 BKD 账号；
5. `流水有底稿无` — 流水里出现但 BKD 没有的账号，以及无法识别的文件；
6. `重复文件` — 按 MD5 列出的重复件。

## 3. 核心数据结构

### 3.1 BKD 账号记录

```json
{
  "company": "深圳市海柔创新科技有限公司",
  "bank": "招商银行股份有限公司",
  "acct": "755932641710201",
  "digits": "755932641710201",
  "canon": "755932641710201",
  "currency": "人民币",
  "amount": 6981697.32
}
```

- `digits`：账号去掉所有非数字字符后的字符串；
- `canon`：`digits` 去掉前导 0，用于兼容银行导出时丢前导 0 的情况；
- `amount`：BKD 期末余额（本币），仅用于展示，不参与匹配。

### 3.2 流水文件记录

```json
{
  "name": "交易查询，深圳市海柔创新科技有限公司，755932641710201，人民币，20260101-20260630，共7676笔.xlsx",
  "rel": "交易查询，...xlsx",
  "path": "...",
  "ext": ".xlsx",
  "size": 123456,
  "md5": "..."
}
```

### 3.3 Mapping 记录

```json
{
  "file": "...",
  "accounts": [ ... ],        // 匹配到的 BKD 账号，可能多个
  "method": "文件名含账号 / 内容识别 / 同源PDF / 多账户合并流水",
  "status": "已匹配-文件名 / 已匹配-内容 / ...",
  "raw_account": "...",       // 未匹配时识别到的原始账号
  "raw_candidates": [ ... ],  // 所有识别到的候选账号
  "nonbkd": [ ... ],          // 不在 BKD 的账号
  "note": "..."
}
```

## 4. 处理流程

### Step 0：枚举文件

遍历流水文件夹，**排除**：

- 以 `.files` 结尾的辅助目录（HTML 框架文件的碎片）；
- 输出文件本身（避免把 mapping 表当成流水）；
- Excel 临时文件（`~$` 开头）。

得到 **207 份**流水文件。

### Step 1：读取 BKD 账号

读取 `C.00 BKD`，按第 2.1 节规则提取 159 个银行存款账号。

### Step 2：计算文件 MD5

对每份流水计算 MD5，用于识别重复件。典型重复：

- `BR_STATEMENT_09072026*.xlsx` 共 26 份；
- `AISTMTPRINT*.xlsx` 多份重复；
- `B443...` / `EXCELB443...` 成对重复。

重复件不删除，仍在 mapping 中逐文件列示，只在备注里标注“内容重复”。

### Step 3：按优先级匹配

匹配优先级从高到低：

#### 3.1 文件名含完整账号

把文件名中的连续数字与 BKD 账号比对，命中即匹配。

```text
filename_digits = 文件名去掉非数字
for each bkd_account:
    if len(bkd_account.digits) >= 8 and bkd_account.digits in filename_digits:
        match
```

适用：`交易查询，...，755932641710201，...`、`对账单，...，755954797510202，...`、`账户明细查询_..._03006017389...`、`20260709111514_443066436013009856813.xls` 等。

#### 3.2 Excel 内容识别（.xlsx）

许多文件名不含账号（AISTMTPRINT、BR_STATEMENT、20260709 批次、historydetail 等），需要读内容。

关键点：

1. **必须调用 `ws.reset_dimensions()`**  
   部分银行导出的 sheet dimension 是错误的（例如 `BR_STATEMENT_09072026 (11).xlsx` 显示 `max_row=1`、`max_col=1`，但实际有数据）。不 reset 会漏读。

2. 只读前 **40 行 × 30 列**，避免大表全量读取。

3. 优先找“本方账号”字段，按以下顺序：
   - 表头/单元格文本匹配：
     `本方账号 | 选择账号 | 交易账号 | 查询账号 | 账号 | 帐号 | 账户号码 | Account No / Account Number`
   - 如果标签和值在同一行相邻单元格，取右侧第一个非空单元格；
   - 如果值是逐行重复的（如 `historydetail795.xlsx` 的“本方账号”列），取该列出现次数最多的值；
   - 如果找不到本方账号字段，则取**文件中最早出现的 BKD 账号**作为本方账号（交易明细里的对方账号通常排在后面）。

4. 如果表内只有“对方账号”而没有本方账号字段，**不能**把对方账号当成本方账号，标记为“无法识别本方账号”。

5. 账号变形兼容：
   - 前缀分行号：`011-672789-001` → `011672789001`，匹配 BKD `672789001`；
   - 账号后缀：`03006017389` → 匹配 BKD `0039294103006017389`；
   - 前导 0：`112059423` → 匹配 BKD `0112059423`。

#### 3.3 二进制 .xls 内容识别

当前环境**没有** `xlrd` / `pandas`，无法直接读老式 `.xls`。实际采用字节级扫描：

```text
读取文件前 8MB
分别用 latin-1、utf-16le、utf-16be 解码
把所有非数字字符去掉，得到数字串
在数字串中查找 BKD 账号（含去前导 0 的变体）
取“最早出现”的 BKD 账号作为本方账号
```

这样做的依据：银行流水的表头（本方账号）在文件中通常出现在交易明细之前；交易明细中的对方账号位置更靠后。

**局限**：如果账号在文件中是数字型单元格（double），或文件经过压缩/加密，字节扫描可能找不到；这时会落到“无法识别”或需要人工确认。

#### 3.4 特殊文件：多账户合并流水

`AccountStatementListResults.xls` 和 `AccountStatementListResults (2).xls` 是**一份文件包含多个账户**的合并流水。

处理方式：

1. 先把 HTML 标签去掉；
2. 解析 `Search Criteria → Account: 'Equals' ... Cheques` 之间的账号清单；
3. 逐个账号匹配 BKD；
4. 一个文件对应多个 BKD 账号，在 `文件映射` 中拆成多行；
5. 清单中不在 BKD 的账号（如 `1064159042`）单独进入 `流水有底稿无`。

`AccountStatementListResults (1).xls`、`(3).xls` 是 HTML 框架文件，无交易数据，标记为“辅助文件/无数据”。

#### 3.5 PDF

处理顺序：

1. 文件名含完整账号 → 直接匹配（如 `Transaction_Details_8110301013600853520_1.pdf`）；
2. 同目录有同名 `.xls/.xlsx` → 继承同名 Excel 的账号；
3. 以上都没有 → 扫描 PDF 文本；
4. 扫描不到 → 标记“待确认-PDF”。

**已知案例**：`historydetail455.pdf` 是图片型/扫描型 PDF，解压后是图像数据，没有文本层，也没有同名 Excel，因此无法识别本方账号。

#### 3.6 账号后缀兜底

对“流水有底稿无”里识别出的原始账号，再做一次后缀匹配：

```text
if BKD.canontail.endswith(raw_account_canon) and len(raw_account_canon) >= 8:
    match
```

例：`03006017389` → BKD `0039294103006017389`。

## 5. 匹配状态定义

| 状态 | 含义 |
|---|---|
| `已匹配-文件名` | 文件名里直接含 BKD 账号 |
| `已匹配-内容` | 从 Excel/.xls 内容里识别出本方账号 |
| `已匹配-同源PDF` | PDF 继承同名 Excel 的账号 |
| `已匹配-多账户合并流水` | 一份文件含多个 BKD 账号，已拆行 |
| `流水有底稿无` | 流水账号不在 BKD |
| `无法识别本方账号` | 文件里拿不到本方账号 |
| `待确认-PDF` | PDF 无文本层，无法解析 |
| `辅助文件/无数据` | HTML 框架/无交易数据 |

## 9. 复现环境与最小伪代码

### 9.1 环境

- Python 3.13
- `openpyxl 3.1.5`
- 无 `pandas`、无 `xlrd`、无 PDF 解析库
- `.xls` 采用字节扫描（latin-1 / utf-16le / utf-16be）

### 9.2 最小伪代码

```python
# 1. 读 BKD
accounts = []
for row in ws_bkd.iter_rows(min_row=10, values_only=True):
    if row[2] == "银行存款" and row[4]:
        accounts.append({
            "company": row[1], "bank": row[3], "acct": str(row[4]),
            "digits": only_digits(row[4]),
            "canon": only_digits(row[4]).lstrip("0"),
            "currency": row[5], "amount": row[7],
        })

# 2. 枚举文件
files = [f for f in walk(FLOW)
         if not f.dir.endswith(".files")
         and not f.name.startswith("~$")
         and f.name != OUTPUT_NAME]

# 3. 匹配
for f in files:
    # 3.1 文件名
    hits = [a for a in accounts
            if len(a.digits) >= 8 and a.digits in only_digits(f.name)]
    if hits:
        record(f, hits, "文件名含账号"); continue

    # 3.2 xlsx
    if f.ext == ".xlsx":
        own = read_own_account_from_xlsx(f)   # 表头字段/列/相邻单元格
        if own and match_bkd(own):
            record(f, match_bkd(own), "内容识别"); continue
        if own:
            record(f, [], "流水有底稿无", raw=own); continue
        # 否则取最早出现的BKD账号
        ...

    # 3.3 xls
    if f.ext == ".xls":
        text = decode(f.bytes, ["latin-1", "utf-16le", "utf-16be"])
        candidates = find_bkd_accounts_by_position(text)
        if candidates:
            record(f, [candidates[0]], "内容识别"); continue
        ...

    # 3.4 PDF
    if f.ext == ".pdf":
        if same_base_excel_has_mapping(f):
            inherit(f)
        elif account_in_filename(f):
            record(f, ...)
        else:
            record(f, [], "待确认-PDF")

# 4. 非BKD账号 & 无流水账号
nonbkd = [d for r in records for d in r.raw_candidates
          if not match_bkd(d)]
no_flow = [a for a in accounts if a.acct not in mapped_accounts]
```

## 10. 给接手 AI 的建议

1. **先确认日期口径**：本文件夹 207 份流水都是 2026-01-01 至 2026-06-30 的导出；没有 2026-09-30 的数据。若要做 9/30 截止测试，需要先补充 Q3 流水。
2. **不要只用“全文出现过的账号”判断本方账号**：交易明细里大量出现对方账号，必须优先用表头/本方账号字段/最早出现位置。
3. **`.xlsx` 注意 `reset_dimensions()`**：部分文件 dimension 错误，直接读会漏数据。
4. **`.xls` 没有 xlrd 时只能字节扫描**：结果要保留“最早出现”的依据，并对多候选文件人工复核。
5. **重复件先去重再统计金额**：否则同一笔流水会被重复计算。
6. **输出表保留“打开文件”相对超链接**：mapping 表与流水同目录，整体转发后仍可用。
7. **本文档只描述账号 mapping，不包含交易金额合并/截止测试逻辑**；如果下一步要做“某一天流水合并成一张交易表”，需要另行解析各银行交易明细表头、日期、金额、方向、对方户名，并按账号+日期+金额+方向去重。
