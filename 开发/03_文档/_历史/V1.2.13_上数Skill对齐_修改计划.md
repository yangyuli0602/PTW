## 一、两份文档的关系（先定这个，否则会重复实现）

| 文档 | 定位 | 用途 |
|---|---|---|
| Skill v1.1 | **规则本身**：跨项目、跨年度、跨模板版本都成立 | 协议层。定义 Discover/Map/Load/Prove、字段别名、不变量、人机分工 A/B/C/D |
| 逻辑说明 v3 | **实例**：瑞云 20260930 的具体数字与公式 | 回归样例。提供 fingerprint / baseline 的真实取值，不是规则 |

两者明确写了这个分工：Skill 末尾「本 Skill 描述怎么做，不绑定任何客户、期间或单元格；项目实例与回归数字放在各自的 baseline.json」。

**结论**：Skill 进 `03_文档/`，作为**权威规则底本**，代码实现以它为准；逻辑说明 v3 替换现有 v2，只作回归样例，**不得把其中的数字写进代码**。

## 二、差距盘点（PTW V1.2.12 vs Skill 要求）

### 2.1 已经对齐、不需要动的

| Skill 要求 | PTW 现状 | 判断 |
|---|---|---|
| 不写死单元格，按表头语义定位 | `_locate_bkd_cols` 按表头文字匹配 | ✅ 一致 |
| 不写死 sheet 顺序 | 按表名解析，不按序号 | ✅ 一致 |
| OAR 精确 /1000 不 ROUND | `round(v/1000, 6)`，仅浮点收敛 | ✅ 一致（6 位不是舍入到分） |
| 空值不写 0，留空标黄 | `gap` 机制 + FFFF00 | ✅ 一致 |
| 上年有本期无必须保留 | `_priorOnly` 金额 0 + Notes | ✅ 一致 |
| 幂等 upsert | `bkd_key` 业务键 | ✅ 一致 |
| 数据检查 | PTW 五组（比文档四组多"辅助核算可用性"） | ✅ **PTW 更全，保留五组**，文档侧补一句 |

### 2.2 冲突点（必须裁决）

| # | 冲突 | 裁决 | 理由 |
|---|---|---|---|
| C1 | 文档四组检查 vs PTW 五组 | **保留五组**，把第五组写进 Skill 的 §7 | 第五组（货币资金辅助核算五态成因）是 PTW 实测有效的能力，砍掉是倒退 |
| C2 | 文档"截止性池按 ±N 天裁剪" vs PTW 从序时账直接抓 | **保留 PTW 实现**（`_build_cutoff`），文档注明"PTW 口径：跳过模板池，直接从序时账按期间+阈值抓转账" | 文档自己说"样本池-CUT 本版仍是全量副本，工具应自行按测试期间过滤"——PTW 的做法正是它要求的，只是不经过模板池 |
| C3 | 文档"OAR 类别由 mapping 派生，增删要重跑" vs PTW 只填三行 | **保持三行 + 其余留空标黄** | 定期存款/大额存单的流动非流动拆分是 C 级判断。强行自动派生会产出"看起来对但没依据"的数 |
| C4 | 文档 TE 779,338.37 具体值 vs PTW 用 `amt_threshold=100000` | **新增 TE/SAD 读取**：从模板 `PMTE` 找，找不到用默认并在报告标 `TE_NOT_READ` | 文档明令"永远从 PMTE 读，不写常数"。现在连读都没读 |

## 三、决策（把所有"待定"钉死）

| 决策 | 结论 | 理由 |
|---|---|---|
| D1 | **不重构** Discover/Map/Load/Prove 主链路 | `core.py` 2618 行已收敛；四阶段作为**对外概念和新增能力的组织方式**，不推翻现有 `_locate_bkd_cols` / `_fill_bkd` |
| D2 | 指纹、配置包、不变量、baseline **先做**，排在所有科目改动之前 | 它们横切所有科目，晚做每个科目都要返工两次 |
| D3 | TOD **分两期**：一期自动（池+标签+总体/剔除/关键项），二期回填（抽样回链+测试表） | 二期依赖外部抽样工具的输出单元格，本期先留接口 |
| D4 | G3 **排在 TOD 之后** | G3 的价值一半在"账龄桶"结构，需要 TOD 的"分桶+不变量"经验打底 |
| D5 | C.02 / C.02a **做**，但按「模板里存在该 sheet 才执行」触发 | 不是"不做"，是条件执行；没有这张表的小项目直接跳过并记理由（符合 Skill §3.1 的 C 级判断描述） |
| D6 | 科目包抽象 **等 G3 做完再抽** | 只有两个科目时抽象是猜的；G3 是第三个形态（供应商级+账龄），抽出来的才准 |
| D7 | 费用上期回捞 **做**，规则按 Skill §5.2「（账簿, 科目名）从上期同名 BKD 取」 | 这是当前最刺眼的缺口，整列黄 |
| D8 | TE/SAD **从模板读**，读不到用默认并在 `warnings` 标 `TE_NOT_READ` | 既满足"不硬编码"，又不会因为没有 PMTE 就整条流程停住 |

## 七、明确不做的事（不是待定，是结论）

| 不做 | 理由 |
|---|---|
| 把生成逻辑改成"AI 现场写 Excel" | 不可复现、不可追溯、上下文装不下（详见前次分析） |
| 让 AI 直接产出 OAR 的类别拆分 | 定期存款/大额存单拆分是 C 级判断，自动派生等于伪造依据 |
| 自动填对账单、自动下"无调节/无受限"结论 | Skill §8 D 级禁止项 |
| C.02 / C.02a 在无对应 sheet 时强行创建 | 会破坏"非目标 sheet 逐字节不变"的承诺 |
| 科目包抽象提前到 V1.2.13 | 只有两个科目时抽象是猜的，第三个（G3）才是检验 |

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 指纹过严导致正常改动被拦 | 指纹只含"结构"（表名/表头/行数/链接），不含数据；数据变化不触发 |
| 配置包导入把上年的判断带进来 | 判断类一律置 `待复核`，不自动 confirmed（D2 的硬约束） |
| TOD 标签算法跑偏 | 用逻辑说明 v3 的瑞云数做回归：预提冲销按段净额 0、负值分类 −65,664.02 + −3,414,411.93 = −3,480,075.95 |
| G3 账龄桶边界错 | 6 桶边界写进 `invariants.yaml`，桶合计必须等于期末余额 |
| 改 `core.py` 引入回归 | 每版先跑 `baseline compare`，差异必须逐项解释才能打包 |
