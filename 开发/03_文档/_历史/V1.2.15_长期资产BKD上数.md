## 1. 做了什么

把桌面上那个独立 JS 工具（`固定资产明细表生成/资产打标工具`，12 万字符单文件）已经跑通的
固定资产 K1 明细清单，搬进 PTW：

```
FA list 期末 ┐
FA list 期初 ┼→ 按「细分类型」汇总 → 期初 K~N / 期末 AE~AH（SUMIFS 指向「台账汇总」）
序时账 1501/1502/1505 → 打标 → 本期变动 O~AD（SUMIFS 指向「序时账」）
             └→ 各资产类型小计 + 合计 + 三列 CHECK
```

输出一份 xlsx，三张表：`K1_100Breakdown_4000`（主表）+ `序时账`（打标后的变动明细）+ `台账汇总`（26 行分类汇总）。

## 2. 三条核心设计（按你确认的口径）

### 2.1 类别不写死

模板的 26 行只是**版式骨架**，真正出哪些类别由数据决定：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 台账自带的中文分类名 | 客户台账写着「固定资产-办公用房」就直接用 |
| 2 | 分类对照表 | 上传的 `分类编码/细分类型/资产类型` 三列，编码是 G0100 这种必须有 |
| 3 | 期初台账的「细分类型」列 | 两张表编码相同、一张带名字，自动学到 |
| 4 | 科目余额表的科目名称 | 「固定资产-办公用房」→ 办公用房 |
| 5 | 名称里的中文关键词 | 内置词典（房屋/机器/运输/电子/模具 五类 + 光伏发电等） |
| 6 | 兜底 | 记「未分类」，界面列出来，**不瞎猜** |

模板里没有的类别 → 按同类资产的**样式插行**（搬合并区/行高/数字格式），不够就一行一行加；
模板多余的行**留空不删**（客户自己的分类体系要留）。

### 2.2 期初期末只能来自台账

科目余额表能给「固定资产」总额，给不出 26 个细分类型。所以：

- 有台账：26 行全填满，CHECK 自证平衡；
- 没台账：**直接报错**并指路「先去导入与清洗上传 FA list」，不会生成一份期初期末全空的假底稿。

### 2.3 符号约定（改一个就错几个亿）

| 列 | 口径 |
|---|---|
| 原值 K/AE | 正（借） |
| 累计折旧 L/AF | **负**（贷方） |
| 减值准备 M/AG | 台账「会计年度末重估」（本身为负）；台账只给「减值准备」正数时取负 |
| 净值 N/AH | **原值 + 折旧 + 减值**（加法，因为后两项已是负数） |
| CHECK AI/AJ/AK | 期初 + 本期变动 − 期末 |

这三条是原项目连改三轮才定下来的，已经写成 `test_asset.py` 的断言，不是口头约定。

## 3. 用起来的三步

### 3.1 导入台账（在「一、导入与清洗」）

字段映射的「目标表」下拉里现在会多两项：

- **固定资产台账（期末）** → 合并成 `fa` 表
- **固定资产台账（期初）** → 合并成 `fa_beg` 表

两张表字段一样（21 个），常用映射：

| 客户列名 | 标准字段 |
|---|---|
| 分类 / 分类编码 / 资产分类 | 分类编码 `category_code` |
| 细分类型 / 明细类别 / 分类名称 | 分类名称 `category_name` |
| 资产类型 / 资产大类 | 资产类型 `asset_group` |
| 年末购置值 / 原值 / 购入价值 | 原值 `orig_cost` |
| 累计折旧 / 已提折旧 | 累计折旧 `acc_dep` |
| 会计年度末重估 | 重估 `reval` |
| 当前净帐面值 / 净值 / 净额 | 账面净值 `net_book` |
| 减值准备（正数） | 减值准备 `impair` |
| 资产编号 / 资产名称 / 使用部门 / 启用日期 / 折旧年限 / 残值率 | 同名 |

⚠️ 期初表的「上期末减值」「当期计提减值」两列**故意不映射**（原项目已确认放弃把它们匹配到行上），
`auto_map` 也不会误抓（`impair` 只认「减值准备」这类词，不认裸「减值」）。

### 3.2 上传分类对照表（长期资产页签第 2 步）

三列 xlsx/csv：`分类编码 | 细分类型 | 资产类型`。

- 台账分类是 `G0100` 这种纯编码时**必须给**，否则 18 万行全挤在「未分类」；
- 期初台账自带「细分类型」列时可以不传（程序会学）；
- 上传后存在库里 `_fa_map` 表，整表替换，跟着账套走。

### 3.3 一键生成

期间可留空（BKD 是年度报表，不像费用要切月度）。结果写 `data/bkd_out/固定资产BKD_*.xlsx` + `_最新` 副本。

CLI 等价：

```bash
ptw.py --data-dir data --pretty asset --map 对照表.xlsx --date 2026-09-30 --customer 客户名
```

## 6. 已知限制

1. **只做固定资产**（1501/1502/1505）。在建工程、无形资产、长期待摊、使用权资产形态不同，下一批做。
2. **分类对照表目前只能整表替换**，没有"增量补几条"的界面（`rows` 入参支持手工录入，但没有列表编辑 UI）。
3. **台账明细不搬进底稿**：只搬 26 行汇总（输出 1.8MB / 2 秒）。要看 18 万行明细请直接开客户原台账；
   如果审计要求底稿内可逐项追溯，需要加一个「附台账明细」开关（预计 +9 秒 / 12MB）。
4. **模板的 49 个外部链接保留原样**：打开会提示"是否更新链接"，指向客户原底稿。要清掉需另做。
5. **打标规则目前 9 条内置**，界面没有规则编辑器（原 JS 工具有）。规则存在 `asset.DEFAULT_RULES`，
   改规则要改代码；下一步接到 `_tag_rules` 表和界面。
6. **累计折旧/减值只支持"台账汇总口径"**：不支持按资产逐项重算折旧（那是 TOD 的活）。
7. **集团多主体没有按主体过滤**：台账带「公司名称」列时，当前是全部合并成一张底稿。
   单体审计要按主体各出一份，需要加主体选择（`read_fa` 加 where + 界面下拉）。
8. **纯英文分类名会落「未分类」**：词典只有中文词（"Server 服务器"能认是因为带中文）。
   英文客户要么给对照表，要么补英文词典。
