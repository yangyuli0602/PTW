# 货币资金 BKD · 专题说明

> 最后更新：2026-11-02
> 新会话接手 BKD 相关任务时，读本文即可，不必重新摸底。

## 一、模块在哪

```
程序/modules/bkd/
├── manifest.json  板块声明（type=embed，entry=bkd.html，static=web）
├── core.py        1883 行：取数、匹配、生成底稿、C.03 截止测试
├── routes.py      324 行：/api/bkd/* 等路由
└── web/           bkd.html + assets/bkd.{js,css}（主程序用 iframe 嵌入）
```

- v2.0.0 起 `server.py` 不再硬编码三板块，改为扫 `modules/*/manifest.json` 自动装配；BKD 声明为 `type=embed`，由主页面通用 iframe 渲染（`/bkd/**` 映射到本目录 `web/`），前端一行 JS 都不用写。
- 数据统一在根目录 `data/`：`bkd_tpl/`（模板）、`bkd_out/`（生成的底稿）、`bkd_work/`。
- 模板文件：`data/bkd_tpl/C SWP 货币资金 模板 V7.xlsx`（EY Skywind，16 个 sheet）。
- **关键**：BKD 不再独立开 duckdb 连接，`read_tb_from_duckdb(keyword, conn=None)` 复用 `ctx.ledger.conn`。原因是同文件不同配置会报 `Can't open a connection to same database file with a different configuration`。所以生成底稿时**不需要先关PTW平台**。

## 一之二、做「其他科目 BKD」时的复用点（2026-11-02 记）

下一阶段要做其他科目底稿，BKD 里这些是与科目无关的通用件，可直接抽出来复用：

- `_open_xlsx` / `_save` / `_find_tpl`：模板读写与定位
- `_grow_cutoff_block` / `_shift_row_dims` / `_retarget_cutoff_zones`：插行时搬样式、行高、条件格式、数据验证（模板带合并单元格就绕不开）
- 账号类单元格设 `@` 文本格式防前导零；金额 `#,##0.00`；日期 `yyyy-mm-dd`
- `read_tb_from_duckdb(keyword, conn)` 的取数口径：只认 `acct_l1` 一级科目，空时兜底 `acct_code`/`acct_name`，**绝不 `LIKE '1002%'`**

与科目强耦合、必须参数化的是：抓哪几个一级科目、模板第几个 sheet、表格起始行与列位、以及类似 C.03 的专项测试算法。别复制整份 1883 行。

## 二、取数口径（金额对不对全靠这）

只抓**一级科目**为 库存现金 / 银行存款 / 其他货币资金 的行：

- 用 `acct_l1`（清洗产出的「一级科目」列）精确匹配，编码 1001 / 1002 / 1012 或对应中文名
- `acct_l1` 为空时兜底 `trim(acct_code)` / `trim(acct_name)` 精确匹配
- **不用 `LIKE '1002%'`**，避免把二级明细和名称含"银行"的无关行误抓
- 明细科目（100201 等）只要 `acct_l1` 归属这三个科目，仍会纳入

## 三、C.03 Cutoff 截止性测试

模板位置：第 15 个 sheet `C.03 Cutoff`。

**表 1.1**：B7=测试阈值（覆盖原公式）、B8=资产负债表日、B11:F13=说明文字（自动生成，末尾留人工补理由）。
**表 1.2**：期末前数据区**第 20-24 行**、期末后**第 29-33 行**（各预置 5 行，超出自动插行并复制样式/行高/条件格式/数据验证）。

**列位**：B 样本号 / C 公司 / D 付款银行 / E 付款账号 / F 付款日期 / G 凭证号 / H 币种 / I 付款金额(负) / J 收款银行 / K 收款账号 / L 收款日期 / M 收款金额(正) / N 是否跨期 / O 备注 / **P Check=`=M+I`**。

**配对算法**（`find_transfers`）：
1. 第一轮：同凭证号 + 同主体 + 同一天 + 金额相等的一借一贷（凭证号按月重复，配对键必须带日期，否则跨月错配）
2. 第二轮：跨期配对 —— 付款日与到账日分处资产负债表日两侧、金额相等、主体相同
3. 归表按**付款方日期** ≤ 截止日 → 期末前，> 截止日 → 期末后
4. 未配对的单边行进"单边清单"留档

**填数细节**：E/K 账号设 `@` 文本格式防前导零；I/M 用 `#,##0.00`；F/L 用 `yyyy-mm-dd`；P 列保留公式。

## 四、踩过的坑（别重犯）

| 坑 | 表现 | 修法 |
|---|---|---|
| `is_money_account` 用全等 | 序时账 `acct_l1` 全空 → 一条都判不进，样本区全空 | 改「任一命中」：全等 + 名称含关键字 + 编码取前 4 位 |
| 合并单元格 | `insert_rows` 不搬行高/合并区/条件格式 | `_grow_cutoff_block` + `_shift_row_dims` + `_retarget_cutoff_zones` 手工同步 |
| `_find_tpl()` 依赖 `KZ_DATA` | 换 `KZ_DATA_DIR` 测试时报「未找到内置模板」 | 测试时把模板一并复制到临时 data 目录 |
| `.xls` 支持漏前端 | 后端改了 `load_wb_any`，但 `bkd.js` 的 `input.accept` 仍是 `.xlsx,.xlsm`，浏览器把 .xls 灰掉 | 改 accept；**模板上传仍只收 xlsx/xlsm**（转格式会丢样式公式） |

`.xls` 走自研 `core/xlsread.py`（纯 Python OLE2 + BIFF8，无 xlrd/pandas），`db._ensure_xlsx()` 转成 `.conv.xlsx` 后复用 xlsx 通道。

## 五、脱敏数据测试发现的 P0 问题（金额直接错）

这些是**清洗/映射不到位**导致的，不是 BKD 代码问题，但会直接毁掉底稿：

1. 多账簿 TB「方案层级」列未识别为主体 → 16 家公司混成一个，`matched=0`
2. TB 的「合计」行 /「多账簿(01)」汇总行 / 父级科目行未清洗 → 金额重复（实测银行存款显示 193.76 亿，正确 14.23 亿）
3. 序时账「合计」总计行（`_src_row=56706`）未清洗 → 发生额翻倍
4. 多币别 TB 本币/原币列错乱（「期初余额(借)」是原币却被当本币，「本位币」认词缺失）
5. 「综合本位币」汇总行与各币别明细行未区分 → 本币重复加总

其他：`currency` 缺「币别」认词；`bank_account` 误映射到「编码」列（致 cutoff 账号识别失败）；`is_money_account` 误判 6603 财务费用（名称含"银行存款"）。

## 六、待办：OCR 影像核对（方案已定，未开工）

### 约束（用户明确）
- 影像资料**不能脱敏、不能外传**，只能在客户那台电脑本地处理
- 那台电脑**不能接后台 API**（无外网）
- 机器**只有 CPU，无独显**
- 影像混合：银行回单 / 凭证扫描件 / 手机拍照都有
- 文件名**部分带银行账号**，部分不带

### 技术选型（已定）
| 环节 | 选型 |
|---|---|
| 识别引擎 | **RapidOCR**（onnxruntime，纯 CPU）—— 不用 PaddleOCR（Windows 装 paddle 麻烦） |
| 预处理 | OpenCV：纠偏、去阴影、自适应二值化 |
| 字段抽取 | 关键词锚定 + 正则（日期/金额/账号/户名） |
| 匹配 | **Python 脚本精确匹配，绝不用 LLM** |
| 底稿输出 | openpyxl |

**为什么不让 LLM 做匹配**：银行账号 16-19 位纯数字，大模型认长数字串是明确弱项，会看错、会编造，且错得很自然。脚本 `if 账号 in 文件名` 是确定性的。

### Qoder 的角色（用户问过）
- Qoder **不能当识别引擎**：默认模型是云端的（阿里云/Claude/GPT），把影像拖进去 = 上传影像，违反"不能外传"
- 它能接本地 Ollama（设置 → 模型 → 自定义 → OpenAI Compatible → `http://localhost:11434/v1`，可开"视觉"），但那是**在那边现场改代码/调参**用的
- 正确定位：**Qoder 是开发调试台，不是流水线引擎**

### 两阶段匹配
1. **归入账户组**：文件名带账号的 → 脚本提取账号直接归组；没账号的 → OCR 识别出账号再归组；都识别不出 → 进"待人工确认"，不猜
2. **组内配对到样本**：按 `金额（精确到分）+ 日期（前后 1-2 天窗口）` 匹配；一对多/多对一单独标记（往往就是问题）；配不上记"未见影像"；影像多余记"未匹配到样本"（可能漏记）

### 核对底稿设计
新建 sheet（不覆盖 C.03），一行一笔样本：
`样本编号 | 影像文件名 | 影像路径 | 凭证号 | 影像提取值(日期/金额/收付款账号/户名) | 账上值 | 逐项比对结论 | 综合结论(相符/不符/未见影像/影像多余) | 置信度(高/低) | 差异说明 | 复核人`

三条底线：可追溯（保留影像路径 + OCR 原文）、可复现（记录引擎版本）、**留白给人**（AI 只出机械一致性结论，定性判断必须人工）。

### 进度到哪了
- 停在「**先验识别率**」这一步：计划先写一个"把文件夹里影像全部 OCR 成文本并导出 Excel"的小工具，让用户看识别率；不行就换引擎，不白做

- **已验证可跑**：runtime/python 3.13 embeddable 下 `sys.path.insert(libs)` 后 RapidOCR 初始化 0.8s，识别 1000×620 回单 2.8s / 25 个文本块，中文准确
