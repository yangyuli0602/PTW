> 改动范围：只动 `程序/core/recon.py`，不碰清洗、不碰 BKD、不动数据
> 日期：2026-11-03

## 1. 结论：不是「缺一个视图」，是两边归一口径不一致

报告给了两个方案（复制视图 / 核对时归并）。查下来根因是**两侧用了不同的归一规则**：

```python
# 余额表：按币别字符串分组，只把「综合本位币」和空 归到本位币组
cur_tb = "CASE WHEN 空 OR '综合本位币' THEN '本位币（合计）' ELSE trim(currency) END"
# 序时账：整表强制归到本位币组（第 702 行，{CUR} 是字面量）
jr_sql = """ SELECT ... '本位币（合计）' AS currency ... FROM "journal" """
```

余额表按实际字符串分组、序时账一律归本位币组。只要余额表的币别不是`综合本位币`，两边就永远对不上：

| 余额表币别写法 | 序时账币别 | 第三组结果（改造前） |
|---|---|---|
| A 全是`人民币` | 人民币 | **4 行**：`本位币（合计）` 2 行报「仅序时账有」，`人民币` 2 行 |
| B 全是`综合本位币` | 人民币 | 2 行，全部一致 ✅ |
| C 双视图`综合+人民币` | 人民币 | 4 行，多出的`人民币`组按原币比 |
| D 真多币种`综合+美元+人民币` | 人民币 + 美元 | 5 行，正常 |

B 能过纯属巧合——那份余额表恰好写了`综合本位币`。

## 2. 顺带发现：第一组在 A 场景下是空转的

第一组的判定条件全是 `currency = '本位币（合计）'`。币别写`人民币`时，这个条件永不成立：

- `tb_open_net` / `tb_end_net` / 四项平衡检查全部不执行
- `status` 落到 `ELSE '平衡'`

实测（借 160 / 贷 0 的明显不平数据）：

```
第一组：['甲公司', '人民币', ..., '平衡']        ← 空转报通过
```

**这比第三组报差异严重得多**：数字栏是空的，结论却写「平衡」。本次一并修好（同一套归一）。

## 3. 改法：先按主体定形态，再给每行归组

新增三个共用函数（`core/recon.py` 顶部，紧跟 `entity_expr`）：

| 函数 | 作用 |
|---|---|
| `cur_base_pred(col)` | 行级：这一行是不是本位币汇总行（`综合本位币/本位币/记账本位币/本币/人民币本位币` 或空） |
| `cur_shape_sql(ent, table)` | 主体级：`has_base`（有没有汇总行）、`n_other`（除汇总行外几种币别） |
| `cur_group_preds(alias, t_alias)` | 返回两个条件：本位币组取哪些行、外币组取哪些行 |

判定规则：

| 主体的形态 | 本位币组 | 外币组 |
|---|---|---|
| `has_base = 1` | 汇总行（本币列） | 其它币别（原币列） |
| `has_base = 0` 且 `n_other <= 1` | **整个主体**（本币列） | 不生成 |
| `has_base = 0` 且 `n_other >= 2` | 全部行本币列合计 | 各币别（原币列） |

第三条不能省：导出时没带汇总行的多币种客户，如果无脑并进本位币组，原币核对就全跳过了。

配套两处：

- **外币组按「主体 × 币别」开**（`fx_pairs`），不再是「全表出现过哪些币别」。原来甲公司有美元，会给乙公司也开一个空美元组。
- **外币组要两边都给得出原币**（`tb_has_fx` 且 `jr_has_fx`），缺一边就 `fx_p = FALSE` 并提示「外币组已跳过，共 N 行外币」。否则双视图 + 序时账无原币的客户会看到一整片「仅余额表有」。

实现上把原来「一趟 `GROUP BY` 用 `CASE` 分币别」改成「本位币组和外币组分别聚合再 `UNION ALL`」——因为单币种主体要整体归入本位币组，而没有汇总行的多币种主体，同一行既要进本位币组（本币列）又要进原币组，一趟聚合表达不了。

## 4. 改动点

| 位置 | 改什么 |
|---|---|
| `core/recon.py` 顶部 | 新增 `BASE_CUR_WORDS`、`cur_base_pred`、`cur_shape_sql`、`cur_group_preds` |
| `_check_tb_self` | `WITH g AS (...)` → `WITH cur_ent AS (...), b AS (...), f AS (...), g AS (b UNION ALL f)`；外层 SELECT 没动 |
| `_pair_check` | `tb_sql` 拆成两组 `UNION ALL`；`jr_sql` 外币分支改成 `JOIN fx_pair`（`VALUES` 内联实体×币别） |
| `_pair_check` 排序 | `ORDER BY` 末尾补 `k.currency`。不同币别撞同一科目时前面几个键全并列，不加这列导出的行序每次都不一样 |
| `_check_tb_self` 勾稽差 | `round(..., 6)` 并把 ±5e-7 以内归零。分组方式变了，浮点累加顺序跟着变，会冒出 `-3.7e-09` 和 `-0.0` |

## 6. 会看到的行为变化

1. 币别写成`人民币`（或任何单一币别）的主体，**不再出现第二个币别组**，原来成批的「仅序时账有 / 仅余额表有」消失。
2. 第一组在单币种主体上**开始真的报不平**。如果之前这类客户显示「全部平衡」，现在冒出几条不平，那不是新增问题，是把一直没做的检查补上了。
3. 双视图 + 序时账没有原币时，`人民币`组不再出现，改为一条提示「外币组已跳过，共 N 行外币」。
4. 第三、四组的组数可能变少（外币组按主体×币别开），提示里会写「开组 N 组，涉及 M 种币别」。
5. 勾稽差列不再出现 `-0.0` 和 `1e-09` 这类显示。

## 7. 没做的

- **「复制为综合本位币视图」的派生动作**：不做。凭空造一份汇总行会同时影响第五组的账户行数、账户清单家数，以及 BKD 里「排除综合本位币行」这条防线——把一个展示口径问题变成数据问题，代价更高。
- **「(未标注主体)」行**：真实数据里有 1 行主体为空（综合本位币），第一组会出现一行 `(未标注主体)`。这是既有行为（主体表达式兜底），本次没动。
- 第四组的 759 条异常属清洗未达标（没有科目全称），与币别无关，见《AI提示词_清洗达标》。
