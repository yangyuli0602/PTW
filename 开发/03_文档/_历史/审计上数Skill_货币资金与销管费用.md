# 审计底稿上数 Skill：货币资金 + 销管费用

> 目标：任何人（或 AI）拿到一套新项目、新版本的底稿，都能按本 Skill 复现同一套上数逻辑，而不是改脚本里的 cell 地址。
>
> v1.1 增补：OAR 类别增删与上期重述、负值独立成池、抽样工具回链、截止性池、测试表回填（依据 2026-11-04 销管费用最终版）。
>
> 配套实例：`底稿/06_核对与分析/审计底稿上数逻辑说明_BKD_OAR_TOD.md`（瑞云 20260930，含具体数字，仅作回归样例，不是规则本身）。

---

## 0. 三条“不写死”原则

1. **不写死单元格**：所有区域由“表头语义 + 数据边界 + 合计行标签”现算；插入行后重算，不沿用旧地址。
2. **不写死结构**：sheet 顺序、表名后缀（如 26930）、列的位置、合计行位置都可能随版本变化，按名称模式与表头指纹定位。
3. **不写死数字**：TE、汇率、阈值、比例全部引用源单元格或配置；校验用“不变量”（A 应等于 B），不用“应等于 100,067,778.85”。

违反任一条，换项目或换版本就会失效。

## 1. 角色与产物

```
数据侧                         底稿侧（模板）
TB（账户/科目余额）  ──┐
序时账（凭证级）      ──┼──▶  BKD（明细底稿）──▶ Lead（科目汇总+调整）──▶ OAR（千元报表口径）
明细账（往来级）      ──┤                │
银行流水/对账单      ──┘                └──▶ TOD（交易级细节测试）
主数据（映射表、PMTE、汇率）
```

| 产物 | 说明 |
|---|---|
| BKD | 唯一原始录入层（账户/科目/供应商） |
| Lead | 科目级汇总 + 审计调整 + 与 TB 勾稽 |
| OAR | 千元列示 + 变动分析 + CHECK |
| TOD | 样本池、剔除、关键项、代表性样本、测试表 |
| 差异报告 | 待确认、未匹配、黄标、Check 非零清单 |

**单一数据源原则**：只有 BKD 的金额列与样本池的金额列允许“录入”；Lead/OAR/派生表一律公式。

> 同一套流程可直接复用到其他“科目余额型”底稿（如预付账款 G、应收/应付），只需替换字段别名与派生表规则；BKD → Lead → OAR 的骨架不变。

## 2. 输入契约

### 2.1 数据侧最低字段

| 数据 | 必需字段 | 常见别名（需归一） |
|---|---|---|
| TB（货币资金） | 主体、科目、银行/机构、账号、币种、原币余额、本位币余额 | 公司/账套、科目名称、存款机构、账号1、期末余额 |
| TB/序时账（费用） | 账簿、期间、凭证类型/号、摘要、科目编码、科目名称、币种、借方金额 | 会计期间/月份、凭证字号、一级科目 |
| 明细账（预付） | 主体、供应商、款项性质、期初、借贷发生、期末、账龄/受益期 | 往来单位、核算内容、年初余额 |
| 主数据 | 主体全称↔编号↔账簿；科目名称↔费用类别 | 全称/简称/编号/账簿名称；for OAR |
| 参数 | TE/SAD、资产负债表日、汇率（含来源与日期） | PMTE!B5/B6、即期汇率 |

### 2.2 归一化（先做，后上数）

- 科目编码：`Number(code).toFixed(3)`（`6601.0280000000002` → `6601.028`）。
- 币种：统一为 `人民币/美元/港元/新加坡元/欧元`；`USD/CNY/HKD/SGD/EUR` 建别名表。
- 日期：Excel 序列值与 `yyyy-mm-dd` 双向转换；期间列解析为 1–12 的整数。
- 金额：去千分位、去括号负数、保留 2 位（写回时用全精度 `String(+v)`）。
- 账号：一律按文本处理；写入前把单元格格式设为 `@`。
- 空值：不写 0；未取得的数据留空并标黄。

## 3. 四阶段流程（Discover → Map → Load → Prove）

### 3.1 Discover：先“认表”，再动数

1. **列 sheet**：从 `xl/workbook.xml` + `xl/_rels/workbook.xml.rels` 取“表名 → part”，**不假设 sheetN 顺序**。
2. **识别表族**：按名称正则匹配，不要求完全相等：

```yaml
cash_lead:    ["C.00 *Lead*", "C.00 引导表"]
cash_bkd:     ["C.00 BKD", "C.00 *明细*"]
cash_oar:     ["OAR *", "*OAR*"]
cash_confirm: ["C.01 Confirmations*"]
cash_sec:     ["C.01b *", "*特殊账户*"]
cash_class:   ["C.00b *", "*Other classification*"]
cash_recon:   ["C.02 *", "*Bank reconciliation*"]
cash_fx:      ["C.02a *", "*外币测算*"]
exp_lead:     ["Uexp.00 Lead", "*费用*Lead*"]
exp_bkd_sell: ["VC.00 *销售费用BKD*"]
exp_bkd_admin:["VD.00 *管理费用BKD*"]
tod_pool:     ["样本池-TOD", "*TOD*样本池*"]
tod_wp:       ["*TOD 预审*剩余*", "*TOD*预审*"]
tod_neg:      ["样本池-负值"]
tod_cut:      ["样本池-CUT*"]
```

3. **内容签名兜底**：名称匹配不到时，用表头关键词打分（例如同时出现“银行/账号/币种/期末账面”即判为 BKD）。
4. **记录指纹**：表名、表头行号、表头哈希、数据行数、合计行、外部链接目标文件名 → 写入 `fingerprint.json`。下次运行先比对；不一致即进入“版本差异”流程（§8）。

> **非 EY Canvas / Skywind 模板**：保持四层语义不变（明细层 → 科目层 → 分析层 → 测试层），只新增一套 sheet 名与字段别名。若模板没有 Lead，可由 BKD 直接生成 OAR，但必须补一条“BKD 合计 = TB”的勾稽；若模板没有 TOD（小项目），按 C 级判断跳过并记录理由。

### 3.2 Map：把“语义字段”映射到“当前列”

每个字段维护一组别名，匹配时归一化（去空格/换行/括号注释/全半角）：

```yaml
BKD_CASH:
  company:   ["公司名称", "主体", "账套名称"]
  subject:   ["科目名称", "会计科目"]
  bank:      ["银行/存款机构名称", "开户行", "存款机构"]
  account:   ["账号1", "银行账号", "账号"]
  currency:  ["币种", "币别"]
  amount_orig: ["期末账面金额（原币）", "原币余额", "期末余额(原币)"]
  amount_local: ["期末账面金额（本币）", "本位币余额"]
  nature:    ["货币资金账户的性质和用途", "账户性质", "性质"]
  restricted:["受限资金", "受限金额"]
```

**定位算法**

```text
headerRow = 前 20 行中，与别名集合匹配得分最高的行
for 每个语义字段:
    col = 在 headerRow 中按别名模糊匹配（归一化后 contains/相似度）
    若缺失 → 记入“缺列清单”，不猜
dataStart = headerRow + 1
dataEnd   = 从 dataStart 向下，直到“关键字段全空 且 金额列空”的第一行 − 1
totalRow  = 标签列包含 合计/总计/Total 的第一行（在 dataEnd 之后）
```

> 永远不要用“第 10 行到第 135 行”这种常量；不同版本会多一行说明、少一行账户、加一列受限。

### 3.3 Load：只写原始层，其余用公式

- 原始层：BKD 的金额列、样本池的金额/标签列、明细账的供应商级余额。
- 公式层：合计、结构比、变动、OAR、派生表、勾稽。
- **幂等 upsert**：按主键“有则更新、无则插入”；本期不再存在的账户/供应商不要直接删（保留 0 余额与销户证据），只做标记。

| 表 | 主键 |
|---|---|
| 货币资金 BKD | 科目名称 + 银行/机构 |
| 费用 BKD | 账簿 + 科目编码 |
| 预付明细 | 主体 + 供应商 + 款项性质 |
| 样本池 | 源行号（唯一） |
| 账户代号/映射 | 原始名称/数字串（只追加不换号） |

- 写公式同时写缓存值；新增公式后删 `calcChain`、设 `fullCalcOnLoad`。
- 插入行必须同步：行号、单元格地址、同表公式引用、合并区、条件格式、`dimension`；随后按“新数据边界”重写 `SUM(首行:末行)`。

### 3.4 Prove：用不变量验收

校验分三类，全部执行：

1. **结构不变量**：行数/列数/合并数/字符串数符合预期；非目标 sheet 逐字节不变（OOXML 场景）。
2. **勾稽不变量**：见 §7 的清单，全部应为 0 或已解释。
3. **回归不变量**：与 `baseline.json` 的合计值比对；差异必须列原因，不允许静默。

## 4. 货币资金 Skill

### 4.1 表族与角色

| 表 | 角色 | 上数方式 |
|---|---|---|
| 口径 mapping | 主体全称↔编号↔账簿 | 主数据 |
| C.00 BKD | 账户级明细（含 0 余额/销户） | **原始录入** |
| C.00 Lead | 科目级汇总 + 调整 + TB | 公式 |
| OAR | 千元列示 | 公式 |
| C.01 / C.01b | 函证 / 平台账户 | 派生 + 人工 |
| C.00b | 现金/现金等价物分类结论 | 派生 + 人工 |
| C.02 / C.02a | 余额调节 / 外币测算 | 派生 + 人工 |

> 表名中的编号（如 `OAR 26930`）是项目/底稿序号，不是识别依据；去掉编号仍应能识别。

### 4.2 C.00 BKD

**写入**：主体、科目（银行存款/其他货币资金）、银行、币种、原币、美元本位币（港澳新）、人民币本位币、是否函证、Notes、受限资金（人工）。

**回捞**：账号与账户性质用“科目+银行”去上期 BKD 取；取不到留空，不生成新编号。

**保留**：0 余额、本年销户账户必须保留（完整性证据）；销户信息写 Notes。

**受限资金**：金额写在 BKD 的“受限资金”列（每笔一次），Lead 用审计调整从“其他货币资金”重分类到“受限资金”，两处不得重复计数。

**合计**：`SUM(本币列 dataStart:dataEnd)`，勾稽 Lead 的期末账面数合计。

### 4.3 C.00 Lead

- 科目行（库存现金/银行存款/其他货币资金/定期存款/大额存单/受限资金）由模板固定语义，不固定行号。
- `期末账面数 = SUMIFS(BKD 本币, BKD 科目, 本行科目)`
- `审计调整 = SUMIFS(调整表金额, 调整表科目, 本行科目)`
- `未审 = 账面 + 账表调整`；`审定 = 未审 + 调整`
- `变动 = 审定 − 上期`；`变动% = 变动/上期`（上期为 0 时按模板约定填 1 或空）
- TB 勾稽行：链接到 console TB 的对应单元格；**注意可能由两项相加**（如 `T13 + T17`），删项会静默改变结果。
- Diff 行必须为 0；不等于 0 时输出“科目/预期/实际/可能原因”。

### 4.4 OAR

- 千元换算：**精确除以 1000，不 ROUND**（若模板历史版本用 ROUND 且带 `+1` 凑数，明确标注为遗留，不复制）。
- 同一科目可能并存多张 OAR（如本期、上期模板遗留、不同底稿号）：按“表内期间列/标题年份 + 表头结构”选本期那张；旧版只作存档，不作为上数目标。
- 每行金额 = Lead 对应科目审定数 / 1000；合计 = SUM；CHECK = Lead 合计/1000 − 合计 = 0。
- 主表之外的手工附表（定期存款/大额存单到期表）由项目组维护，工具只读不重排。

### 4.5 派生表

| 表 | 规则 |
|---|---|
| C.01b | 取 BKD 中“其他货币资金且非零”的平台账户；对账单列未取得→留空标黄；差异列用 `IF(I="","",I-G)` 避免假差异 |
| C.00b | 先判断模板是“明细式”还是“结论式”。结论式：现金 = Lead(银行存款+其他货币资金)；现金等价物按判断填 N/A 或明细；H44/H45 勾稽 |
| C.02 | 先判断“是否存在调节项”。无 → 结论 + 表1.2/1.3 填 N/A；有 → 按账户填表1.1 并做双向核对（企收银未收/银收企未收） |
| C.02a | 按币种 `SUMIF` 原币与本币；差异 = 原币×汇率 − 本币；最后一行勾稽 BKD 合计 = 0 |

### 4.6 货币资金校验不变量

```text
Σ BKD 本币            == Lead 期末账面数合计
Σ BKD 受限列          == Lead 受限资金调整行
Lead 未审             == Lead 账面 + 账表调整
Lead 审定             == Lead 未审 + 调整
Lead TB Diff          == 0（三项：账面/审定/上期）
OAR 合计×1000         == Lead 审定合计（精确 /1000 时）
OAR CHECK             == 0
C.01b 合计            == BKD 其他货币资金 − 已单独列示的受限/保证金（差异需解释）
C.00b 现金总额        == Lead(银行存款+其他货币资金)   # 仅结论式模板
C.02 调节后差异       == 0
C.02a 勾稽            == 0
```

## 5. 销管费用 Skill

### 5.1 表族与角色

| 表 | 角色 | 上数方式 |
|---|---|---|
| 口径 Mapping | 科目全称↔费用类别（for OAR）；账簿↔简称 | 主数据 |
| VC/VD BKD | 科目级本期/上期发生额 | **本期账面数原始录入** |
| OAR-销售/管理 | 按费用类别的千元分析 | 公式 |
| 样本池-TOD | 凭证级总体 + 标签 | **由序时账派生** |
| 样本池-负值 | 负值子总体 | 由主池按标签筛选 |
| 样本池-CUT-期前/后 | 截止测试池 | 由主池按测试期间筛选 |
| TOD 预审+剩余 | 总体/剔除/关键项/抽样/测试表 | 公式 + 人工执行 |
| 抽样工具输出 / 抽样项目详情 | 样本量与样本明细 | 外部工具粘贴 |
| 截止性测试 / 复核法律费用 | 配套程序 | 独立 + 人工 |

### 5.2 VC/VD BKD

- 本期账面数（E）是唯一录入点；账表调整通常为空。
- 未审 = 账面 + 账表调整；审定 = 未审 + 审计调整。
- 上期未审按（账簿, 科目名）从上期同名 BKD 回捞；上期调整列若为模板遗留且恒 0，标注但不修。
- 费用类别 = `XLOOKUP(科目名称, 映射表 C:C, 映射表 D:D)`。
- **多个期间快照并存**（如本期 0930、预审 630、上期 0930）：按表名年份或表内“本期/上期”日期选择，不按 sheet 顺序；预审快照只读，不写。
- 合计行按“合计”标签定位；TB 链接行与 Diff 行按模板语义定位，Diff 必须为 0（允许链接舍入 ±0.01）。

### 5.3 样本池-TOD 构建

```text
输入：序时账（1..12 月）
过滤：科目名称 含“费用_” AND 期间 ∈ [1..12]
字段：源行号、期间、日期、凭证类型、凭证号、摘要、科目编码(3位)、科目名称、
      币种、借方原币、未审本币、OAR口径、剔除类别、账簿
折算：未审本币 = 币种=="美元" ? 原币×期末汇率 : 原币
```

- **汇率按期间段区分**：预审段与年审段可能使用不同汇率（如 6.8836 / 6.8454）；在池中按“所属段”折算，并在 Notes 说明。
- 零发生额行不进入池。
- 同一凭证多行是不同分录，**不要按行签名去重**。

### 5.4 标签算法（顺序即优先级）

**第一层：性质类**（命中即打标，不参与配对）

```text
职工薪酬           if OAR口径 == "职工薪酬"
股份支付           if 科目名称 含 "股权激励"
使用权资产折旧     if 科目名称 含 "使用权资产折旧"
固定资产折旧       if 科目名称 含 "累计折旧" 或 "折旧费"
无形资产摊销       if 科目名称 含 "无形资产摊销"
长期待摊费用摊销   if 摘要 含 "长期待摊费用"
```

> 先判“使用权资产折旧”，再判“折旧费”，否则前者被后者吞掉。

**第二层：预提冲销配对**

```text
for row in rows:
    if 已有性质标签: skip
    if |amount| < 0.005: skip

key = half + "|" + code3 + "|" + abs(amount).toFixed(2)
      half = 期间 ∈ pre ? 1 : 2          // pre 为配置的预审区间，如 [1,6]；两段各自配对

组内：pos 降序 vs neg 升序，1:1 配对，双方标“预提冲销”
```

- 必须按 half 分组：跨段配对会把一段的净额挪到另一段。
- 验收：每段预提冲销净额 = 0（浮点误差 < 1e-6）。

**第三层**：其余负值 → “负值”；其余 → “否”。

### 5.5 总体 / 剔除 / 剩余

| 区块 | 规则 |
|---|---|
| 1.1 总体 | 两段分别 `SUMIFS(池金额, 科目含销售/管理, 期间≤预审末月 或 >预审末月)`；合计与 BKD 全年 `SUMIFS` 勾稽 |
| 1.2 剔除 | 每类 `SUMIFS(池金额, 标签, 期间≤预审末月)`；`剩余段 = 合计 − 预审段`；BKD 同口径对比，差异 ROUND 2 位后应为 0 或注明 |
| 剩余总体 | 总体 − 剔除 |
| 关键项 | 金额 ≥ 阈值（通常 100% TE，取自 Lead / BKD 阈值单元格）且未剔除；**预审段**若已单独执行，引用预审版 TOD（如 `630TOD`）的笔数与金额，不重复抽样 |
| 代表性样本 | 样本量由抽样工具决定，**从工具输出页回链**（如 `TOD!G48 = 抽样工具输出!G64`），不手填；按金额比例拆分到两段 |
| 负值专项 | 负值可单独成池（`样本池-负值`）并单独抽样；分类表必须满足“冲销预提 + 其他性质 = 负值合计”，抽样结论另页记录 |

**类别不是固定清单**：OAR 的行项目由“科目名称 → 费用类别”映射表派生，新增/删除一个类别会同时改变本期合计的构成与上期可比数；映射表增行后，必须重跑 OAR 并确认 CHECK 仍为 0，不能沿用旧类别列表。

**测试表回填**：抽样完成后，表1（预审）/ 表1.2（年审）按“抽样ID（=池的源行号）/ 样本类型 / 日期 / 凭证号 / 摘要 / 科目 / **币种** / 凭证金额 / 供应商 / 证据 / 交易凭据日期与金额 / 差异 / 属性 A、B、C / 异常解释”回填；差异 = 凭证金额 − 支持性证据金额；异常用 NB 编号统一解释。工具只回填来自池的字段，证据与结论属人工。

### 5.6 费用校验不变量

```text
池合计              == Σ 各标签金额
预提冲销净额        == 0（按段）
总体（预审段+剩余段） == BKD 全年（按费用类别）
BKD 审定合计        == 未审合计 + 审计调整合计
剔除合计 − BKD 同口径 == 0（或逐项解释）
剩余总体            == 总体 − 剔除
剩余总体 − 关键项   == 抽样总体
负值：冲销预提 + 其他 == 负值合计
OAR 各类别合计      == BKD 审定数（同一 mapping）
OAR CHECK           == 0（类别增删后仍须为 0）
```

### 5.7 截止性测试与法律费用（配套程序）

- **截止性测试**：测试期间由公司制度决定（例：报销须在发生日起 1 个月内完成 → 取资产负债表日 ±31 天）；起止 = `Lead!C3 ± 天数`，阈值取 BKD 的阈值单元格；样本分“期前/期后”两段记录。
- 截止性样本池独立维护；若模板给出的池未按天数裁剪（与主池相同），工具应自行按测试期间过滤，不得直接复制主池。
- **法律费用复核**：无超过阈值的项目时，表1 整行 `N/A`、合计 0，并写明“无大于测试阈值的法律费用，不进一步执行审计程序”；有则逐项列示并考虑发函。

## 6. 通用公式与写法约定

1. 汇总一律 `SUMIFS/SUMIF` 指向“整列”，避免插入行后失效：
   `=SUMIFS('C.00 BKD'!$I:$I,'C.00 BKD'!$C:$C,$D37)`
2. 合计行显式限定“当前数据边界”：
   `=SUM(H{dataStart}:H{dataEnd})`，插入行后重算边界再写。
3. 跨表引用用**表名**，不用 sheet 序号：
   `='C.00 Lead'!J37`
4. 外部链接不认 `[n]` 编号，认目标文件名（`console TB20260930`）；链接缓存值可能由多项相加，删除任一项都会改变结果。
5. 文本账号写 `t="inlineStr"` 或共享字符串 + 单元格格式 `@`；数值金额不套文本格式。
6. 未取得的数据：留空 + 填充 `FFFF00`，并在 Notes 写原因；不写 0、不写“待定”。

## 9. 失败模式与处置

| 现象 | 根因 | 处置 |
|---|---|---|
| Check 非 0 | 口径差异/漏项/汇率 | 输出科目级差异明细，不调平 |
| 合计与明细对不上 | 插入行后未重写 SUM 边界 | 重算 dataStart/dataEnd 并重写 |
| `#REF!` | 派生表引用被删 sheet/行 | 重建引用或固化为值 |
| 账号变科学计数 | 文本格式丢失 | 单元格 `@` + 字符串写入 |
| Excel 打开报修复 | 空 `dcterms`、残留关系、错误 sharedStrings 索引 | 删除 docProps 或写合法日期；重打包前校验关系 |
| 单表摘出后数值全 0 | 缓存值未写、公式未重算 | 保留 `<v>` 缓存；删 calcChain + fullCalcOnLoad |
| 脱敏后仍可搜到名称 | 未剪 sharedStrings（含其他 sheet 的未用字符串） | 按被引用索引重建 sharedStrings |
