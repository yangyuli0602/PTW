# AI 速查 · WP 初稿生成（压缩版）

> 原文：`AI作业指南_WP初稿生成.md`。只删解释与示例篇幅，**硬约束一字未改**。
> 原则：工具让数字对得上，AI 让判断站得住。

## 0. 分工
| 级 | 谁做 | 任务 |
|---|---|---|
| A 机械规则 | 工具 | 本年 BKD/Lead 上数、合计、勾稽、TOD 抽样、回归比对 |
| B 起草+确认 | 工具给建议，人点确认 | 取数口径、TE/SAD、阈值、样本量 |
| C 必须判断 | **AI 起草，人确认** | **上年数归集、OAR 变动原因、受限资金、分类结论** |
| D 禁止 | 谁都不做 | +1 / ROUND / 手填调平、自动下「无异常」结论 |

本文件只覆盖两个 C 级任务：上年 WP→上年数、OAR 变动分析。A/B 级在页面点按钮即可。

## 1. 任务一：上年 WP → 上年数
上年底稿各客户 sheet 名、列位、表头行都不同，正则识别遇改版会**静默错位**（比报错危险），所以由你判断结构。

**输入**：页面「WP初稿生成 → 货币资金 → 上年 WP → 导出结构探测包」给出的 markdown（含各 sheet 行列数、表头匹配分、推测表头行、前几行内容）。

**要做三件事**
1. 挑出 BKD 明细表：通常表名含 `BKD` 且首行有 公司/科目/银行/账号/期末金额；表名是「明细」「breakdown」「附表1」时按内容判，别只看名字。
2. 定表头行 = **字段名那一行**，不是第一行数据。两行表头（第 1 行分类、第 2 行借/贷）取**第 1 行**。
3. 看数据区间：表头下一行起到最后明细；中间合计/小计/说明行不用特意排除，平台按科目名过滤。

**返回 JSON**
```json
{"sheet":"C.00 BKD","header_row":9,"data_start":10,"data_end":135,
 "note":"第 9 行是字段名行；第 137 行是合计，故数据止于 135"}
```

**判断依据（按此顺序）**：① 有「账号」或「银行/存款机构」列（BKD 标志）② 期末账面金额分原币/本币两列 ③ A 列编号、B 列公司名 ④ 数据行数 ≈ 账户数（几十到几百；上千行多半是序时账）⑤ 末尾 `SUM(...)` 合计 + `RX` + `- Lead` 勾稽。

**硬约束**
- 不许猜列：看不清就回 `{"error":"...请人工确认"}`，不要编 header_row。
- 不许改数：只判结构，不动金额、不补缺失行。
- 必须给 note：一句话说清依据，人要能复核。
- 对不上要报：平台显示「解析出 N 个账户、合计 X」，与上年 Lead 期末审定数差得离谱就是表头行选错，回去重看。

**平台用法**
```
POST /api/build/prior/apply  {"fid":"...","spec":{"sheet":"...","header_row":9}}
→ {"rows":126,"sum":100067778.85,"sample":[...]}
```
`sum` 必须与上年 Lead 期末审定数合计差异 < 0.01，否则 sheet/header_row 选错。

## 2. 任务二：OAR 变动分析
OAR = 报表口径分析表，**千元单位**，由 Lead 公式链接。你只做一件事：对「|变动额| ≥ TE」的项目，读序时账说清**是哪家公司、什么性质的事项**。

口径（工具算，你复核）：
```
变动额 = 本期审定数 − 上期审定数
变动率 = 变动额 ÷ |上期审定数|   （上期为 0 留空，不写 100%）
超阈值 = |变动额| ≥ TE          （TE 从 Lead 的 C4 读，不要自己假定）
```

**不要花力气解释的正常变动**：定期存款到期/新购（科目间搬家，总额不变）、外币折算差、受限资金重分类（BKD P 列 → Lead I 列）。

**步骤**
1. 定位差额。
2. 按 科目+期间 过滤序时账，金额降序看前 20 笔，找单笔接近或几笔合计等于变动额的凭证。
3. 读摘要判性质，**摘要原文照贴不改写**。
4. 归因到具体主体/事项，一句话说清（公司 + 事项 + 金额 + 凭证号 + 摘要）。
5. 配不上就明说「变动 X，序时账未见对应凭证，可能为期初余额调整，需问客户」——**比编一个原因好一百倍**。

**输出 JSON**
```json
[{"account":"银行存款","period":"2026-09","cur":1422875244.88,"prior":1200000000.00,
  "delta":222875244.88,"company":"9H公司","nature":"新增欧元定期存款",
  "evidence":["记-2026-03-0012 摘要：欧元定期存款存入 11,691,344.42 EUR"],
  "confidence":"高","needs_client":false}]
```
`confidence` 只能 高/中/低；`needs_client=true` 表示要问客户，不要为了好看填 false。

**硬约束**
- 不许抹平：不许用「其他」「零星」凑余额。
- 不许编摘要：evidence 必须是真实存在的摘要原文或凭证号。
- 不许下结论：「未发现异常」「无需进一步程序」只能人写，你最多写「已核对，未见对应凭证」。
- 不确定性要标出：配不上、只能部分解释、摘要看不懂都写进 note。

## 3. 任务三：长期资产（固定资产）BKD

只做**固定资产**（1601/1502/1605 或 1501/1502/1505）。在建工程、无形资产、长期待摊、使用权资产**不做**，别去找。

### 数据前提（缺一条就出不来）

| 数据 | 标准表 | 说明 |
|---|---|---|
| FA list 期末 | `fa` | 字段映射选「固定资产台账（期末）」 |
| FA list 期初 | `fa_beg` | 选「固定资产台账（期初）」；缺了期初全 0、CHECK 不平 |
| 固定资产序时账 | `journal` | 一级科目含「固定资产/累计折旧/固定资产减值准备」 |
| 分类对照表 | `_fa_map` | **可选**：分类是 G0100 这类纯编码时必须有 |

### 分类怎么来的（六级，命中即止）

台账分类名（含中文）→ 对照表 → 期初台账的「细分类型」列 → 余额表的科目名 → 中文关键词词典 → 未分类（列清单，不猜）。
模板里没有的类别会**按同类资产样式插行**；模板多余的行留空不删。

### 口径（不许改）

原值**正** / 累计折旧**负** / 减值=会计年度末重估（本身为负）/ 净值 = 三者**相加**。
CHECK = 期初 + 本期变动 − 期末，非零必须解释，**不许调平**。
合计 = 各资产类型小计之和（不是 SUM 区间，否则小计被算两遍）。

### 打标：12 条默认规则

报废 / WBS 前缀（在建转入）/ AFB 前缀（计提）/ 资产拆分 / 暂估挂账 / 编码调整 / 调拨（划转）/ 转售 / **购置** / **购入** / **处置** / 计提。
未命中的进「未打标」清单，**不会静默丢弃**——看到这个数就要补规则或让人确认。
资产拆分、调拨是一借一贷，只能归类不能剔除（剔了净额变 0）。

### 常见坑

- 台账分类是纯编码又没给对照表 → 序时账的科目翻译不过来 → 变动列全 0，CHECK 差额恰好等于变动额。
- 期初表与期末表的分类不一致（本期新增/销户）→ 期初为 0 是正常的，CHECK 会等于变动额，属正常。
- 台账混了「合计」行没清洗掉 → 多出一个叫「合计」的分类、金额翻倍。

## 4. 任务四：销管费用（VC/VD）BKD + OAR

### 数据前提

| 数据 | 标准表 | 说明 |
|---|---|---|
| 序时账 | `journal` | 一级科目 = 销售费用 / 管理费用 |
| 上年度费用底稿 | —（不落库） | **可选，但没有它就没有变动分析**：K 列全空，只能按本期金额判 |

### 上期审定数（K 列）怎么来

上传上年 VC/VD 两张表（须有「上期审定数」列）→ `POST /api/upload` 拿 fid →
`POST /api/build/exp/prior` 校验能认出多少键 → 生成时带 `prior_fid`。

匹配顺序：`(规范化账簿名, 科目名称)` → 退 `("", 科目名称)`。
都不中则 K 留空并进待确认清单，**理由必须区分**「未提供上年费用底稿」和「该科目在上年费用底稿里没匹配到」。

### 口径（不许改）

- 本期账面数 = 借方 −（贷方 − 结转损益贷方）。月末「结转本期损益」会把科目冲平，
  不剔除算出来全是 0；但**禁止按关键字整行剔除**（「结转----确认上市费用」是真实费用）。
- OAR 口径（BKD 最右 R 列）：薪酬 / 折旧摊销 / 广告费 / 单列大额 / 其他。
  单列门槛 = 该科目**合计** ≥ 100 万（约 2×TE）——按合计判，不按单行
  （中介费 1,304 万拆到 8 个账簿每行 160 万，逐行判会全落「其他」）。
- 变动额 = 本期审定数 − 上期审定数；变动率 = 变动额 ÷ |上期审定数|（上期为 0 留空，不写 100%）。
- 挑分析对象：`|Δ| ≥ max(SAD, TE×50%)` **且** `|Δ%| ≥ 10%`，按 |Δ| 降序。
  只看金额会出现「变动 0.3% 也写一段分析」；只看率会让小科目翻倍挤掉大额变动。
- 分析段**按口径写、不按科目名**；一句一段，金额/占比/构成写进句子里，不要用表格。
  **工具会按证据直接写成业务描述**（先归性质：市场投放/人力成本/中介与专业服务…，
  再说集中度与方向），不罗列公司名＋金额；只有序时账里找不到可归类证据时才留
  「【待AI撰写：…】」占位并标黄。`ptw.py oar-fill` 可覆盖工具写的描述，只换文字、公式保留。

### 常见坑

- **TE 不写进 Lead C4** → C22（波动幅度）= 0 → 「进一步调查」的 `ABS(L)>=0` 恒真 →
  整张表 176 行全标「是」，等于没判。界面走「一键生成」时也要传 TE（这条断过）。
- 模板 **VD 的认定等级 C8:C11 是空的**（VC 填了 Minimal），空着同样让 VD 恒「是」，空则按 Minimal 起。
- 明细表 **D 列是科目名称不是金额**，`TEXT(D10,"#,##0.00")` 作用在文本上原样返回，
  句子会变成「金额 销售费用_宣传推广费 元」——这是上一版的乱码根因，改列引用才对。
- 「进一步调查」列模板只在 3 行写了公式，插行后断掉；`ABS("")` 在没有上期数时直接 `#VALUE!`。

## 6. 这个模块没做的（别去找）
货币资金 TOD（货币资金没有 TOD，TOD 是费用的）、受限资金判定（C 级，工具只给 P 列和合计校验）、C.01b/C.00b/C.02 结论（工具出骨架，结论人写）、G3 预付/待摊（缺 G3 工作簿原件）、**长期资产只做固定资产**（在建/无形/长期待摊/使用权资产待做）、**集团多主体没做主体过滤**（台账带公司列时全部合并成一张；费用上年数在多主体同科目名时会串）。
