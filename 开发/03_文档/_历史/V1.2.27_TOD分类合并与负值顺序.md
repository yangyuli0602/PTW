# V1.2.27 · TOD 分类并入「是否排除」+ 负值改到最后判

> 2026-11-05。产物 `01_测试/TOD分类合并_V1.2.27_验证/`。

## 一、两处改动

### 1. 不再有独立的「TOD 分类」列

原来 TOD 池比截止性池多 4 列（TOD 分类 / 是否关键项 / 抽样ID / 说明），
其中「TOD 分类」是把 cutoff 的粗分类（薪酬 / 股权激励 / 折旧 / 预提冲销 / 负数）
再映射一次得到的 —— 同一批数据两套标签，改一处忘一处就会打架。

现在**只保留一套**：`是否排除` 直接按 TOD 模板 1.2 剔除项的颗粒度取值。

| 取值 | 对应模板 1.2 |
|---|---|
| 结转损益 | 不剔除（不是费用发生，期末结账） |
| 工资薪酬 | 行 23（股权激励并入，本质仍是人工成本） |
| 固定资产折旧费 | 行 19 |
| 使用权资产折旧费 | 行 20 |
| 无形资产摊销费 | 行 21 |
| 长期待摊费用摊销费 | 行 22 |
| 租赁费 | 行 24 |
| 预提费用（含预提和冲销） | 行 25 |
| 负值 | 行 27 b 段 |
| 否 | 参与关键项筛选 |

TOD 池回到 **18 列**（15 + 是否关键项 / 抽样ID / TOD 说明），
TOD 年审的 SUMIFS 直接从 `$N` 列（是否排除）取，不再依赖 P 列。

### 2. 负值排到最后

判定顺序从：

```
结转损益 → 负值 → 性质
```

改成：

```
结转损益 → 科目性质（工资/折旧/摊销/租赁）→ 预提冲销 → 负值 → 否
```

原来一上来就判负值，一笔「折旧 -5 万」会被负值桶吃掉，a 段的固定资产折旧费就少一块。
现在先按性质归类，**剩下那些说不出性质的负数**才进「负值」。

瑞云数据前后对比：

| 桶 | 改前 | 改后 |
|---|---|---|
| 工资薪酬 | 2,969（只含正数） | **3,244** |
| 固定资产折旧费 | 63 | **65** |
| 使用权资产折旧费 | 67 | **102** |
| 无形资产摊销费 | 22 | **26** |
| 租赁费 | 51 | **62** |
| 预提费用 | 201（只含正数） | **392** |
| 负值 | 743（所有负数） | **225** |

## 二、连带修正的三处

### 1. G25「预提费用」变成 0 是**对的**

预提和冲销成对出现，一正一负，净额必然为 0。
但只显示一个 0 会让审阅人以为「这家没有预提费用」，所以给 G25 加了批注：

> 本行为净额：预提 9,001,093.82、冲销 -9,001,093.82，一正一负相抵为 0。
> 预提与冲销的分项金额见「表2 冲销预提费用」，逐笔见「样本池-TOD」。

### 2. 表2 改成分析**全部负值**

原来 D83 只统计「负值」桶。现在负数分散在 a 段各桶（工资 -184 万、折旧 -212 万…），
只算「负值」桶会漏掉 1,300 万，审阅人会以为负值只有 336 万。

现在：

```
D82 冲销预提费用 = 预提桶里的负数            -9,001,093.82
D83 其他性质     = 全部负值 − D82            -7,331,039.08
D84 合计                                    -16,332,132.90
D85 核对 = D84 − 全部负值（不含结账）              0
```

「全部负值」用 `SUMIFS(金额, 金额<0) − SUMIFS(金额, 分类="结转损益", 金额<0)` 表达。

### 3. 01.4 不受影响

`fill_target` 的筛选条件是 `excl != "否"`，分类变细不影响 —— 仍然是 5 个样本。

## 四、顺带说明

`G25 = 4.7e-10` 是浮点残差（几十万行累加），不是真金额。会计格式下显示 0.00。
**没有做 ROUND 调平** —— 那是 D 级禁止动作，残差也不会影响 G29/G31 的守恒。
