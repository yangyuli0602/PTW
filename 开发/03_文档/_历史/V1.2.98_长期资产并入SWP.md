## 3. 问题 → 做法

### 3.1 为什么会多出一个板块

上一版为守住「默认不改既有代码」这条红线，把 SWP 新建成了独立板块 `fa_swp`，但**只做了引擎、
没做页面**：`manifest.json` 声明 `entry: fa_swp.html`，而 `web/` 是空目录（git 连空目录都不收）。
结果侧边栏挂了第四块，点进去是空白，实际只能命令行跑。产品上不该有两个「长期资产」。

### 3.2 做法：入口合并，引擎不动

- 删 `fa_swp/manifest.json` → 第四块消失；`程序/modules/fa_swp/` 保留为**引擎库**，被 bkd 直接 import。
- 长期资产页（`wp_fa`）改跑 `/api/build/fa_swp/plan|run`，四步：读取余额表与序时账 →
  类别与口径核对 → 关键信息 → 一键生成。
- 预览接口只读不写：类别矩阵、TB 重复导入去重、TB 与序时账的类别互校、表4 折旧费用勾稽。
- 生成接口直接调 `fa_swp.build.build()`，产物落在 `bkd_out/`，返回下载链接。

### 3.3 旧链路的两个前提一起消失

旧版要求客户另给 **FA list（期末/期初）** 和 **分类对照表**，缺一个就出不来；新链路只用
「一、导入与清洗」已合并好的科目余额表 + 序时账。相应地：

- 旧的六级「台账分类名 → 对照表 → 科目名 → 关键词词典」推断逻辑随 `asset.py` 一起删除；
- `--map` 参数保留但忽略（传入时打印提示），避免老脚本静默改变行为。
