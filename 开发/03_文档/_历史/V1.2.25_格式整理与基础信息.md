## 一、表格格式

### 1. 调整汇总表（BKD 下方，你截图的第一处）

原来的问题：模板在这块只给了 B 列的**左边线**和末行**底线**，表头却有 7 列宽 ——
填进去的调整分录看不出行，右边三列（20260930 / 20251230 / FOR BKD）干脆悬空。
中间还埋着一条深蓝横带（`FF333399`，原是「波动说明」的分隔线），正好落在数据区
第五行，把表格拦腰截断。

改法：
- 表头 7 列统一：Arial 10 加粗、浅蓝底 `D9E2F3`、居中、细框、行高 20
- 数据区铺 **7 列 × 20 行**完整细网格，行高 18
- 两列金额设 `#,##0.00` 右对齐
- 抹掉深蓝横带
- 列宽按内容重设（调整说明 / 科目名称 / FOR BKD 各 30，两列日期各 15）

SUMIFS 的取值范围仍是 300 行（`data_end = head_row + max(300, 20)`），
所以网格只画 20 行不影响取数 —— 项目组真填到第 30 行也照样算进去。

### 2. VC&VD.01.2 TOD 年审（你截图的第二处）

原来的问题：模板各区块框线长短不一（有的只有左侧一条，表头却铺满 7 列），
深灰装饰块三大片（`A6A6A6`），E/F 列塞着红字示例，金额列是 General 没千分位。

改法（`expense_tod._tidy()`，在插行、写值全部完成之后跑一次）：

| 项目 | 处理 |
|---|---|
| 框线 | 每个区块按「表头 + 数据」重画细网格 |
| 表头 | 浅灰 `D9D9D9` + 加粗 + 居中 + 自动换行 |
| 字号 | 全页统一 10 号（保留原字体名和颜色） |
| 深灰装饰块 | 一律抹白（theme 色取不出 rgb，只能整块清） |
| E/F 列红字 | 改黑（`样本池-TOD` / `固定资产20260930` 这类是实际值，不是示例） |
| 金额 | `#,##0.00` + 千分位 |
| 数量列 | `0`（原来显示成 `19.00`） |
| 表1 表头 | 行高 62（"获得的支持性证据的名称及编号"不再被截断），数据行 16 |
| 待填提示 | 纯黄 `FFFF00` → 浅黄 `FFF2CC`，和 BKD 的黄色一致 |

**保留不改的**：`Rx` 复核标记的红字（EY 惯例，红了才有意义）、1.2 里 `b. 负值`
的红字加粗。

## 二、基础信息可填入（截图第三、四处）

### 1. Lead C6 / C7 不再空着

Lead 页原来只有客户名称、资产负债表日、TE、SAD 四项有值，**适用会计准则（C6）和
记账本位币（C7）永远是空的**，两格黄色空框吊在那里。

现在平台「关键信息」卡多了 4 个输入项：

| 字段 | 写到哪里 | 说明 |
|---|---|---|
| 名义金额 SAD | Lead C5 | 留空按 TE×10% |
| 适用会计准则 | Lead C6 | 下拉：中国企业会计准则 / 小企业会计准则 / IFRS / 留空 |
| 记账本位币 | Lead C7 | 文本，如「人民币」「CNY」 |
| 四项认定等级 | BKD C8:C11 | 完整性 / 发生 / 计量 / 列报披露，下拉 Minimal/Low/Moderate/High |

**认定等级为什么必须填**：C8:C11 → D8:D11 → **E8 = MIN(D8:D11) → C22 = E8**，
C22 就是「波动幅度」阈值，也是截止性测试的金额门槛。四个格空着 → E8=0 → C22=0 →
O 列 `ABS(L)>=0` 恒真 → 整张 BKD 的「进一步调查」全是「是」，抽样门槛等于没有。
所以默认填 Minimal，但可以改。

后端链路：`bkd.js` → `/api/build/wp/run` → `_run_exp` → `build_expense_workbook`
→ `_write_te` / `_fill_sheet`。CLI 也开了同样的口：

```bash
ptw.py exp --standard "中国企业会计准则" --currency "人民币" \
           --assurance "Minimal,Low,Minimal,Minimal" --sad 55000
```

留空就**保持空白**，不猜一个默认准则 —— 猜错比空着更糟。

## 三、顺手修的一个接口 bug

`/api/build/wp/run` 返回 400：

```
TypeError: keys must be str, int, float, bool or None, not tuple
```

`oar_map.build()` 返回值里带了个 `resolved`，key 是 `(主体, 科目)` 元组
（内部给 OAR 页查口径用）。它被原样塞进 `info["oarMap"]`，`json.dumps` 直接拒绝。

现在 `info` 里只外传 `sheet / oarRows / oarLast / companyRows / companyLast /
pendingCount`，`resolved` 和 `pending` 留在内部。

**这个 bug 是 V1.2.20 加 `resolved` 时就埋下的** —— 只是 CLI 走 `json.dump(default=str)`
不报错，只有界面点「一键生成」才会撞上。

## 五、已知边界

1. **调整表网格只画 20 行**。填满后往下还有框的空白（模板原有），但不再有细网格；
   要更多行列跟我说，改一个参数。
2. **列宽是共用的**。TOD 表1 的 G（摘要）/M（凭据日期）列宽是给上面 1.1/1.2 表设计的，
   表1 只能靠表头换行和行高适配，没法单独加宽 —— 除非把列拆开（会动模板结构）。
3. **认定等级默认 Minimal 是工具的选择，不是审计结论**。风险高的项目组要自己调，
   调高之后 C22 会跟着变（E8 = MIN），阈值和样本数一起变，这是对的。
