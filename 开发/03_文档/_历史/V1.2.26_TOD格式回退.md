# V1.2.26 · TOD 页格式回退：只插行、只填值

> 2026-11-05。产物 `01_测试/TOD格式回退_V1.2.26_验证/`。

## 一、我上一版做错了什么

V1.2.25 我写了个 `_tidy()`，把 TOD 页**整页重刷**了一遍：

- 抹掉模板的深灰装饰块（`A6A6A6`）
- 表头统一改成浅灰 `D9D9D9`
- 全页字号统一 10 号
- 每个区块按「表头 + 数据」重画细网格
- E/F 列红字改黑

这等于**重新设计了一份底稿**，不是甲方给的模板。用户明确否掉：模板原样保留，只在需要的地方插行、填值。

## 二、但"格式乱"另有真凶

查下来根因不在模板，在 `copy_sheet()`：

```python
nc._style = copy(c._style)     # ← 错
```

`_style` 是 `StyleArray`，里面全是 `fontId / fillId / borderId` 这些**索引**。
索引只在源工作簿的样式表里有意义，搬到费用底稿（它自己一套样式表）就指向了别的样式。

结果：`Arial 10 加粗` 变成 `微软雅黑 14`、`medium` 边框变 `thin`、底纹整片丢失。
**而且不报错** —— 所以我第一轮看到"字体大小不一致、框线不全"，以为是模板的毛病，
转头去重刷格式，把问题搞得更复杂。

正确写法是复制样式的**值**：

```python
nc.font = copy(c.font)
nc.fill = copy(c.fill)
nc.border = copy(c.border)
nc.alignment = copy(c.alignment)
nc.protection = copy(c.protection)
nc.number_format = c.number_format
```

这个 bug 从 V1.2.24 建 TOD 页起就在，一直没人发现。

## 三、现在的做法

| 动作 | 处理 |
|---|---|
| 复制模板页 | 按**值**复制字体/填充/边框/对齐/保护/数字格式 |
| 插入行 | `_copy_style()` 从上方同列继承（含行高），列范围 B~S 全覆盖 |
| 填值 | 只写 value |
| 数字格式 | `_fmt()`：**模板已有格式一律沿用**，只有模板是 `General` 才补 |
| 待填标记 | L~S 加浅黄 `FFF2CC`（这是新信息，模板没有） |
| 表头行高 / 字号 / 底色 / 边框 | **一律不动** |

`_tidy()` 整个删掉（129 行），连带它的 scrub / paint / 强制对齐。

## 四、验证方式变了

不再靠"看着顺眼"，改成**逐格比对模板**：

```
模板原有区块：11-15 / 17-31 / 34-39 / 55-69 / 77-85 / 99-100
比什么：字体名、字号、加粗、四边框线（底色允许我们加，因为 L~S 是待填标记）
结果：407 个「有内容或有样式」的格里，**399 格完全一致**
      剩下 8 格是第 100 行的空表头格，只有默认字体差异（Calibri 11 → 宋体 10，无文字）
```

这条比对已经写进 `tmp/test_cutoff.py`（第 51 条断言），以后谁再重刷格式会直接 FAIL：

```
ok  TOD 页格式与模板一致（只插行不改样式）
ok  格式比对覆盖到位（模板有样式格 > 300）
通过 51 / 51
```

## 五、数字没变

```
F15 总体       70,311,758.90
G29 剔除合计   28,878,677.75
G31 剩余总体   41,433,081.15
D90 负值核对   0
E35 关键项数   19
```

回归 **17 通过 / 0 失败**，全表重算零错误。

## 六、一条教训

`except Exception: pass` 把两条错误同时藏起来了：

1. `copy_sheet` 的样式索引错位（不报错，只是难看）
2. 我加 `_fmt` 时函数没定义，`fill()` 抛 `NameError`，被 `build()` 的
   `except` 吞进 `info["tod"]["reason"]`，界面上只看到"TOD 页没内容"，
   却不知道是代码错。

现在 `build()` 的错误会带到返回值里，但 CLI 仍然只在 `--pretty` 下显示。
**以后凡是 `except` 包住整段写入的，必须把 reason 冒到 warnings。**
