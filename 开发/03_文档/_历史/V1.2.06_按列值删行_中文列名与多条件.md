## 1. 列名改成中文

**原来**：前端硬编码一份 `DEL_COLS`，下拉直接显示 `acct_code`、`company_name`。

**现在**：列清单和中文名从**标准字段定义**取（`core/fields.py` 的 `TARGETS`），接口 `GET /api/delete-rows/modes`：

```
序时账 31 列：日期 / 会计期间 / 凭证类型 / 凭证号 / 唯一凭证号 / 摘要 / 科目编码 / 科目名称 …
科目余额表 38 列：公司名称 / 账簿名称 / 科目编码 / 科目名称 / 科目全称 / 一级科目 / 币别 …
```

顺带的好处：原来 `DEL_COLS` 只列了 17 个「常删」字段，**日期、金额、期末余额这些没进下拉**，想按日期删行根本选不到。现在两张表的全部标准字段都能选。

前端仍保留一份极简兜底（接口取不到时用内部列名），但中文名只存在后端一处——避免以后加字段时要改两边。

## 2. 多条件「且」

条件从「一组固定控件」改成**可增删的条件行**：

```
条件  公司名称   等于   1A公司(100)                        ✕
且    科目名称   等于   银行存款                            ✕
                                          ＋ 添加条件
```

- 每行：判断列 / 条件 / 值，行尾 ✕ 删掉这条
- **多条之间是「且」（AND）**，全部满足才删
- 条件类型从 2 种扩到 5 种：

| 条件 | 语义 |
|---|---|
| 等于 | 忽略首尾空格和大小写的精确匹配（原样保留） |
| 包含 | 子串匹配，`%` `_` 按**字面**处理 |
| 不等于 | 留下等于该值的行，其余全删，**含该列为空的行** |
| 为空 / 不为空 | 不填值，按该列有没有内容判断 |

## 3. 顺带修掉的三个隐患

这三个都是「多条件 + 更多人用」之后必然踩到的：

**① 「包含」把 `%` `_` 当通配符。** 用户在值里输 `1002%` 或 `10_`，SQL 的 `LIKE` 会当模式匹配，一下删掉一大片，而且从界面上看不出为什么。现在转义并加 `ESCAPE '\'`，实测「包含 `10_`」= 0 行、「包含 `%`」= 0 行（按字面）。

**② 「不等于」漏掉空值。** SQL 三值逻辑下 `NULL <> '银行存款'` 结果是 NULL，不算命中——用户以为「不是银行存款的都删了」，实际留下一批空行。现在显式带上空值，实测 `等于 381 + 不等于 75 = 456`，正好是全部行数。

**③ 值没填就删。** 原来空串会被当成「等于空」，等于「删掉这一列为空的所有行」。现在空值必须显式选「为空 / 不为空」，否则报错：

```
条件「科目名称」没填值；要按空值删请把条件选成「为空」
```

## 4. 先试算，再确认

点「删除匹配行」不再直接删，而是先调一次 `dry_run`：

```
将从「科目余额表」删除 103 行（当前 456 行）。

公司名称 等于「1A公司(100)」
且 科目名称 等于「银行存款」

将被删的前几行：
  公司名称=1A公司(100)，科目编码=1002，科目名称=银行存款，币种=美元(USD)…
  …

删除直接生效、不可撤销（会先把整张表备份到 work 目录）。确定吗？
```

- 试算出的 N 和实际删除行数**保证相等**（同一条 WHERE，中间没有别的写入）
- 样例按中文列名展示，内容相同的行不重复列
- 删完若整表变 0 行，额外提示「这张表已被删空，请确认条件是不是写宽了」

老接口调用方式继续可用（`{table, col, mode, value}`），内部转成单条 `conditions`。已在本机回归过。

## 6. 验证

**接口层**（脱敏库副本，tb 456 行 / journal 100 万行）：

| 用例 | 结果 |
|---|---|
| 单条件 公司名称=1A公司(100) | 160 行 |
| 再加 科目名称=银行存款（且） | **103 行**，比单条件少 57 |
| 真删同一条件 | deleted=103，456 → 353，试算与实际一致 |
| 删完再试算 | 0 行；其他公司的银行存款仍有 278 行 |
| 不等于 银行存款 | 75 行（381 + 75 = 456，空值已计入） |
| 包含 `10_` / `%` | 0 行（通配符已转义） |
| 值为空 / 未选列 / 列不存在 | 三条都返回 400 + 中文原因 |

**界面层**（浏览器实测）：

- 下拉 32 项全中文：日期、会计期间、凭证类型、凭证号、唯一凭证号、摘要、科目编码、科目名称…
- 两条条件并排显示，第二行前面是「且」，✕ 与「＋ 添加条件」对齐正常
- 确认弹窗文案与上面第 4 节一致，数字 103 与接口试算一致

## 7. 没做的

- **「或」（OR）条件**：本次只做「且」。混合且/或需要括号分组，界面和语义都会复杂一档，等你确认是否有真实场景。
- **条件里存"上次用的"**：切页签后清空。多条件场景下，保留上一次的条件反而容易误删。
