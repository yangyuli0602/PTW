## 一、P0-1：`absPath` 未清理（上卷）

**文件**：`1凭证2026（脱敏）.xlsx`
**位置**：`xl/workbook.xml` 的 `mc:AlternateContent` → `x15ac:absPath@url`
**实测值**：

```
https://eychinamanaged-my.sharepoint.cn/personal/adam_yy_li1_cn_ey_com/Documents/
Desktop/FDE/04_SHENZHEN HAIROU…/PBC/2026余序/脱敏交付/序…
```

一条 URL 同时暴露四类信息：

1. **客户英文全称**（含 `INTELLIGENT TECHNOLOGY LIMITED`）
2. **个人账号 / 姓名**：`adam_yy_li1`、`Adam YY Li`
3. **机构域名**：`eychinamanaged-my.sharepoint.cn`、`cn_ey_com`
4. **项目目录结构**：`FDE/04_<客户>/PBC/2026余序/脱敏交付`

**为什么只有上卷**：另两卷由 WPS 生成（`docProps/custom.xml` 有 `KSOProductBuildVer`），源文件本就没有该节点；上卷是 Excel 保存过的（带 `mc:AlternateContent`）。说明清理逻辑要么只对"已存在该节点"的文件生效了一次，要么脚本只处理了部分部件。

**修法**：删除整个 `<mc:AlternateContent>…</mc:AlternateContent>` 块（连 `mc:Ignorable` 里的 `x15ac` 前缀声明一起处理），不要只删属性值。

## 三、P0-3（方法论）：残留扫描与替换范围同源，PASS 不成立

说明 §5 写："4,273 个词条在**全部 XML 部件**中 0 命中"，据此判残留扫描 PASS。

**但这个结论不成立**，理由有三层：

1. **范围同源**：替换改的是 `sharedStrings.xml` / `worksheets/*.xml` / `workbook.xml`；扫描扫的也是这三个。`workbook.xml` 的属性值 `absPath` 里有客户英文全称，扫描仍报 0 命中 —— 说明扫描只看 `<t>` 文本节点，不看属性值；而替换也一样。**替换器看不到的地方，扫描器同样看不到。**
2. **词表同源**：扫描用的是替换用的那 4,273 条词表。词表里没有的词（英文全称、人名、路径、域名）永远不会被"命中"，自然 0 残留。
3. **账号不在词表**：190 个账号在 `accounts.list`，不在 4,273 条词条里。所以"0 命中"**根本没覆盖账号**。

**修法**：残留扫描必须是独立环节——

- **独立词表**：客户中英文全称、全部曾用名/简称、190 个账号原值、已知人名清单、机构域名、路径片段（`Desktop`/`PBC`/`FDE`/用户账号）、`sharepoint`、`personal/`。
- **全条目扫描**：zip 内每一个 entry 都要扫，包括 `docProps/*`、`customXml/*`、`[Content_Types].xml`、`xl/workbook.xml` 的**属性值**。
- **输出定位**：命中必须给出 `文件 → 部件 → 上下文片段`，不能只报一个数字。
- **独立性要求**：扫描代码不能复用替换代码的正则和遍历函数。

## 五、P1-2：§二 两条结论互斥，"截断"假设被自身数据推翻

- 结论：三卷是"同一套导出**按每卷约 100 万行切分**的互补分卷"。
- 风险提示：上/中卷"恰好 1,000,000 / 1,000,003 行，**疑似触发导出工具的行数上限**，若被截断总数会偏小"。

**这两条不能同时成立**，而且第二条被数据直接推翻：中卷实测 1,000,004 行 **> 1,000,000**。若工具在 100 万行截断，中卷不可能多出 4 行。

真实情况是：脚本在第 100 万行、第 200 万行处切分（1,000,000 / 1,000,004 / 87,713 恰好拼成 2,087,717），**不是截断**。

**修法**：删掉"截断"风险提示；若确实要用导出工具的行数上限做旁证，应先确认工具上限值，不能靠"数字接近 100 万"推断。

## 六、P1-3："合并后唯一行"用词错误

§二 写"合并后唯一行 2,087,716"。但 2,087,716 = 三卷直接相加，**一行都没去**。同一节又说三卷合计有 60,324 + 186,000 + 2,687 = 249,011 行签名重复。

若真去重，唯一行应为 **1,838,706**。两个数字差 24.9 万，读者无法判断"去重到底做了没有"。

**修法**：把"合并后唯一行"改成"合并总行数（未去重）"，并注明"签名重复 249,011 行，经抽样确认为不同明细行，未删除"。

## 七、P1-4：分卷切断了凭证 43037 —— 单卷做凭证核对会假报不平

说明文档称"上卷末行与中卷首行属同一张凭证的不同分录，可直接拼接"。—— **这条经实测是对的**（已验证），但漏了它带来的后果：

```
上卷末行：1A公司 2026-06-26 记-43037  科目 2202.01.01 / 2221.01.03.01
中卷首行：1A公司 2026-06-26 记-43037  科目 2202.02.01
```

凭证 43037 被拆在两卷。**任何人拿单卷跑"凭证借贷平衡"检查，这张凭证必然不平**，会被当成数据问题报出来。

**修法**：说明文档必须加一句明确限制——"凭证级校验只能在三卷合并后执行；单卷的凭证不平属切分假象，不是数据错误。"

## 八、P1-5：账号未纳入残留扫描，且 190 与 141 无勾稽

- §三 声明账号 190 个；§5 表格"账号代号化"列：79 / 62 / 0 / 0 / 0 = **141 处**。
- 剩下 **49 个账号去向未说明**：是这批文件里没出现？还是出现了但漏替换？无法判断。

并把 190 个原账号本身加入残留扫描词表。

## 十、P1-7："可逆脱敏"表述不严谨

- 映射是**多对一**：外部公司 2,153 种写法 → 2,123 个代号；客商 2,009 种写法 → 1,993 个代号。多对一在数学上**不可逆**。
- 说明自己的往返抽样也印证了：上卷 102,388 条里逐字一致 100,774 条 = **98.4%**，另有 280 条写法变体、1,334 条简称膨胀。

**修法**：全文把"可逆"改成"**可回退到等价写法**"，并明确"回退件不等于原件，不得作为原始证据使用"。

## 十一、P1-8：回退路径第三方不可执行

§六 的回退命令依赖 `Qoder CN.exe` + `ELECTRON_RUN_AS_NODE`，路径还是占位符 `<Qoder CN 安装路径>` / `<skills>`。

对外承诺"可逆"，却给不出第三方可执行的路径 —— **可复核性不成立**。

## 十二、P1-9：结构对比只比数值，无法发现文本被误改

§5 定义"结构对比"= 单元格数、公式数、合并数、sheet 名单、数值单元格个数、数值合计。

这些全是**数值侧**指标。文本被误改、被替换成空、被截断，一律 PASS。而脱敏动的恰恰是文本。

**修法**：加三项文本侧指标——非空文本单元格数、共享字符串条目数、文本总字符数。允许替换造成的长度变化，但要求"替换前后文本单元格个数一致"。

## 十三、P1-10：剔除"子集"文件靠推断，不靠验证

§二 剔除 `凭证_2026-银行（货币资金JE）` 的理由是"科目属 1001/1002，是全量序时账的子集"。这是**按科目推断**，不是**按行验证**。

如果该文件含全量序时账里没有的凭证（不同账簿、补录、7 月数据），剔除就丢数据，而且不会有人发现。

**修法**：抽 5,000 行签名，验证每一行都能在全量三卷中找到；找不到的行数必须为 0，或逐条解释。`货币资金TB` 同理（按科目 + 金额双向核对）。

## 附录：本复核用的检查方法（可复现）

```python
# 1. 行数：数 <row，不看 dimension（dimension 可能是旧值）
NEEDLE = b"<row"
n = 0; carry = b""
with inner.open("xl/worksheets/sheet1.xml") as f:
    while chunk := f.read(8 << 20):
        data = carry + chunk
        n += data.count(NEEDLE)
        carry = data[-(len(NEEDLE) - 1):]     # 只带未完的半个标签，避免重复计数

# 2. 元数据
inner.read("xl/workbook.xml")      # 搜 b"absPath"
inner.read("docProps/core.xml")    # 搜 cp:lastModifiedBy
inner.read("docProps/app.xml")     # 搜 Company / Manager / TitlesOfParts

# 3. 全条目扫描（注意：必须扫属性值，不只是 <t> 文本节点）
for p in inner.namelist():
    blob = inner.read(p)
    for kw in MARKS:                   # 独立词表
        if kw in blob:
            print(p, kw)
```

> 注意：**行数统计不要用"每块前 N 字节重叠加起来数"的写法**——重叠加起来会把边界处的 `<row` 数两遍。我第一版就踩了这个坑，得出 1,000,010 的错值。
