# 长期资产 BKD 上数 · 现状分析与实现路径

> 分析对象：`D:\桌面\固定资产明细表生成`（含 `资产打标工具` 与 `数据1，已脱敏.xlsx`、`资产BKD模板.xlsx`）
> 目标：把已经跑通的固定资产 BKD 生成能力，并入 PTW `三、WP初稿生成` 板块，成为第 3 个子页签
> 结论日期：2026-11-04 · PTW 当前版本 1.2.14

---

## 0. 结论（先看这五条）

1. **能做，而且大部分逻辑已经验证过**：现有 JS 工具在同一份数据上做过 Excel 全量重算，26 行 × 8 列期初期末零差错、三段合计与源表分毫不差。移植不是重写，是**换执行引擎 + 补通用性**。
2. **但这个板块比货币资金/费用多一层数据源**：期初、期末必须来自客户的**资产台账（FA list）**，科目余额表只能给总额、给不出 26 个细分类型。所以「一键生成」的前提是先有台账，没有台账只能出变动列。
3. **模板的 26 个细分类型是这家客户（4000 主体）自己的分类**，不是通用标准。照抄 26 行写死，换客户立刻废。必须改成**模板驱动 + 行动态**，这是整个方案的核心设计点。
4. **现有工具 70% 逻辑可直接移植**（模板布局解析、SUMIFS 生成、小计/CHECK 公式、打标匹配），**30% 必须扔**（自研 zip/inflate 500 行、浏览器端存储、8 条写死的打标规则）。
5. **建议先做固定资产（1601/1602/1605），在建工程/无形资产/长期待摊/使用权资产放第二批**。它们的 BKD 表形态不同（在建工程是"工程项目清单"、无形资产是"权证清单"），强行塞进一张模板只会得到四不像。

## 1. 现有工具盘点

### 1.1 它现在能做什么

一条完整链路，纯前端（`index.html` 单文件 + `xlsx.full.min.js` + 内置模板 base64）：

```
上传数据包 → 自动识别 序时账三表 / mapping / FA list / FA list期初
  → 按 8 条关键词规则对摘要打标（原文子串匹配，可配）→ 得到「凭证类型」
  → 用 mapping 把「总账科目 / 分类码」映射成「细分类型 + 资产类型」
  → 把三张变动表合并成一张「序时账」（多一列「科目分组」）
  → 在资产BKD模板.xlsx 上原地打补丁（保留全部字体/边框/填充/外部链接）
  → 26 个明细行写 SUMIFS（变动列引用序时账、期初期末引用 FA list）
  → 5 个资产类型小计行 + 1 个合计行 + 3 列 CHECK
  → 输出 xlsx（含 序时账 / FA list / FA list期初 三张数据表）
```

## 3. 为什么不能照抄现有两个板块

| 维度 | 货币资金 C.00 | 销管费用 VC/VD | **长期资产 K1** |
|---|---|---|---|
| 主数据 | 银行账户（TB 直接给） | 费用科目（TB + 序时账） | **客户资产台账（TB 给不了）** |
| 分行依据 | 账号 | 科目全称 | **资产分类（客户自建，26 个）** |
| 模板依赖 | 中（16 列固定） | 中（列序固定） | **高（行 + 列都随客户变）** |
| 判断密度 | 低（性质/函证/受限） | 中（费用归类） | **高（打标 + 分类 + 变动归因）** |
| 单次规模 | 111 行 | 295 行 | **26 行 + 33K 序时账 + 180K 台账** |
| 失败模式 | 串行、翻倍 | 丢行、少计 | **静默错位（CHECK 不平但没人看）** |

一句话：货币资金是"一维列表"，固定资产是"二维报表 + 两张大附表"，模板的约束强一个量级。

## 4. 数据依赖矩阵（哪些自动、哪些必须客户给）

| 模板区域 | 数据来源 | 自动化程度 | 缺数据时 |
|---|---|---|---|
| K~N 期初原值/折旧/减值/净值 | FA list期初 | 自动（SUMIFS） | **必须客户给**，否则整块留空标黄 |
| O~T 原值变动 | 序时账 1501 + 打标 | 自动（规则 + AI 兜底） | 可降级：只出总计，不拆列 |
| U~Y 折旧变动 | 序时账 1502 + 打标 | 同上 | 同上 |
| Z~AD 减值变动 | 序时账 1505 + 打标 | 同上 | 同上 |
| AE~AH 期末 | FA list | 自动（SUMIFS） | 必须客户给 |
| 分类行（26 行） | 模板 / mapping / 上年 BKD | 自动（模板驱动） | 客户模板自带 |
| AI~AK CHECK | 公式 | 100% 自动 | — |
| 差异解释 | 序时账摘要 + AI | **只出证据，不落结论** | 留占位符标黄 |

**结论**：这个板块的"一键生成"是**两段式**——
- 有台账：26 行全填满，CHECK 自证平衡；
- 只有账套（如瑞云那种无台账客户）：只填 7 个变动列 + 按科目汇总，期初期末留空标黄，CHECK 只做"变动合理性"。

### P0 · 骨架与变动列（不依赖台账也能跑）

|---|---|

| 模板 | `data/bkd_tpl/K1_100Breakdown 资产模板.xlsx`（用户可替换，同货币资金） |
| 数据 | 复用现有 `journal` / `tb`；资产清单走**导入清洗通道**（`_sheets.stg_table`），不新建导入器 |
| 逻辑 | 按 1501/1502/1505 筛序时账 → 打标 → 按「细分类型 × 凭证类型」SUMIFS 写 O~AD |
| UI | 第 3 个页签「长期资产」：选模板 → 选资产清单表 → 打标规则 → 一键生成 |
| 验收 | 7 个变动列金额与源表三段合计一致（本批数据：-789,883,285.37 / +836,481,595.08 / +278,884,974.69）；无台账时期初期末留空且标黄；`data/` 零改动 |

### P1 · 期初期末（接台账）

| 项 | 内容 |
|---|---|
| 逻辑 | mapping（两种键）→ 细分类型；FA list / FA list期初 → 按细分类型 SUMIFS 写 K~N、AE~AH |
| 符号 | 原值正 / 累计折旧**负** / 减值=重估（负）/ 净值=**三者相加**（三轮才定死，见 §7.2） |
| 验收 | 26 行 × 8 列与独立 Python 基准逐格一致；合计 K39..AH39 与本报告 §1.2 完全一致；CHECK 原值≈0 |
| 依赖 | 客户必须提供两张 FA 表 + mapping；缺 mapping 时按「总账科目前 4 位 + 资产清单分类名」推断并**列出未匹配清单**，不静默丢 |

### P2 · 模板泛化（决定"能不能给别的客户用"）

| 项 | 内容 |
|---|---|
| 行动态 | 读模板 C 列得分类清单；客户分类多于模板行 → `_insert_rows_keep_layout` 插行（搬合并区/行高/样式）；少于 → 不删，空行保留 |
| 列定位 | 不用 K..AK，改由第 5 行分组 + 第 6 行表头文字定位；缺列记 warning 不报错 |
| 上年复用 | 有上年底稿时，**直接读上年资产 BKD 的分类清单和期初数**，与本年台账逐类核对（多/少/改名三类差异出清单）——比对新模板更可靠 |
| 验收 | 换一份分类 40 个、列序不同的模板，仍能生成且 CHECK 平衡；分类差异（新增/销户/改名）出清单 |

### P3 · AI 判断（只出证据、不落结论）

| 项 | 内容 |
|---|---|
| 打标兜底 | 规则未命中的摘要进"待判断队列"，AI 给建议 + 置信度，人工确认后回写规则库 |
| 变动归因 | 本期/上期按细分类型对比，`|Δ|≥门槛 且 |Δ%|≥10%` 挑对象，按 `|Δ|` 降序，附序时账摘要证据（同 OAR 口径） |
| CHECK 解释 | 差异非零时列出可能原因（期间差/分类错/期初未审），**不写结论**、不调平 |
| 落点 | 结论写进单元格的文字段，用 `AI_TOKEN` 占位符 + 标黄 + `ptw.py fa-fill` 回填（完全复用 `oar-fill`） |
| 验收 | 未写结论的格子有占位符且标黄；回填只换文字不破公式 |

## 6. 关键技术决策（含实测）

### 6.1 执行引擎：openpyxl（不用自研 zip 打补丁）

现有 JS 工具自研了 zip/inflate/deflate 约 500 行，只为了保住样式。PTW 侧实测 openpyxl 完全够：

| 测试 | 结果 |
|---|---|
| `load_workbook(keep_links=True)` | 0.85s，49 个 externalLinks 全部读入 |
| 写 33,448 行 × 10 列 | 0.49s |
| 保存（含模板 1.2MB + 数据） | 2.44s，输出 2.0MB |
| 追加 175,420 行 FA list + 保存 | 1.82s + 6.99s，输出 4.8MB |
| Excel 打开验证（COM） | **正常打开无修复**，2 个 sheet，单元格值正确 |
| zip 条目 | 109 → 108（只少 sharedStrings，正常） |
| externalLinks | 49 → **49，全保留** |

结论：走 openpyxl，砍掉 500 行不可维护代码。代价是"默认不把 18 万行 FA 明细搬进输出"（见 6.3）。

### 6.2 活动列：全部按表头文字定位

沿用 `readTplLayout` 的思路并强化：
- 第 5 行找「本期原值变动」→ 锁定分组表头行（**先定位行，再定位列**）
- 第 5 行合并区 + 第 6 行文字 → 得 `{组名: {列名: 列号}}`，组内同名列取首次出现
- 「固定资产类别」列 = 明细行锚点；其左一列（B）空 → 分组标题行（小计落点）
- 「合计」行向下找，找不到退回"最后一条明细行 + 1"
- 定位失败一律**告警 + 中止**，不猜

### 6.3 FA 明细要不要进底稿：默认不进，可勾选

| 方案 | 输出体积 | 生成耗时 | 可追溯性 |
|---|---|---|---|
| 搬 18 万行明细进 sheet | 12.6MB | +9s | 最好，逐项可查 |
| **只搬 26 行汇总表（推荐默认）** | 1.5~2MB | 3~4s | 够用：SUMIFS 链汇总表，汇总表另有"原始文件+行数+校验和"三行溯源信息 |
| 勾选"附明细"时搬全量 | 12.6MB | +9s | 最高 |

建议默认第二种。审计要看明细时再勾选，避免每份底稿都 12MB。

### 6.4 打标规则库

- 表 `_tag_rules`（同 `_recipes` 模式）：`name / scope(原值|折旧|减值) / match_type(包含|前缀|后缀|正则) / keyword / vtype / priority`
- 默认 8 条（报废 / WBS / 资产拆分 / AFB0 / 转售 / 调拨 / 暂估挂账 / 编码调整），**关键词必须是原文子串**（这是上一轮踩过的坑：不能拿标签名反填关键词）
- 规则冲突（同一关键词对应两种凭证类型）必须列出让人定，`调拨` 就是这种
- 未命中不静默：进"未打标清单"，界面显示条数 + 前 20 条摘要

## 7. 风险与陷阱（每条都是实际踩过的）

1. **行是客户特定的**。26 行 = 4000 主体的 26 个细分类型。写死 26 行，换客户必错。→ 模板驱动 + 行动态。
2. **符号约定错一次就是几亿的差**。三轮才定下来：原值正、累计折旧**负**、减值=重估原值（负）、净值 = 三者**相加**。任何一项改符号，净值公式必须同步改。→ 写进单元测试断言，不留口头约定。
3. **小计行会被重复计入合计**。原合计 `SUM(O8:O37)` 包含小计行 17/19/25/33 → 双计。必须 `SUM(O7,O17,O19,O25,O33)`。
4. **资产类型「其他」模板里没有**。按资产类型分组会丢数，只能按细分类型定位行。
5. **FA 两张表最后一行是合计行**（分类为空）。不跳过就翻倍。
6. **表头有空格噪音**：`累 计折旧`、`上期末减值 `。所有表头匹配必须先去空白（含全角）。
7. **打标不能按关键词整行剔除**。资产拆分/调拨天然成对出现（一借一贷），按关键词删会把净额删成 0。→ 只做归类，不做剔除（这条是 OAR「结转」事故的同类形态）。
8. **49 个外部链接**。打开会提示"更新链接"，指向客户原底稿。要么保留（默认，与客户原文件一致），要么生成时清空 `externalLink` 关系。**必须先定**，否则每份底稿都弹窗。
9. **模板的空白高亮**（条件格式 `LEN(TRIM(B10))=0`）。openpyxl 能保留，但**不要手写 fill 涂死**——这是货币资金 BKD 踩过的坑：涂死后填了值还是黄的。
10. **19 万行台账的读取**。用 `read_only=True` 流式读，别 `load_workbook` 全解析（15MB 文件会吃掉 1GB 内存）。

## 8. 需要你确认的三件事

1. **数据从哪来**：长期资产的台账（FA list）和 mapping，是跟账套一起打包进"数据包"，还是单独上传？影响导入通道设计和"一键生成"的按钮数。
2. **模板从哪来**：用客户自己的资产 BKD 模板（每客户不同），还是我们维护一份标准分类模板（客户分类往标准上映射）？我建议前者 + 上年 BKD 兜底，因为客户的分类体系就是他自己底稿的行。
3. **范围**：第一批只做固定资产（1601/1602/1605），还是把在建工程/无形资产一起做？我建议先做固定资产——瑞云那份账套固定资产 5.37 亿、无形资产 7,965 万、在建工程 4,733 万，但**没有台账**，正好可以先跑 P0 降级路径验证。
