# 测试与回归（开发用）

> 什么时候读：改了 `开发/程序/` 里任何东西，或发版前。
> 判据只有一条：**13 个脚本全部退出码 0**。打印"通过"但退出码非 0 的，算失败。

## 一、跑全部（在平台根执行）

```bat
for %f in (开发\01_测试\自动回归\test_*.py) do (
  ..\..\tmp\buildenv\Scripts\python.exe %f
)
```

命令行的等价写法（Git Bash）：

```bash
for f in 开发/01_测试/自动回归/test_*.py; do
  tmp/buildenv/Scripts/python.exe "$f" >/dev/null 2>&1 && echo "PASS $f" || echo "FAIL $f"
done
```

## 二、13 个脚本覆盖什么

| 脚本 | 覆盖 |
|---|---|
| `test_aux` / `test_base_cur` | 辅助核算、综合本位币口径 |
| `test_book_infer` / `test_clean_guard` | 账簿推断、清洗护栏 |
| `test_derive_l1` / `test_negate` | 一级科目派生、整列取反 |
| `test_fa_swp` / `_cards` / `_cols` / `_fmt` / `_shrink` | 固定资产 SWP 五个切面 |
| `test_html_import` | HTML/GBK 伪 xls 导入（23 项断言） |
| `test_zip_expand` | 压缩包导入 |

## 三、没被覆盖的地方（要人工看）

- **清洗全链路**（`自动回归/run_clean.py`）需要一份真实账表，参数是外部的，不进自动回归。
- **打包态**没有任何自动测试：打出来的 exe 要手工起一次，看 `/api/modules` 的 version 与板块清单。
- **底稿数值正确性**靠 `tools/wp_diff.py` 对比基线，不在这 13 个脚本里。

## 四、踩过的坑

- 脚本用 `sys.exit(0/1)` 表示结果；**没有 `sys.exit` 的脚本等于假通过**。
- 临时目录用 `tempfile.mkdtemp(..., dir=平台根/tmp)`；本机"移回收站"会失败并留下
  `tmp/ptw_html_*` `tmp/ptw_zip_*`，跑完用 `3_整理工作区.bat` 清。
- 数据目录一律 `KZ_DATA_DIR` 指临时目录，**绝不指向 `data/`**。
