# 14 · C.02a 外币测算

> 目的：验证外币账户的折算是否正确。**本表用「本币」列，不用折算人民币列**——拿折算后的数验证折算等于自证。

## 1. 表结构

按币种一行，`SUMIF` BKD 的币种列汇总（列按表头文字定位，下面的字母只是常见位置）：

```text
币种（B）        = 本期真实出现的币种（人民币恒在第一行）
原币金额（C）    = SUMIF(BKD 币种列, 本行币种, BKD 原币列)
折算汇率（D）    = 资产负债表日该币种中间价；人民币行固定 1
折合本位币（E）  = 原币 × 汇率
账面人民币金额（F）= SUMIF(BKD 币种列, 本行币种, BKD 折算人民币列)   ← 表头原叫「账面本位币金额」
差异（G）        = 折合 − 账面
```

- **合计行**：标签写在**最前面（币种列）**，原币 / 折合 / 账面人民币 / 差异四列都有合计。
  （模板原先把「合计」写在「账面本位币金额」列上，把那一列的金额挤掉了。）
- **Check 行（合计行下一行）**：一行两处并列勾稽，都应为 0
  ```text
  原币：C合计 − 'C.00 BKD'!原币合计     ← 完整性控制（这列混着多币种，相加不是金额）
  人民币：F合计 − 'C.00 BKD'!折算人民币合计  ← 真正的金额勾稽
  ```
- 「账面本位币金额」已改名「账面人民币金额」：F 列取的是 BKD 折算人民币列，本来就是人民币口径；
  叫「本位币」会被理解成各主体自己的本位币（香港主体记的是美元），方向一错就查到别处去了。
- 人民币行汇率写 `1`，不需要人工填。

## 2. 汇率从哪来（V1.2.92 起自动）

- 按**资产负债表日**去人行「人民币汇率中间价」栏目页现查该日公告，翻页定位到当天；
- 找到公告页 → 本机 Edge/Chrome 无头截整页 → 存 `data/fx/pbc_YYYYMMDD.png` → 自动插入本表 Notes 下方；
- **只认当天**：该日没有公告（周末/节假日）就判「未发布」，**绝不借用相邻交易日**；
- 公告页 URL 缓存到 `data/fx/pbc_urls.json`，同一日期以后零请求。

需要人工补的只有三种：该日无公告 / 无浏览器或截图白页 / 不通外网。任务卡 `c02a-fx-shot` 会写清是哪一种。

**补图后必须重新生成一次**，程序会自动插入，任务随之消失。

## 3. 取不到汇率时

- 留空 + 批注 + 标黄，返回 `needRate`；**不填 0、不猜**；
- 全部汇率缺失时本表不成立，要在交付说明里写明「外币测算未完成」。

## 4. 校验

```text
Check 行：原币合计 − BKD 原币合计 == 0        （完整性控制）
Check 行：人民币合计 − BKD 折算人民币合计 == 0（金额勾稽）
人民币行汇率 == 1
外币行：原币 × 汇率 与 账面人民币 的差异可解释（汇兑折算差、BKD 折算率没按主体填等）
```

差异不为 0 的常见原因：

| 现象 | 原因 |
|---|---|
| 某币种差异 = 本币全额 | 该账户**没有原币**（清洗时丢了 `*_fx`）→ 回阶段2 体检 |
| 差异小且零星 | 折算率口径不同（账面用月均/月初汇率）→ 解释，不改数 |
| 人民币行也有差异 | 汇率不是 1，或引用了别的行 |

## 5. 与 BKD 折算列的关系

BKD 的「折算率」是**按主体**填的（人工列），C.02a 的汇率是**按币种**取的人行中间价。两者口径不同：

- BKD 折算率用于出报表口径金额；
- C.02a 用于验证折算是否合理。

**不要把 C.02a 的汇率回填进 BKD 折算率列**，除非项目组明确要求统一口径，并在说明里写明。
