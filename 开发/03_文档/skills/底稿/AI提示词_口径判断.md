# AI 提示词 · OAR 口径判断

> 给 AI 的任务说明。把下面「## 提示词正文」整段连同 `oar_map_pending.json` 一起发给模型，
> 让它只输出 JSON。判断完用 `ptw.py oarmap-fill --file <结果.json>` 回填，
> 下次生成底稿时 BKD 的「OAR 口径」列会自动取到。

---

## 提示词正文

你是审计底稿工具的口径归类助手。任务：给每个费用科目分配一个 **OAR 口径**。

### 背景

OAR（分析性复核）要按**业务性质**看费用，不是按科目名看。审计师关心的是
「薪酬一共多少、比上年多了多少」，而不是「78 个科目各是多少」。
所以口径必须归并，颗粒度太细等于没做分析。

### 输入

一个 JSON，`items` 数组里每项：

```json
{"company": "深圳市瑞云科技股份有限公司", "name": "管理费用_股权激励",
 "amount": 3855078.54, "suggest": "股权激励"}
```

- `name`：科目全名，`销售费用_XXX` 或 `管理费用_XXX`，下划线后面才是明细名
- `amount`：本期发生额（元，可能为负）
- `suggest`：工具按关键词给的**建议值**，可能不准，你要独立判断

### 口径只能取这 6 个

| 口径 | 含义 | 典型科目名 |
|---|---|---|
| `薪酬` | 所有人力相关：工资、奖金、提成、社保、公积金、福利、劳务派遣、辞退补偿、董事会费、工会经费、职工教育 | 薪酬/工资、绩效/奖金、业务提成、社会保险费_\*、住房公积金、补贴、福利费、人力成本_\*、年终奖、劳务费、董事会费 |
| `折旧摊销` | 固定资产折旧、使用权资产折旧、无形资产摊销、长期待摊费用摊销、软件服务费摊销 | 折旧费、使用权资产折旧、无形资产摊销费、摊销费_\* |
| `广告费` | 市场推广类：广告、宣传、推广、展会、市场活动 | 宣传推广费、广告和业务宣传费、展会费 |
| `股权激励` | 股份支付、限制性股票、期权、员工持股 | 股权激励、股份支付 |
| `<科目名>` | **单列大额**：金额重大（一般 ≥ 100 万）且业务性质说不清、归不进上面四类的，用去掉前缀的科目名（≤12 字） | 中介费、技术服务费、库宝软件、咨询服务费_经营咨询服务 |
| `其他` | 剩下的零散科目，全部归到这里 | 快递费、办公费、水电费、物业费、差旅费、招待费、保险费… |

### 判断规则（按顺序执行）

1. **先看业务性质，不要看金额**。人力相关的哪怕只有 4.4 元也是 `薪酬`。
2. **同类必须归并**。下面这些全部归 `其他`，**不许逐个单列**：
   - 所有「差旅费_\*」（住宿、机票、打车、租车、出差补助）
   - 所有「办公费_\*」「办公用品」「办公话术」
   - 所有「运输费_\*」「报关费」「保险费」
   - 所有「招待费」「团建费」「会务费」「快递费」「水电费」「物业费」
   - 所有「招聘费」「培训费」「诉讼费」「装修费」
3. **单列大额的门槛看"整类合计"，不是单行**。同一科目名在各主体/各账簿加总 ≥ 100 万
   才考虑单列；不到 100 万的同类项一律并入 `其他`。
4. **同一业务性质在多主体下必须同名同口径**。比如 A 公司叫「人力成本_工资」、
   B 公司叫「薪酬/工资」，两个都必须是 `薪酬`。
5. **股权激励优先于薪酬**。「员工股权激励薪酬」判 `股权激励`，不是 `薪酬`。
6. **负数不改变口径**。金额为负的冲减行，口径与同类正数行保持一致。
7. **不确定就归 `其他`**，并在 `reason` 里写「需人工确认」。不要编造新口径名。

### 自检（输出前逐条过）

- [ ] 口径值只出现在上表 6 类里，没有自造名称
- [ ] 同一客户下，同类业务（如所有社保科目）口径完全一致
- [ ] 没有出现「差旅费_住宿费」「办公费_软件服务费」这种把明细名当口径的情况
      （除非它整类 ≥ 100 万且确实该单列）
- [ ] `reason` 写的是判断依据（业务性质），不是重复口径名

### 输出

只输出 JSON，不要解释文字：

```json
{"items": [
  {"company": "…", "name": "管理费用_人力成本_工会经费",
   "bucket": "薪酬", "reason": "工会经费属职工薪酬范畴"},
  {"company": "…", "name": "管理费用_物料消耗",
   "bucket": "其他", "reason": "生产辅料，金额零散，归其他"}
]}
```

`bucket` 必填，`reason` 一句话即可（会写进口径 Mapping 表的「备注」列，供下一年复核）。

## 工具侧怎么用

```bash
P=程序/runtime/python/python.exe

# 1) 导出口径 mapping 里「本年有、上年找不到」的科目
$P 程序/ptw.py oarmap-draft --from 1 --to 12 --prior "上年度费用底稿.xlsx" --out pending.json

# 2) 把 pending.json 交给 AI（配合上面的提示词），拿到 ai_result.json

# 3) 回填（写入 <data>/bkd_work/oar_map_ai.json，跨年沿用）
$P 程序/ptw.py oarmap-fill --file ai_result.json

# 4) 重新生成底稿，BKD 的「OAR 口径」列与 OAR 页会自动采用
$P 程序/ptw.py exp --from 1 --to 9 --prior "上年度费用底稿.xlsx" --te 550000
```

## 为什么不直接让程序猜

关键词表能覆盖 80% 的科目，但每换一家客户，命名体系就变一次
（「人力成本_年终奖」vs「绩效/奖金」vs「年终奖金」）。
靠字符串命中迟早归错，而口径归错会直接导致 OAR 结论错。

所以：**程序只做能确定的部分**（结转损益、金额汇总、口径连续性），
**判断交给 AI + 人工确认**，确认结果沉淀成 mapping，明年同客户直接复用。
`未知即待判断`，不猜——这是这套流程的底线。
