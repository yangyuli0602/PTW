# 01 · 导入、清洗与映射

> 对象：执行「上传账套 → 清洗 → 字段映射 → 合并 → 数据检查」的 AI。
> 本文件是唯一依据，**不要再去翻 `_历史/` 里的旧指南**（内容已并入本文）。

## 0. 铁律（违反毁数据）

1. 不改 `程序/` 下任何代码，只走 HTTP 接口。
2. 不删 `程序/../data/`（账套库、上传件、导出件都在里面）。
3. `raw_<sid>` 只读：清洗只写 `stg_<sid>`，`clean/reset` 永远可回退。
4. 不猜列名：必须与 `GET /api/state` 的 `columns` 一字不差（含全角括号、空格）。
5. 每步自检，不通过不进下一步。

## 1. 启动

```bat
set KZ_PORT=8790
set KZ_NO_BROWSER=1
set KZ_DATA_DIR=D:\ptw_work\data
程序\runtime\python\python.exe 程序\server.py
```

- 不设 `KZ_PORT` 从 8787 起找空闲，实际端口看启动横幅。
- **不设 `KZ_DATA_DIR` 会写到 `程序\../data`（用户真实账套）**。换账套、做测试必须设。
  横幅里的数据目录不反映该变量。
- 只监听 127.0.0.1。探活 `GET /api/modules` 应返回 version + 3 个板块。

## 2. 客户端（标准库即可，存成 ptw.py）

```python
import json, os, urllib.parse, urllib.request
BASE = "http://127.0.0.1:8790"
def _req(m, p, body=None, raw=None, name=None, timeout=3600):
    d = raw if raw is not None else (json.dumps(body, ensure_ascii=False).encode() if body is not None else None)
    r = urllib.request.Request(BASE + p, data=d, method=m)
    if raw is None and body is not None: r.add_header("Content-Type", "application/json")
    if name: r.add_header("X-Filename", urllib.parse.quote(name))
    with urllib.request.urlopen(r, timeout=timeout) as resp:
        return json.loads(resp.read().decode())
def get(p): return _req("GET", p)
def post(p, b=None, **kw): return _req("POST", p, b if b is not None else {}, **kw)
def upload(path):
    return _req("POST", "/api/upload", raw=open(path, "rb").read(), name=os.path.basename(path))
def q(sql, limit=2000): return post("/api/query", {"sql": sql, "limit": limit})
```

## 3. 数据流与表名

```
upload → inspect → import(原始表) → clean/save+apply(或 apply-all) → mapping → merge → recon → recon/export
```

| 表名 | 含义 | 何时有 |
|---|---|---|
| `raw_<sid>` | 原始表，带内部列 `_src_row` | 导入后 |
| `stg_<sid>` | 清洗后 | 应用清洗后 |
| `_dropped_<sid>` | 被剔除行（`_src_row,step,step_name,reason`） | 应用清洗后 |
| `tb` / `journal` | 合并后的标准表 | merge 后 |
| `_recon_*` | 检查结果表 | 检查后 |

## 4. 导入

```python
up = upload(r"D:\客户资料\科目余额表_2026.xlsx")
insp = post("/api/inspect", {"fid": up["file_id"], "target": "tb"})
res  = post("/api/import", {"fid": up["file_id"], "sheet": "Table1",
                            "header_row": 2, "header_rows": 1, "target": "tb"})
sid_tb = res["sid"]
```

- `target` 只有 `tb` / `journal` 两个值；固定资产台账另有 `fa` / `fa_beg`。
- **表类型可以自动识别，但要人复核**：`POST /api/detect` 按「表头优先、文件名兜底」打分，
  表头出现「凭证」直接判序时账；分差不够就返回空串（不硬猜）。
  比对前**列名先归一**（去空格/全角/标点），所以手工敲的「分 类」「原 值」「累 计 折 旧」也能认出来；
  但**列名本身原样保留**，不改客户看到的表头。名称里带「对照 / 映射 / mapping」的表直接不猜——
  那是映射表不是账（瑞恒的「分类对照」带着「累计折旧」列，会被凑分误判成台账）。
- `header_row` 系统已识别；preview 里若是标题/空行则手工指定（从 1 数）。两层表头 `header_rows=2`。
- 自检：`GET /api/state` 核对 `n_rows` 与 Excel 行数；**把 `columns` 原样记下**。
- **导入只做「原样入库 + 认列 + 猜目标表」，不预置任何清洗动作**（`clean=[]`）。
  每张表的脏法都不一样，预设配方删错一行（把真实分录当重复）比少删一行危险得多；
  动作由人/AI 按第 5 节诊断自己配，或套用方案库里验证过的（第 7 节），配没配对由「数据检查」兜底。

### 4.1 文件夹批量导入（界面侧，无接口）

「导入原始数据」卡片可以拖入或选择**整个文件夹**，递归扫描全部子目录，一次把一套账全收进来。

- 收 `.xlsx / .xls / .csv`（`.xlsm / .txt / .tsv / .html / .htm` 同样可读），其余按「非目标格式」跳过并计入汇总。
- **格式按文件头判，不按后缀判**（`db._ensure_xlsx`）：OLE2 → `.xls`（或加密 xlsx）；zip 且含
  `xl/workbook.xml` → xlsx；`<?xml` + `mso-application` → SpreadsheetML（提示另存）；
  HTML 特征 → **网页表格**，解析后转成真 xlsx 再走原流程。
  所以「后缀写成 `.xls` / `.csv` / `.txt`、内容其实是 HTML」这类导出（ERP、网银常见，
  特征是 Excel 打开乱码、改成 `.html` 就正常）能直接被识别，待导入里标「网页表格 · 已转换」。
  一个 HTML 里多张表 → 每张表一个工作表（表名取 `<caption>` 或表前文字，没有则「表N」）；
  合并单元格只保留左上角的值，被覆盖的格子留空（复制会让金额被重复求和）。
- **扫描阶段就跳过**：`~$xxx.xlsx`（Office 锁文件）、`.tmp/.temp/.crdownload/.part/.bak/.swp`
  （未下载完或临时）、0 字节空文件、`thumbs.db / .DS_Store / desktop.ini`、`._xxx`（macOS 资源分支）、
  `__MACOSX / .git / node_modules / $RECYCLE.BIN / 点开头目录`。
- `readEntries` **单次最多返回 100 条**，必须循环读到返回空数组为止，否则大目录会静默漏文件；
  目录层级上限 12 层（防软链接死循环）。
- 拖文件夹时 `dataTransfer.files` 只有一个 0 字节占位，必须走 `webkitGetAsEntry()` 递归；
  选文件夹走 `input[webkitdirectory]`，用 `webkitRelativePath` 拿相对路径。
- 导入后给一张「上次扫描结果」：共扫描 / 成功 / 失败 / 跳过（按原因归类并带样例），
  失败逐条给原因（损坏、后缀与实际格式不符、被占用、编码识别失败）。
- 待导入列表显示**相对路径**，不同子目录里的同名 `序时账.xlsx` 不会混成一个。
- 这一层只做「上传 + 识别 + 进待导入」，真正落库仍要点「导入这组 / 全部导入」。

## 5. 诊断（最需要判断力的一步，不要套默认配方）

先 `q(f'SELECT * FROM "{T}" LIMIT 20')` 看长相，再逐项体检：

| # | 查什么 | 怎么判 | 命中后 |
|---|---|---|---|
| 1 | 空行/重复表头/页脚 | 看首尾几行 | `drop_empty`、`drop_keyword` |
| 2 | 汇总层（多账簿/合并方案/合计主体） | 按主体 group by 求和，某主体 ≈ 其余之和 | **必须删**，否则金额翻倍 |
| 3 | 重复账簿层（`GB-*`、`副账簿`、`合计`） | 逐账簿金额与余额表逐家对比 | **必须删**（`mode=正则`） |
| 4 | 外币原币行（本币列也有折算值） | 按币别 group by | **不要删**（会丢原币），检查按币别分组 |
| 5 | 两表期间范围是否一致 | 按期间 group by | 不一致则 recon 必须传 `period_from/to` |
| 6 | 行数是否整百万 | 看行数 | 疑似导出截断，**必须写进报告** |
| 7 | 科目层级分隔符（`_` / `-` / `.`） | 看科目名称样例 | 决定 `add_l1` 的 `sep` |

一级科目怎么来：有独立列→直接映射；名称层级拼接→`add_l1`；编码带层级且父子同存→`add_acct_path`（会删非末级父行，慎用）；
编码定长无分隔符（`10020101`）→`derive_l1`（按前 N 位切，并用标准科目表补名称）。
**`acct_l1` 要名称（应付账款），不要编码（2202）。**

序时账必做唯一凭证号（凭证级平衡按整凭证汇总，凭证号跨账簿/月份会撞）：

```python
{"type":"add_voucher_key","enabled":True,
 "params":{"entity":"账簿","period":"期间","vno":"凭证号","sep":"-","name":"唯一凭证号"}}
```

## 6. 清洗

```python
post("/api/clean/save", {"sid": sid, "steps": steps})
r = post("/api/clean/apply", {"sid": sid})       # 或 post("/api/clean/apply-all", {})
```

- 先 `clean/preview` 试运行看每步删几行，再 apply。
- apply 返回 `total_before/total_after/dropped/steps[]/error`；apply-all 返回 `{ok,ok_n,skipped,failed,items[]}`，单表失败不中断。
- 步骤有序，`enabled:false` 保留不执行；列名不存在的动作自动跳过并 warning。

19 个动作（全部单条 SQL；以 `GET /api/clean/types` 为准）：

| type | 名称 | 参数 |
|---|---|---|
| `drop_empty` | 删除空行 | `cols`(空=全部), `mode`(all/any) |
| `drop_empty_key` | 按关键列判空删行 | `cols` |
| `drop_subtotal` | 删除小计行 | `cols`（只认格子开头/结尾的合计小计） |
| `drop_keyword` | 按关键词删行 | `col`, `kw`(逗号分隔), `mode`(包含/全等/正则), `reason` |
| `drop_base_cur` | 删除综合本位币行 | `col`(币别列，留空自动找) |
| `keep_base_cur` | **只保留综合本位币行** | `col`（与上一项互斥，二选一） |
| `drop_dup` | 整行去重 | `cols` |
| `trim_text` | 文本归一 | `cols` |
| `pad_code` | 编码补零 | `col`, `length`(0=自动推断) |
| `negate_col` | 整列取反 | `col`, `mode`(flip / to_negative / to_positive) |
| `fill_down` | 向下填充 | `col`, `partition`(可选分区列) |
| `fill_const` | 填充固定值 | `name`, `value` |
| `derive_level` | 科目级次推断 | `col`, `name` |
| `add_l1` | 提取一级科目 | `col`, `sep`, `name` |
| `derive_l1` | 按编码派生一级科目 | `col`, `name_col`(可选), `length`(0=自动推断), `out_code`, `out_name`（定长编码按前 N 位；只派生不删行） |
| `add_acct_path` | 生成一级科目（含删非末级） | `code`, `name`, `entity`, `sep`, `join`（另有 `amount/parent_tol/aux/detail_first/group_cols`） |
| `split_aux` | 辅助核算拆分 | `col`, `sep`, `strip` |
| `add_voucher_key` | 生成唯一凭证号 | `entity`, `period`, `vno`, `sep`, `name` |
| `check_balance` | 勾稽校验 | `open`, `dr`, `cr`, `end`, `tol`（只报不删） |

**`drop_base_cur` / `keep_base_cur` 是互斥的一对，必须二选一**：客户导出里「综合本位币」
汇总行与分币别明细行常常并存，两层金额相等——同时上数会翻倍，只取汇总层又没有原币明细。
选哪一个决定底稿有没有原币列，属口径选择，必须留在清洗配方里（留痕），平台不替你默认。

参考配置（**列名与关键词按第 5 节诊断结果改，不能照抄**）：

- 余额表：`drop_empty` → `drop_keyword`(方案层级含「多账簿」，reason=汇总层) → `add_l1`(科目名称, sep=`_`)
- 序时账：`drop_empty` → `drop_keyword`(账簿 正则 `GB-|副账簿|合计`) → `add_l1`(科目全名) → `add_voucher_key`

自检：每步 before/after 是否符合预期；删错了立刻 `clean/reset`；看删了哪些行用 `clean/dropped`。

**合计行判定口径**：关键词必须在「格子开头或结尾」，不做子串匹配
（否则「其他合计性支出」会被当合计删掉）。`clean` 与 `audit` 两处必须同一口径。

**过滤动作返回的是「保留条件」**：`_b_drop_*` 都要写「留下的行」，
写反会变成只留合计、删光明细。

**`negate_col` 只翻符号，不改别的东西**：先 `try_cast`（去掉千分位）判是不是数字，
文本行（合计、备注）、空值、0 一律原样保留——否则「合计」会被拼成「-合计」、0 变成「-0」。
翻符号走字符串层面，所以 `1,234.00 → -1,234.00` 的千分位和小数位写法不变；列序、列类型都不变。

**`derive_l1` 解决「定长编码没有分隔符」**：`10020101` 用 `add_l1` / `add_acct_path` 都切不开。
它按前 N 位切出「一级代码」，再用**标准科目表**补「一级科目」名称，一次出两列，只派生不删行。

- 名称三级兜底：内置 `程序/rules/std_accounts.json` → `data/std_accounts.json`（客户覆盖，同码覆盖、新码追加）
  → 本表里**编码正好等于该前缀**那一行 → 都没有就只写编码（兜底行数写进步骤 note）。
  注意不能拿「该前缀下第一行」的名称：`22110101 基本工资` 会给 `2211` 写出「基本工资」，比留空更难发现。
- `length=0` 自动推断：候选位数 2–12 逐个统计「标准表命中率」，取命中率 ≥50% 的最短一档。
  只有 8 位明细码、没有 4 位父行时，4 位前缀能命中 `1002/1122`，8 位本身命中不了 → 判成 4。
  若数据里长短码并存但标准表全不命中，取最短的那档；都没有则返回 noop 并提示手填。
- 推不出位数 / 列里没有数字编码 / 未选列 → 三种 noop 各有明确文案，不会静默产出空列。

## 7. 映射

`mapping` = `{标准字段: 源列名}`，可先 `POST /api/suggest` 让系统猜。**先清洗再映射**（才能映射到生成列）。

- **tb**：主体 `company_name` 或 `book_name`（至少一个）；`acct_code/acct_name/acct_full/acct_l1/currency`；
  金额四组 `open/cur/ytd/end` × `debit/credit`，本币一对 + 原币 `_fx` 一对，没有外币就只映射本币。
- **journal**：`vdate/period/vtype/vno/voucher_key/summary/acct_code/acct_name/acct_full/acct_l1/debit/credit/amount_fx/currency/book_name`，
  可选 `person/checker/poster/counterparty`。
  注意：**序时账原币是单列 `amount_fx`**，不是借/贷两列，合并时按方向自动拆 `debit_fx/credit_fx`。
- **fa / fa_beg**：固定资产台账（期末 / 期初）。**V1.2.98 起固定资产底稿不再消费这两张表**（直接从 TB + 序时账取数，见 `../底稿/11_固定资产.md`）；映射保留，历史项目导入不受影响。
- 自检：`acct_l1` 必须映射（缺了第三组直接报错）；`currency` 缺了只能核本币。
- 主体兜底：`company_name` → `book_name` → 全归「(未标注主体)」。多公司账套必须提供其一。
- 完整动作与参数以 `GET /api/clean/types` 为准。

### 7.1 账簿名称 / 公司名称：可以不给列

这两列是**必备字段**，但源表常常没有这两列。靠 `mapping["_book"]` / `mapping["_company"]` 指定来源：

| 配置 | 取值 | 说明 |
|---|---|---|
| `_book: {mode:"col", col:"账簿"}` | 某一列 | 源表有账簿列时首选 |
| `_book: {mode:"file"}` | 文件名 | **自动剥掉「_科目余额表」「-序时账」这类尾缀**；剥完只剩年份（如「2026年」）则不剥 |
| `_book: {mode:"sheet"}` | 工作表名 | 一账簿一 sheet 的导出 |
| `_book: {mode:"const", value:"1A公司2026年账"}` | 手填 | 单主体账套最快 |
| `_company: {mode:"books"}`（缺省） | 账簿对照表 | 按 `book_name` 匹配 `_books`，取公司名/简称 |
| `_company: {mode:"col", col:"公司"}` | 某一列 | 源表自己有公司列 |
| `_company: {mode:"book"}` | 等于账簿名称 | 单体账套、账簿名就是公司名 |

两种来源可叠加：例如 `_book=file` + `_company=books`（文件名当账簿名，再去对照表换公司全称）。
`_company=col/book` 时不再被对照表覆盖（`_apply_books` 用 `COALESCE` 只补空）。
合并后 `book_name/company_name` 仍为空 → 自检 `tb_required` / `jr_required` 直接判不达标。

**清洗动作从零开始配**，三条路：
1. 页面上「套用配方」——`GET /api/clean/types` 里的 `presets`（`generic` 通用余额表、`aux_rows` 辅助核算成行…）；
2. 「导入清洗方案」/ `POST /api/recipes/apply`——用以前验证过的方案；
3. 逐条 `POST /api/clean/save` 自己拼。

配完先 `GET /api/clean/audit` 看逐项结论，再合并、跑五组检查。
方案要留用就 `POST /api/recipes/save-many`（body `{plans:[{name, steps}]}`）。

## 8. 合并（带清洗达标门禁）

`post("/api/merge", {"target":"tb"})`、同法 journal。同目标表 UNION，重复执行幂等整表重建。

**门禁**：合并完会立刻跑一次清洗达标体检（`audit(scope="pre_merge")`），只判**会导致假不符/假数据**的硬项：

| 会被拦（阻断） | 不拦（只提示） |
|---|---|
| 合计/小计行残留、父科目与明细并存、必备字段空（编码/名称/一级科目/账簿/公司）、序时账缺借贷或一级科目 | 辅助核算整列缺失（客户没填，平台造不出来）、综合本位币与明细并存、一级科目是纯编码、行数整百万 |

- 被拦时返回 **409** + `blocked:true` + 不达标清单（每项带 `fix`），**标准表已回滚到合并前**；
- 确要带病合并：`{"target":"tb","force":true}`，不达标项会写进 `warnings` 留痕、返回 `forced:true`；
- 页面上会摊开清单，给「去清洗页修 / 仍要强制合并」两条路。

**这意味着：不要再跳过「检查清洗达标」直接合并。** 三/四组出现大面积假不符时，先看是不是没删合计行、没删父科目。

自检：`tb`/`journal` 行数 ≈ 各 sheet 之和；`count(DISTINCT voucher_key)`；**`warnings` 必读**。

## 9. 四组检查

```python
r = post("/api/recon", {"period_from":"2026-01","period_to":"2026-12","tol":0.01,"tb_base":"ytd"})
```

- `period_from/to` **只影响第三、四组**（一、二组永远全量自平衡）。传 `1`~`12` 或 `2026-01` 均可，
  系统归一化，**不要自己拼字符串比较**（`'10' < '6'`）。
- `tb_base`：`ytd`(默认)/`cur`/`open`/`end`。

| 组 | 内容 | 期望 |
|---|---|---|
| 一 | 余额表按公司×币别：本期/累计借贷平衡、期初+借−贷=期末 | 全平衡，勾稽差 0 |
| 二 | 序时账按公司：总额/月/唯一凭证号平衡（只列不平凭证） | 0 问题 |
| 三 | 两表按公司+一级科目（分币别） | 差额 0 |
| 四 | 两表按公司+科目全称（分币别） | 差额 0 |

判读（别误报）：

| 现象 | 结论 |
|---|---|
| 一组个别公司本期不平 | 父子科目同存重复汇总，**真问题**，用 `add_acct_path` 删非末级 |
| 一组外币行发生额不平 | 借美元贷人民币正常，系统只判外币行余额勾稽 |
| 三/四组大量「仅余额表有」且金额 0 | 正常，零金额单边已判一致 |
| **不符率 > 50%** | **口径错了**：汇总层没删/重复导入/期间错位/币别没分，回第 5 节 |
| 总额对、个别科目差固定金额 | 真实串户或漏记，按凭证号定位 |
| 二组凭证表为空 | 全部平衡，正常 |

验收：一组全平衡；二组总额/每月/不平凭证均 0；三组本币总额差 <0.01；四组非零不符 =0。
1~2 不满足是**数据本身**问题，据实报告不要修数据；3~4 大面积不符是**你的口径**问题。

导出：`post("/api/recon/export", {"name":"TB序时账核对"})` → 按返回 url 下载。

## 10. 执行顺序

启动探活 → 上传+inspect+import（记 sid 与 columns）→ 逐表诊断并写下结论 → 写 steps 先 preview 再 apply →
全部映射 → merge tb/journal → recon（期间按诊断结论传）→ 按第 9 节区分数据问题/口径问题 → 导出 → 出报告。

## 11. 陷阱（实战踩过）

1. 外币原币行本币列有值，全取会让本币虚增数十倍；做法是按币别分组，不是删。
2. 汇总层主体金额恰等于各公司之和，必须删。
3. `GB-*`/`副账簿`/`合计` 与主账簿重复，全导会放大数倍；用逐家金额比对证明。
4. 两表期间不同必须传 `period_to`，否则比的不是同一段时间。
5. 行数整百万疑似截断，影响「核对是否完整」的结论，必须写进报告。
6. `acct_l1` 存名称不存编码。
7. 期间字符串比较 `'10'<'6'`，平台已 `lpad` 归一，自己写 SQL 同样要注意。
8. 「综合本位币」汇总行与各币别明细行不能同时全取（本币会重复加总）。

## 12. 报告必须含

数据表（文件/工作表/原始行数/清洗后/剔除/剔除原因）→ 口径（每个判断及依据：汇总层为何删、账簿层为何删、
期间如何限定、币别如何处理）→ 四组结果（检查组数/总行数/问题数/结论）→ 待客户确认（截断嫌疑、数量级异常等）。
