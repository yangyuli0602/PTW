> 版本：2026-11-12（对应平台 V1.2.105）

## 0. 先建立正确的心智模型

**平台不做判断，只做确定性计算。**

| 谁做 | 做什么 |
|---|---|
| 平台（代码） | 取数、匹配、写表、写公式、插行保格式、勾稽核对、留痕 |
| AI | 诊断数据脏法、起草口径归类与变动原因、识别上年底稿结构、汇总证据、写报告 |
| 人 | 签署结论、确认阈值与汇率、处理黄格缺口 |

任何「自动下结论」的动作都是禁止的：自动判「无调节项」、自动判「无异常」、用 `+1`/`ROUND` 调平差额——这三类属于最高优先级违规。

## 1. 起步：环境与客户端

```bat
set KZ_PORT=8790
set KZ_NO_BROWSER=1
set KZ_DATA_DIR=D:\ptw_work\data     :: 必须设！不设会直接读写用户真实账套
程序\runtime\python\python.exe 程序\server.py
```

- 探活：`GET /api/modules`，返回 version + 板块清单即正常。
- 只监听 127.0.0.1，无鉴权；客户端用标准库 `urllib` 即可。
- **数据隔离是绝对红线**：跑任何验证必须带 `KZ_DATA_DIR=tmp/xxx`；要测真实账套先 `cp` 副本，绝不直连 `data/`。

```python
import json, os, urllib.parse, urllib.request
BASE = "http://127.0.0.1:8790"
def _req(m, p, body=None, raw=None, name=None, timeout=3600):
    d = raw if raw is not None else (json.dumps(body, ensure_ascii=False).encode() if body is not None else None)
    r = urllib.request.Request(BASE + p, data=d, method=m)
    if raw is None and body is not None: r.add_header("Content-Type", "application/json")
    if name: r.add_header("X-Filename", urllib.parse.quote(name))
    with urllib.request.urlopen(r, timeout=timeout) as resp:
        return json.loads(resp.read().decode())
def get(p): return _req("GET", p)
def post(p, b=None, **kw): return _req("POST", p, b if b is not None else {}, **kw)
def upload(path): return _req("POST", "/api/upload", raw=open(path, "rb").read(), name=os.path.basename(path))
def q(sql, limit=2000): return post("/api/query", {"sql": sql, "limit": limit})
```

## 2. 工作区一 · 导入清洗（最需要判断力的一步）

### 2.1 流程

```
upload → inspect → import（raw_<sid>）→ 诊断 → 配清洗（stg_<sid> / _dropped_<sid>）
       → mapping → merge（tb / journal）→ recon（_recon_*）→ 导出
```

| 表 | 含义 | 何时有 |
|---|---|---|
| `raw_<sid>` | 原始表（带 `_src_row`），**只读** | 导入后 |
| `stg_<sid>` | 清洗后 | 应用清洗后 |
| `_dropped_<sid>` | 剔除行（`_src_row,step,step_name,reason`） | 应用清洗后 |
| `tb` / `journal` | 合并后的标准表 | merge 后 |
| `_recon_*` | 检查结果表 | 检查后 |

### 2.2 导入

```python
up   = upload(r"D:\客户资料\科目余额表_2026.xlsx")
insp = post("/api/inspect", {"fid": up["file_id"], "target": "tb"})
res  = post("/api/import", {"fid": up["file_id"], "sheet": "Table1",
                            "header_row": 2, "header_rows": 1, "target": "tb"})
sid = res["sid"]
```

- `target` 只有 `tb` / `journal`（固定资产另有 `fa` / `fa_beg`）。
- 表类型可自动识别（`POST /api/detect`）但**必须人复核**；名称含「对照/映射/mapping」的表不猜。
- `header_row` 系统已识别；标题/空行在前需手工指定（从 1 数）；两层表头 `header_rows=2`。
- 导入**不预置任何清洗动作**——每张表脏法不同，预设配方删错比少删危险。
- 自检：`GET /api/state` 核对 `n_rows`，**把 `columns` 原样记下**（后续动作必须一字不差，含全角括号与空格）。

### 2.3 诊断：五项必查

| # | 查什么 | 判据 | 命中后 |
|---|---|---|---|
| 1 | 空行/重复表头/页脚 | 看首尾几行 | `drop_empty`、`drop_keyword` |
| 2 | 汇总层（多账簿/合并方案/合计主体） | 某主体 ≈ 其余之和 | **必须删**，否则金额翻倍 |
| 3 | 重复账簿（`GB-*`/副账簿/合计） | 逐账簿与余额表逐家比 | **必须删**（`mode=正则`） |
| 4 | 外币原币行 | 本币列也有折算值 | **不要删**，按币别分组核对 |
| 5 | 两表期间是否一致 | 按期间 group by | 不一致则 recon 必须传 `period_from/to` |
| 6 | 行数是否整百万 | 看行数 | 疑似导出截断，**必须写进报告** |
| 7 | 科目层级分隔符 | 看科目名样例 | 决定 `add_l1` 的 `sep` |

一级科目怎么来：有独立列→直接映射；名称层级拼接→`add_l1`；编码带层级且父子同存→`add_acct_path`（会删非末级，慎用）。**`acct_l1` 存名称，不存编码。**

序时账必做唯一凭证号（凭证级平衡要按整凭证汇总，凭证号跨账簿会撞）：

```python
{"type":"add_voucher_key","enabled":True,
 "params":{"entity":"账簿","period":"期间","vno":"凭证号","sep":"-","name":"唯一凭证号"}}
```

### 2.4 清洗

先 `clean/preview` 看每步删几行，再 `clean/apply`；删错立刻 `clean/reset`（永远可回退）。

19 个动作（全部单条 SQL）：`drop_empty` / `drop_empty_key` / `drop_subtotal` / `drop_keyword` / **`drop_base_cur`（删除综合本位币行）** / **`keep_base_cur`（只保留综合本位币行，与前者互斥二选一）** / `drop_dup` / `trim_text` / `pad_code` / `negate_col` / `fill_down` / `fill_const` / `derive_level` / `add_l1` / `derive_l1` / `add_acct_path` / `split_aux` / `add_voucher_key` / `check_balance`（只报不删）。

> **综合本位币必须显式二选一**：客户导出里「综合本位币」汇总行与分币别明细行常常并存且金额相等。
> 选「删除综合本位币行」→ 保留原币明细，底稿有原币/折算列；选「只保留综合本位币行」→ 按汇总层上数，
> 底稿没有原币明细列。**这是口径选择，必须配在清洗配方里**，平台不会在取数时替你默认。

两条口径不能错：
- **合计行判定**：关键词必须在格子**开头或结尾**，不做子串匹配（否则「其他合计性支出」被删）；
- **过滤动作返回的是「保留条件」**，写反会变成只留合计、删光明细。

### 2.5 映射

`mapping = {标准字段: 源列名}`，可先 `POST /api/suggest`。**先清洗再映射**（才能映射到生成列）。

- **tb**：`company_name` 或 `book_name`（至少一个）、`acct_code/acct_name/acct_full/acct_l1/currency`、金额四组 `open/cur/ytd/end` × `debit/credit`（+ `_fx` 原币对）。
- **journal**：`vdate/period/vno/voucher_key/summary/acct_*/debit/credit/amount_fx/currency/book_name`。**原币是单列 `amount_fx`**，合并时按方向拆 `debit_fx/credit_fx`。
- 账簿/公司名没列时用 `_book` / `_company` 指定来源：`col`（某列）/ `file`（文件名，自动剥尾缀）/ `sheet`（表名）/ `const`（手填）/ `books`（对照表）。
- 自检：`acct_l1` 必须映射（缺了第三组直接报错）；主体兜底 `company_name → book_name → (未标注主体)`。

### 2.6 合并（有门禁）与四组检查

```python
post("/api/merge", {"target": "tb"}); post("/api/merge", {"target": "journal"})
post("/api/recon", {"period_from":"2026-01","period_to":"2026-12","tol":0.01,"tb_base":"ytd"})
```

**合并会被清洗达标门禁拦**：tb/journal 合并后立刻体检，**合计行残留、父科目与明细并存、必备字段空、序时账缺借贷/一级科目**这几项不通过 → 返回 409 + 清单，**标准表回滚到合并前**。
- 处理：按清单里的「怎么修」改清洗动作，重新合并；
- 应急：`{"target":"tb","force":true}` 可强制，不达标项进 `warnings` 留痕；
- **辅助核算缺失不拦**（客户没填，平台造不出来），只提示——它影响底稿账户明细颗粒度，不影响两表对账。

> 排查顺序铁律：三/四组出现大面积不符时，**先查合计行是否删净、父科目是否删净、期间是否一致**，再怀疑数据或代码。验收报告里的"假不符"就是这么来的。

`period_from/to` **只影响第三、四组**；传 `1`~`12` 或 `2026-01` 均可，系统归一化（`'10' < '6'` 的坑平台已 `lpad` 处理）。

| 组 | 内容 | 期望 |
|---|---|---|
| 一 | 余额表按公司×币别：借贷平衡、期初+借−贷=期末 | 全平衡 |
| 二 | 序时账按公司：总额/月/唯一凭证号平衡 | 0 问题 |
| 三 | 两表按公司+一级科目（分币别） | 差额 0 |
| 四 | 两表按公司+科目全称（分币别） | 差额 0 |

**判读（决定是数据问题还是你的口径问题）**：

| 现象 | 结论 |
|---|---|
| 不符率 > 50% | **口径错了**（汇总层没删/重复导入/期间错位/币别没分），回 2.3 |
| 一组个别公司本期不平 | 父子科目同存重复汇总，**真问题** |
| 三/四组大量「仅余额表有」且金额 0 | 正常，零金额单边已判一致 |
| 总额对、个别科目差固定金额 | 真实串户或漏记，按凭证号定位 |
| 二组凭证表为空 | 全部平衡，正常 |

**验收线**：一组全平衡；二组总额/每月/不平凭证均 0；三组本币总额差 <0.01；四组非零不符 =0。

导出：`post("/api/recon/export", {"name":"TB序时账核对"})`。

## 3. 工作区二 · 货币资金（C.00 系列）

### 3.1 表族与顺序

```
C.00 BKD（账户级明细，原始录入）
  → C.00 Lead（科目级汇总，公式）
  → 派生表 C.01b / C.00b / C.02 / C.02a / C.03
  → 检查表
```

**生成顺序敏感**：封面先写（否则 TE 读不到）→ 上年嵌入页先建（BKD 账号列要指过去）→ BKD → Lead → Cutoff → 派生表 → 检查表。

### 3.2 取数口径（金额对不对全靠这）

只抓一级科目 = 库存现金 / 银行存款 / 其他货币资金：

- `acct_l1` 精确匹配；为空时兜底 `trim(acct_code)` / `trim(acct_name)`；
- **不用 `LIKE '1002%'`**（会重复抓二级明细、带进名称含「银行」的无关科目）；
- 「综合本位币」汇总行与各外币明细行**不能同时全取**（本币重复加总）；
- 序时账判断货币资金科目用「任一命中」（全等 + 名称关键字 + 编码前 4 位）。

### 3.3 各表：平台做什么 / 人工做什么

| 表 | 平台自动完成 | 待人工 |
|---|---|---|
| C.00 BKD | 取数、四级匹配（主体+科目+账号+币种）、新增账户插行保格式、性质/函证回捞、缺口标黄 | 折算率按主体确认；受限资金标记；函证判断 |
| C.00 Lead | 行号按文字定位、表1 SUMIF 链接、CRA/Flag 公式、缺科目插行并重指引用、合计/勾稽重写 | 核对 `leadRows` 定位结果；TE/SAD 确认 |
| C.01b / C.00b | 派生结构；差异列 `IF(I="","",I-G)` 防空行算出负账面 | 差异原因、现金等价物分类 |
| C.02 | **只出候选清单，不落笔** | 调节项结论（自动判「无调节项」= 禁止） |
| C.02a | 原币 SUMIF；人民币行汇率=1；外币取不到留空+批注+needRate；汇率截图自动嵌入 | 填真实汇率；Notes 写来源 |
| C.03 Cutoff | 序时账银行间转账跨期配对，截止日强制=资产负债表日 | 样本逐笔核验 |
| 检查表 | 三方勾稽 + 待确认清单（gaps） | 黄格逐项处理 |
| 上年嵌入页 | 整页纯数值嵌入（无公式不串数） | — |

### 3.4 校验不变量（生成后必须全过）

```text
Σ BKD 本币        == Lead 期末账面数合计
Σ BKD 受限列      == Lead 受限资金调整行
Lead 未审         == Lead 账面 + 账表调整
Lead 审定         == Lead 未审 + 调整
Lead TB Diff      == 0（账面/审定/上期三项）
C.01b 合计        == BKD 其他货币资金 − 已单独列示的受限/保证金
C.02a 勾稽        == 0
```

### 3.5 货币资金的坑

1. **0 余额、销户账户必须保留**（完整性证据）；上年有本年无的账户也要进表（0 + Notes）。
2. 折算列接在模板已用列最右，**绝不插模板中间**；合计/勾稽/SUMIF 全走折算人民币。
3. 行号定位是**静默错位**：定不到会退回默认行号而 `ok` 仍为 True——生成后必看 `leadRows`。
4. 封面 C2~C7 必须写（客户/资产负债表日/准则/本位币），否则表头空白。
5. BKD 的「折算率」是人工列（默认 1，按主体填）；**C.02a 的汇率不用人填**——
   V1.2.92 起按资产负债表日现查人行公告页取中间价并自动截图，只在无公告/无浏览器时留任务卡。

## 4. 工作区三 · 销管费用（VC / VD）

### 4.1 表族

```
VC.00 / VD.00 BKD（两张分开）
  → Uexp.00 Lead
  → VC&VD OAR 双页（销售/管理各一页）
  → 样本池-cut off → VC&VD.01.4 截止性测试
  → 样本池-TOD → TOD 年审 + TOD 预审+剩余期间（两版一起生成）
  → 口径Mapping / 调整汇总表 / 负值明细
```

### 4.2 三条不许改的口径

1. **本期账面 = 借方 −（贷方 − 结转损益贷方）**。月末结转会把科目冲平，但**禁止按「结转」关键词整行剔除**（「结转----确认上市费用」是真实费用）。识别用「凭证内含 4103/4104」或摘要精确匹配。
2. **OAR 口径** = 薪酬 / 折旧摊销 / 广告费 / 单列大额 / 其他。单列门槛 = 该科目**合计** ≥ 100 万（按合计判，不按单行）。**同类必须归并**：差旅费_*、办公费_* 一律进「其他」，否则 5 个口径会变 35 个。
3. **变动** = 本期审定 − 上期审定；变动率 = 变动 ÷ |上期审定|，上期 0 时**留空不写 100%**。

### 4.3 上期三段式

```
K 上期未审（上年底稿静态回捞） → L 上期调整（调整表 SUMIFS） → M = K + L
N 变动额 = IF(M="","",J-M)    O 变动% = IF(OR(M="",M=0),"",N/M)
```

K 缺失必须区分两种理由：「未提供上年度费用底稿」与「该科目在上年底稿里没匹配到」。上年 mapping 存的是**账簿名**，本年 BKD 是**公司全称**——建 mapping 前要用账簿对照折一次。

### 4.4 样本池与 TOD

- 池子**只收借方**：贷方几乎全是月末结转，两侧一起收会抵成 0（瑞云实测借方 = 贷方 → 池子合计 0）；
- 池子**只收本期及期后**：先按「期间起月 1 日」掐掉上一年度凭证，否则 TOD 总体比 BKD 多一块；
- 排除顺序**刚性**：`结转损益 → 科目性质（薪酬/四类折旧摊销）→ 预提冲销 → 负值 → 否`。**负值必须最后**（否则「折旧 −5 万」会被负值桶吃掉）；
- 预提冲销 = 同主体 + 同科目码 + 同金额、一正一负，只在剩余行里配，金额下限 100 元；
- 抽样 ID 覆盖「剔除项之外的全部本期样本」，`TOD-0001` 起连续，日后凭证不编号；
- 两版 TOD 同一池子，**预审页合计必须等于年审页 1.1**；
- 所有 SUMIFS 必须带日期上界 `<= DATE(...)`，否则会把次年大额凭证算进剔除项而**不报错**。

### 4.5 三条 AI 通道（旁路文件，重新生成自动合并）

| 任务 | 读清单 | 写结果 |
|---|---|---|
| 口径归类 | `bkd_work/ai_tasks/oar_bucket_pending.json` | `bkd_work/oar_map_ai_result.json` |
| 表2 结论 | `bkd_work/ai_tasks/table2_pending.json` | `bkd_work/table2_concl_result.json` |
| OAR 变动原因 | `bkd_work/ai_tasks/oar_reason_pending.json` | `bkd_work/oar_concl_result.json` |

- 结果侧是**旁路**：不用跑命令、不改正本，重新生成一次自动带上；
- **AI 只换公式最后那段文字**，金额与比例必须走公式，AI 不重复数字；
- 口径来源列只有三个值：`由AI判断` / `上年底稿` / `规则推导-待AI复核`（黄底 + 进待办）；
- 口径 C 列**永不留空**（留空会让 XLOOKUP 取空、SUMIF 静默漏金额）。

### 4.6 费用的坑

| 现象 | 原因 |
|---|---|
| 整表「进一步调查」全「是」 | TE 没写进 Lead C4 → `C22=0` → `ABS(N)>=0` 恒真 |
| `#VALUE!` | 上期数为空，`ABS("")`，必须先判空 |
| OAR 从 10 个口径变 35 个 | 口径词典按别家命名写死，换客户后科目名被当口径 |
| OAR 句写「上期无数据」但三列都有数 | 上期列是 SUMIFS 公式，openpyxl 读回字符串 → `hasPrior` 恒假；应取上期 BKD 实体值 |
| NB 编号全空 | 判阈值读了公式列，应读静态值列 |
| 表 1 右侧叉线 / 底部蓝带横穿 | 模板残留横线未清零；「内容末行」只认有值，应认「有值或有边框」 |

---

## 5. AI 的边界（每次都要守）

| 可以做 | 不可以做 |
|---|---|
| 诊断数据脏法、提清洗方案并写依据 | 改 `程序/` 下任何代码（只走 HTTP 接口） |
| 起草口径归类、变动原因，标置信度 | 自动下「无异常 / 无调节项」结论 |
| 识别上年底稿结构（哪张表、表头第几行） | 用 `+1` / `ROUND` 调平差额 |
| 汇总证据、写报告 | 拿不同期间的两张表对比 |
| 遇歧义列候选并说明「找过哪里」 | 猜列名、猜科目、猜口径、猜汇率 |

**铁律**：未取得资料 → 留空标黄 `FFFF00` + 进待确认清单，**绝不填 0**；差额必须解释，不能抹平；源数据只读，产物另存。

## 6. 首次上手七步

1. 起服务（必带 `KZ_DATA_DIR`）→ `GET /api/modules` 探活；
2. 上传 + import，记下 `columns` 原样；
3. 逐表诊断（2.3 七项），写下每张表的脏法结论——这是后面所有动作的依据；
4. 配清洗 → preview → apply → `clean/audit`；
5. 映射（`acct_l1` 必须有、序时账原币走 `amount_fx`）→ merge tb/journal；
6. 跑四组检查，按 2.6 判读区分「数据问题」与「我的口径问题」；
7. 生成底稿 → 按 3.4 / 4.2 核对不变量 → 出报告（数据表 / 口径及依据 / 检查结果 / 待客户确认）。

---

## 7. 出问题先查这四条

1. 金额成倍偏差 → 汇总层或重复账簿没删；
2. 大面积假不符 → 期间没限定，或币别没分组；
3. 底稿勾稽不平 → 先看 TE 是否写进 C4/C5，再看 Delta 是哪一项；
4. 删错了 → `clean/reset` 回退；`clean/dropped` 看删了哪些行（含 reason）。

**核心风险只有三个**：把汇总层当明细算、把重复账簿算两遍、拿不同期间的两张表对比——做错会出几千项假不符。
