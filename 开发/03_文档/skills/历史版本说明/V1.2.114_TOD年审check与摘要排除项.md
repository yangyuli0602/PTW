# V1.2.114：年审 TOD 补齐 check 列；薪酬 check 摘出股权激励；纯摘要排除项不核对

日期：2026-11-12　对象：瑞云 RAYCLOUD 1-9 月

## 1. 薪酬 check 里还含着股权激励（错误）

股权激励单列成 1.2 一行后，`_fill_check` 里「工资薪酬」仍按 `is_pay_bucket()` 取口径名，
而 `PAY_HINTS` 含「股权激励」「股份支付」—— 工资薪酬的 check 把 385 万股权激励又算了一遍，
与上一行「工资薪酬 26,335,294.68」相差 3,855,078.54。

改法：把薪酬口径名拆成两组，`equity_buckets`（含股权激励/股份支付/限制性股票/期权/员工持股）
给「股权激励（股份支付）」行用，其余 `pay_buckets` 给工资薪酬行用。
现在两行 check 都是 0。

## 2. 纯摘要判定的排除项不做 check，写明原因

长期待摊费用摊销最典型：科目叫「装修费」「办公费」，只有摘要写着
「摊销--N月--长期待摊费用-XX公司」。BKD 侧没有同名科目可加总，硬做差额会显示一个巨大的假差额。

改为：`_summary_only(kind)` 判断该桶所有行的判定依据是否都来自摘要（note 含「摘要「」」），
是则 check 格写 **「摘要判定，不核对」** 并加格批注说明原因与替代核对方式
（到样本池按摘要筛选，与长期待摊费用底稿的摊销额比对）。分段页与年审页同。

## 3. 年审 TOD 补齐 check 列（与分段页一致）

原来只有「预审+剩余期间」页有 check，年审页没有。现在 `_fill_check` 支持两种布局：

| | 1.1 金额列 | 1.1 check | 1.2 金额列 | 1.2 check |
|---|---|---|---|---|
| 分段页 | F/G/H | I（引用 H） | G/H/I | J（引用 I） |
| 年审页 | F | G（引用 F） | G | H（引用 G） |

年审 1.1 只给 12/13 两行（各自对单张 BKD）加 check —— 15 行总体的核对已由 14 行
「与 BKD 合计核对（应为 0）」承担，不重复写。

## 4. check 取整到分

两侧加总顺序不同会差 3e-08，显示成横杠没问题，但脚本按 `check == 0` 机器核验会误判。
`_diff()` 包一层 `ROUND(…,2)`；真实差额（≥0.005）照样显示。
