# 06 · 写死规则与 AI 边界（现状盘点）

> 目的：把「模板 → 最终底稿」这条路上，哪些东西是**钉死的**、哪些是**现场找的**、
> 哪些**交给 AI/人工**，一次说清。
> 盘点依据：`程序/modules/bkd/core.py`、`derived.py`、`web/assets/bkd.js`（2026-11-05 版本）。
> 结论按**风险**排序，不按代码顺序。

## 0. 一句话结论

| 层 | 现状（V1.2.37 之后） |
|---|---|
| **BKD / Lead** | 行和列都按表头文字现场定位，定位失败才退回写死值并告警 |
| **C.01b / C.02a / C.03** | **已改为按表头文字定位列**；同名列靠「第几次出现」区分；必需列缺失则中止写入并在样本区红字提示 |
| **参数** | 资产负债表日与截止期间**统一为一个来源**；前端不再默认「今天 / 本年 12-31」 |
| **封面信息** | 新建共用基础信息（客户/日期/准则/本位币/TE/SAD），一次保存，各底稿 Lead 自动写入 |
| **AI 提示词** | 全平台只有 2 处（清洗达标、费用口径），**货币资金 5 张表一处都没有**，全靠规则 + 人工列 |

## 1. 列定位：从写死到按表头（V1.2.37 已修）

**改前的隐患**（留档，避免回退）：

| 表 | 原写死的列 | 后果 |
|---|---|---|
| C.01b | B~M = 2~12，另加 13/14/15 补边框 | 模板多插一列，公司名写进科目列，整表错位 |
| C.02a | B~G = 2~6 | 同上 |
| C.03 样本区 | B~O = 2~15，Check 列 = 常量 16 | 列的语义绑死，换版模板即错；且 Check 仍配平（一正一负相加为 0），错得没有声音 |

**改后**：统一走 `locate_cols(ws, 表头行, 列规格)`：

- 列规格按「表头文字 + 第几次出现」定义（`C01B_COLS` / `C02A_COLS` / `C03_COLS`）；
- C.03 左右对称，两侧表头一字不差（「银行名称」「银行账号」「交易金额」各出现两次），
  **必须靠出现次序区分付款方 / 收款方**；
- 必需列缺失 → C.01b / C.02a 整表跳过并记 reason，C.03 中止写样本并在样本区红字提示，
  **宁可不写，也不写到隔壁列**。

仍写死的只剩三类，且都不影响金额：sheet 名、C.03 的参数格（B7/B8/B11）、预置行数（用于算插几行）。

对照：**BKD 与 Lead 不写死列**——

- BKD 用 `_locate_bkd_cols()` 按表头文字认列，且**三个关键字段（公司名称 / 科目名称 / 期末本币）
  缺任何一个就返回失败、让上层报错，不降级硬写**；
- 受限列按 `受限资金 / 受限金额 / 本期末实际受限金额` 认；
- 折算两列按 `折算率 / 期末账面金额（人民币）` 认，认不到就在本币列右侧新开。

## 2. 写死单元格（绝对坐标）

| 表 | 单元格 | 写入内容 | 备注 |
|---|---|---|---|
| C.03 | `B7`（7,2） | 测试阈值 | 覆盖模板原有的 `=MIN(Lead!D14,D15)` 公式 |
| C.03 | `B8`（8,2） | 截止期间（资产负债表日） | 本次写成 2026-12-31，正确值应为 2026-09-30 |
| C.03 | `B11`（11,2） | 说明长文本 | 日期/阈值/笔数全部拼进一句话，**改成别的期间时会跟着错** |
| C.03 | 样本区首行 B 列 | 无样本时的红字说明 | 行号动态、列固定 B |
| C.02a | 各行 D 列 | 本位币行汇率写 `1` | 行动态、列固定 |

**Lead 封面六个格（V1.2.37 已接通）**：C2 客户名称 / C3 资产负债表日 / C4 TE /
C5 SAD / C6 会计准则 / C7 记账本位币，由**共用基础信息**统一写入，不再各模块各传各的。

写入方式：`baseinfo.fill_lead_header()` 按标签文字（客户名称 / 资产负债表日 /
可容忍误差 / 名义金额 / 适用会计准则 / 记账本位币）在 Lead 页里现场找，
值写在**标签右侧第一个空格**。所以模板行下移、C 列被挪动都不影响。

顺序上有个硬要求：**先写 C4/C5，再 `read_te_sad()`**。反过来的话 TE 永远走兜底 100000，
认定阈值、截止阈值、波动判断集体失准 —— 而且看不出来。

## 3. 写死但有兜底 + 告警（可接受，但要看得见）

| 项 | 写死值 | 兜底触发条件 | 告警 |
|---|---|---|---|
| BKD 表头行 | 9（`BKD_HEADER_ROW`） | 表头文字探测失败 | 无（静默用 9） |
| Lead 表 1 科目行 | 37 / 38 / 39 | 三个科目没在文字里找全 | `LEAD_ROWS_DEFAULT` |
| Lead 表 2 科目行 | 62 / 63 / 64 | 同上（第 2 次出现找不全） | 同上 |
| Lead 合计行 | 41 / 66 | 定位失败 | 同上 |
| Lead 境外资金行 | 68 | 找不到「存放在境外」 | 同上 |
| Lead 日期行 | 35 | F 列找不到 `=C3` | 同上 |
| C.03 数据块起点 | 20 / 29（`CUTOFF_BEFORE_START`） | `_cutoff_blocks` 找不到「期末前/后银行间转账测试」标题 | 无 |
| BKD 预置行数 | 6（`BKD_PRESET_ROWS`） | 恒定使用（用于算要插几行） | — |
| C.03 预置行数 | 5（`CUTOFF_PRESET_ROWS`） | 恒定使用 | — |

`LEAD_ROWS_DEFAULT` 这条告警必须人工看：它是"没找全"的信号，
一旦客户模板不是 V7 结构，兜底会把金额写进错误的行，而界面只报一句警告。

## 4. 灵活区域（真正按内容找，不是按位置）

| 对象 | 定位方式 | 失败行为 |
|---|---|---|
| BKD 列 | 表头文字打分（`detect_header` + `map_columns`） | 缺关键列 → 返回 None，上层报错 |
| BKD 数据区 | 表头行 +1 起，到「合计」行前一行（`_bkd_span`） | 找不到合计行 → 退 `max_row` 前 500 行 |
| Lead 科目行 | 文字命中「库存现金/银行存款/其他货币资金」，**第 1 次 = 表 1、第 2 次 = 表 2** | 兜底 + 告警 |
| Lead 合计行 | 科目最大行往下 8 行内找「合计」（扫 B~F 列，因为「合计」常写 E 列） | 兜底 + 告警 |
| Lead 日期行 | F 列值为 `=C3` 或 `=$C$3` | 兜底 + 告警 |
| 受限列 | 表头含「受限资金/受限金额/本期末实际受限金额」，排除「受限资产」 | 在本币列右侧新开一列 |
| 折算两列 | 表头含「折算率」「期末账面金额（人民币）」；分配顺序**先受限、后折算** | 在受限列右侧新开 |
| C.03 两个样本块 | 找「期末前 / 期末后银行间转账测试」标题行，表头在其下一行 | 退常量 20/29 |
| C.01b / C.02a 表头行 | 找「科目名称 + 账号」/「原币 + 汇率」 | 兜底 8 行或跳过该表 + 记 reason |
| sheet | 按名字关键字（`C.01b` / `特殊账户`、`C.00 BKD`、`C.03 Cutoff`） | 跳过 + 记 reason |

> 这一层的设计意图写得很明白（代码注释原话）：写死位置的错误是**静默错位**，
> 数字写到隔壁行、SUMIF 打空行，程序还返回成功，比直接报错危险一个量级。

## 5. 定义但没人用的常量（技术债）

| 常量 | 值 | 引用情况 |
|---|---|---|
| `BKD_DATA_START` | 10 | **零引用** |
| `LEAD_ROW_BY_SUBJECT` | {库存现金:37, 银行存款:38, 其他货币资金:39} | **零引用**（实际用 `LEAD_FALLBACK`） |
| `CUTOFF_AFTER_START` | 29 | **零引用**（实际由 `_cutoff_blocks` 现找） |

留着不会出错，但会误导后来改代码的人以为"这里就是写死的"。

## 6. 写死的默认值（会直接影响结果）

| 位置 | 原来 | 现在（V1.2.37） |
|---|---|---|
| `bkd.js` `initCutoff()` | 截止日期默认**本年 12-31** | 输入框只读，**跟随资产负债表日** |
| `bkd.js` 初始化 | 资产负债表日默认**今天**（`todayStr()`） | 从共用基础信息读，读不到就空着等人填 |
| `routes._run_c00` | 按前端传来的 `cutoff_date` 跑 | **强制 `cutoff_date = balance_date`**；资产负债表日为空则不做截止测试并回报原因 |
| `bkd.js` | 阈值默认 100000、前后各 1 天 | 未变（合理默认） |
| `core.py` `TE_DEFAULT` | 100000 | 未变（读不到 TE 时的兜底，有 `TE_NOT_READ` 告警） |
| `core.py` `SAD_RATIO` | 0.1 | 未变 |

**为什么必须强制同源**：两个日期各走各的时，界面打开就是「今天做账套、12-31 做截止测试」，
两者都不等于真实资产负债表日，而且程序不报错。V1.2.36 那版实测就是
「11-05 取数 / 12-31 找样本 / 真实报表日 09-30」，三个日期互不相同。

## 7. AI / 人工边界

### 7.1 全平台只有两处 AI 提示词，都不在货币资金

| 提示词 | 存在形式 | 服务的环节 | 货币资金用不用 |
|---|---|---|---|
| 清洗达标判定 | `core/audit.py` 的 `PROMPT`，页面「复制 AI 提示词」 | 导入清洗 | 用（在清洗阶段，不是底稿阶段） |
| OAR 口径归类 | `03_文档/AI提示词_口径判断.md` + `oar_map.py` 的导出/回填 | 费用底稿口径 | 不用（费用专用） |

**货币资金 5 张表（BKD / Lead / C.01b / C.02a / C.03）没有任何 AI 提示词入口。**
所有判断要么是规则算出来的，要么是留白给人填。

### 7.2 货币资金里的"人工列"（规则不做、AI 也没接）

| 表 | 列/格 | 内容 | 现状 |
|---|---|---|---|
| BKD | I 折算率 | 按主体填资产负债表日汇率 | 默认 1，**不标黄**，靠表头批注提醒 |
| BKD | K 性质用途 | 账户性质（保证金/平台余额/存出投资款…） | **整列空** |
| BKD | O 受限资金 | 受限金额（笔笔只写一次） | 空白，靠批注说明 |
| C.01b | I 对账单金额 | 客户资料，账面派生不出来 | 空，靠模板空白高亮 |
| C.01b | K 账户类型、L 受限金额、M 受限原因 | 人工判断 | 空 |
| C.02a | D 汇率 | 资产负债表日汇率 | 程序取 PBC 当日报价（期间不对），或人工填 |
| C.03 | N 跨期是否在余额调节表体现 | 人工判断（下拉：是/否/无跨期，不适用） | 空 |
| C.03 | B11 末尾 | 截止期间选择的理由 | 程序写前半段，留一句给人 |
| Lead | C4/C5 TE/SAD、C2/C3/C6/C7 封面 | 参数 | **没写进去** |
| Lead | H44/J44/K44（A3 行） | 审计确认数 | 空 → Diff 不等于 0 |
| Lead | K37:K39 | 上期末审定数 | 空 |
| Lead | B48:F50 | 波动说明 | 空白输入区 |

### 7.3 标黄机制（两种，别混）

| 机制 | 颜色 | 用在哪 | 怎么消失 |
|---|---|---|---|
| 程序涂色 `GAP_FILL` | `FFFF00` 亮黄 | 派生表"该有值但没有"的格 | 不会自动消失，重跑才刷新 |
| 模板条件格式 containsBlanks | `FFFFCC` 浅黄 | BKD 明细区、C.01b 输入区 | 填入任意值即消失 |

BKD 的折算率列故意**不标黄**——判断"这一列是系统加的"靠表头批注，不靠颜色，
避免与"待补"的黄色混在一起。

## 8. 风险排序与建议

| 风险 | 位置 | 为什么严重 | 状态 |
|---|---|---|---|
| **1** | 两个日期默认值（今天 / 本年 12-31） | 已造成实际事故：C.03 按 12-31 空跑、派生表表头写成生成日，全都不报错 | **已修**：日期统一为资产负债表日 |
| **2** | C.01b / C.02a / C.03 写死列号 | 换版模板即静默错位，无告警 | **已修**：按表头文字定位，缺必需列中止写入 |
| **3** | Lead 封面六格未写 | 整张表没有主体、没有日期 | **已修**：共用基础信息写入 |
| **4** | `LEAD_FALLBACK` 告警易被忽略 | 兜底把数写错行，界面只一句话 | 待办：告警升级为"结果标记待复核" |
| **5** | 死常量 `BKD_DATA_START` / `LEAD_ROW_BY_SUBJECT` / `CUTOFF_AFTER_START` | 误导维护者 | 待办：删除或接入 |
| **6** | 无 AI 提示词 | 银行名识别、账户性质归类全靠人工 | 待办：可加"账户性质归类"提示词 |

## 9. 判定口径（以后改代码时按这张表自检）

```text
新增/修改一个写入点，先问三句：
1. 这个位置是找出来的还是写死的？
   —— 写死的：有没有兜底？有没有告警？换版模板会不会静默错位？
2. 这个数是算出来的还是判断出来的？
   —— 判断的：有没有留空标黄？有没有进待确认清单？是否禁止填 0 占位？
3. 这个数谁来兜？
   —— 规则能唯一确定的，不要交给 AI；AI 判断的，必须留痕 + 可复核。
```
