# 04 · C.02a 外币测算

> 上数方式：**派生**（从 BKD 按币种汇总）+ 人工（汇率）
> 生成顺序：**第 4 张**，依赖 BKD 定稿
> 模板 sheet：`C.02a 外币测算`

## 1. 角色

按币种把 BKD 的原币与本位币各汇总一次，用「原币 × 折算汇率」重算本位币，
与账面本位币相比，得出**折算差异**。目的是验证外币余额折算是否合理，不是把差异调成 0。

## 2. 表结构（模板 V7 实测）

| 项 | 位置 |
|---|---|
| 标题 | `B2` = `C.02a 外币测算`，`B6` = `外币测算` |
| **表头行** | **第 8 行** |
| 数据区 | 第 9~12 行（**预置 4 行**：USD / CNY / JPY / 空行） |
| 合计 | 第 13 行：`F13` = `合计`，`G13` = `=SUM(G9:G12)` |
| 复核标记 | `G14` = `RX` |
| Notes | `B16` = `Notes 我们记录了所使用的资产负债表日汇率来源：[添加资产负债表…]`，`B17:F19` 合并为输入框 |

表头（第 8 行）：

| 列 | 表头 | 含义 |
|---|---|---|
| B | 原币币种 | 三字母代码 |
| C | 原币金额 | `SUMIF` 取 BKD 原币列 |
| D | 折算汇率 | **人工/取数**，1 单位原币 = 多少本位币 |
| E | 折合本位币 | `C × D` |

实测生成形态：9 个币种行（9~17：CNY/HKD/USD/EUR/SGD/JPY/AUD/GBP/KRW）、
合计 18（`F18`=合计，`G18`=SUM）、RX 19、Notes 21~22。

## 3. 哪些币种进表

**取 BKD F 列实际出现的币种，去重，按「本位币在前、其余按金额降序」排。**

- 本位币（CNY）恒在第 1 行，汇率恒为 `1`；
- 其余币种按 BKD 本币金额降序（便于阅读，不影响计算）；
- **不要在模板里预置 USD/CNY/JPY 就只做这三个**（模板预置是示例，不是清单）；
- 本期出现但金额为 0 的币种也保留（说明"有这个币种的账户，只是期末无余额"）。

实测：BKD 出现 9 个币种 → C.02a 9 行，一一对应。

## 4. 每个数怎么来

| 列 | 公式（第 r 行） | 说明 |
|---|---|---|
| C 原币金额 | `=SUMIF('C.00 BKD'!$F${ds}:$F${de},$B{r},'C.00 BKD'!$G${ds}:$G${de})` | 汇总该币种**原币** |
| D 折算汇率 | 人工/取数 | 本位币行 = 1 |
| E 折合本位币 | `=IF(D{r}="","",C{r}*D{r})` | **先判空再乘**，空汇率不许算成 0 |
| F 账面本位币 | `=SUMIF('C.00 BKD'!$F${ds}:$F${de},$B{r},'C.00 BKD'!$H${ds}:$H${de})` | **必须是 H 列（期末账面金额本币）** |
| G 差异 | `=IF(D{r}="","",E{r}-F{r})` | 空汇率不产生差异 |

### 关键口径：F 列只能取 H，不能取 J

- `H` = 期末账面金额（本币），是各主体**自己账套的本位币**数；
- `J` = 期末账面金额（人民币）= `H × 折算率`（BKD 的折算率列，按主体填，人工可改）；
- 本表算的是「**账上人民币金额** vs 原币×期末汇率」，所以 F 取 **J**：
  主体本位币若不是人民币（港、新、欧、美等），H 是美元/欧元，拿 H 去比人民币的 E 会差出十倍。

> **前提：折算率必须按主体填对。** 折算率 = 该主体本位币 → 人民币 的汇率；
> 本位币就是人民币的主体填 1。折算率与 H 的币种不匹配时，F 不是人民币，差异全是假的。
>
> **先确认 H 到底是什么币种**，别凭"这家公司境外"就想当然：用「H ÷ 原币」算出隐含汇率，
> 如果它等于当期中间价（如美元户 6.81），说明 H 已经是人民币，折算率就该填 1；
> 如果它等于 1（本币=原币），说明 H 是该主体本位币，折算率才要填实际汇率。
> 2026-11-05 这次就是先按"港新是美元本位币"去改折算率，实测 H/原币 = 6.8109（人民币），
> 填了反而会重复折算、把合计放大 6.7 倍。

### 关键口径：汇率必须是资产负债表日的

- 外币测算用的是**资产负债表日**的即期汇率（或准则允许的近似汇率），不是出报告的日期。

**取汇率的两个通道（2026-11-05 加）**

| 序 | 通道 | 说明 |
|---|---|---|
| 1 | 人民银行公告页 | 权威原文，可截图留证。**栏目页只列最近约 20 个工作日**，账期早一点就翻不到 |
| 2 | 中国外汇交易中心历史接口 | 兜底。按日期一次取回全部 25 个币种，`100JPY/CNY` 类要除 100、`CNY/MOP` 类要取倒数 |

> **教训**：改之前只走人行栏目页。9-30 的公告被翻出首页后，`find_announcement` 返回空，
> 汇率整列留空、C.02a 全表空跑，而程序不报错。当时旧文件之所以"能跑通"，
> 是因为那个数据目录里早有一份 9-30 的汇率缓存，命中缓存就不联网了——
> 换台机器、换个数据目录立刻失效。**缓存命中不代表取数通道还活着。**

处理方式：

- 两个通道都拿不到 → 汇率列**留空标黄**，让项目组填，Notes 写明"待补资产负债表日汇率"；
- **不许拿生成日汇率顶替还不标注**——这是最容易被复核挑出来的错；
- 该日没有中间价（周末/休市）时按自然日往前退最多 7 天，并把实际使用日期写进 Notes，
  不允许静默换日期。

### 汇率时点指纹（2026-11-05 加）

差异明显时，程序自动反推账上用的是哪一天的汇率：

1. 按币种汇总「原币」与「本币」，算出账面隐含汇率；
2. 取账面金额最大的币种做指纹，与资产负债表日中间价比，偏差 ≤0.3% 视为正常，不提示；
3. 偏差大时，逐个比对资产负债表日所在月及往前 4 个月的月末中间价，命中判据为相对误差 <0.1%；
4. 命中就写进 C.02a 的结论："账面折算汇率（USD 6.8109）与 2026年6月30日 的中间价一致，
   与资产负债表日 2026-09-30 的 6.7351 不同（+1.1%）：请确认账套期末是否就是资产负债表日"。

**为什么值得做**：2026-11-05 那次差异 579 万，靠人工逐币种比对才查出"账套其实是 6 月末"。
机器能算的事不该留给人，也不该让它安静地留在表里。

### 公告截图：平台截不了，交给使用它的 AI

**为什么不自动截**：分发给客户的运行时是 python embeddable，没有浏览器驱动、没有 Pillow，
既打不开网页也嵌不了图。开发机上装了 `playwright-cli` 时能截，但不能指望客户机有。

**更关键的一条**：只有拿到「人行公告原文链接」时才允许自动截图。交易中心那个页面
打开是**当天**数据，拿它截出来的图日期对不上资产负债表日——那是假证据，比没有更糟。
所以 `source != PBC` 时一律不截，只留任务卡。

### 差异 ≠ 错误

`G` 列合计（`G18`）通常**不为 0**，它反映的是"账上折算汇率"与"期末汇率"之间的差异，
是测算结论，不是要做平的目标。

- 不许为了让它归零去调汇率或调金额（禁止动作：`+1` / `ROUND` 调平）；
- 差异较大的币种应在 Notes 说明原因（汇率波动、账上按月初汇率折算等）。

## 5. 校验

```text
Σ F 列（全币种）  == BKD J 列合计 == Lead F41        ← 本位币口径闭合
Σ C 列（全币种）  == BKD G 列合计（原币，仅外币可比，本位币行原币=本币）
CNY 行 D = 1，且 E = F（差异必须为 0）
每行 D 非空 → 否则整行 E/G 为空，该行要进"待补汇率"清单
B 列币种集合 == BKD F 列去重集合（不多不少）
Notes 里的汇率与 D 列实值一致（不许只写到小数点后 4 位就当成精确值）
```

> 最后一条是实测问题：Notes 写「HKD=0.8560」，实际 D 列是 `0.85601`，
> 复核人拿两个数一比就说"底稿自己前后不一致"。

## 6. 格式要求

- 金额 `#,##0.00`；汇率 `0.000000`（6 位，避免 0.004987 这类小币种被显示成 0.00）；
- 差异列正负都显示，不用红色/绿色区分（不是涨跌）；
- 人工填的汇率列标黄 `FFFF00`，机器取的汇率不标黄但要在 Notes 注明来源与日期。

## 7. 已知坑

1. **SUMIF 引用整列 F:F**：模板用的是 `'C.00 BKD'!F:F`，改成有限区间时要与 BKD 实际数据行对齐；
   反过来，如果保持整列引用，BKD 下方新增的任何文字（如 Notes 行）都会被算进匹配范围。
2. **币种写法必须与 BKD 完全一致**：BKD 写 `USD`，本表写 `美元`，SUMIF 直接返回 0，且不报错。
3. **空汇率陷阱**：`E = C*D` 在 D 空时算出 0，再减 F 就是「差异 = −账面」，
   一眼看过去像核对出巨额差异。必须 `IF(D="","",…)`。
4. **本位币行不能跳过**：CNY 行看似"汇率 1 没什么可算"，但它是校验合计的必要一环——
   少了它，Σ F ≠ Lead 合计。
5. **模板预置 4 行**，实测扩到 9 行。合计行按"数据末行 + 1"现算，不按 13 行写死。
