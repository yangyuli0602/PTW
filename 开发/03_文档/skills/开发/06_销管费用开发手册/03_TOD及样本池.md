# 03 · TOD 及样本池（01.2 两版 + 样本池-TOD）

> 覆盖三张表：`VC&VD.01.2 TOD 年审`、`VC&VD.01.2 TOD 预审+剩余期间`、`样本池-TOD`。
> 模板自带的 `VC&VD.01.2 详细测试 TOD` 只有标题与说明文字，**生成后隐藏**（不填数、不删）。
> 模板：`data/bkd_tpl/TOD SWP U_Exp 202YXXDD XYZ公司.xlsx`（跨工作簿整页复制）。
> 基准：`费用BKD_TOD双版_重算值.xlsx`（年审 108 行 / 预审 131 行 / 池 10,709 行）。

## 1. 为什么两版一起生成

模板里本来就有两版：

- `TOD 年审`：全年一个总体，一张明细表
- `TOD 预审+剩余期间`：金额拆「预审段 / 剩余段」两列，明细也拆两张

项目组两种做法都在用，工具**两版同时出，谁用哪份自己删**。
两页看的是**同一份池子**，所以必须满足：

```
预审页 1.1 H 列合计  ==  年审页 1.1 F15（总体金额）
```

## 2. 样本池-TOD（18 列）

> **位置**：紧跟在 `TOD 年审` 与 `TOD 预审+剩余期间` 之后（第 10 张），在 `VD.01.3` 之前。
> 由 `expense.SHEET_ORDER` 统一排，不由 `write_pool` 自己挪。

在 `样本池-cut off` 的 15 列后面加 3 列（分类已合进「是否排除」，不另开一列）：

| 列 | 名称 | 说明 |
|---|---|---|
| A | 序号 | 台账连续号，从 1 起 |
| B | 主体 | 公司全称 |
| C | 科目代码 | 文本，保前导零 |
| D | 科目名称 | |
| E | 归属 | 销售费用 / 管理费用 |
| F | 日期 | 凭证日期 |
| G | 期间 | `2026-09` |
| H | 凭证号 | |
| I | 摘要 | |
| J | 币种 | |
| K | 原币金额 | |
| L | 折算率 | 本币/原币，取不到按 1（外币主体标黄，见 §9） |
| M | 折合人民币 | **TOD 所有 SUMIFS 都打这一列** |
| N | 是否排除 | 分类，取值见 §4 |
| O | 排除说明 | 人话说明为什么排 |
| P | 是否关键项 | 是 / 空 |
| Q | 抽样ID | `TOD-0001` 起 |
| R | TOD 说明 | 一句话，说明这行为什么这样处理 |

池子**全量**（含资产负债表日后 30 天凭证），一行一笔，看得见每笔怎么被判的。

## 4. 1.2 剔除：八桶 + 负值，一笔只进一个桶

| 行 | 桶 | 池子里的取值（N 列） | F 列 X-ref |
|---|---|---|---|
| 19 | 固定资产折旧费 | 固定资产折旧费 | 固定资产+日期 |
| 20 | 使用权资产折旧费 | 使用权资产折旧费 | 使用权资产+日期 |
| 21 | 无形资产摊销费 | 无形资产摊销费 | 无形资产+日期 |
| 22 | 长期待摊费用摊销费 | 长期待摊费用摊销费 | 长期待摊费用+日期 |
| 23 | 工资薪酬 | 工资薪酬 | 应付职工薪酬+日期 |
| 24 | 租赁费 | 租赁费 | 使用权资产+日期 |
| 25 | 预提费用（含预提和冲销） | 预提费用（含预提和冲销） | `—`（不指向任何底稿） |
| 26 | 其他剔除金额 | （模板留位，工具不填） | — |
| 27 | b. 负值 | 负值 | 见表2 负值分析 |

> **预提费用填 `—`，不指向任何底稿。** 它是靠「同主体 + 同科目 + 同金额一正一负」配对识别的，
> 没有哪张底稿能承接（曾写「其他应付款」，但项目组按这个名字找不到对应底稿）。
> 与「其他剔除金额」同样处理：只占位、不拼日期（`—20260930` 那种拼接要避免）。

公式（G 列）：

```
G19 = SUMIFS('样本池-TOD'!$M$4:$M$<末>, '样本池-TOD'!$N$4:$N$<末>, "固定资产折旧费", '样本池-TOD'!$F$4:$F$<末>, "<="&DATE(2026,9,30))
```

三条硬规矩：

1. **日期上界必须带**。池子是全量的（含日后 30 天），不加会把次年 1 月的大额凭证算进剔除项，
   `G31` 对不上 `F15`，**而且不报错**。
2. **一笔只进一个桶**。负数先按性质归桶（工资薪酬 -184 万、折旧 -212 万…），
   归不进任何性质的才进「负值」。
3. **结转损益不进任何桶**。它是期末结账，不是费用发生；在池子里 N 列就是「结转损益」，
   TOD 的 SUMIFS 不匹配这个值，自然被排除在八桶之外。

基准：G19 356,054.61 / G20 807,403.71 / G21 60,657.98 / G22 0 / G23 30,736,048.19 / G24 199,348.19 /
G25 0（预提与冲销相抵）/ G27 −3,361,213.49；G29 剔除合计 28,798,299.19；G31 剩余总体 41,513,459.71。

### 4.1 预提费用那格要写批注

预提与冲销必然一正一负、净额为 0。只显示一个 0，看起来像「没有预提费用」。
在该格加批注写清两侧金额：「本行为净额：预提 X、冲销 −X，一正一负相抵为 0」。
**批注只写口径，不写结论**（数字随数据变，批注是快照）。

## 5. 1.1 总体 / 2 关键项 / 3 剩余

```
F12 = 'VC.00 销售费用BKD'!J<合计行>      （动态定位，别写死 J205）
F13 = 'VD.00 管理费用BKD'!J<合计行>      （别写死 J150）
F15 = SUM(F12:F13)
F35/E35 = COUNTIFS(池 P 列,"是") / SUMIFS(池 M 列, 池 P 列,"是", 日期上界)
F39/E39 = 合计
E44 = G31 − F39（扣除剔除项和关键项后的剩余总体）
```

- F36（性质特殊）、F37（其他风险）是职业判断，**工具不填，留空标黄 `FFF2CC`**
- 关键项排序：按 |金额| 降序写进表1，不要按池子顺序（审计要先看大的）

## 6. 表1 明细（关键项）

- 表头 55，明细 56 起，容量 14 行（56~69）；超出先整行插入，插完从模板首行逐格复制造型
- 列：C 抽样ID / D 样本类型（关键项）/ E 凭证日期 / F 凭证号 / G 摘要 / H 科目编码 /
  I 科目名称 / J 凭证金额 / K 供应商（可从摘要抽，抽不到空着）/ L~O 支持性证据（人工）/
  P~R 属性测试 A/B/C / S 异常解释
- 只写我们能给的（抽样ID、日期、凭证号、摘要、科目、金额、对方单位），人工项留空**不标黄**
  （整列都空，标黄等于刷屏）

## 7. 表2 负值分析（分析的是「全部负值」，不是一个桶）

这是最容易做错的地方：负数现在按性质散在 a 段各桶里，只统计「负值」桶会漏掉一大半。

```
全负        = SUMIFS(M, M,"<0") − SUMIFS(M, N,"结转损益", M,"<0")
D82 冲销预提 = SUMIFS(M, N,"预提费用（含预提和冲销）", M,"<0")
D83 其他性质 = 全负 − D82
D84 合计     = D82 + D83
D85 核对行   = D84 − 全负   →  必须为 0
```

基准：D82 −9,001,093.82 / D83 −7,331,039.08 / D84 −16,332,132.90 / D85 0。

- 「是否抽样」：按 |D82|、|D83| 与门槛（TE×50%）比，给出「是/否」
- b.1 抽样策略：**人工写**，只给空白格标浅黄
- b.2 负值明细：只列 |金额| ≥ 门槛的，按金额升序（最负的在最上）

## 8. 抽样ID 规则（最容易被误解的一条）

**编号覆盖「剔除项之外的全部本期样本」，不是只给关键项编号。**

- 池子按台账顺序（日期 → 主体 → 科目 → 凭证）从上往下读，`TOD-0001` 起连续
- 抽到 `TOD-1477`，能在池子往下数第 1477 个样本找到它——这就是抽样名册
- **不按金额排序编号**：金额序会随数据变化整体重排，上一版底稿里的编号全部对不上
- 日后凭证不编号（属截止性测试范围），`TOD 说明` 写「资产负债表日后凭证，属截止性测试范围」
- 剔除行不编号，`TOD 说明` 写清剔除原因（「期末结转，不构成费用交易」/「XX：已在其他底稿执行程序」）

## 9. 外币主体

折算率按「本币 / 原币」取，取不到按 1。有外币主体时全表照常生成，但要在报告里给警告：
「有 N 行折算率按 1 计，折合人民币实际是外币金额」，并把池子 L 列标黄，提示填期末汇率后重算。
**不许静默当 1 处理完就结束。**

## 10. 跨工作簿复制整页（技术红线）

`openpyxl` 不能跨工作簿 `copy_worksheet`，必须逐格复制。但：

```
✗ nc._style = copy(c._style)     # 样式索引，跨工作簿后指向另一套样式表
✗ nc.font = c.font               # 同理会串
✓ 逐属性 copy：font / fill / border / alignment / number_format 的「值」
```

用错的表现：字体变、加粗丢、medium 变 thin、底纹全没，**而且不报错**。

复制完用 `wb.move_sheet` 把两页移到 `VC&VD.01.2 详细测试 TOD` 之后（年审在前、预审在后），
不要沉到 `Skywind` 那些内部表后面。

## 11. 坑

| 现象 | 原因 / 处理 |
|---|---|
| G31 与 F15 差一块 | 剔除 SUMIFS 漏了日期上界（把日后凭证算进来了） |
| G29 合计重复计算 | 一笔进了两个桶（负数既进性质桶又进负值桶） |
| 表2 合计对不上 G27 | 只统计了「负值」桶；要用「全部负值 − 结转」 |
| 抽样ID 从 TOD-1037 起跳 | 只给关键项编号，或按金额排序编号 |
| 预审页 H 列 ≠ 年审页 F15 | 两页用了不同池子/不同期间切法 |
| 池子行数两版差几十行 | 池子写了两遍且中间改了分类；必须同一份 rows 写两次 |
| 表1 明细超过 14 行后格式全丢 | 插行后只写值没复制样式 |
| 关键项把日后凭证也选进来 | 关键项只在 `vdate ≤ 资产负债表日` 里挑 |
| 模板页复制过来白底黑字 | 用了 `_style` 索引，改成逐属性复制 |

## 12. 上一期 TOD 引用（预审段，V1.2.71 起）

### 12.1 为什么不能重算

「本期」指一年内的两期（如 9/30 年审 vs 6/30 预审）。**两期的重要性水平不同**（TE、CRA 百分比都可能变），
用本期阈值去重算上期期间，得到的是「新尺子量旧期间」的数，与上期底稿上签过的数对不上，
复核时无法解释差异。所以预审段一律取上期原值。

### 12.2 做法

1. 上一期 TOD 按**年审模板**（`VC&VD.01.2 TOD 年审`）整页搬进本年底稿，新 sheet 名 `上期TOD_<上期资产负债表日>`
2. **只搬值，格式与颜色全部保留**：用两份 workbook（`data_only=True` 取值、`False` 取样式）逐格合并，
   再补列宽 / 行高 / 合并区 / 网格线。不用 `copy_worksheet`（同簿才行，且会把公式带过来）
3. 本期「预审+剩余期间」的**预审段**改为链接该页；**剩余段仍从本期池子算**（本期新增期间，上期没有）
4. 页位置：紧跟 `VC&VD.01.2 TOD 预审+剩余期间`（由 `expense.SHEET_ORDER` 的 `上期TOD_` 前缀规则排）

### 12.3 链接映射（`expense_tod.PRIOR_LINKS`）

| 本期格 | 含义 | 上期格 |
|---|---|---|
| F11 / F12 | 1.1 总体·预审（销售 / 管理） | F12 / F13 |
| G19~G27 | 1.2 剔除·预审（八桶 + 负值） | G19~G27（同行） |
| G29 / G31 | 剔除合计 / 扣除后总体·预审 | G29 / G31 |
| E36~F38 | 2 关键项·预审（数量/金额，三行） | E35~F37 |
| E40 / F40 | 关键项合计·预审 | E39 / F39 |

`F15`（=SUM）、`I29`（=G+H）、`I31`、`E45`（=G31-F40）都是模板公式，输入已来自上期，**不写死链接**。

### 12.4 表1（预审阶段明细）

预审段引用上期后，表1 **不再按本期阈值重挑关键项**，只在首行写一句
「预审阶段的关键项与样本见「上期TOD_xxx」页表1」。
否则会出现「2 段写 7 个、表1 列了 12 行」——同一页两个口径。

### 12.5 前置条件与失败处理

**上期底稿必须有公式缓存值**。程序生成、未经 Excel 打开保存的 xlsx 里公式没有缓存值，
`data_only` 读出来全空，搬进来就是一张白页。

`copy_prior_tod_as_sheet` 会统计搬过来的数值个数，少于 5 个直接**报错并回收该页**：
「上一期 TOD 里没有可用数值（公式没有缓存值）。请先用 Excel 打开该文件、保存一次，再重新生成。」

### 12.6 入口（V1.2.84 起：与上年度费用底稿共用一个上传口）

上一期 TOD 本来就在上一期底稿这同一册 WP 里，界面**只要传一次文件**：

- 前端：只保留「上一期底稿」一个拖拽位。上传后 `/api/build/exp/prior/plan`
  一次解析同时返回两类页——BKD 明细页（选 VC / VD）+ TOD 页（选预审段引用哪张），
  TOD 下拉默认选推荐项（优先年审页），不选就不引用。
- 生成参数：`prior_fid` + `prior_sheets` + `prior_tod_sheet`。后端在
  `prior_tod_fid` 缺省时**用 `prior_fid` 取字节**，所以不需要第二份文件；
  只有显式给了 `prior_tod_fid` 才另读一份（兼容旧页面与「TOD 单独一册」的情况）。
- 命令行：`ptw.py exp ... --prior <上期底稿>` 即可，`--prior-tod` 变成可选项
  （不给就用 `--prior` 那份；TOD 单独放在别的文件时才需要显式指定）。
- `_load_prior_tod` 只取原始字节、不做解析；解析与搬运交给
  `expense_tod.copy_prior_tod_as_sheet`。
- 旧的 `/api/build/exp/prior-tod/plan` 保留（只认 TOD 页），供单独一册时探测。

### 12.7 上期是「预审+剩余期间」模板（V1.2.72 起）

上期自己也分段执行时（如 630 拆 1-3 / 4-6），它的 F 列只有 1-3 月。
**本期预审段要的是 1-6 全量，必须取它的合计列 H/I/J**，取 F 列会漏掉 4-6 月且不报错。

两套映射（`PRIOR_LINKS_ANNUAL` / `PRIOR_LINKS_SPLIT`，由 `prior_links(kind)` 选）：

| 本期 | 含义 | annual（年审页） | split（分段页） |
|---|---|---|---|
| F11 / F12 | 1.1 总体 | F12 / F13 | **H11 / H12** |
| G19~G27 | 1.2 剔除八桶+负值 | G19~G27（同行） | **I19~I27** |
| E36·F36 ~ E40·F40 | 2 关键项 | E35·F35 ~ E39·F39 | **I36·J36 ~ I40·J40** |

注意行号也不同：split 的 1.1 在 11/12 行，annual 在 12/13 行；2 段在 36~40（annual 是 35~39）。

**类型判定**（`tod_kind`，按内容不按名字）：表里 D 列有「本期全部费用交易」（`_is_tod_sheet`）才算 TOD 页；
再看第 8~14 行有没有「剩余」二字——有 = split，没有 = annual。
「详细测试 TOD」那种只有标题的说明页会因为认不到 1.1 标签被排除。

**选择顺序**（`_pick_prior_tod`）：
`手动指定 > 精确名「TOD 年审」> 精确名「预审+剩余期间」> 内容探测`。
两页都在时优先年审页（单列、覆盖全期）；年审页是空壳时改选分段页。

### 12.8 手动指定工作表

页签常被改名（「TOD」「630底稿」「Sheet3」），所以支持项目组自己指。

V1.2.84 起与上年度费用底稿合并探测，一次解析给两类页：

```
POST /api/build/exp/prior/plan   (multipart, 字段名 prior；旧的 prior_tod 也接受)
  → { fid, sheets:[{sheet, kind, usable, rows, ...}], recVC, recVD,
      tod:{ sheets:[{sheet, kind, usable, hasValues, rows}], recommended } }
```

前端在「上一期底稿」那块下方依次出三个下拉：销售费用用哪张表、管理费用用哪张表、
上一期 TOD 用哪张表（默认选推荐项，说明「本期预审段将取该页合计列」）。
单独一册 TOD 时仍可调 `/api/build/exp/prior-tod/plan`（字段名 `prior_tod`）。

生成参数：`prior_tod_sheet`（命令行 `--prior-tod-sheet`）。
指定的页认不出 TOD 时**报错不回退**：「指定的工作表「X」不是可识别的 TOD 页」——
静默换一张比报错更糟。

### 12.9 期间衔接校验

本期预审截止日应与上期资产负债表日相等。不等时**照链但出 warning**：

> 本期预审段截至 2026-06-30，上期 TOD 覆盖到 2026-03-31，两段不衔接；接缝期间的金额需单独说明

硬阻断会让项目组没法出底稿，静默又会漏过问题，所以取 warning 并写进 `priorTod.warning`。

### 12.10 数据来源 X-ref（预审页 E 列）

预审段来自上期 TOD、剩余段来自本期样本池，所以 E 列写**两个来源**：

```
上期TOD_20260630 + 样本池-TOD
```

不能只写上期页名——剩余期间那半列确实是本期池子算的，只写一个来源等于说错话。

### 12.11 CHECK 列（V1.2.73 起，每行合计右侧）

位置：1.1 在 **I** 列（H=合计右侧），1.2 在 **J** 列（I=合计右侧），表头红字 `check`。

核对口径是**本期 BKD 的「本期未审数」合计（G 列）**：

| 行 | check 公式 |
|---|---|
| 1.1 销售（I11） | `H11 − VC!G205` |
| 1.1 管理（I12） | `H12 − VD!G150` |
| 1.1 总体金额（I15） | `H15 − (VC!G205 + VD!G150)` |
| 1.2 工资薪酬（V1.2.82） | `I23 − (SUMIFS(VC!G,VC!T,"薪酬") + SUMIFS(VD!G,VD!T,"薪酬") + 股权激励…)`，T 列＝BKD 的「OAR 口径」 |
| 1.2 折旧摊销四类 | `I<行> − (SUMIFS(VC!G,VC!D,"<该桶在池子里出现过的科目名>") + …)` |
| 1.2 租赁费/预提费用/其他剔除/负值 | 固定 `-`（不可比，批注说明原因） |

**合计行号不能写死**：VC 是 205、VD 是 150（管理费用明细少 55 行）。
`_bkd_total()` 按 D 列「合计」标签现找，写死会减到空格子上，算出「差一个亿」的假差额
（实测过：I12 一度显示 "-"、I15 显示 31,975,085.07，都是这个原因）。

显示规则：相等 → `-`；不等 → 差额；任一侧空 → `-`（无可比数，不是通过）。

**1.2 为什么只算这几个桶**：折旧、摊销四个桶在 BKD 里各对应多个明细科目，
按科目名逐个精确匹配可以落地；工资薪酬改用 **OAR 口径列**整段匹配，
与池子分桶同源（V1.2.82）；租赁费/预提/其他/负值不是科目维度，写 `-` 并加批注。

### 12.12 上一期 BKD 也整页搬入（V1.2.74 起）

同一个 `prior_tod` 文件里通常就带着上一期的 VC.00 / VD.00 BKD。
生成时一并搬成 `上期BKD_<日期>_VC` / `_VD` 两张表（只搬值、格式原样），
紧跟在本期 VD.00 之后。

本期 BKD 的「上期未审数」（K 列）由静态数字改成链接：

```excel
=IFERROR(SUMIFS('上期BKD_20260630_VC'!$G$30:$G$167,
                '上期BKD_20260630_VC'!$C$30:$C$167,$C30,
                '上期BKD_20260630_VC'!$B$30:$B$167,$B30),"")
```

- 匹配键 = **科目编码（C）+ 账套名称（B）**，取上期页的「本期未审数」G 列
- 数据区上界按上期页 D 列「合计」行现算（上期 VC 只到 167，本期 175 行多出的查不到 → 空）
- 上期 BKD 缺失时自动退回原来的 `prior_map` 静态回填，不会因此报错

**实测勾稽（瑞云，本期 9/30、上期 6/30）**：

```
K205（上期未审合计） 20,996,668.05   ← 1-6 月
J205（本期审定合计） 38,336,673.83   ← 全年
N205（变动金额）     17,340,005.78   ← 恰好等于 TOD「剩余期间」G11
```

这条等式是可以当验收标准用的：**N 列合计 = TOD 剩余段合计**，两处不相等说明 K 列链接取错了期间。

### 12.13 上期页隐藏 / CHECK 不用 IFERROR（V1.2.75 起）

**上期页默认隐藏**：`上期BKD_*`、`上期TOD_*` 都是给链接做依据的证据页，项目组平时不翻，
生成后 `sheet_state="hidden"`（与「详细测试 TOD」同一处理）。链接指向隐藏页照常取值。

**CHECK 全部是公式，且不包 IFERROR**：

- `IFERROR` 会把 `#REF!/#VALUE!` 一起吞成「-」，等于「引用断了也算 check 通过」，
  与这一列的用途正相反。现在引用一断就直接显示错误，一眼看得见。
- 无对应 BKD 科目的两行（其他剔除 / 负值）写 `="-"` 的公式常量，不写裸文本。
- **V1.2.82 起工资薪酬不按关键词**：直接对 BKD 的「OAR 口径」列匹配薪酬类口径名，
  池子分桶用的也是这份 mapping，两侧同一批科目，差额只可能是金额差。折旧摊销四类仍是
  按池子里该桶**实际出现过的科目名**逐个精确 SUMIFS（不再用 `*关键词*` 模糊匹配）：

| 桶 | 匹配方式 |
|---|---|
| 工资薪酬 | BKD「OAR 口径」列 = 池子里出现过的薪酬类口径名（薪酬 / 股权激励…） |
| 固定资产折旧费 | 池子里该桶出现过的科目名，精确匹配 |
| 使用权资产折旧费 | 同上 |
| 无形资产摊销费 | 同上 |
| 长期待摊费用摊销费 | 同上 |
| 租赁费 / 预提费用 / 其他剔除 / 负值 | `-`（不是科目维度，天然不可比） |

匹配用**事实**（池子里实际有哪些科目名、口径名），不是规则 —— 用 `*关键词*` 模糊匹配时，
两侧是同一个模糊规则，看着勾稽通过，其实错也一起错。

### 12.14 口径Mapping 混入非科目（V1.2.75 修复）

`read_prior` 原来读到「合计」只 `continue` 不 `break`，把 BKD 表1 下方汇总区也读了进来：

```
A3|20832935.73、OAR 口径|上期审定数、check|0、合计|20832935.73
```

这些假科目全被打成「上年-规则推导」，混在口径Mapping 里污染口径判断。现在：

- 遇到「合计」行 **break**（表1 数据区到此为止）
- 科目名是纯数字/纯符号的跳过
- 账套名是 `A3 / check / Diff / OAR 口径 / 上期审定数 / 本期审定数` 的跳过

### 12.15 CHECK 就是一行减法（V1.2.76 起，推翻 12.13 的写法）

12.13 那版用 `IF(OR(...))` 把「0 差额」和「无可比数」都变成文本 `-`，还套了 `ROUND`、`IFERROR`。
三层都是多余的：

| 写法 | 问题 |
|---|---|
| `IFERROR(...)` | 把 `#REF!/#VALUE!` 吞成 `-`，报错也算通过 |
| `IF(OR(A="",B=0),"-",...)` | 0 与「无可比数」不可区分；整列混文本与数字，`SUM` 静默跳过 |
| `ROUND(x,2)` | 显示两位由格式管，公式不需要凑整 |

现在：

```excel
=$H11-('VC.00 销售费用BKD'!$G$205)
=$I23-(SUMIFS('VC...'!$G$30:$G$210,'VC...'!$D$30:$D$210,"*薪酬*")
      +SUMIFS('VD...'!$G$30:$G$210,'VD...'!$D$30:$D$210,"*薪酬*"))
```

显示交给**会计专用格式（货币符号＝无）**：

```
_ * #,##0.00_ ;_ * -#,##0.00_ ;_ * "-"??_ ;_ @_
```

零显示为右对齐横杠，值仍是 0 —— 可 `SUM`、可排序、可条件格式标黄。
实测 `SUM(J19:J27)=12,200,871.21`（能加总），`I11` 显示 `-` 而底层是 `0`。

无对应 BKD 科目的两行（其他剔除 / 负值）仍是 `="-"` 公式常量，因为确实不参与核对。

## 13. 排除项与 check 改口径（V1.2.80）

### 13.1 默认排除项：六类，**不含租赁费**

```
固定资产折旧费 / 使用权资产折旧费 / 无形资产摊销费（含无形资产折旧）
长期待摊费用摊销费 / 工资薪酬（含股权激励） / 预提费用（配对识别）
```

`cutoff_kind()` 不再对「租赁」返回 `KIND_RENT`，租赁费归「否」进样本池。

为什么去掉租赁费：短期租赁与低价值租赁**直接计入费用、没有使用权资产**，
不适用「使用权资产底稿已测过」这条免责逻辑；一刀切排除会让样本池漏掉一整类
高金额业务，而这一类又没有别的底稿可以替代测试。

模板 1.2 的 D24「租赁费」行**保留行位**（不动模板结构），但金额恒为 0、
F 列写「—」、G24 加批注说明。**不要**让它链接上期 TOD —— 上期是按旧口径剔的，
引过来就变成"口径说不含、数字里还剔着"。

### 13.2 check 改为「按池子里的科目名称」精确引用

```excel
-- 旧（V1.2.79 及以前）
=$I23-(SUMIFS(VC!$G$30:$G$210,VC!$D$30:$D$210,"*薪酬*")+SUMIFS(VD...))
-- 新（V1.2.80）
=$I23-(SUMIFS(VC!$G$30:$G$210,VC!$D$30:$D$210,"销售费用_薪酬/工资")
      +SUMIFS(VD!$G$30:$G$210,VD!$D$30:$D$210,"销售费用_薪酬/工资")
      + … 该桶在池子里出现过的每一个科目名，两张 BKD 各一次)
```

旧写法的病灶：两侧是**同一个模糊规则**。BKD 里只要有一条名字带「薪酬」的科目
就被算进来，池子里也是按同一个关键词分的桶 —— 看起来勾稽通过，其实错也一起错。

新写法的名称表来自 `rows` 里 `excl == 该桶` 的 `name` 去重集合，是**事实**，不是规则。

三种情况仍然写 `="-"`，并在 J17 批注里说明：

| 情形 | 原因 |
|---|---|
| 两侧相等 | 通过 |
| 预提费用 | 按「同主体+同科目码+同金额一正一负」配对识别，桶里只装配对成功的两笔，BKD 那边是科目全年余额，口径天然不可比（实测差 3,777 万） |
| 负值 / 其他剔除 / 租赁费 | 不是科目维度，或本期该桶无科目 |

实测（瑞云 1-9 月）：折旧三类、工资薪酬四行 check 全为 `0`；预提费用、负值等 5 行 `-`。

### 13.3 上期样本原样复制（不再写「见上期页」）

预审段的 `k1` 本来就置空（预审样本以上期为准），以前这里只写一句
「预审阶段的关键项与样本见「上期TOD_xxx」页表1（上期原样保留，此处不重复列示）」。

问题：底稿是**按本期这一页**看和归档的，跳页引用一多，样本、抽样ID、对方单位
就在本页消失，复核人无法在本页核对"预审到底抽了哪几笔"，也没法和上期做增减对比。

现在 `_copy_prior_samples()` 逐行搬 C~S 列（值 + 数字格式），行数超模板容量按需插行，
搬完按新行号重写 O 列 `=J-N`。定位用 `_first_sample_block()`：找 C 列「抽样ID」那行
往下读到「异常解释」，**不写死行号**（年审版表头 55、预审+剩余版 59，上期还可能插过行）。

### 13.4 关键项的两个「人工判断项」默认填 0

2 段第 37/38 行（`性质特殊[款项性质]`、`[其他项目组认为存在风险的样本]`）
E/F/G/H 四列默认写 **0**，不再引上期、不再黄底。

理由：这两项是审计师的判断结果，工具不替人决定，也不该套用上期（上期的特殊款项
跟本期未必同类）；写 0 表示"本项未识别到"，比留白清楚 —— 空白读起来像忘填，
还会让合计行看着像缺数。项目组识别到时直接改数，模板的 E39/F39 合计自动跟着变。

## 17. 池子只含借方 / 阈值按本币 / 工资按 OAR（V1.2.82）

### 17.1 贷方凭证不进池子

`read_pool()` 加了 `AND coalesce(debit,0) <> 0`，只收借方行。理由与影响见
`04_Cutoff及样本池.md` §16.1。对 TOD 的直接影响：

- 池子行数减半（瑞云 10,709 → 6,714），减少的 3,995 行全是月末结转贷方；
- 1.1 总体（预审页）合计从 0 变回 70,311,758.90，与年审页 F15 相等；
- 「结转损益」桶恒为 0，`N,"<>结转损益"` 的条件保留作兜底；
- 「否」桶仍是 2,658 行 —— 删掉的都是结转，没有误伤正常费用。

### 17.2 关键项阈值只看本币

判定统一走 `_base_amt(r)`，取池子的「折合人民币」（= 台账借方本币金额）。
「原币金额」列只供查看，不参与任何比较：一笔 5 万美元、汇率 7，按原币 5 万比是
未达阈值，按本币 35 万才是关键项。

为让复核不用猜，「TOD 说明」直接写出判定金额与阈值：

```
关键项：本币 220,218.00 ≥ 阈值 137,500.00
未达关键项阈值（本币 12,345.67 < 137,500.00），进代表性样本池
```

阈值是 `TE × 50%`，不是 `--te` 本身（瑞云 `--te 275000` → 阈值 137,500）。

配套：折算率存**全精度**，只把显示格式设成 6 位。存 6 位会让「原币 × 折算率」
回不到本币，瑞云 6,714 行累计差 1 元出头，池子合计与 BKD 就差这一块多 ——
实测改后外币行乘积误差最大 0.0000。

### 17.3 工资薪酬按 OAR 口径（同 §13.3）

`mark_exclusions(rows, oar_map)` 里，OAR 口径属人工成本 → `KIND_PAY`；OAR 明确给了
别的口径，关键词不得再判成薪酬。口径挂在行的 `oarBucket` 上，`_fill_check` 反过来
把它收成口径名清单，对 BKD 的「OAR 口径」列做 SUMIFS。

瑞云实测：3,225 行口径「薪酬」+ 10 行「股权激励」，工资桶金额 30,736,048.19，
check = 0。与 V1.2.80 的关键词分桶结果**逐行一致** —— 说明改口径没改变金额，
只是把判断依据从「科目名猜」换成「OAR 已经定过的分类」，以后科目名变化也能自动跟随。

股权激励并入工资薪酬，是因为模板 1.2 只有「工资薪酬」一行；不并入的话这 10 行
被排除出池子却无处核对，池子与 BKD 的勾稽会断。
