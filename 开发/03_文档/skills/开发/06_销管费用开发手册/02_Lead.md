# 02 · Lead（Uexp.00 Lead）

> 一页纸：六个基本信息格 + 一张两行的科目汇总表。
> 基准：`01_测试/TOD双版_V1.2.36_验证/费用BKD_TOD双版_重算值.xlsx` 的 `Uexp.00 Lead`。

## 1. 它在流程里的两个时刻（容易搞混，必须分开）

Lead 不是「一次写完」，而是被写两次：

| 时刻 | 写什么 | 为什么必须在这个时刻 |
|---|---|---|
| **BKD 之前** | C3 资产负债表日、C4 TE、C5 SAD、C6 准则、C7 本位币（客户名 C2 也可此时写） | C22 = TE×50% 是 BKD 全部判断的阈值；TE 不在位就整表失真 |
| **BKD 之后** | 表1 两行的索引号与金额链接 | 必须指向 BKD 实际的合计行，而合计行位置要等明细写完才知道 |

所以：**开发次序是第 2 块，运行时机是「参数格最早、汇总表最后」。**

## 2. 基本信息格（固定坐标，模板未插行，可以直接用）

| 格 | 标签（B 列） | 值 |
|---|---|---|
| C2 | 客户名称 | 客户全称，逐字与底稿一致 |
| C3 | 资产负债表日 | `2026-09-30`（文本或日期均可，下游按前 10 位取） |
| C4 | 可容忍误差(TE) | 数字，`#,##0.00` |
| C5 | 名义金额(SAD) | 数字，`#,##0.00`，缺省 = TE×10% |
| C6 | 适用会计准则 | 「中国企业会计准则」等，**猜不出就留空，不编默认值** |
| C7 | 记账本位币 | 「人民币」等，同上 |

### 2.1 客户名为什么必须写 C2

模板 B2 是标签「客户名称」，**值在 C2**。
D2:K7 是一整块说明文字的合并区（「此工作底稿需要与以下 Canvas PSP guided workflow forms 一起使用…」）。
早期版本写 D2，被合并区挡住，**静默无效**，页面上永远看不到客户名。

### 2.2 TE / SAD 的缺省

- 未传 TE 时取 C4 现值；C4 也空才用 55 万兜底，并在生成报告的 `info` 里标注「用了默认值」
- 未传 SAD 时取 `round(TE×0.1, 2)`
- **不写 TE 的后果不是报错，是静默错**：BKD C22=0 → `ABS(N)>=0` 恒真 → 全表「是」；TOD 关键项只剩「金额≥0」→ 全部成为关键项；01.4 门槛 0 → 测试期全量进表3

## 3. 表1（科目汇总，第 23~26 行）

```
B23  表1
B24  科目名称 | C24 索引号 | D24 本期账面数 | E24 账表调整数 | F24 本期未审数
     G24 审计调整数 | H24 本期审定数 | I24 上期审定数
B25  销售费用  C25 VC.00 销售费用BKD
B26  管理费用  C26 VD.00 管理费用BKD
```

- D/E/F/G/H/I 六列全部是**指向 BKD 合计行的链接**，不是重算值
- 索引号 C25/C26 写的是 **sheet 名**，点进去要能跳到对应 BKD
- 上期列 I 链 BKD 的 M 列（上期审定数）；上期缺失时为空

基准值：

| 科目 | 本期审定（H） | 上期审定（I） |
|---|---|---|
| 销售费用 | 38,336,673.83 | 51,660,694.97 |
| 管理费用 | 31,975,085.07 | 20,832,935.73 |
| 合计 | 70,311,758.90 | 72,493,630.70 |

## 4. 安永标记对照区（第 12~21 行）

`TB 已与科目余额表核对无误` / `PY 与上年最终审定数核对一致` / `A3 与未审数、审定数核对一致` / `A5 与审计调整核对一致` / `FS 与财务报表核对无误` / `w 低于SAD放弃进一步调查` / `Rx 重新计算无异常` / `m 不在测试范围` / `SL 已与明细账核对无误`。

这一区是给人看的图例，**代码不填、不改**。只在表1 或 BKD 用到某个标记时，保证语义一致（例如用了 `Rx` 就必须真的重算过）。

## 5. 链接必须重指真实合计行

模板里写的是 `'VC.00 销售费用BKD'!E34`——那是**模板原始状态**的合计行。
只要某个科目明细超过 4 行，合计行就下移，链接会静默指向某条明细，金额少算最后一行且不报错。

做法：
1. BKD 写完，拿到每张表的合计行号（按 D 列「合计」定位的实时结果）
2. 重写 Lead 表1 的六个链接：`='<sheet>'!<列><合计行>`
3. 重写后回读一次，比对 `Lead 表1 H列 == BKD J列合计`，不等就报警

## 6. 坑

| 现象 | 原因 / 处理 |
|---|---|
| 客户名怎么都不显示 | 写到 D2 了（合并区），必须写 C2 |
| Lead 合计比 BKD 少一行金额 | 用了模板写死的 `E34` / `J150`，要按实时合计行重指 |
| 整表判断失真 | C4 TE 空 → C22=0，先写 TE 再算任何阈值 |
| C6/C7 出现莫名其妙的准则/币种 | 代码给了默认值；应留空，让项目组填 |
| 表1 索引号点了跳不过去 | C 列写成了文件路径或编号，应写 sheet 名原文（含空格） |
