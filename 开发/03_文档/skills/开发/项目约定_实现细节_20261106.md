## 一、清洗口径（动 clean.py 前必读）

- **filter 类动作返回「保留条件」**（`WHERE cond` 建结果表）。`_b_drop_subtotal` 曾漏 `NOT` 变成只留合计。
- 合计/小计判定：**关键词必须在格子开头或结尾**，不做子串匹配（否则删掉「其他合计性支出」）。`clean._b_drop_subtotal` 与 `audit.tb_subtotal` 必须同口径。
- `_num` 只解析「数字+千分位+货币符号+单位」，含文字返回 NULL。
- `_period_norm` 年份限 19xx/20xx/21xx，8 位数字要月日合法，否则科目码/流水号被当日期。
- `_header_names` 去重要逐列检查到唯一，不能靠计数加后缀。
- 方案库 `_recipes`；导入清洗方案必须入库（`POST /api/recipes/save-many`）；`/api/clean/apply-all` 逐表复用 `clean_apply`；导入时每 sheet 自动套 `clean.preset()` 6 步。

## 二、数据检查口径（别再退回单组/单币别）

- `core/recon.py run()` 四组各自 try：①余额表自平衡 ②序时账自平衡（总额/月/凭证）③两表公司+一级科目 ④两表公司+科目全称。期间过滤只作用③④。
- 主体一律 `entity_expr()`：company_name → book_name → (未标注主体)。
- 每组带 `headers`+`view_cols`，落 `_recon_*` 表供导出（导出读表不重算）。
- 余额表是**多币别长表**：综合本位币行 + 外币原币行，不能全取也不能删外币行；按币别分组比。序时账原币单列 `amount_fx`，按借贷拆 `debit_fx/credit_fx`。
- **借贷平衡只按本币判**；零金额单边算「一致」。
- **期间比较必须 `lpad(period,2,'0')`**（曾因 `'10'<'6'` 造成 13,443.39 假差异）。
- `acct_l1` 存科目**名称**不是编码。加字段只改 `CANON`，`_init()` 的 ALTER 会迁老库。

## 三、BKD 通用硬规矩

- **折算率按主体**：右侧「折算率」（人工默认 1）/「折算人民币」（公式）接在模板已用列最右，绝不插中间；合计、勾稽、SUMIF 全走折算人民币。
- `bkd_key = 主体+一级科目+（账号 或 银行/科目）+币种`，少一维就串行。
- 上年有本期无的账户必须进表（0 + Notes 说明）。
- **行号/sheet 序号一律动态定位**：C.00 最终版 137 合计/139 勾稽，C.01b 与 C.00b 位置互换过——按表名解析，不按序号。写死会静默错位（SUMIF 打空行、`=J37` 指标题行）而 `ok` 仍 True。
- 空白模板 `C SWP 货币资金 模板 V7.xlsx` 是 B~L 十一列，实际底稿 A~M 十三列 + P 受限资金——改前先拿真实底稿。

## 四、插行/插列（坑最多，2026-11-04/05 反复踩）

- openpyxl `insert_rows/insert_cols` **只搬格子，不搬合并区、列宽、公式**，新插入的是裸格（无字体无底纹）。
- **解除合并必须在插列之前**：按旧坐标解到"旧合并区、新内容"时，`_clean_merge_range` 会把成员格的值**和样式**一起清成 Normal。实例：模板 `N28:N29`/`O28:O29` 纵向合并，插列后模板的『变动金额』『变动%』正好落进去，被清成两格空白（V1.2.35 修）。
- `insert_rows` 不搬合并区 → 说明输入框会压进数据区，用 `_insert_rows_keep_layout`。
- 跨工作簿复制样式不能用 `nc._style = c._style`（StyleArray 索引错位），必须逐属性 copy font/fill/border/alignment/number_format。
- 插行后公式不会跟：行内公式统一用 `_write_formulas` 重写；引用写 `$` 防拉丢。
- 找「页底」不能扫装饰列（S 列整列深蓝），认 B~H ≥5 格深蓝的横带。

## 五、费用底稿 VC/VD（动 expense.py / expense_*.py 前必读）

- 列位（插两列后）：A 简称 / B 账套 / C 科目码 / D 科目名 / E 账面 / F 账表调整(默认0) / G 未审 / H 结构比 / I 审计调整 / J 本期审定 / K 上期未审(静态回捞) / L 上期调整 / M 上期审定 / N 变动额 / O 变动% / P X-ref / Q 波动判断 / R 定性(默认否) / S Notes / T OAR 口径。
- **上期三段式**：`M=IF(K="","",K+L)`；`N=IF(M="","",J-M)`；上期空则变动额/率留空，不能算成"全是本期新增"。
- 简称列（A）是调整表 SUMIFS 的匹配键；`I` 用 SUMIFS 匹配 简称+FOR BKD。
- X-ref 认不出**打 `/`**，不标黄不写待确认；日期跟资产负债表日（如 `应付职工薪酬20260930`）。
- 表1（按 OAR 口径汇总）：红标题 C00000、只要外框+表头内框、合计无上下框、A3 引用主表 A3、check = 表内合计 − 表内 A3（本期上期都有）；表2 内外框齐全、每段 `NBx：` 前缀、分析过的口径在 BKD 的 Notes 回写 NB 编号（红加粗）。
- 金额用**千元表述**：`TEXT(x/1000,"#,##0")&" 千元"`，OAR 同口径。
- **OAR 现场生成、不抄上年**：`|Δ|>=门槛 且 |Δ%|>=10%`，按 |Δ| 降序；明细只取审定数；结论 AI 写，`ptw.py oar-fill` / `ai-fill` 只换文字保留公式；未写结论留占位符标黄。
- **OAR 的上期数必须从「上期BKD」页取实体值**（V1.2.83）：BKD 的 K/M 列是 SUMIFS 公式，openpyxl 读回字符串 → `hasPrior` 恒假 → 句子写「上期无数据」而表上 E/F/G 全有数。按 `(账套名称, 科目编码)` 匹配 `prior_bkd[...]["values"]`（搬页时已读好）。句子结构同时改成 `IF($E="",…)` 自适应，不靠生成时的值定死结构。
- **OAR 分析交给 AI 的证据要按 `subjects` 合并**（V1.2.83）：证据字典的键是**科目名**，拿口径名去查永远空（V1.2.82 及以前 `groups` 一直是空数组，AI 只能写空话）。结论落 `bkd_work/oar_concl.json`，重新生成自动带上。
- **OAR 按类别拆两页**（V1.2.79）：`VC&VD OAR 销售费用` / `VC&VD OAR 管理费用`，各自「一、汇总 / 二、变动分析 / 三、说明」，互不引用；两页合计必须各自等于对应 BKD 的 J 合计（对不上就是 T 列有行没归桶）。
- **BKD 主表 A3 行留空**（V1.2.79，与货币资金一致）：不写 `=J<合计>`，只设数字格式；Diff/表1 check 公式保留 —— 没填时 Diff 显示合计（一条待办），填了才比对。表1 的 A3/check 对空值做守卫，A3 空时 check 也留空，不拿 0 冒充「已勾稽」。
- **「是否需调查」一律嵌套 IF，不要 `OR(ABS(x)>=阈值, …)`**：Excel 的 OR/AND 不短路，上期为 0 时变动率返回 `""`，`ABS("")` 会把整格算成 `#VALUE!`。
- **待判断口径的 C 列不能留空**：`本年新增-待判断` 必须写「未匹配-待判断」，否则 BKD 的 XLOOKUP 取回空白，OAR 按口径 SUMIF 静默漏掉那一块（实测漏 76 万，表1 合计 ≠ BKD 合计）。
- **对方单位只能从摘要抽**（真实账套 counterparty 填充率 0），强弱后缀两级匹配，单字噪声词不进表。
- **摘要含「结转」≠ 结转损益**：口径写 `借 −（贷 − 结转损益贷方）`，禁止按关键字整行剔除。
- 口径不能靠关键词表：换客户科目名全不一样 → 建「口径Mapping」sheet（上年主体+科目 → 口径，本年反向识别，缺口 AI 判 + 标人工复核），BKD 的 OAR 口径列用 XLOOKUP 双层匹配（主体|科目 → 科目名兜底）。
- 认定等级默认全 Minimal；空着会让 C22（=E8=MIN）为 0，判定恒为"是"。
- 截止性测试判定顺序**刚性**：结转损益 → 科目性质 → 预提冲销（同主体+同科目码+同|金额|）→ 负值 → 否。
- V1.2.80 起：**租赁费不再默认排除**；池子金额**只取借方**（纯贷方行取负，保住负值分析）；TOD 1.2 的 check 改为**按池子里出现过的科目名称**逐个精确 SUMIFS，不再用 `*关键词*` 模糊匹配；预审段样本从上一期 TOD 表1 **原样逐行复制**（不再写「见上期页」）。细节见手册 03 §13、04 §16。
- OAR 口径、OAR 变动分析、BKD 表2 的结论都走 **AI 通道**：`exp --ai-out` 导出 → 平台 AI 判断 → `ai-fill` 回填；OAR 来源列写「由AI判断」+ 依据与置信度，表2 结论落 `bkd_work/table2_concl.json`、OAR 分析落 `bkd_work/oar_concl.json`，保证重新生成不丢。
- **「是否排除」不再走配置表**（V1.2.79 回退）：撤掉「排除Mapping」段、`--excl-map`、`body.excl_map`、`build_excl_map`/`excl_map_from_sheet`；池子 N 列回到写文本。要改判定就改 `cutoff_kind()` 的关键词表（改规则，不是改某一版数据）。

- TOD 页只**插行不改格式**；分类复用截止测试的细分类（不单开一列），颗粒度对齐 TOD 1.2 剔除项。

## 六、长期资产 BKD（动 asset.py 前必读）

- 类别不写死：台账分类 → `_fa_map` → 期初台账「细分类型」→ tb 科目名 → 关键词 → 未分类（列出来不猜）。模板没有的类别插行，多余留空不删。
- 期初期末只能来自 FA list；没台账必须报错，不许出空壳。`read_fa` **按编码分组**（按名称会把期初期末拆两组、期初变 0）。
- 期初/期末两组表头是**日期**（K5/AE5），按先后判。
- 符号：原值正 / 折旧负 / 减值（年度末重估，负）/ 净值 = 三者**相加**；CHECK = 期初+变动−期末。
- 打标必须含 **AFB 前缀→计提**；资产拆分一借一贷只能归类不能剔除。
- 合计 = `SUM(各小计行)`，不用 `SUM(区间)`。

## 七之二、货币资金 Lead 口径（V1.2.59 定稿，动 `_fill_lead` 前必读）

- **表1 C 列（总账科目编码）走公式**：`IFERROR(INDEX(上年Lead!$C$编码区,MATCH($D行,上年Lead!$D$科目区,0)),"")`；没有上年 Lead 才退回内置 1001/1002/1012。上年标 `NA` 的科目（定期存款/大额存单）本年也显示 `NA`，与上年口径一致。
- **波动判断 O 列**：`=IF(OR(L="",M=""),"否",IF(AND(ABS(L)>=波动额,ABS(M)>=波动%),"是","否"))`。空数字判「否」而不是留空；两个阈值按 B 列「波动幅度」标签现找（`_lead_threshold_refs`），不写死 `$C$30/$C$31`——模板上方多一行说明就整体下移。
- **披露区两行**（「其中：存放在境外的款项总额（如适用）」「所有权或使用权受到限制的货币资金」）：本期 C **留空**；上期 D 用**跨过合计行**的宽区间（`t2SubjExt/t2AmtExt`，从表2 首行到最后一条科目文字）SUMIF 上年 Lead 表2。用 `_lead_block` 的窄区间永远取不到——它见「合计」就停。
- **表2 有、表1 没有的科目**（本年「存放财务公司款项」找不到）：本期数填 **0**，不留空。留空与填 0 在对账时看着一样，但表2 合计会与表1 差一截，复核人得逐个猜哪格漏填。
- **调整汇总表只保留五列表头**（调整类型/主体/调整说明/科目名称/调整金额），程序不再写任何数据行。以前自动塞一条「重分类/受限资金/金额/说明」会把五列串成一行看不懂的内容，而且表1 I 列已直接链接 BKD 汇总格，不需要借调整表转手。
- **合计前那行空行与合计行的 O/P 列不留淡黄**：空白高亮 CF 的 sqref 收窄到科目行（`_clear_seq_row_marks`）。条件格式是算出来的颜色，光把 fill 设 None 没用，必须改 sqref；P 列（定性判断）在科目行上仍保留黄底提示。
- 覆盖检查：`tmp/test_prior_lead_layout.py`（34 项，含 `t1Code`/`t2SubjExt`）、`tmp/test_lead_rows.py`（26 项）、`tmp/test_v14.py`。

## 九、测试与代码改动

- **测试脚本没有 `sys.exit` 就是假通过**；regress 会按输出兜底（含 `✗`/`失败 N 项`/`Traceback` 判 FAIL），新脚本仍要自己 exit。
- 打印型脚本（test_c00/test_flow）标 CHECK 不显示 PASS；依赖 DB 的接口测试用独立 scope。攻击性测试在 `tmp/attack_*`（tmp 被 gitignore，换机会丢）。
- 默认不改既有代码；用户明确要求时：① 先 commit/备份 ② 改完全量逐格比对证明输出不变 ③ 编译检查 + 真实数据跑全链路。
- git 基线 `4ba8023`；改前 `git status` 干净，改后 commit，出问题 `git checkout .`。

## 十、性能

- 导入预览走 `xlsxinfo.preview_cells`（XML 直读，快 9~677 倍）。硬天花板是 DuckDB `read_xlsx` 单线程，threads/insertion_order 等调参全部更慢——别再试。

## 十一、工程结构（板块与路由）

- 板块 = `程序/modules/<key>/`，必须有 `manifest.json`（key/label/order/type；embed 型加 entry+static）。
- 一步并两页：children 加 `subs:[{k,label}]` + 前端 `SUB_TABS` 登记 + 各自 HTML 开头 `subTabBar()`。
- 路由在 `routes.py` 的 `GET_ROUTES`/`POST_ROUTES`，**路径自带 `/api`**；加板块不改 `server.py`；embed 型不用写 JS。
- 版本号只改 `server.py` 的 `VERSION`。
- 启动：`启动PTW平台.bat` → `程序/server.py`（127.0.0.1，8787 起找空闲）。
- 内置 Python：`程序/runtime/python/python.exe`（3.13 embeddable，无 pip，加包只能解压 wheel）。
- 本机验证浏览器用 `playwright-cli --browser=msedge`，命令必须同一次 bash 调完。
