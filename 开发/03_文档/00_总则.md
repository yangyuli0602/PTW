# 00 · 总则（状态机）

> 每次开工先读这一份，按阶段走。**每个阶段只有三件事：读哪份 → 做什么 → 什么算完成。**
> 不按阶段走也能跑出文件，但那不叫完成——判据不过就是没过。
> 版本：本文件随平台发包，`applies_to` 见 `SKILL.md`；**平台版本对不上就不要开始**。

## 0. 全局红线（任何阶段都不许破）

1. 源数据只读，产物另存；验证一律用临时数据目录（`KZ_DATA_DIR`），**绝不指向 `data/`**。
2. 不改 `程序/`、不改 `data/bkd_tpl/` 模板、不改底稿里的公式与金额。
3. 未取得资料 → 留空标黄 `FFFF00` + 进待确认清单，**不填 0 占位**。
4. 差额必须解释；禁止 `+1`、`ROUND` 调平；禁止自动判「无异常 / 无调节项」。
5. 判断类字段（性质用途、是否函证、受限金额、调节项）**只起草不拍板**。
6. 报告只写「跑过了」不算交付，必须给出**判据的通过情况**。

## 阶段一览

| 阶段 | 做什么 | 完成判据 | 不过怎么办 |
|---|---|---|---|
| 0 | 核环境与版本 | 平台版本 == `SKILL.md` 的 `applies_to` | 停，换包 |
| 1 | 核输入指纹 | `PBC/项目/指纹.json` 与当前数据一致 | 停，找对数据 |
| 2 | 导入清洗 | 零/一/二组全绿、一级科目无纯数字 | 回清洗，不许凑 |
| 3 | 生成底稿 | 5 条不变量 + `tasks` 全结清 | 按表分册逐条查 |
| 4 | 核输出 | `wp_diff.py` 退出码 0，或差异已解释 | 报差异，不许声称一致 |
| 5 | 交付 | 交付件齐全（见 §6） | 补 |

## 阶段0 · 核环境与版本

**读**：`SKILL.md`

```bat
程序\runtime\python\python.exe 程序\server.py      :: 或双击 启动PTW平台.bat
GET /api/modules                                    :: 返回 version 与板块清单
```

- 判据：返回的 `version` **必须等于** `SKILL.md` 里的 `applies_to`。
- 对不上：说明包与文档不是一套，停。**不要"先跑跑看"**——文档与代码漂移时，越认真越错（曾出现文档写"平台没有汇率源"、代码早已自动取价）。
- 数据目录：`--data-dir` 指向临时副本时，模板 `bkd_tpl/` 与 `project_info.json` 必须一并存在。缺模板会 `TPL_MISSING`（连 C.02a 都不生成），缺项目信息 TE 会失准。

## 阶段1 · 核输入指纹（最容易被跳过、也最容易出差异的一步）

**读**：`PBC/项目/指纹.json`；生成/更新用 `程序/tools/input_fingerprint.py`

```bat
程序\runtime\python\python.exe 程序\tools\input_fingerprint.py --data-dir "<数据目录>" ^
    --prior "上年底稿.xlsx" --out "PBC\项目\指纹.json"
```

指纹里有什么：库文件 sha256、`tb`/`journal` 行数、货币资金行数与本币合计、期间、主体数、上年底稿 sha256 与行数。

- 判据：现算指纹与 `指纹.json` **逐项相等**。不等就是换了数据或换了期间，**不是"差不多"**。
- 不等时：先确认是不是新一期数据（是 → 人工核过后更新指纹并记一笔），否则停。
- 同一客户同一期，行数/金额变了但没人改数据 → 说明清洗口径被动过，回阶段2。

**为什么放在生成之前**：实测两套账的差异 70% 来自数据（缺开户行、缺原币、账号改号、上年底稿损坏），不是 AI 不会做底稿。

## 阶段2 · 导入清洗

**读**：`01_平台使用说明.md`（§2 工作区一）+ `02_导入清洗.md`（通用规则）+ `PBC/项目/清洗映射规则.md`（**客户差异只在这里**）

顺序：`upload → inspect → import → 清洗 → mapping → merge → recon`。

- 判据：零/一/二组 `bad = 0`；三/四组差异逐条有结论；`select distinct acct_l1 from journal where acct_l1 ~ '^[0-9]+$'` 为空。
- **综合本位币必须显式二选一**（`drop_base_cur` 删汇总行 / `keep_base_cur` 只留汇总行）。这是口径选择，不是技术细节：选前者底稿有原币与折算列，选后者没有。**必须写进项目级规则**，不能靠每次现场决定。
- 合并有门禁（409 + 清单），按清单改，不要习惯性 `force`。
- 不通过：回清洗改动作 → 重跑 `clean/apply` → `merge`。**不要带着红组往下做底稿。**

### 清洗交付给底稿时的四样体检（缺一样，底稿必错）

| 查 | 合格 | 不合格的表现 |
|---|---|---|
| 账户识别键 `aux1` | 「开户行/账户名 + 账号」，跨年写法一致 | `aux1` = 主体名 → 两年 **0 匹配、全部判新增** |
| 原币 `*_fx` | 外币户有值 | 全空或等于本币 → 原币列失真、C.02a 按 1:1 算 |
| 账号 | 与上年集合比对 | 账号改号 → 一对假「销户 + 新开户」 |
| 综合本位币 | 与项目级规则一致 | 不复核 → 金额翻倍或原币列消失 |

体检不过：**回清洗侧修** > 在运行副本上补（补了什么必须写进说明）> 停下来问人。原库与清洗代码一律不动。

## 阶段3 · 生成底稿

**读**：`04_货币资金_总览.md`（先读，定顺序）→ 再按科目读 `05` ~ `09_货币资金_C03`

```bat
程序\runtime\python\python.exe 程序\ptw.py --data-dir "<数据目录>" --pretty cash ^
    --date 2026-09-30 --customer "客户全称" --standard "中国企业会计准则" --currency "人民币" ^
    --te 550000 --sad 55000 ^
    --prior "上年底稿.xlsx" --prior-lead "上年底稿.xlsx"
```

参数缺一不可：`--date` 缺 → 封面空、汇率找错天；`--customer` 缺 → 表头没主体；`--te` 缺 → **程序直接报错**（不再静默按 10 万算）；`--prior` 缺 → 识别列全空、上年数不链接。

> 确实只能按默认阈值跑（例如客户尚未定重要性水平），加 `--allow-default-te`，并在交付说明里写明"TE 为默认值"，否则复核人会当成已确认。

### 上年底稿的三种坏法（都真实发生过）

| 症状 | 原因 | 处理 |
|---|---|---|
| 打不开、报 XML/`sharedStrings` 错 | 脱敏/还原工具替换含 `<si><t>` 的文本时没转义 | **本机 Excel 打开 → 另存**，用修复件；不要自己拼 XML 猜着修 |
| 「性质/用途」「Notes」列是 `#N/A`/`#REF!` | 上年底稿自身是坏值 | 平台按空处理（不写进本年）；更早的版本要先升级 |
| 表2 认不到（上年数不链接、披露区空白） | 表2 表头是公式（`=J36`），文件没被 Excel 打开过就没有缓存值 | 平台按结构兜底；仍认不到会写 warning → **必须人工核表2** |

最小可用检查：`C.00 BKD` 有数据行、明细合计 ≈ `C.00 Lead` 表1 上年数、有 `C.00 Lead` 表2。三者不齐先修文件，别指望平台兜。

### 生成后先看这 6 个字段（就在 JSON 里）

| 字段 | 合格标准 |
|---|---|
| `ok` | `true`（**但不等于结果对**） |
| `main.rows` / `main.amount` | 与明细行数、合计自洽 |
| `main.stats` | `matched/newCount/missCount/byKey/byAcct` 能解释 |
| `main.derived.c02a` | `status` 正常；`fxSourceKind`/`fxAnnounceUrl` 有值说明取价成功 |
| `main.leadRows` | 必须是现场定位结果，退回默认行号说明模板结构变了 |
| `tasks[]` / `blockingTasks[]` | `blocking` 未结清 = 没做完 |

### 5 条不变量（必须全过）

```text
Σ BKD 折算人民币 == Lead 期末账面数合计
Lead 未审 == 账面 + 账表调整
Lead 审定 == 未审 + 调整
Lead TB Diff == 0（账面 / 审定 / 上期）
C.02a 末行勾稽 == 0
```

不平：输出「科目 / 预期 / 实际 / 可能原因」，**不许调平**。

### 必须用本机 Excel 真开一次

`Ctrl+Alt+F9` 全表重算，查三处：隐藏的 `上年 *` 页有无 `#REF!`/`#N/A`、C.02a 的图形对象在不在、Lead 的 Diff 是否 0。解析库能读回 ≠ 能用。

## 阶段4 · 核输出（证明「结果一样」）

**读**：本节 + `PBC/项目/输入清单.md`（该期的关键数）

```bat
程序\runtime\python\python.exe 程序\tools\wp_diff.py "PBC\项目\基线.xlsx" "<新底稿.xlsx>" --json diff.json
```

- 退出码 `0` = 逐格一致（公式 + 静态值 + 每表图片数）；`1` = 有差异（报告列到格）；`2` = 读不了。
- 「检查」页的生成时间/来源路径、绝对路径、版本号、`_xlfn.` 前缀会被自动抹平，不算差异。
- 只有缓存值不同、公式一致的，用 Excel 重算再比一次。

**三档"一样"，别混着说**：跑通 → 金额一致 → **逐格一致**。只有第三档能说「同样的结果」。

## 阶段5 · 结清任务卡并交付

`tasks[]` 每条都要有结论：已完成 / 无法完成 + 原因 / 非必需。

| id | 怎么结 |
|---|---|
| `c02a-fx-shot` | 看图在不在 `data/fx/pbc_YYYYMMDD.png`；补完**必须重新生成** |
| `c01b-statement` | 向客户要对账单，填 C.01b I 列 |
| `c02-recon` | 人工判断有无调节项（无对账单时不得自动下结论） |
| `c00b-equiv` / `c00b-restricted` | 人工判现金等价物范围 / 受限金额 |
| `exp-oar-bucket` | 读 `bkd_work/ai_tasks/oar_bucket_pending.json`，判定写 `bkd_work/oar_map_ai_result.json`，**重新生成** |
| `exp-table2-concl` | 读 `table2_pending.json`，结论写 `table2_concl_result.json`，**重新生成** |
| `exp-oar-reason` | 读 `oar_reason_pending.json`，文字写 `oar_concl_result.json`，**重新生成** |

**别只看 `warnings`**：生成结果里有 `aiTasks[]`（结构化待办）和 `deliverableReady`（能不能交付）。
`aiTasks[].status` 有四种：`pending`（还没写）/ `partial`（写了一半）/ `done`（够数了）/ `unknown`。
`deliverableReady=false` 即"文件生成了，但判断文字还没写"，不得宣称完成。
每条的 `readPath` 是要读的清单、`savePath` 是结果文件、`expectCount` 是应有条数（写完自己数一遍）。

### 交付件（≥4 样）

1. 底稿 xlsx（文件名带客户与资产负债表日）；
2. 生成时的 JSON（`warnings` / `tasks` / `stats` 是这次的口径证据）；
3. 汇率公告截图（若程序自动截）；
4. 一份说明：输入是什么、补过什么、哪些格还空着、谁签字；
5. 有基线的，附 `wp_diff` 报告。
