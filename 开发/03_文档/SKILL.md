# PTW 底稿平台 · 入口

> 你是**操作员**，不是开发者。不改 `程序/` 下任何代码，不改模板，不猜列名、不猜科目、不猜汇率。
> 平台只做确定性计算；判断类结论（账户性质、是否有调节项、现金等价物范围）**只起草，不拍板**。

## 三步

1. **读** `文档/00_总则.md`（约 170 行）。它是状态机：现在处在哪个阶段、该读哪份、完成判据是什么。
2. **核**版本与输入：平台版本必须等于本文件 `applies_to`；输入必须与 `<客户>_PBC/项目/指纹.json` 一致。
3. **跑** `程序\runtime\python\python.exe 程序\ptw.py --pretty cash ...`，按总则逐阶段的判据验收。
   跑完**先看 `aiTasks[]`**（不要只扫 `warnings`）：`status` 不是 `done` 的，
   按它给的 `readPath` → `savePath` 做完，**再重跑一次**；
   `deliverableReady=false` 就不算完成。

```bat
:: 起服务（页面方式）
启动PTW平台.bat

:: 命令行生成（AI 用这条，输出 JSON）
程序\runtime\python\python.exe 程序\ptw.py --data-dir "<客户数据目录>" --pretty cash ^
    --date 2026-09-30 --customer "客户全称" --te 550000 --sad 55000 ^
    --standard "中国企业会计准则" --currency "人民币" ^
    --prior "上年底稿.xlsx"
```

## 五条红线

1. 源数据只读；产物另存；**不改 `data/` 正式库**，验证一律用临时数据目录。
2. 未取得资料 → 留空标黄 + 进待确认清单，**绝不填 0**。
3. 差额必须解释；禁止 `+1`、`ROUND` 调平。
4. 判断类字段不替客户下结论；不自动判「无异常 / 无调节项」。
5. 版本对不上、指纹对不上、基线比对不过 —— **都不算完成**，如实报告。
