# PTW平台 · 离线审计看账与底稿工具

> 一个绿色免安装的本地看账工具：把几十个 Excel/CSV 账表丢进来，自动拼成一张千万行级的**序时账**和**科目余额表**，然后像查数据库一样查账。
> 全程不联网，数据只存在本机。

---

## 一、怎么启动

整个工具就是一个文件夹：根目录只有一个 `启动PTW平台.bat`，双击它就能用。

```
PTW平台\                        ← 放在硬盘任意位置（建议 D:\PTW平台，路径别带 # ）
├─ 启动PTW平台.bat              ← 双击这个，别的都不用点
├─ data\                       ← 数据目录（清洗后的 duckdb、规则、你导入的 excel 都在这里）
│   ├─ ledger.duckdb           ← 账套数据库（序时账 + 科目余额表）
│   ├─ uploads\                ← 用户导入的原始 excel/csv
│   ├─ exports\                ← 查账导出 / 备份 / 数据包
│   ├─ bkd_tpl\ bkd_out\ bkd_work\  ← 底稿生成（BKD）的模板与产出
│   └─ work\ logs\             ← 临时文件与日志
└─ 程序\                       ← 代码与运行时（一般不要动）
    ├─ server.py               ← 统一服务入口
    ├─ core\                   ← 共享数据层（账套、清洗、核对引擎）
    ├─ runtime\                ← 内置 Python（含 duckdb / openpyxl）
    ├─ web\                    ← 主前端（左侧导航由板块清单驱动）
    └─ modules\                ← 各板块（一个目录 = 一个板块，可整体替换）
        ├─ ingest\             ← 板块一「导入与清洗」
        │   └─ manifest.json   ← 板块声明（名称、排序、子项）
        ├─ analysis\           ← 板块二「查账与分析」
        └─ bkd\                ← 板块三「底稿生成」（独立页，自带 web\）
```

1. **双击 `启动PTW平台.bat`**。
2. 会弹出一个黑色命令行窗口，同时浏览器自动打开 `http://127.0.0.1:8787/`。
   - 这个黑窗口**不要关**，关了工具就停了。
   - 用完直接关窗口即可，数据会保留在 `data` 目录里，下次再启动还有。

> 首次运行 Windows 可能弹「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」即可。
> 如果 8787 端口被占用，程序会自动往后找 8788、8789…，以黑窗口里打印的地址为准。

### 板块与扩展

界面左侧导航按「板块」组织，当前三个：

1. **导入与清洗**（4 步）：导入数据 → 清洗与映射 → 合并与检查 → 分享导出。
   - 第 2 步「清洗与映射」页内两个页签：数据清洗 / 字段映射；
   - 第 3 步「合并与检查」页内两个页签：合并成表 / 数据检查。
2. **查账与分析**：SQL 查账、规则、导出。
3. **底稿生成**：底稿自动生成（直接读清洗后的科目余额表，零导入）。导航下三个子级：
   **货币资金**、**销管费用**、**固定资产（原长期资产）**。
   其中「银行存款『账面信息』表」一张卡片，可按账套自动填出官方《1.银行存款-账面模板》并下载（详见第 5 步后的「底稿生成」小节）。

每个板块是 `程序\modules\` 下的一个目录，由目录里的 `manifest.json` 声明：叫什么、排第几、有几个子项、是不是独立页。启动时服务自动扫描装配，**加一个新板块只需新建一个目录，不用改 `server.py` 和 `app.js`**（独立页型板块连 JS 都不用写）。更新某个板块时整体替换对应文件夹即可，互不影响。

## 二、操作流程（导入与清洗共 4 步）

### 第 1 步：导入数据

把 xlsx / csv 拖进虚线框，或者点击选择（可一次多选）。

- **压缩包（.zip）直接拖进来就行**：客户 ERP 常按账/按主体导出成 zip（如 `DMOL_xxx.zip` 里是明细账 xlsx），
  上传后服务端自动解开，包内每张表格当成一个待导入文件，路径照样显示（`DMOL_xxx.zip / 明细账 / xxx.xlsx`）。
  包里夹带的 `~$` 临时文件、readme.txt、docx、内层 zip 会单独列在「跳过」里说明原因。
  只有**平台数据包**（含 `manifest.json`）才会提示改用中间「导入数据包（zip）」入口。

- 文件是**边传边落盘**的，不进浏览器内存，几百 MB 的 csv 也就几秒。
- **格式按文件内容认，不按后缀认**：后缀写成 `.xls / .csv / .txt`、内容其实是网页表格的
  （ERP / 网银「导出 Excel」常见，特征是 Excel 打开乱码、改后缀成 `.html` 就正常），
  会自动解析并转成 Excel 工作表，待导入里标「网页表格 · 已转换」，一个 HTML 里多张表就拆成多个工作表。
- 每个工作表单独处理，不做任何清洗，**原样**存成一张"原始表"（全部按文本存，所以 `1001` 的前导零、`记-0001` 都不会丢）。
- 系统会自动猜表头在第几行、占几行，并高亮提示。猜得不对就改两个数字：
  - `表头行`：真正的列名在第几行（上面常有大标题行）
  - `占 行`：表头占几行。**两层表头填 2**（典型科目余额表：第一行"期初余额 / 本期发生额 / 期末余额"，第二行"借方 / 贷方"）
- 不确定就点「预览」，看前几十行原始内容，**点某一行**直接设为表头。

**待导入区按表头分组**：列名一样的表自动归到一张卡片里（列顺序不同也算同一套表头），所以

```
同表头 ×5   公司名称、科目、本年累计借方、本年累计贷方（4 列）   5 个文件 / 5 张表
            目标表 [科目余额表 ▾]   表头行 [1] 占 [1] 行   [导入这组（5 张）]
```

- **一组只选一次目标表**，一次导完组内所有表——十个分公司十张同格式余额表，不用点十遍。
- 卡片右上「明细」展开后能看到组内每个文件、每张表、大概多少行；单张也能「只导这张」或改自己的表头行。
- 判分组的依据是**列名指纹**（去掉空格、标点、全角半角差异后比对），所以「期初借方(本币)」和「期初借方（本币）」算同一种。
- 不想要某一组就点「移除这组」，不会影响其他组。

导入时可以先选「目标表」（序时账 / 科目余额表），也可以先不选，到第 2 步的「字段映射」再选。

**同一页下面还有「账簿对照表」**（可选，但一旦要做多主体的账就很有用）：

如果科目余额表 / 序时账里没有「公司名称」这一列（很多财务软件的导出模板里确实没有），就导入一份对照表：

| 账簿名称 | 公司名称 | 公司简称 |
|---|---|---|
| 张三公司2026年账 | 张三科技有限公司 | 张三 |
| 李四公司2026年账 | 李四贸易有限公司 | 李四 |

- 点「导入对照表」，选 xlsx / csv，系统会猜哪一列是账簿名称、公司名称、简称，猜错了手工改下拉。
- 导入是**追加/覆盖**：账簿名称相同的以最后一次为准。同一账簿名称在表里有俩不同公司名称时，会提示你。
- 之后在「字段映射」页给每张表指定「账簿名称」从哪来（某列 / 文件名 / 工作表名 / 手填），合并时会自动把公司名称和简称带到序时账和科目余额表里。
- 匹配不上的账簿名称会在合并结果里列出来——那通常是别名不一致（多了"2026年"、全角空格、全称 vs 简称）。

#### 1.0 导入失败/异常文件怎么处理

单个文件出问题不会中断整批，底部汇总会写「成功 N 个，失败 M 个」，并列出每个失败文件的原因。
三种情况分开报，别混为一谈：

| 情况 | 提示 | 怎么办 |
|---|---|---|
| **文件加密**（Excel 设了打开密码） | 「该文件已加密（需要密码），请在 Excel 里另存为不加密版本后重试」 | 让客户另存一份不加密的 xlsx。加密的 xlsx 底层不是 zip，以前会被误报成"文件已损坏" |
| **文件损坏**（下载不全、被截断、CRC 错） | 「无法解析：文件可能已损坏，或后缀与实际格式不符」 | 重新获取原文件；对照表/账表都要重导 |
| **某张工作表损坏**（文件能打开，但这张表有内容读不出单元格） | 待导入区顶部红色提示「N 张工作表疑似损坏」，不并入"空表已跳过" | 让客户重新导出这个文件。**千万别当成空表忽略**，那样数据会静悄悄少一块 |
| 真空表（封面页、模板页） | 「N 张空表已自动跳过」 | 不用管 |
| **压缩包**（客户 ERP 按账导出） | 自动解开，包内表格进待导入，其余列在「跳过」 | 不用管；内层 zip 需先解开再拖 |
| 压缩包已损坏 / 内层被加密 | 「压缩包已损坏，或不是 zip 格式」「已加密，无法解压」 | 重新获取原文件 |

导入数据包（zip）时，包内某个文件读不出来（损坏或被单独加密）只跳过那一个，其余照常导入，
结果里会写「包内有 N 个文件读取失败，其余已导入」并列出文件名。

#### 1.1 三类数据源

平台的标准表有三张，导入时给每张表选一个「目标表」：

| 目标表 | 内容 | 用来做什么 |
|---|---|---|
| 序时账 `journal` | 凭证分录：日期、凭证号、摘要、科目、借贷 | 数据检查、查账分析、TOD 抽样 |
| 科目余额表 `tb` | 科目级余额：期初 / 本期发生 / 期末 | 数据检查、BKD 上数、账户清单 |
| **银行流水 `flow`** | 银行账户交易明细：本方账号、对方账号、收付、余额 | **内部转账识别、截止性测试** |

银行流水和其他两张走的是同一套流程（导入 → 清洗 → 映射 → 合并），不需要另外装东西。
合并后会多拿一份「账户清单」做配对，判断每笔流水的对方是不是本公司账户。

### 第 2 步：清洗与映射

导航上是一步，页内两个页签：**数据清洗** 和 **字段映射**。先洗完再映射，顺序不要颠倒——映射是认列名的，列变了要重新映射。

#### 2.0 清洗达标标准（先看这一节）

这一页顶部常驻一块「清洗达标标准」横幅，把验收标准直接摆出来——因为清洗是整条链路的分水岭：
**洗过头的表现是删掉了真实数据，洗得不够的表现是留着父科目和汇总层**，两种错误在页面上
都只是「数字对不上」，看不出根因。

标准两句话：

- **科目余额表**：只留末级科目，没有父科目、没有合计/小计、也没有「核算维度=合计」的汇总行；
  银行存款必须带账号、往来科目必须带客商；一级科目已派生，编码和名称不为空。
- **序时账**：日期、凭证号、摘要、科目编码都不为空；借贷金额不能两边都空；一级科目已派生。

三个按钮：

| 按钮 | 作用 |
|---|---|
| **检查清洗达标** | 逐项判定并给出「改法」，结果标绿/红；只有阻塞项会否决整体结论 |
| **复制 AI 提示词** | 复制一段完整提示词，可直接粘给使用本平台的 AI，让它按标准洗、按格式输出结论 |
| 收起 | 把横幅折叠起来，腾出工作区高度 |

自检对应接口 `GET /api/clean/audit`，只读不改数据，合并前可以反复点。
它读的是**已合并的标准表**，所以第一次点会提示「还没有合并」——那是正常顺序：
先洗、再映射、合并、然后回来点自检，不达标再回去改。

提示词原文也存在 `03_文档/AI提示词_清洗达标.md`，可以直接分发给别的 AI。

#### 2.1 数据清洗

余额表从财务软件导出来，经常带着各种脏东西：合计行、分页重复的表头、页脚"制表人"、科目名称前的全角缩进空格、辅助核算明细单独占一行导致科目编码空着……这一步就是清这些。

- 左边选一张原始表，右上角有**内置配方**（通用余额表 / 辅助核算明细成行 / 单列辅助核算拆分 / 最轻清洗），一键套用后再按需改。
- 动作列表可以**上下移、单独关掉、删掉、再加**，常用的有：
  - **删空行（可按 N 列判空）**、按关键词删行（合计/小计/重复表头/页脚）、整行去重
  - 文本归一（去全角空格缩进）、编码补零
  - 向下填充（把科目编码/名称填满辅助核算明细行）
  - **填充固定值**（整列填同一个值，补「公司名称」「币种」这类全表统一的字段）
  - **提取一级科目**（见下）
  - **按编码派生一级科目**（见下，定长编码按前 N 位 + 自动补科目名称）
  - **生成一级科目**（见下，多级编码展开 + 按主体删非末级）
  - **生成唯一凭证号**（见下，公司名称-期间-凭证号，用于按整张凭证核对）
  - 科目级次推断、辅助核算拆分（`客户:A/部门:B` → 三列）
  - 勾稽校验（期初+借−贷=期末，只出报告不改数据）

**「提取一级科目」怎么用**：余额表常把编码和名称挤在一列——`1001-库存现金`、`1001 库存现金`、`管理费用/办公费`。

- 源列选那一列（通常是科目编码或"编码-名称"列），分隔符填 `-`（有几种就都写上，留空 = 默认一整套 `- _ / 空格 . : | 、`）。
- 系统取**第一个分隔符之前**那一段，生成新列（默认叫「一级科目」）：`1001-库存现金` → `1001`，`管理费用/办公费` → `管理费用`。
- 生成后到「字段映射」页把它映射到标准字段 **`acct_l1`（一级科目）**，第 3 步的数据检查就按它归集。核对**只认这一列**，余额表和序时账都要映射上。
- 适合编码列不规范、或者干脆没有编码列（只有"科目全名"）的余额表。

**「生成一级科目」怎么用**：当科目编码是多级点分结构（`1002` → `1002.01` → `1002.01.01`，总类→分类→明细）时，用它一次完成四件事：

1. **分列一级编码**：按分隔符取科目编码第一段，生成新列「一级编码」。
2. **填一级科目名**：每个「主体 + 一级编码」第一次出现（最靠上）那行的科目名称，向下填到同一组所有明细行，生成新列「一级科目」。
3. **拼科目全称**：从一级到本级逐级拼接各级科目名称，生成新列「科目全称」。拼接符默认 `_`，可改成 `-` `/` 等。
   - 例：`1002.01.01` 深圳平安银行南山支行 → 全称 `银行存款_银行明细_深圳平安银行南山支行`。
   - 如果某级名称本身已经是完整路径（含 `_` 这类分节符，例如 `其他业务收入_其他`），
     就直接用它、不再前置父名，避免拼成 `其他业务收入_其他业务收入_其他`。
4. **按主体删非末级行**：同一主体内，某行编码若被其它行的编码当作前缀（且更长），就是非末级。
   **但父行带着自己的金额时不能删**：
   - `560406 研发费用_测试费 136,446.45` = 1,941.13 + 134,505.32 → 纯汇总，删
   - `560406_BM00003 行政部 1,941.13` ≠ 子行 134,505.32 → 它自己还有金额，**保留**
   判断方式是比较父行金额与子行合计（叶子后代之和，或全部后代之和，任一吻合即视为纯汇总），
   容差由参数「父行残值容差」控制，默认 0.01 元。
   `1121` 下面没有 `1121.01` → 保留；`1002` 下面有 `1002.01` 且金额相等 → 删。

- 参数：科目编码列、科目名称列、**主体列**（账簿名称/公司名称那一列）、编码分隔符（默认 `.`）、全称拼接符（默认 `_`）。
- **主体列是关键**：多账簿/多公司混在一张表时，每个主体独立判断末级，A 公司的 `1121` 是末级、B 公司的 `1121` 下面还有 `1121.01`，互不误删。主体列留空会用不了这个动作（会提示未选主体列）。
- 被删的非末级行照常记入「被剔除的行」，留痕可查。
- 适合「科目编码本身带层级、且要做末级明细底稿」的余额表；和「提取一级科目」的区别是：那个只是取第一段、不删行、不拼全称，这个做的是完整展开。

**「按编码派生一级科目」怎么用**：科目编码是**定长、没有分隔符**的（`10020101`、`660201`、`1002302001`），
前两个动作都切不开（一个靠分隔符、一个靠点分），用这个。

- 选「科目编码列」；有「科目名称列」就一起选上，用来给标准表查不到的编码兜底取名。
- **一级编码位数**填 `0` = 自动推断：先看内置标准科目表能认出几位前缀（8 位明细码的前 4 位能命中 `1002`、`1122`，
  8 位本身命中不了，于是判成 4 位），再看数据里长短码是否并存。推不出会提示你手填（8 位明细码通常填 4）。
- 一次生成**两列**：「一级代码」（`1002`）和「一级科目」（`银行存款`）。到「字段映射」把 **一级科目** 映射到 `acct_l1`。
- 名称三级兜底：**内置标准科目表**（`程序/rules/std_accounts.json`，82 个常用一级科目）→ **本表里编码正好等于该前缀那一行**的名称
  → 都没有就只写编码。这一步会把「标准表命中 / 数据补名 / 按编码兜底」各多少行写在动作下方的说明里。
- 客户科目表和标准表不一样：在 `data/std_accounts.json` 放同名文件即可（`{"accounts": {"5501": "营业费用"}}`），
  同码覆盖、新码追加，**不用改代码**。改完重跑清洗即生效（预览就生效，不用重启）。
- **怎么知道该补哪些码**：看这一步动作下方的说明——「按编码兜底 N 行（如 5501、9999）」，
  括号里就是要补的码；补完再跑一次，兜底行数应降到 0。也可在查询页跑
  `select acct_l1, count(*) from tb where regexp_full_match(acct_l1,'[0-9]+') group by 1`。
- **这份表跟着客户走，别当成通用准则表**：同一个码在不同账套可能是不同科目（例：`4201` 在一家是
  盈余公积、在另一家是其他综合收益）。字典是全局的、不分公司，遇到这种冲突**不要填**，留编码人工确认，
  否则会有一家的底稿被静默改名。换客户就换这份文件。
- 只派生、不删行；要删父行请用「生成一级科目」。

**多账簿余额表必须开「核算维度明细优先」**

多账簿导出的结构是「所有账簿汇总 → 各账簿科目汇总 → 各账簿维度明细」，科目编码只写在最上面那层。
向下填充之后，同一科目下会同时有「科目汇总行（核算维度为空）」和「维度明细行」，
两者编码完全一样，只看编码分不出该删谁——这正是以前会丢明细、或者留着汇总行重复计数的地方。

| 参数 | 怎么填 |
|---|---|
| **核算维度列（可选）** | 选「核算维度名称」。任一列非空即视为明细行 |
| **有明细时只保留明细行** | **开**。有明细的科目只留明细、删掉汇总行；没有明细的科目仍保留一行，不会整个科目消失 |
| **分组列（可选）** | 多币种表把「币别」选上。否则「美元有明细」会把「欧元只有汇总」的行一起删掉 |

**操作顺序有讲究，顺序错了会得到 0 行：**

```
文本归一 → 全局向下填充（科目编码、科目名称，不要按账簿分区）
        → 按关键词删「所有账簿」层 → 生成一级科目（开明细优先）
```

- **必须全局向下填充**：科目编码只在「所有账簿」那一行，若按账簿分区填充，每个账簿内部起点就是空的。
- 顺序反过来（先删「所有账簿」再填充），编码已经没了、无值可填，整表会变成 0 行。
  平台会在这一步提示「本步把 N 行清成了 0 行」——看到这句先回来查顺序，不要以为是数据问题。
- 「所有账簿」层必须删掉，否则会和账簿明细重复计一次金额。

开着明细优先后，剔除原因会分三类记进「被剔除的行」：**非末级科目行 / 有明细的汇总行 / 无明细科目的同码重复行**。
哪一类数量明显不对，一眼就能看出来。若某科目的明细合计与原汇总行不一致，**不会自动调平**，
差额会在后面的余额平衡检查里暴露出来。


**「生成唯一凭证号」怎么用**：把「公司名称 + 会计期间 + 凭证号」拼成一列，得到能唯一定位一张凭证的主键。

- 为什么需要：多公司账套里各家的凭证号都从 `记-001` 重新编号。只按凭证号分组，会把甲公司的 `记-001` 和乙公司的 `记-001` 当成同一张凭证，借贷自然不平——这是假问题，白查。
- 参数：**公司名称列**（多公司必选；单公司账套可留空）、**会计期间列**（月份/所属期间，如 `2026-01`）、**凭证号列**、分隔符号（默认 `-`）、新列名（默认「唯一凭证号」）。
- 拼出来的样子：`甲公司-2026-01-记-001`。某一段为空时自动跳过该段，不会出现 `甲公司--记-001` 这种空档。
- 生成后到「字段映射」页把它映射到标准字段 **`voucher_key`（唯一凭证号）**，数据检查的「2.3 凭证平衡」就按它归集。
- 不生成也能查：数据检查时发现没有映射这一列，会现场按「公司名称+期间+凭证号」拼一个临时键并给出提示，结果一样；区别是没法在导出/查账里按这个键复用。
- **删空行的判空列可以多选**（勾选框，不是单选下拉）。勾 2 列以上就是"这 2 列都为空的才算空行"：
  - 只勾「科目编码、科目名称」→ 这两列都空才删，比"任意一列为空就删"安全得多，不会误删"摘要空但金额有值"的正常行。
  - 一个都不勾 = 所有列都为空才算空行。
  - 「判空方式」还能切成"所选列任一为空就删"，用于"科目编码必须填"这类硬性要求。
- 点**试运行**：只算不落库，直接告诉你每一步删了几行、前后各 20 行对照。
- 点**应用清洗**：结果写成"清洗表"，后面映射/合并用的就是它。
- **只想洗这一张**就点「应用清洗」；**全部配好了想一次洗完**，点旁边的「**全部清洗（N 表）**」——按每张表各自的配置逐张跑，跑完弹一个结果表，列出每张表洗前洗后行数和剔除了多少行。只算已启用的动作；没配动作的表会标「跳过」；某一张失败不影响其余表。
- **原始表一列都不会动**。被剔除的行全部记在案，「看被剔除的行」能看到是第几步、按什么规则剔除的。
- 想反悔就点「恢复到原始」。

**清洗方案会记进「方案库」**（页面右上角的下拉框）：

- 点「**应用清洗**」跑通一次，这套动作就自动登记成一个方案（名字取工作表名，同名不重复登记）。之后在右上角下拉框里选中 → 点「套用」，就能把这套动作原样套到另一张表上。
- 也可以在右上角点「**存为方案**」自己起名（比如「余额表-通用」），或者选中后「删除」。
- 套到一张列不一样的表时，表里不存在的列对应的动作会自动跳过并提示，不会整条流水线失败。

**方案还能导出成 xlsx 存档**（换版本、换机器、给同事）：

- 点「**导出清洗方案**」得到一个 xlsx：**一种清洗模式一个 sheet**，每行一个动作，参数压成一列 JSON；另带 `_说明`、`_方案清单`、`_映射`。
- **`_映射` 是按「表头」关联的，不是按文件名**——文件名每年都变（2025年余额表.xlsx → 2026年余额表.xlsx），表头不变。所以换一年的账，只要表头一样，映射备份照样认得。
  - 表头签名 = 列名去掉空格、标点、全角半角差异后排序取哈希。**列顺序不同也算同一套表头**（映射本身是按列名走的）。
  - `_映射` 里同时存了人眼能看的「表头摘要」和「表头(规范化)」原串，手改也看得懂。
- 点「**导入清洗方案**」选这个 xlsx，会列出里面所有方案，选一个套到当前工作表。**当前表头和文件里某份映射备份对上了**，底部会出现「同时套用字段映射」的勾选框（只对同名列生效）；对不上就不显示，只套清洗动作。
- **只导一次就够**：弹窗里「把文件里的 N 个方案存入方案库」默认勾着，点「套用」时文件里的**所有**方案（不止你选的那个）会一起进方案库。之后处理其它工作表，直接在右上角下拉框选中 → 点「套用」即可，**不用再导一遍这个文件**。
- 勾选框去掉也能用，只是方案不进库，下次还得重新导文件。
- sheet 名就是方案名，可以直接改成好认的名字；复制一个 sheet 改名就等于多存一个方案。
- 导入时会自动剔除系统不认识的动作、以及当前表里不存在的列，并告诉你剔了哪些，不会让整条流水线炸掉。

> 设计上清洗在映射**之前**：因为它会改变行结构（填值、删行、拆列），得先把结构弄稳，再对列做映射。

#### 2.2 字段映射

左边选一张原始表，右上角选它属于**序时账**还是**科目余额表**。选完系统会按列名自动匹配，比如"期初余额_借方"自动对上 `open_debit`。

- 一共 25 个（序时账）/ 37 个（科目余额表）标准字段，右侧下拉可以逐个人工改。
- 支持"借方"、"借方金额"、"借方发生额"这类同义列名；也支持"金额 + 借贷方向"的单列形式（会自动拆成借方/贷方）。
- **本币和外币金额在同一个列表里**，靠标签后缀区分：`期初借方(本币)` / `期初借方(外币)`。没有外币核算就整块留空，不影响合并；系统不做汇率折算。"币种"字段填 `USD` / `HKD` 这类原币代码。
- 改动**即时保存**，不用点保存按钮。
- 表头一样的多个文件，映射好一张后点「套用到 N 张同表头表」，一次搞定。

**账簿信息**（页面最上方一行）：决定「账簿名称」这个字段从哪来。

| 来源 | 适用场景 |
|---|---|
| 从某一列取 | 原表里本来就有"账簿名称/账套名称"列 |
| 用文件名 | 一个文件一本账，文件名就是账簿名（最常见） |
| 用工作表名 | 一个 Excel 里每个 sheet 一本账 |
| 手工填写 | 就一本账，直接填死 |

填了账簿名称，配合第 1 步的账簿对照表，合并时就会自动带出公司名称和公司简称。

**科目余额表的辅助核算**在页面下方单独一块，分三层：

| 层 | 是什么 | 怎么填 |
|---|---|---|
| 位置槽 `aux1/aux2/aux3` | 原样承接导出文件里的辅助核算列 | 对应原始列，1 列也行 3 列也行 |
| 类型 | 这一列装的是银行账号 / 客商 / 部门 / 项目 / 职员 / 存货 | 下拉选；一格多类型（`客户:A/部门:B`）选「混合」，系统按前缀自动分 |
| 语义列 `bank_account` 等 | 合并时从位置槽里抽出来的干净值 | 不用填，自动派生 |

全部不填也没关系：`aux1/2/3` 照样原样保留，还能用 `aux_text` 一列做全文模糊搜（`WHERE aux_text LIKE '%阿里%'`）。

### 第 3 步：合并与检查

同样是一步两个页签：**合并成表** 和 **数据检查**。合并产出标准表，检查校验标准表平不平、两表对不对得上。

#### 3.1 合并成表

点「生成标准表」，把映射到同一目标的所有原始表 UNION 成一张标准表。

- 重复点会整表重建，不会重复累加。
- 每行都带 `src`（来自哪个文件/工作表）和 `src_row`（原始行号），查账时能追回原表。
- 生成后可以看统计：行数、借贷合计、借贷差、日期范围、科目数。
- 如果第 1 步导入过账簿对照表、第 2 步的字段映射里指定过账簿名称，合并后会多一块「账簿对照匹配结果」：多少行匹配上、哪些账簿名称对不上。

**合并银行流水后多一步配对**：拿科目余额表里的货币资金账户生成「账户清单」，
逐行判断对方账号在不在清单里。结果写在 `is_internal` 一列，三态：

- `1` 内部划转（对方账号在清单内）
- `0` 对外收付（对方账号不在清单内）
- **空** 无法判定（本方账号没配上清单，或对方既无账号也无户名）

配不上的行会单独列出来，分四类给动作：本方账户未入清单 / 对方无账号无户名 /
对方只有户名 / 对方账号未命中清单。清单补全后点「重新配对」即可，**不用重导流水**。

#### 3.2 数据检查（五组平衡）

这一页回答五个问题，**五组互相独立**：某一组数据不具备条件，只让那一组报错，不影响其他组跑。

| 组 | 查什么 | 前提 |
|---|---|---|
| 一 | 科目余额表自己平不平 | 有余额表 |
| 二 | 序时账自己平不平 | 有序时账 |
| 三 | 两表按「公司 + 一级科目」对不对得上 | 两表 + 一级科目列 |
| 四 | 两表按「公司 + 科目全称」对不对得上 | 两表 + 科目全称（缺则用科目名称） |
| 五 | 货币资金有没有账户级明细，够不够做 BKD | 有余额表（有序时账更完整） |

##### 币别怎么分组（一、三、四组共用一套判定）

币别不能只看单行就分组——同一个「人民币」，在这个主体身上是本位币，在另一个主体身上可能是外币。所以先按**主体**看形态，再决定每行归哪一组：

| 主体的形态 | 怎么分 |
|---|---|
| 有「综合本位币」这类汇总行 | 本位币组取汇总行（本币列），其它币别各自成组比原币 |
| 没有汇总行、只有一种币别 | **整个主体并入本位币组**（比本币列），不再单独开一个币别组 |
| 没有汇总行、有多种币别 | 本位币组取本币列合计，各币别另成原币组 |

> **V1.2.96 起：第一行那种情况在清洗阶段就没了。** 余额表的「综合本位币」行与
> 「人民币」「美元」这些具体币别行是同一批钱的两个视图，两份都算会翻倍（瑞云实测
> 14.23 亿 → 28.46 亿），而且这一行**看不出具体币别**，对原币核对没有任何用处。
> 所以清洗预设里多了一步「删除综合本位币行」，删完下游就不用每处再判一次。
> 保护：如果整张表都是汇总行（客户只导出了汇总视图），这一步自动跳过，不会把表清空。

三条规则都是为了让两边用同一个口径。**最常见的坑**：单币种系统的余额表把币别写成「人民币」，而序时账的币别列是空的——如果不归并，余额表出「人民币」组、序时账出「本位币（合计）」组，两边永远对不上，会成批报「仅序时账有」，看着像几百个科目都错了，其实一笔都不差。

另外两条：

- **外币组按「主体 × 币别」开，不是按全表币别**。甲公司有美元、乙公司没有，就不会给乙公司造一个空的美元组。
- **外币组要两边都给得出原币**。余额表没有原币列、或序时账没有原币金额，就只比本币合计，并在页面提示「外币组已跳过，共 N 行外币」。否则会吐出一整片「仅余额表有」，把真正的问题淹掉。

**共同的分组键 = 公司名称**：有公司名称用公司名称，没有用账簿名称，两者都没有归到「(未标注主体)」（单主体账套等价于全表合计，不受影响）。
为什么按公司分组：多公司/多账簿混在一套数据里时，只按科目合计出问题只看到「1001 差 8 万」，根本不知道是哪家公司。

##### 一、科目余额表 · 借贷发生额与余额平衡

按「公司 × 币别」逐组查，**本位币组**和**各外币组**分别验：

| 组 | 判什么 |
|---|---|
| 本位币（合计） | 本期借 = 贷、本年累计借 = 贷、期初+本期借−本期贷 = 期末 |
| 外币（美元/欧元…） | 只验「期初+本期借−本期贷 = 期末」，**不验借贷相等** |

- 为什么外币组不验借贷相等：一张凭证可以借美元、贷人民币，单个币别的借贷发生额本来就不等，本位币折算后才平。
- 表里本币列（期初/本期借/本期贷/期末/勾稽差）和原币列**并列**，还有一列「币别」，一眼能看出哪个币种出问题。
- 本位币组行：原币列空；外币组行：本币列空。这是按币别分行展示的必然结果，不是缺数据。
- 期初净额 = `open_bal`，没有就用 `open_debit − open_credit`；期末同理。原币用对应的 `_fx` 列。
- 余额表缺期初或期末列时，勾稽那条自动跳过并在页面上提示。
- 余额表没有原币列时，只出本位币组，并提示「本次只核本币」。

##### 二、序时账 · 借贷平衡（三层）

2.1 **总额平衡**：该公司全部期间的借方合计 = 贷方合计
2.2 **月平衡**：每个会计期间借方 = 贷方。月度不平往往是跨月串账、期末结转漏做
2.3 **凭证平衡**：每张凭证借方 = 贷方。这是最深一层，能直接定位到「哪一张凭证做错了」

- 凭证的唯一性靠**「唯一凭证号」**（`voucher_key`）：在清洗里用「生成唯一凭证号」拼出 `公司-期间-凭证号`，再映射到「唯一凭证号」。
- 没有映射这一列也能跑：系统会现场按「公司名称 + 期间 + 凭证号」拼一个临时键，并在提示里说明。不生成的区别只是没法在导出/查账里复用这个键。
- 2.3 只列出**借贷不平的凭证**（平的是绝大多数，列出来没意义），小标题会写明「N 张凭证，其中不平 M 张」。

##### 三、科目余额表 × 序时账 · 按「公司 + 一级科目」

口径：余额表取你选的那一对发生额（默认本年累计本币），序时账取借贷在期间内求和，逐项比。

**按币别分两层**，一张表里同时给本币列和原币列，另有「币别」列：

- `本位币（合计）` 行：余额表取 `综合本位币` 的行、序时账取全部行，比**本币**金额；
  （V1.2.96 起清洗已删除汇总行，这一行改由「人民币 + 空币别」的行合成；若你用的还是
  老方案没带那一步，仍按汇总行取，行为不变）
- `美元(USD)`、`欧元(EUR)`… 行：两边都只取该币别，比**原币**金额。

- **一级科目取「一级科目」列**（`acct_l1`）：清洗里用「提取一级科目」从**科目名称**按 `_` 拆第一段（`应付账款_结算应付_材料款` → `应付账款`），
  或原表自带，或者**定长编码用「按编码派生一级科目」按前 N 位切**（位数可自动推断）。
- 余额表和序时账两边都必须映射上、且都有值，否则这一组直接报错，提示回去补齐。
- **零金额单边算「一致」**：余额表每个科目×币别都有一行（金额可能是 0），序时账只有实际发生的科目，两边都 0 的判一致，不刷屏。
- 明细第一列是「主体」，同一科目在不同公司和不同币别分别成行；上方还有**按公司汇总**（科目数 / 一致 / 不符 / 单边 / 净额差异），对不上时先看这张。

**余额表口径**（下拉框）：`本年累计(本币)`（默认）/ `本期发生(本币)` / `期初(本币)` / `期末(本币)`，决定余额表取哪一对**本币**借/贷列：

| 口径 | 借方列（本币） | 贷方列（本币） |
|---|---|---|
| 本年累计（默认） | `ytd_debit` | `ytd_credit` |
| 本期发生 | `cur_debit` | `cur_credit` |
| 期初 | `open_debit` | `open_credit` |
| 期末 | `end_debit` | `end_credit` |

原币列自动跟 `_fx` 后缀；序时账始终是 `debit` / `credit`（及 `debit_fx` / `credit_fx`）。余额表没有所选口径的两列会报错，提示换口径或补映射。

##### 四、科目余额表 × 序时账 · 按「公司 + 科目全称」

第三组只到「银行存款」这一层，真出问题往往在「银行存款_工行」这种末级。第四组把粒度降到最后一级。

- 键优先取 **`acct_full`（科目全称）**：清洗里「生成一级科目」会产出「科目全称」列（如 `银行存款_银行明细_工行`），映射到「科目全称」即可。
- 两边都有全称才按全称比；有一边缺，退到 **`acct_name`（科目名称）** 并明确提示「本次按科目名称核对」。
- 余额表有全称、序时账没有（或反过来）时，两边口径不一致会产生大量单边，看到满屏「仅余额表有」先检查这里。

**期间过滤**：`从` ~ `到`（如 `2026-01` ~ `2026-12`）只作用于**第三、四组对账**。第一、二组是自平衡，永远看全量数据。

**看结果**

- 顶部「检查结论」：检查项 / 通过 / 有问题 / 问题合计。点任意一行直接跳到那组明细。
- 每组卡片右上角标签：绿「通过」/ 红「N 项待查」/ 红「无法检查」（附解决办法）。
- 「只看有问题的」默认勾着。**该组本来就全部平衡时不过滤**，会显示全量（否则会显示成一张空表）。
- 差额口径统一是 **余额表 − 序时账**，红色数字就是超过容差的那一列。
- 「**导出 Excel**」：一个工作簿多张工作表——`结论汇总` + 每组一张明细（2.1/2.2/2.3 各一张），表头中文、数字保持数值型，可直接进底稿。
- 明细超过 500 行时页面只渲染前 500 行，完整数据在导出的 Excel 里。

**对不上怎么查**（按出现频率）：

| 现象 | 常见原因 |
|---|---|
| 第一组「本期发生额不平」 | 余额表里父级行和明细行同时存在（`1002` 和 `1002.01` 都在），发生额被算了两遍 → 清洗里加「生成一级科目」按主体删非末级 |
| 第一组「余额勾稽不平」 | 期初+借−贷与期末对不上，通常是期初列或期末列的映射错了（借/贷列选反） |
| 第二组总额平、凭证平，但第三组全军覆没 | 余额表口径选错了（表里只有本期发生额却选了默认「本年累计」），或所选口径的两列没映射上 |
| 第二组只有个别凭证不平 | 真实问题：那张凭证做错了。按「唯一凭证号」去找原始凭证 |
| 第二组月月都不平、总额却平 | 跨期过账：凭证日期和会计期间不一致，或期末结转记到了下月 |
| 第三组某几个科目差固定金额 | 序时账漏记/多记凭证；或该科目有明细级科目没导进来 |
| 第三组大量「仅余额表有」 | 科目在一边存在、另一边没有（新设科目、已清理科目、下挂明细后一级行被删） |
| 第四组满屏单边，第三组却正常 | 科目全称两边口径不一致（一边是全路径、一边是末级名称），回清洗统一用「生成一级科目」 |
| 所有组主体只有一个「(未标注主体)」 | 公司名称和账簿名称都没映射 → 多公司账混在一起算了，先补映射或导入账簿对照表 |
| 第一组本来就该不平（有损益结转） | 结转损益后收入/成本类科目发生额单边，看本年累计差额是否等于结转金额 |

**按列值删行**（数据检查页下方）：对已合并的标准表**直接删行**，用于剔除不需要的科目或记录（比如把某个不纳入核对的辅助科目、某家已处置的子公司整段删掉）。

- 选「表」（序时账 journal / 科目余额表 tb）→ 每行选「判断列」（下拉里是中文名）→ 选条件 → 填值。
- 条件可以**一条条加**（「＋ 添加条件」），**多条之间是「且」**。例：
  `公司名称 等于「1A公司(100)」` ＋ `科目名称 等于「银行存款」` → 只删同时满足的行，其他公司的银行存款不受影响。
- 条件类型：

  | 条件 | 含义 |
  |---|---|
  | 等于 | 忽略首尾空格和大小写的精确匹配 |
  | 包含 | 子串匹配。`%` `_` 按**字面**处理，不当通配符 |
  | 不等于 | 留下等于该值的行，其余全删（**含该列为空的行**） |
  | 为空 / 不为空 | 不用填值，按该列有没有内容判断 |

- 点「删除匹配行」时**先试算**：弹窗会写「将删除 N 行（当前 M 行）」、列出每条条件和即将被删的前几行，确认后才真正执行。**试算计出的 N 和实际删的行数一定相等。**
- 删除**直接生效、不可撤销**，执行前会把整张表快照备份到 work 目录（`_delbak_*.parquet`），误删可找回来。
- 删完如果整张表变 0 行，会额外提示「这张表已被删空」，多半是条件写宽了。
- 这是唯一能改动「数据包导入成品」的手段——数据包导入后没法回清洗/映射改，若要微调数据就用这里。

#### 查账与分析：查账分析

左边是规则库，14 条常用规则，按"序时账 / 科目余额表 / 交叉核对"分类。选中一条：

- **表单模式**：填参数（科目前缀、金额阈值、关键词…），点「运行」。
- **SQL 模式**：直接看/改这条规则的 SQL，改完运行不影响原规则；想留下来就点「保存为规则」。
- 结果可以导出 CSV（带 BOM，Excel 直接打开不乱码）或 Excel。
- **导出的表头自动换成中文**：库里存的是 `acct_code` / `end_debit` 这类英文标准名，导出的文件里会变成「科目编码」「期末借方」。手写 SQL 里自己起的别名（`AS 我的编码`）不会被改，原样带出。这样导出的 CSV 直接发给同事、或者再导回本工具，都能被自动识别上字段。
- 「自由 SQL」可以写任意查询，同样支持导出。

数据量大也不怕：1000 万行做科目汇总、日期区间筛选、凭证平衡检查，通常在 **100 毫秒以内**出结果。

#### WP初稿生成：货币资金 / 销管费用

进「三、WP初稿生成」板块（独立页），导航下分两个子级：**货币资金**、**销管费用**。
页面按能力分两区：**工具能力**（机械规则，不需要判断）与 **AI 能力**（需要判断，工具只负责备料）。

**工具能力**

- **本年 Lead + C.00 BKD**：直接读清洗后的 `tb` 表，取 1001/1002/1012，按
  「主体 × 银行 × 账号 × 币种」写进 C.00 BKD 明细，Lead 用 SUMIF 打链接。
  - 列位、表头行、合计行**全部按表头文字定位**，不写死列字母——本地 V7 模板是 B~L 十一列，
    客户实际底稿可能是 A~M 再加班 P，两种都能跑。
  - **取不到资料一律标黄 FFFF00 并进「待确认清单」**：性质、是否函证（职业判断）、
    银行名/账号（源表没有）、上期数。零余额账户照样保留，不按非零过滤。
- **费用 VC/VD BKD**：序时账按「账簿 × 科目编码」汇总，**先剔除「结转本期损益」类贷方再算**
  ——不剔除的话月末结转会把每个费用科目冲平，全部算成 0。B 列填映射后的公司名，
  原始账簿在检查表「账套映射」里可追溯。需先上传「账簿↔公司」对照表，否则 B 列整列标黄。
  - 最右侧多一列 **OAR 口径**（薪酬 / 折旧摊销 / 广告费 / 单列大额 / 其他）。
    单列门槛是「该科目**合计** ≥ 100 万（约 2×TE）」，按合计判不按单行——中介费 1,304 万
    拆到 8 个账簿每行 160 万，逐行判会全落进「其他」。
  - 「进一步调查基于波动幅度？」按行补公式；没有上期数时退回「本期金额是否达阈值」，
    不会出 `#VALUE!`。
- **费用上年数（K 列上期审定数）**：第 2 步上传上年度的 VC/VD 底稿（要有「上期审定数」列），
  工具按「账簿 + 科目名称」回填，账簿名变了会自动退回只按科目名匹配。
  匹配不上的留空并进待确认清单，理由会区分「未提供上年费用底稿」和「上年底稿里没匹配到」。
  - **不传也能生成**，但 K 列全空、变动额/变动率算不出来，OAR 只能按本期金额判。
  - CLI 等价：`ptw.py exp --prior 上年度费用底稿.xlsx --te 550000`
- **费用 OAR**：销售费用、管理费用**分两块**，各自按 OAR 口径汇总（SUMIF 引用 BKD 的 R 列 + J 列）。
  分析段是一句一段的叙述（金额、变动、变动率、占比、主要构成都写在句子里），不是表格。
  - 挑分析对象：`|变动额| ≥ max(SAD, TE×50%)` **且** `|变动率| ≥ 10%`，按 |Δ| 降序。
    只看金额会出现「变动 0.3% 也写一段分析」；只看率会让小科目翻倍挤掉大额变动。
  - TE 写在 Lead C4（默认 55 万，界面第 3 步可改），SAD 默认 TE×10%，
    **波动幅度 C22 = TE×50%** —— 这个不写，整张表的「进一步调查」会恒为「是」。
  - **分析段由工具直接成文**：先按业务性质归类（市场投放 / 人力成本 / 中介与专业服务 /
    股份支付 / 折旧摊销 / 技术服务 等 10 类），再写集中度与规模方向，例如
    「本期全部为市场投放，其中「某公司」一项占六成左右；整体规模较上期明显收缩。」
    不再逐笔罗列公司名＋金额（明细在 BKD 的 R 列与导出的 evidence JSON 里）。
  - **写出来就不标黄**；只有序时账里找不到可归类证据时才留「【待AI撰写：…】」并标黄。
    `ptw.py oar-fill` 可覆盖工具写的描述，只换文字、公式保留。
  - 注意：描述里的「六成左右」「明显收缩」是**生成时快照**，金额/比例是公式会跟着变，
    区间词不会。数据大改请重新生成，别手改。
  - 「为什么」仍是审计判断，工具只写「是什么」，不编原因。
**AI 能力**

- **上年 WP → 上年数**：上年底稿每个项目的 sheet 名与列位都不一样，工具先导「结构探测包」
  （每个 sheet 的行列数、表头匹配分、前 12 行样张），交给 AI 判断哪张是 BKD 明细、表头在第几行；
  AI 回一个 `{sheet, header_row}` 再按它解析。判断规则见`文档/10_费用.md`（§10 截止性测试）与 `文档/09_货币资金_C03.md`。
> 模板在 `data/bkd_tpl/`：`C SWP 货币资金 模板 V7.xlsx`、`U_exp SWP VC&VD 模板.xlsx`。
> 模板改版直接替换同名文件；列位变了代码会按表头重新识别。

#### WP初稿生成：固定资产（长期资产）

导航下第三个子级 **固定资产**，四步：读取余额表与序时账 → 类别与口径核对 → 关键信息 → 一键生成。
只做**固定资产**（1601 原值 / 1602 累计折旧 / 1603 减值准备）；在建工程、无形资产、
长期待摊、使用权资产这一版不做。

**V1.2.98 起不再需要资产台账。** 旧版要客户另给 FA list（期末/期初）、再上传分类对照表，
两个文件任一缺失就出不来。现在数据全部来自「一、导入与清洗」已经合并好的
**科目余额表 + 序时账**：期初取 TB、变动取序时账，期末 = 期初 + 变动，两边必须勾稽。

**前置数据（只有两样）**

1. 科目余额表（含 1601/1602/1603，且带类别辅助核算，如 `ZCLB02_SYS/机器设备`）
2. 序时账（固定资产相关凭证）
3. 模板 `K1 SWP 固定资产 202YMMDD XYZ公司.xlsx` 随包内置，**不用上传、也不用替换**

**类别从哪来**：TB 与序时账的辅助核算**并集**，并互校。只出现在序时账的类别会直接拦住
（年初来自 TB、变动来自序时账，口径分叉时期末必然对不上，而表面只是「差异若干元」）；
只出现在 TB 的只提示——本期一笔业务都没有（不提折旧、不购置、不处置）是正常业务。

**行与列都由数据决定**：表1 的变动行跟着清单的「新增方式 / 处置方式」走（瑞云长出
「改造转入」「转固冲回」两行）；类别列块跟着实际类别数走（4 类就只出 4 块、多余空块删掉；
8 类以上自动插列；超过 12 类会明确报错让你合并）。表2/表3 的行数与类别数对齐。

**口径**：原值 / 累计折旧 / 减值准备在底稿里**都记正数**，净值 = 原值 − 折旧 − 减值
（与旧 K1_100Breakdown 的「折旧记负、三者相加」相反）。CHECK 与 TB 核对块不平会当场拦下，
不调平。

> 输出 17 张 sheet：K.01（表1~表4）、K.00 Lead、FA list、新增清单、处置清单，
> 外加三张**隐藏**的辅助页（上年 K.01、上年 Lead、TB 固定资产），右键取消隐藏可查来源。
> 资产编码、使用部门、折旧年限是按凭证摘要重建的，页首有红字说明，**不可作为审计证据**。

**命令行等价写法**：

```bat
ptw.py --data-dir data asset --date 2026-09-30 --customer 客户名
```

| `qty` / `price` / `currency` | 数量 / 单价 / 币种 | — |

| `dept` / `counterparty` | 部门 / 往来单位 | 文本 |
| `person` / `checker` / `poster` / `attach` | 制单 / 审核 / 过账 / 附单据数 | 文本 |

共 **25 个**字段（含一级科目、原币借贷、账簿名称、公司名称与简称）。

### 科目余额表 `tb`

**本币金额**（记账本位币，一般是人民币）：

| 字段 | 含义 |
|---|---|
| `open_debit` `open_credit` `open_bal` | 期初借方 / 期初贷方 / 期初余额净额 |
| `cur_debit` `cur_credit` | 本期借方发生 / 本期贷方发生 |
| `ytd_debit` `ytd_credit` | 本年累计借方 / 本年累计贷方 |
| `end_debit` `end_credit` `end_bal` | 期末借方 / 期末贷方 / 期末余额净额 |

**外币金额**（原币，`_fx` 后缀，和上面 10 个一一对应，全部选填）：

`open_debit_fx` `open_credit_fx` `open_bal_fx`
`cur_debit_fx` `cur_credit_fx`
`ytd_debit_fx` `ytd_credit_fx`
`end_debit_fx` `end_credit_fx` `end_bal_fx`

**科目信息**：`company_name`（公司名称）`book_name`（账簿名称）`short_name`（公司简称）`acct_code` `acct_name` `acct_l1`（一级科目）`level`（科目级次）`currency`（币种）`direction`（余额方向）

共 **37 个**标准字段（18 个科目/主体/本币信息 + 10 个外币 + 9 个辅助核算）。

> **公司名称 / 币种 / 本年累计借贷都是必备字段**。余额表导出时这些往往不是"一列数据"（抬头写着"XX公司 2026年10月"、整份表都是人民币），而是一行一个值也没有。这种情况用清洗里的「填充固定值」新增一列（列名就叫 `公司名称` / `币种`，取值填公司名 / 人民币），再回映射页对上即可；如果有账簿对照表，把「账簿名称」指到文件名/工作表名，公司名称和简称会自动带出来。

> **本币和外币是两套独立数值，系统不做汇率折算。** 有外币核算的科目（外币银行户、境外往来），本币列放人民币金额、外币列放原币金额，`currency` 放 `USD` / `HKD` 之类。没有外币核算就整块留空，不影响合并。自动匹配靠列名里的「外币 / 原币 / 外汇 / 美元 / 港币」等字样区分——`期初借方(本币)` 进 `open_debit`，`期初借方(原币)` 进 `open_debit_fx`，不会串。

辅助核算部分：

| 字段 | 含义 |
|---|---|
| `aux1` `aux2` `aux3` | 位置槽，原始辅助核算文本，原样保留 |
| `bank_account` | 银行账号/账户 |
| `counterparty_name` | 客商（客户/供应商/往来单位） |
| `dept_name` `project_name` `person_name` `item_name` | 部门 / 项目 / 职员 / 存货 |
| `aux_text` | `aux1|aux2|aux3` 拼接，用于全文模糊搜 |

> `open_bal` / `end_bal` 没映射时，会自动按 `借方 − 贷方` 算净额；外币的 `open_bal_fx` / `end_bal_fx` 同理。
> 语义列由「位置槽 + 类型」自动派生：类型选「客商」，这一列里 `客户:阿里巴巴` 就取到 `阿里巴巴`；选「混合」，则按 `客户:/部门:/银行:` 前缀分发到各自语义列。

## 四、SQL 速查

> SQL 里一律用下面这些英文列名；**导出的文件会自动换成中文表头**，不用自己写 `AS 科目编码`。

```sql
-- 某科目全部逐笔
SELECT vdate, vno, summary, debit, credit FROM journal
WHERE acct_code LIKE '1002%' ORDER BY vdate LIMIT 500;

-- 按摘要关键词找
SELECT vdate, vno, summary, acct_code, debit FROM journal
WHERE summary LIKE '%咨询服务%';

-- 凭证借贷不平
SELECT period, vno, sum(debit)-sum(credit) AS d FROM journal
GROUP BY 1,2 HAVING abs(d) > 0.005;

-- 期末余额最大的科目
SELECT acct_code, acct_name, end_bal FROM tb
ORDER BY abs(coalesce(end_bal,0)) DESC LIMIT 20;

-- 按客商看期末余额（辅助核算语义列）
SELECT counterparty_name, sum(coalesce(end_bal,0)) AS 余额
FROM tb WHERE counterparty_name IS NOT NULL GROUP BY 1 ORDER BY 2 DESC;

-- 按银行账号找（存款科目）
SELECT acct_code, acct_name, bank_account, end_bal FROM tb
WHERE bank_account IS NOT NULL;

-- 辅助核算全文模糊搜
SELECT acct_code, acct_name, aux_text, end_bal FROM tb
WHERE aux_text LIKE '%阿里巴巴%';

-- 按公司 / 币种汇总（多套账、外币科目用）
SELECT company_name, currency, count(*) AS 科目数,
       sum(coalesce(end_debit,0)) AS 期末借方, sum(coalesce(end_credit,0)) AS 期末贷方
FROM tb GROUP BY 1,2 ORDER BY 1,2;

-- 本年累计发生额（发生额 = 借 + 贷，净额 = 借 − 贷）
SELECT acct_code, acct_name,
       coalesce(ytd_debit,0) + coalesce(ytd_credit,0) AS 本年累计发生额,
       coalesce(ytd_debit,0) - coalesce(ytd_credit,0) AS 本年累计净额
FROM tb WHERE coalesce(ytd_debit,0) + coalesce(ytd_credit,0) <> 0
ORDER BY 3 DESC LIMIT 50;

-- 外币科目：原币 vs 本币（隐含汇率 = 本币 / 原币，查异常折算用）
SELECT acct_code, acct_name, currency,
       end_bal_fx AS 期末原币, end_bal AS 期末本币,
       round(coalesce(end_bal,0) / nullif(end_bal_fx,0), 4) AS 隐含汇率
FROM tb WHERE coalesce(end_bal_fx,0) <> 0
ORDER BY abs(coalesce(end_bal,0)) DESC;

-- 外币发生额汇总（按币种）
SELECT currency, sum(coalesce(cur_debit_fx,0)) AS 原币借方,
       sum(coalesce(cur_credit_fx,0)) AS 原币贷方,
       sum(coalesce(cur_debit,0)) AS 本币借方,
       sum(coalesce(cur_credit,0)) AS 本币贷方
FROM tb WHERE coalesce(cur_debit_fx,0) + coalesce(cur_credit_fx,0) <> 0
GROUP BY 1 ORDER BY 1;

-- 某科目三栏式明细账（带累计）
SELECT vdate, vno, summary, debit, credit,
       sum(coalesce(debit,0)-coalesce(credit,0))
         OVER (PARTITION BY acct_code ORDER BY vdate, src_row
               ROWS UNBOUNDED PRECEDING) AS 累计
FROM journal WHERE acct_code LIKE '1122%' ORDER BY vdate;
```

规则里可以用 `{{参数名}}` 占位，**参数按原文替换**：文本参数请自己带引号，例如 `LIKE '%{{kw}}%'`；数字参数直接写 `> {{amt}}`。

## 五、常见问题

**日期显示成 45658 之类的数字？**
那是 Excel 的日期序列号。系统在合并时已经自动转换（45658 → 2025-01-01），标准表里的 `vdate` 一定是 DATE 类型；只有"原始表"里仍是原始文本。

**科目编码的前导零丢了？**
不会丢。原始表全部按文本存，合并时 `acct_code` 也是文本。除非源文件本身已经被 Excel 转成数字。

**金额带千分位、全角负号、括号负数？**
转换时会自动处理：`1,234.56` → 1234.56，`(1,000.00)` → −1000，`￥1,200` → 1200。

**导入很慢？**
xlsx 解析比 csv 慢，百万行大约 20–60 秒，几十个文件串行导入要耐心一点（有进度提示）。同样的数据存成 csv 会快好几倍——如果源系统能导出 csv，优先用 csv。

**清洗把该留的行删了怎么办？**
不用猜。点「看被剔除的行」，每一条都标了第几步、什么原因（空行 / 合计行 / 重复表头 / 页脚 / 整行重复），原始行号也在。确认删错了就把那个动作关掉、重新应用，或者「恢复到原始」从头来。

**辅助核算拆不开 / 拆错了？**
看两点：①「辅助核算拆分」动作里的分隔符是不是你文件里真正用的（`/`、`、`、`；`）；②映射页里那一列的类型有没有选对。一格多类型的选「混合」，系统会按 `客户:` `部门:` `银行:` 这些前缀分发，不会把整格塞进所有语义列。

**核对报"需要一级科目列 / 两边都要有值"？**
第三组只认「一级科目」这一列。先在第 2 步「清洗与映射 → 数据清洗」里，对科目余额表和序时账**各加一步「提取一级科目」**（选编码/名称列 + 分隔符），再到同一步的「字段映射」把两张表各自生成的那一列都映射到「一级科目」，两边都映射好再回来核对。
如果只是想看两表对不对得上、不想拆一级科目，可以看第四组（按科目全称）——它用 `acct_full`，缺了就退到 `acct_name`，不强制要求一级科目。

**凭证平衡提示"没有映射唯一凭证号"？**
不是错误，是提示系统临时按「公司名称+期间+凭证号」拼了键。想固定下来：清洗里加「生成唯一凭证号」→ 字段映射里把这列映射到「唯一凭证号」。单公司账套不映射也没问题。

**核对时余额表是 0，序时账有数？**
大概率「本年累计借方/贷方」没映射上。到字段映射页看 `ytd_debit` / `ytd_credit` 是否是"未映射"，余额表里那两列通常叫"本年累计借方发生额"。如果源表确实没有本年累计，可以改成核对"本期发生额"：导出一份临时视图，或者先在清洗阶段补齐。

**账簿名称匹配不上对照表？**
99% 是别名不一致：多了"2026年账"、全角空格、简称对全称。合并结果里会把对不上的账簿名称列出来，照着在对照表里补一条同名记录即可。系统匹配时会先 trim 掉首尾空格。

**清洗方案换版本后能直接用吗？**
能。导出的 xlsx 里动作名、参数都是稳定的类型标识，导入时如果某个动作类型在新版本里不存在，会跳过并告诉你，不会整条流水线失败。列名对不上的动作也会自动剔除并列出来。

**机器内存要多大？**
DuckDB 会把中间结果溢写到硬盘，8GB 内存跑千万行没问题；跑几十亿行才需要更大内存。硬盘留足 3–5 倍原始数据的空间（库文件 + 临时文件）。

**能不能多人同时用？**
当前版本是单机模式（服务只监听 127.0.0.1）。多人协作用「导出数据包」分发。如果确实需要局域网共享，把 `server.py` 里 `ThreadingHTTPServer(("127.0.0.1", port)` 改成 `0.0.0.0`，别人访问 `http://你的内网IP:8787` 即可（注意公司网络策略）。

**数据存在哪？**
`程序\data\ledger.duckdb`（数据库）、`程序\data\uploads`（原始上传文件）、`程序\data\exports`（导出结果）、`程序\data\rules.json`（规则库）。
要彻底重置就关掉窗口，删掉整个 `程序\data` 目录，下次启动会自动重建。

**规则怎么改？**
两种方式：界面里 SQL 模式改完「保存为规则」；或者直接编辑 `程序\data\rules.json`（结构：`{rules:[{id,cat,name,desc,params:[{key,label,type,default}],sql}]}`），改完刷新页面即可。

```
PTW平台（文件夹名 01_PTW框架）\
├─ 启动PTW平台.bat        ← 唯一的启动入口，双击它
├─ data\                 ← 运行时数据（账套、上传、导出、规则），换机器可只拷这一个

   ├─ server.py          ← 本地服务（仅标准库 + duckdb），板块自动装配
   ├─ core\              ← 数据层：导入/清洗/映射/合并/核对/查询
   │   ├─ clean.py       ← 清洗流水线引擎
   │   ├─ fields.py      ← 标准字段字典与列名自动匹配
   │   ├─ db.py          ← DuckDB 数据层（导入/合并/核对/导出/分享）
   │   ├─ recon.py       ← 一级科目发生额核对引擎
   │   └─ recipe.py      ← 清洗方案 xlsx 读写
   ├─ web\               ← 前端页面（离线，无 CDN）
   ├─ rules\default_rules.json  ← 内置规则（首次启动复制到 data\rules.json）
   ├─ modules\           ← 各板块（一个目录 = 一个板块，含 manifest.json）

   └─ 使用说明.md        ← 这份文档
```

**V1.1.04（2026-11-02）· 账面信息表：账号/开户行取数修正**

- **分组键补上账号**：原来按「主体 × 科目」归组，同一家公司同一个「银行存款」下挂多个账号时，不同账号的币别行会被混成一行、账号取 `max()` 也不对。现在按「主体 × 科目 × **账号**」归组（实测脱敏账套 161 个账号 → 161 行，与源表逐一对应，合计仍为 1,422,875,244.88）。

**V1.1.01（2026-11-02）· 原币按币别核对 + 期间过滤修复**

> 版本号体系调整：清洗阶段开发中，所有版本统一 **V1.1.xx**；清洗彻底完成后才到 V1.2.01。

- **修复期间过滤的字符串比较 bug（影响所有核对结果）**：期间列是 `1`…`12` 这种不补零月份时，字典序里 `"10" < "6"`，原来的 `period BETWEEN '1' AND '6'` 会把 10/11/12 月一起算进来。实测因此产生过一笔 13,443.39 的"假差异"（1A 公司 10/11/12 月各 4,481.13）。现在比较前统一 `lpad(period, 2, '0')`，`2026-01` 这类等长格式不受影响。

**v1.0.5（2026-10-26）**

- **导出 CSV / Excel 的表头改为中文**。库里仍然是英文标准列名（`acct_code`、`end_debit`），这样写 SQL 时含义明确、也不影响已有规则；但导出的文件第一行换成「科目编码」「期末借方」这类中文表头，发给同事或直接打开都不用再对照字典。
  - 手写 SQL 里自己起的别名（`SELECT acct_code AS 我的编码`）不会被翻译，原样带出。
  - 同一份 SQL 里出现两个同名列时，自动加 `(2)`、`(3)` 后缀区分。
  - 导出的 CSV 用中文表头后，**可以直接回灌本工具**并被自动识别上字段（实测 25 个字段全中）。
- 导出仍走"库内直接写文件"的方式，不把结果读进内存：50 万行导出 75 MB 用 0.2 秒。

**v1.0.4（2026-10-26）**

- 新增清洗动作 **「填充固定值」**：新增一列整列填同一个值。公司名称、币种这类"整张表共用一个值"的字段，用它补成标准列再去映射。

**v1.0.3（2026-10-26）**

- 修掉「应用清洗」后必现的报错 `Cannot read properties of undefined (reading 'length')`。原因是应用接口返回的数据里少了「原始样本」两个字段（只有试运行接口会带），界面渲染时读空值就崩了。
  影响范围要注意：**清洗其实已经成功落库了**，报错只发生在刷新界面那一步，所以看到报错时不要重复点，数据是好的。现在应用后会正常刷新并展示「清洗已应用」+ 前后对照。
- 顺带加固：应用流程改成「先落库、再渲染、渲染出错不回滚也不吞结果」，任何界面问题都不会再让人误判成清洗失败。
- 「试运行」的结果面板不再被误标成「清洗已应用」，两者标题区分开了。

**v1.0.2（2026-10-26）**

- 新增**数据清洗**步骤（第 2 步）。9 个原子动作：删空行、按关键词删行、整行去重、文本归一、编码补零、向下填充、科目级次推断、辅助核算拆分、勾稽校验。每个动作可单开关，支持内置配方、逐步试运行、前后对照。

**v1.0.1（2026-10-26）**

- 修掉一个会**整份文件都打不开**的致命问题：当 xlsx 里有**完全空白的工作表**（封面页、模板页、财务软件导出的空白首表、图表页）时，预览接口会对这张空表直接报错 `BinderException: No rows found in xlsx file`，导致整个文件的解析失败、连里面正常的表也导不进去。
  现在的处理：空表/图表页在「待导入」里灰着标成「空表（没有数据行）」并自动跳过，不再影响同一份文件里其它工作表；实在点它导入也会给一句人话提示，而不是一串英文异常。
- 单列工作表（只有 1 列数据）同样不会再被误判。
- 「全部导入（N 张）」只统计有效工作表，空表不计入。
